feat(debug-tree): 两帧结构对比读生命周期两端，不拿两棵截断的树相减

路线图里"两帧结构对比"一直挂着。最先排除两个看着省事的做法：

- 在 `tree()` 上加 `--since`：一个问题两种口径 —— `tree` 答"那一帧长什么样"，
  diff 答"两帧之间发生了什么"；
- 视图层取两次 `tree()` 相减：两份响应各被 `depth` / `limit` 截断，相减会把截断
  误读成"没变化"。

采纳独立查询 `StructureQuery::treeDiff()`：出生取 `f`、离开取 `g`、重建取区间内帧
记录的 `rebuilt`，都是写好的事实，不是两份投影的差。区间左开右闭 `(base, frame]`，
`diff(A,B)` 与 `diff(B,C)` 拼起来正好是 `diff(A,C)`，第 B 帧不重复算。

没有逐帧父 / 类型快照（A67 明说不做），所以移位与改型**不报** —— 报了就是拿现在
冒充当时；`coverage.structureSnapshot=false` 把边界写在结果里。三条不完整自报：
`unknownBirth` / `unknownGone`、起点早于 `Recorder::NODE_TTL_FRAMES`、重建区间缺帧；
合成 `complete`。帧记录提到、节点表已查不到的重建节点保留 id，类型留空并标
`known=false`，不编名字。空结果配上"不完整"不等于"没发生"。

`Recorder::NODE_TTL_FRAMES` 从 private 提 public 只为让审查面读保留期：常量不产生
机器码，写面方法面不变（A69 的读写分家不受影响）。

接入面：协议 `QUERY_SPECS` 一处声明 `treeDiff(base, frame, limit)`；门面一条分派，
`QuerySeamsTest` 的"单条 return"照样咬；CLI 新出口 `tree-diff` 与 `View\TreeDiff`
（`+` 出生 / `-` 离开 / `~` 重建，`Fit` 统一列宽）；Web 新路由 `/api/tree-diff`
与侧栏"两帧对比"面板，显式点"对比"才发请求，不跟轮询白拿数据。
`check-web-routes.php` 的路径正则补上连字符，否则真接上的路由被误报死路由。

判据 `TreeDiffTest` 10 条：出生只看 `f`、离开只看 `g`、相邻区间拼合、重建按帧聚合、
缺帧记录自报、未知重建节点保 id、未知出生不猜、未来帧 / 逆区间 / 显式 0、TTL 外自报、
limit 省行数。8 组变异全咬红（出生改从 `s` / 忽略离开 / 左端点含入 / 缺帧恒 0 /
未知出生当新增 / 未来帧不拒绝 / 未知重建丢行 / 离开左端点含入），每组前还原，
末尾复跑全绿。WebTest 加一条：Web 与 CLI 的 `rows` / `coverage` 逐值相同，
未来帧在 HTTP 上也明确拒绝。
