# `apps/` 应用总览

这里平铺 8 个工程目录（每个一个 `project.yml`）。**它们不是 8 个同类示例**，
按用途分四类——先看这张表，再决定该读哪个。

| 类别 | 目录 | 定位（摘自各自的 `project.yml`） | 给谁看 |
|---|---|---|---|
| **能力示例** | [`showcase/`](showcase/) | LayUI 式示例台；35 个页面，每页一个控件能力点 | 应用开发者 · 查控件怎么写 |
| | [`tutorial/`](tutorial/) | 从零写一个应用：hello / 计数器 / 浮层 / 异步四段 | 应用开发者 · 入门 |
| | [`users/`](users/) | M3 出口判据：值缝 / 动作缝 / 多页 / 表单 / 加速键 | 应用开发者 · 业务广度 |
| | [`watermark/`](watermark/) | 真实业务闭环：OSS 直传 + 异步任务 + 结果轮询 | 应用开发者 · 业务深度 |
| **最小出口判据** | [`hello/`](hello/) | M1 出口判据：一个窗口画出 "Hello Drift" | 构建链回归（非示例） |
| **量具** | [`bench/`](bench/) | v7 阶段 0 微基准：装箱 / 阶段耗时（不是能力示例） | 框架维护者 |
| | [`pacing/`](pacing/) | 帧节奏量具：真窗口量 `waitEvents()` 间隔分布 | 框架维护者 |
| **开发工具** | [`dev/`](dev/) | 开发态壳：桥接静态编译，业务 PHP 运行期动态加载 | 框架维护者 |

## 为什么量具 / 工具也在这里

构建工具只认 `apps/<名字>/project.yml` 这一条路径约定（`drift-build` / `drift-codegen` /
`gen-version` 都按它 glob）。量具与开发壳住在 `apps/` 是工具约束，不代表它们是示例——
`bench/` 的 `project.yml` 里就明写"别拿它当示例读"。

## 常见误区

- **"应用太多，能不能合并？"** —— 不能。四类的验证职责各不相同，合并会毁掉各自判据；
  详见 [`docs/REVIEW-示例应用整合-2026-11-16.md`](../docs/REVIEW-示例应用整合-2026-11-16.md)。
- **"要不要改名叫 `examples/`？"** —— 不。`apps/` 与 `examples/` 都是成熟惯例，
  这里只有 4/8 是示例，改名反而把量具塞进"示例"目录；
  详见 [`docs/DECISION-apps目录命名-2026-11-16.md`](../docs/DECISION-apps目录命名-2026-11-16.md)。

> 本表是定位导航，不写设计内容；各应用细节读各自的 `project.yml` 与源码。
