# B7：出口注册表——把「手册」变成 schema 的视图

> 上轮推荐「统一出口手册：让总入口从各出口 schema 聚合生成」。实测后发现这个推荐
> 只说对了一半：分裂不止在动词表，两级 `--help` 走的是两条完全独立的路径，且
> 总帮助里还藏着第二份手写动词表——它已经漏了 `loop`。

## 一、证伪三件事

### 1. 动词表不是一份，是两份，而且已经不同

`bin/drift` 的 `$debug` 闭包里有一张 12 项 `$verbs`（`brief … loop`）；文件末尾的
总帮助 nowdoc 里另有一张 11 项的手写列表。上一轮我加 `loop` 时改了前者和注释里的
「十二个出口」，**忘了后者**。

实测 `php bin/drift help` 的输出里没有 `loop`。两个后果：

- 开发者从总入口看不到最新出口，只能去读源码；
- 两张表的描述措辞还不一样（`report` 在总帮助里多了「旧写法仍可用」的括注），
  谁也不知道哪句是新的。

这不是「将来可能漂」，是已经漂了。手写清单的代价不在写的时候，在加东西的时候。

### 2. 两级 `--help` 是两条独立路径，输出差 20 行

```
php tools/debug-brief.php --help     → 27 行，schema 生成的完整选项表
php bin/drift debug brief --help     →  7 行，正则从 docblock 抠「用法：」段 + 一句「完整参数见…」
```

总入口的 `$usage()` 用 `preg_match('/\n \* (用法：…)/')` 读脚本文档块。它不认识
`OptionSet`，所以：

- schema 上新加的参数，从总入口问帮助永远看不见；
- docblock 里的示例写了已改名的参数，没有任何判据会发现；
- 同一个问题「brief 有哪些参数」，从两个入口问到两份不同答案。

上轮说「help 从 schema 生成」只对**出口自己的** `--help` 成立。总入口那条路没动过。

### 3. 只从 `Commands::extras()` 聚合会漏掉两个出口

`Commands::extras()` 有 10 项（驱动出口）。`ctl` 与 `host` 不在里面——前者是控制面、
后者是 stdio 进程，都不解析驱动词表。若把 `extras()` 当动词表，总帮助会从 12 项变成
10 项，而且「新增一个出口忘了注册」仍然咬不住：注册这件事还是散在 `bin/drift` 的
`$verbs` 里。

`ctl` 的 `--frames=N` 与 driver 的 `--frames=N` 语义还不同（「走 N 帧再停」vs「驱动
N 帧」）。B6 的 schema 管不到它，正因为它在 schema 外面。这个分裂本轮**不消除**
（见 §四），但要让它在一个注册表里可见，而不是藏在两份清单的缝里。

## 二、方案比较

| 方案 | 做法 | 为什么否决 / 采纳 |
|---|---|---|
| A. 只把总帮助的参数段从 schema 生成 | 改 `bin/drift` 一处 | 治标：两张动词表仍是两张，两级 help 仍是两条路径 |
| B. **出口注册表作为唯一真相** | 每个出口声明一次 `{动词, 脚本, 摘要, 类别}`，所有手册从它派生 | **采纳**。动词、脚本、描述、分发四件事一次声明；与 cobra 的 `Command.Use/Short` + click 的 `get_help()` 同构 |
| C. 扫描 `tools/debug-*.php` 自动发现 | 运行时目录扫描 | PHP 没有自注册魔法：要么 require 每个文件（有副作用），要么从注释解析（等于另一种手写）。还会捡到临时脚本 |
| D. 生成 markdown 手册交给 `doccheck` | 写一份 `docs/reference/debug.md` | `doccheck` 只查链接/结构，不查语义；多一份生成物不等于多一个判据 |

B 与 A 的差别不是「多做一个」，而是把不变量从「参数表别漏」升级成「**出口清单只有一份**」。
后者才同时覆盖 §1 和 §3。

## 三、三条裁决

### 1. `Registry` 是出口元数据的唯一声明处

`tools/Debug/Cli/Registry.php` 声明 12 项：`verb / script / about / kind`。
`kind` 只有两个值：`driver`（10 项，走 schema）与 `protocol`（`ctl` / `host`）。

`bin/drift` 不再持有 `$verbs` 数组：分发、动词清单、总帮助里的子列表全部读注册表。

### 2. 两级 `--help` 同源，且只有一处生成

新增 `Commands::helpFor(string $verb)`：**用法示例（从脚本文档块抠一次）+ schema 选项表**。

- 出口自己的 `--help`（`Commands::parseOrExit`）调它；
- `drift debug <verb> --help` 也调它。

判据逐字节比对两者。这是「新增参数忘了写文档」的真正落点：参数表从 schema 来，
不是从人会忘记更新的散文来。示例仍是散文，但判据要求示例里出现的每个 `--opt`
都在 schema 里声明——示例可以短，不能过期。

`protocol` 出口没有 schema 参数，`helpFor()` 对它们仍走文档块（行为不变）。

### 3. 总帮助的 debug 段用占位符生成，不再手抄

nowdoc 里放一行 `__DRIFT_DEBUG_VERBS__`，输出前替换成注册表生成的列表。
不把整个 nowdoc 改成可插值字符串：那里面以后加一个 `$` 就会变成静默的插值 bug。

`drift debug --help` 与总帮助的动词表都从 `Registry::lines($indent)` 出，缩进不同、
内容同源。

## 四、`ctl --frames` 的分裂本轮不消除

它的语义是「走 N 帧再停」，driver 的是「驱动 N 帧」——虽然都是帧数，但动作的主体不同。
改名成 `--step` 更准，但会动到协议工具的手工流程和文档，而本轮的目标是**发现权**
（让每个出口在注册表里可见），不是重写控制面。记在欠账里，不夹带。

## 五、判据

| # | 判据 | 防的是什么 |
|---|---|---|
| 1 | 注册表动词集合 == `tools/debug-*.php` 的文件集合 | 新增出口忘了注册 / 注册了没写脚本 |
| 2 | 每项 `script` 文件存在 | 注册表指向空气 |
| 3 | 总帮助列出的动词 == 注册表，描述逐字相同 | 第二份手写表漏 `loop`（已发生） |
| 4 | `drift debug --help` 每项描述 == 注册表 | 两份清单措辞漂移 |
| 5 | `drift debug <verb> --help` == 出口自己 `--help`，10 个 driver 出口逐字节相同 | 两级 help 分裂（已发生） |
| 6 | 两级 help 都含 schema 声明的全部选项 | 新增参数忘了写文档 |
| 7 | 示例里的 `--opt` 都在 schema 里 | 示例用了已改名/已删除的词 |
| 8 | `drift debug <verb>` 分发到注册表指定的脚本 | 分发表与手册表各说各话 |
| 9 | `ctl` / `host` 在注册表里且 `help` 非空 | 只从 `extras()` 聚合漏掉协议出口 |
| 10 | 未知动词列清单并以 2 退出 | 收敛入口不能靠猜 |

## 六、破坏性说明

`drift debug <verb> --help` 的输出从「几行示例」变成「示例 + 完整选项表」。
旧行为没有丢信息（示例保留），只是多了一份本来就该在那里的参数表。
`tools/debug-*.php --help` 输出不变（只加示例前缀，若 docblock 有用法段）。
