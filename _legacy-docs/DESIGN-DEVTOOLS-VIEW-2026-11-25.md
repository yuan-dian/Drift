# DevTools 视面重设计：给证据一个画布

> 裁决稿。回答一个问题：为什么证据这么精确，用起来却不像 DevTools。
> 结论不是"再加几个面板"，而是**补上成熟 GUI DevTools 的第一性要素——同一份渲染结果**。
> 机制细节见 [debug-model](../docs/concepts/debug-model.md) / [evidence-model](../docs/concepts/evidence-model.md)；
> 本文只回答形态与顺序。

## 一、诊断：不是能力不足，是形态错配

现有实现的能力已经在多数 GUI 框架之上：因果是精确记录的（不是采样推断）、几何带约束传播链、重画带层缓存归因、重放是重新执行、证据包可导出可交叉验证。这些连 Chrome DevTools 都没有。

但用户的原话是"没有 main 分支直观""点了可以有信息显示""跑偏了"。这不是嫌功能少，是**形态不对**。

数一下出口构成（`tools/Debug/Cli/Registry.php:27-45`，18 条）：

| 类别 | 数量 | 形态 |
|---|---|---|
| 宿主侧（host / serve / ctl） | 3 | 无界面 |
| 消费者 | 15 | 其中 **14 个纯文本**，1 个可视化（web） |

投入比 14:1，而真实使用比应该反过来。原因不是前 14 个写错了——它们各自都对，`cascade` / `constraints` / `repaints` 甚至是这套系统最值钱的部分——而是**它们全部回答"事后某一问"，没有一个回答"现在长什么样"**。

后果是证据越精确，人越难信。系统说"node 42 在 (100, 200, 80, 32)"，用户无法用眼睛验证这句话对应屏幕上哪一块。**不可验证的精确，等于不可信。**

## 二、成熟工具的三角

把五个成熟参照摆在一起，它们做的其实是同一件事：

| 工具 | 渲染结果（第一角） | 树（第二角） | 坐标归属（第三角） |
|---|---|---|---|
| Chrome DevTools | 页面本身就是 | DOM 树 | box model 三层高亮 |
| Flutter Inspector | 真机画面镜像 | Widget 树 | 真窗口点选 ↔ 树双向同步 |
| Android Layout Inspector | 应用截图 | View 树 | 点画布选中节点 |
| Qt GammaRay | 远程画面 | 对象树 | 属性面板实时联动 |
| Spy++ | 窗口高亮框 | 窗口/线程树 | 命中链 |

五者无一例外。**没有"画面"这一角的工具不存在。**

Drift 现在有第二角（`boxes` 平铺带 `parent`，能拼树）、有第三角（`pick` 的命中链、`boxModel`、`highlight`）、唯独第一角缺席。这就是"不直观"的全部原因——不是树不够好，是**你告诉用户一个坐标，却不给他看那块像素**。

## 三、为什么画面一直缺席

不是疏忽，是架构偏见。

证据有四条纪律：确定性、可跨进程、可断言、进包。而"画面"四条全违反：会过期、跨进程要传字节、像素不可断言、体积压不进包。于是系统只留下了能进证据的那一具残影——**几何**。

`/api/boxes` 返回的是矩形，`draw()`（`tools/Debug/View/web/app.js:250-308`）拿这些矩形在浏览器 canvas 上描空框。这是几何的必然归宿：**几何能进证据，像素不能，所以屏幕上只剩几何。**

于是设计的第一条结论：

> **画面要成为一等类型，但它永远不是证据。**

这两件事必须同时成立。只承认前半句会污染基线（像素噪声让 `--assert` 天天红）；只承认后半句就是今天这样（画面进不了系统）。

## 四、目标形态

单页四区，共用同一个 `frame` 号：

```
┌─────────────┬──────────────────────────┬─────────────────┐
│ 树           │ 画布                      │ 检查器           │
│ Element 树   │  应用当前画面（矢量）       │ boxModel        │
│  ├ Widget    │  + 选中框 / 内边距 / 外边距 │ 约束传播链       │
│  ├ Box       │  + hover 祖先链            │ 重画归因         │
│  └ 因果树    │                          │ 属性 / 状态      │
├─────────────┴──────────────────────────┴─────────────────┤
│ 时间轴：帧环 scrub，画布/树/检查器同时跳                       │
└──────────────────────────────────────────────────────────┘
```

四条交互契约（这是"像 DevTools"的定义，缺一条就不能叫 DevTools）：

1. **画布点一下 → 树展开到该节点，检查器跟上**（`pick` 已有坐标命中链，缺的是把它接到画布上）
2. **树点一下 → 画布上该节点自己画的像素高亮**（不是画一个几何框估算，是这一节点的绘制命令重画一遍）
3. **时间轴拖一下 → 三区同步跳帧**（帧号是三区唯一的对齐键）
4. **检查器里读到的每个数，都能在画布上指出来**（反过来也成立：画布上看到的每块像素，都能查它是谁画的）

第 4 条是这套设计区别于普通"预览窗口"的地方——它把已有的证据面和新的画面面**互相钉死**。

## 五、分层与边界纪律

新增一层，与 L1 证据**并列、不交叉**：

```text
L3 消费者     Web 单页四区（主）        CLI 15 出口（可脚本化 / CI / 可复制）
                    |                          |
V2 投影       SVG 文档（带 data-node）     ——
                    |
V1 视面       一帧 IR：命令流 + 节点归属   ——
                    |
V0 采集       TeeCanvas（仅订阅时录制）    ——
                    |
L1 证据       FrameStore / GeometryStore / NetworkStore / ...（不动）
```

纪律四条，全部可检查：

1. **视面不进包**：IR 不进 `Evidence`、不进 `Digest`、不参与 `Baseline`。理由：像素或命令流的抖动会让基线判据假红，而基线是这套系统唯一能进 CI 的东西。
2. **视面可丢**：帧环只留 N 帧（建议 120），丢帧不影响任何证据查询。
3. **帧号是唯一对齐键**：三区读同一个 `frame`，不允许"树是第 49 帧、画布是第 58 帧"。
4. **采集只在订阅时打开**：没有观察者时 `TeeCanvas` 不挂载，生产零成本。这条沿用 `paint` 已有的"观察者存在才记账"形态。

### 视面对采集的要求：末帧全量，不是变化量

现有 live 几何是 `Changed` 语义（`RecordOptions::resident()`），静止时不再采样——实测只采到第 1、49 帧。几何这样做是对的（省），但**视面要的是"最后一帧的完整画面"，不是"这一帧变了什么"**。

所以采集要为视面单独满足一条：**订阅期间每帧落一份全量几何 + 全量 IR**，代价用"只在订阅时"限住。这不是给现有采集加开关，而是承认两类消费者对采集的要求本质不同：

| | 证据 | 视面 |
|---|---|---|
| 要什么 | 变化（省，O(变化量)） | 末帧全量（全，O(节点数)） |
| 何时采 | 一直 | 仅订阅 |
| 可丢 | 否 | 是 |
| 进包 | 是 | 否 |

把这条写进文档，是因为不写清楚，下次一定有人想"优化"成复用同一份采集，然后画面又只出两帧。

### 画面怎么送：IR → SVG，不用像素

理由（详见上一轮评估）：IR 是矢量的、自足的（`LayerCache` 命中是完整重放，`src/Rendering/LayerCache.php:54-62`）、带排版权威（`Glyph` 有 `codepoint/advance/offsetX`，`src/Text/Glyph.php:17-24`，浏览器不重排所以不漂）、跨进程可传、无平台像素 API。

- 像素（`RasterCanvas::toRgba()` / `SkiaCanvas::toRgba()`）：保真但是死的，不可缩放、不可按节点过滤、默认后端刻意不让像素进 PHP（`src/Platform/Win32/Win32SkiaSurface.php:110`）。
- IR：可缩放、可按 `data-node` 高亮、可存档 diff、可翻历史帧。抗锯齿与字体 hinting 与真机有差，**所以它不是证据，永远不替代 golden**。

这条边界写死：**golden 归 Raster，视面归 SVG。**

## 六、对标矩阵

| 能力 | Chrome | Flutter | Android LI | **Drift 现状** |
|---|---|---|---|---|
| 实时画面 | 页面本身 | 真机镜像 | 截图 | **无** |
| 树形浏览 | DOM | Widget | View | 无（`boxes` 平铺，`app.js` 只有下钻） |
| 画布 → 树 | 有 | 有 | 有 | 半（`pick` 有命中链，没接到画布） |
| 树 → 画布高亮 | 有 | 有 | 有 | 有（`highlight` 一次一个节点，靠真窗口描边） |
| 框模型三色叠层 | 有 | 有 | 有 | 有查询（`boxModel`），无呈现 |
| 属性面板 | 可编辑 | 只读 | 只读 | 有查询（`props`），无入口 |
| 帧时间轴 | Performance 录制 | 有 scrub | 快照切换 | 有 `frames`，无视图 |
| 重绘 / layer 归因 | Paint flashing、Layers | Repaint rainbow | 无 | **有，且带未命中原因** |
| 布局约束链 | 无（CSS 声明式） | Layout Explorer | 有 | **有逐跳复算，领先** |
| 因果（谁写、谁重建、父传播） | initiator 估算 | rebuild stats | 无 | **有精确边，领先** |
| 可断言的基线回归 | 无 | 无 | 无 | **独有** |
| 编辑热改 | 有 | 有 | 无 | `eval` 逃生门 |
| 接入真实应用 | 天生 | 天生 | 天生 | **不能（白名单，`tools/Debug/Target.php:72-84`）** |

读法：右三行（因果、约束、基线）是**领先**，左四行（画面、树、点选、时间轴）是**结构性缺失**。所以重设计的重点不在补深度，在补浅层——**把已经领先的证据接到一个看得见的表面上**。

## 七、分期与判据

每期都有可证伪判据，按项目惯例配源码级变异自检（改坏一处，判据必须咬红）。

### P0 接入：先让它能调试真实应用

现状：`Target::resolve()` 只认 `Drift\Dev\Smoke\App\*` 与示例台路由白名单（`tools/Debug/Target.php:72-84`）；`--attach` 只在 2/18 出口声明（`tools/Debug/Cli/Commands.php:35,58`），8 个出口会报"未知参数"。

- 目标解析改为：先 `class_exists` 全名尝试，再走「已在运行的会话发现」（`.drift/session.json`），最后才回落到示例台。
- `--attach` 上提到 `OptionSet` 的公共段（与 `--from` / `--session` 同处），18 个出口一次全覆盖——`Source::resolve()` 已经实现了唯一一份逻辑，缺的只是声明。
- 判据：① 一个不在白名单的测试应用能被 `debug web` 驱动；② 一条命令扫全表，18 个出口对 `--attach` 的接受数 = 18（现在是 2）。
- 变异：故意让一个出口不声明 `--attach`，扫描判据红。

### P1 画面：IR → SVG 进 web

- `DisplayList` → 中性 JSON：op 数字 + 参数，对象走引用表（`OP_DRAW_LIST` 是共享引用，不能当树展开），`Paragraph` 展开成 glyph 列表。
- 服务端生成 SVG（不在浏览器写 19 op 重绘器）。
- 判据（硬）：同一帧分别走「直接 replay 到 Raster」与「导出 JSON → 解析回来 → replay 到 Raster」，两次 `toRgba()` **逐字节相等**。序列化丢任何一个字段，这条立刻红。
- 判据（覆盖）：19 种 op 每种至少被一帧用到并正确还原，漏一种即红（可复用 `DisplayListOpCoverageTest` 的形态）。
- 变异：故意漏 `OP_DRAW_ELLIPSE` 的半径参数 → 字节判据红。

### P2 归属：树 ↔ 画布双向

- 录制时补节点归属：`RecordingCanvas` 加"当前节点"，命令带上 node 号；只在订阅时开。
- 判据：选中 node 42 时，SVG 里 `data-node="42"` 的元素数与「`paint` 查询里 node 42 真画的命令数」一致；不是 0 也不是全部。
- 变异：故意让归属错一层（子节点命令记到父），判据红。

### P3 时间轴：帧环 scrub

- 帧环 120 帧，三区同步跳。
- 判据：scrub 到第 N 帧，树/画布/检查器自报的 frame 号三者相等；且丢掉第 N-1 帧后证据查询不受影响（视面可丢的验证）。
- 变异：让画布读 `frame+1`，判据红。

### P4 覆盖层与检查器

- 框模型三色叠层（内容/内边距/外边距）、hover 祖先链（对齐 main 分支的蓝/黄框语义）。
- 检查器接上已有查询：`boxModel` / `constraints` / `paint` / `props`。
- 判据：画布上量到的内边距像素宽 = `boxModel` 的 padding 值（允许 1px 取整误差）；检查器显示的每个数与对应查询的 JSON 逐字段一致（不允许前端自己算派生值）。

## 八、不做

- **编辑热改**：AOT 编译 + 不可变树，实时改属性的成本收益比极差，且会让调试器变成第二个真相源。`eval` 已是逃生门。
- **像素保真承诺**：视面与真机必然有抗锯齿/字体差异。承诺"一模一样"就必然失信。golden 仍走 Raster。
- **在浏览器里实现渲染后端**：要自己复刻 clip 栈、layer 语义、预乘 alpha、抗锯齿近似，两份实现必然漂移。SVG 映射能拿到 90% 的收益，成本低一个数量级。
- **堆转储**：PHP 无此 API，已由 `memory` 的存活跨度定格（A55）。

## 九、与现有路线图的关系

`docs/concepts/debugger-roadmap.md` 把 Web 视图记为「切片：缺树、时间轴」。本稿修正这个判断的两处：

1. **缺画面是第一因，缺树与时间轴是第二因**。先补树会得到一个「有树但没有画面」的产品，仍然不直观——这正是当初的坑。
2. **顺序调整**：接入真实应用（P0）必须在画面之前。否则画面再漂亮，也只能看示例台。

其余判断（采集预算、编译归属、内省归 PHP）不变，本稿不推翻它们。

## 附：一句话

成熟 DevTools 的共性是「树在某处、画面在某处、两者用坐标绑定」。Drift 已经有两角且都比同行精确，缺的只是第三角——而它恰好是被证据纪律排除在外的那一角。
