# 04 · 绘制与双后端

## 1. 一句话

绘制是 `Canvas` 接口的扁平 op 流：节点 `paint($canvas)` 直接画，`canvas` 在画每个子盒前已
`translate` 到盒原点，所以 `paint` 内部以 (0,0) 为盒左上角。

**生产路径不录制**：`Frame::run()` 把 `beginFrame()` 返回的画布直接递给 `paintComposed()`，
真机是 `SkiaCanvas`、无窗预览是 `RasterCanvas`，都不经过 `DisplayList`。录制只用于
`LayerCache` 重绘边界、测试夹具与 golden。

三个实现：`SkiaCanvas`（真 Skia 后端）/ `RasterCanvas`（纯 PHP 软光栅，测试与 golden 基础）/
`RecordingCanvas`（录成 `DisplayList` 供回放）。`Canvas` 现有 18 个绘制/状态方法 +
1 个帧末自证，`DisplayList` 有 17 个 `OP_*`。

## 2. `Canvas` 接口（`src/Rendering/Canvas.php`）

| 方法 | 说明 |
|---|---|
| `save()` / `restore()` | 状态作用域；块内的裁剪 / 层必须显式配对，回收时机由后端自证 |
| `translate(float,float)` | 改 PHP 侧 offset，**从不调 Skia**——每个 draw 自己把偏移加进坐标 |
| `transform(Matrix2D)` | 真仿射才切坐标模式、下推 Skia CTM；纯平移走 `translate()` 快路 |
| `pushClip(Rect)` / `popClip()` | 裁剪栈 |
| `pushClipPath(Path)` | Extended：复用 `popClip()` 的裁剪栈 |
| `drawRect(Rect, Paint, radius=0)` | 直角/圆角 |
| `drawParagraph(Paragraph, Paint, x, y)` | 文本；段里存 `Paragraph` 引用，字形位图在回放时才产生 |
| `drawEllipse(Rect, Paint)` / `drawLine(...)` | Core |
| `drawPath(Path, Paint)` / `drawImage(...)` | Extended / 双端支持 |
| `drawShadow(Shadow)` | Optional：当前仅 Skia |
| `pushLayer(opacity)` / `popLayer()` | 合成层；层深计入配平断言 |
| `blurBackdrop(sigma, rect)` | Extended：Raster 近似为不模糊 |
| `capabilities(): int` | 能力位掩码，调用方查一次 |
| `assertFrameBalanced(): void` | 帧末自证：未配对的状态压栈必须归零 |

★ 坐标纪律：`translate()` 只改 PHP 侧 `offsetX/offsetY`，**绝不调 Skia**——每个 draw 必须自己把
偏移加进坐标。新 op 照"几何走画布 translate()"写 ⇒ 落在画布原点、被盒裁掉 ⇒ 真机**完全无墨**
而解释器全过。

★ 状态栈纪律：Skia 侧只有**一条** `SkCanvas` 保存栈（matrix 与 clip 同栈）：
`save`（变换锚点）/ `push_clip` / `push_clip_path` / `push_layer` 都压这一条，
`restore` / `pop_clip` / `pop_layer` 都弹这一条。`SkiaCanvas::$skiaDepth` 是它的 PHP
侧镜像，`restore()` 按 `save()` 记下的栈深一次性退回（等价 Skia / Android 的
`restoreToCount`）。`RasterCanvas` 则是变换 / 裁剪 / 层三条独立栈。接口只要求
"帧末回到基线 + 调用方显式配对"，不规定内部栈数；把任一实现的多栈模型写进接口
会让另一侧的帧末自证失去依据。

## 3. 能力唯一真相源

`CanvasCapabilities::CAP_*`（10 位）是唯一事实源；各后端支持情况由
`RasterCanvas::supportedCapabilities()` 与 `SkiaCanvas::capabilities()` 的返回值给出：

| 位 | RasterCanvas | SkiaCanvas |
|---|---|---|
| `CAP_ELLIPSE` / `CAP_LINE` / `CAP_GRADIENT` / `CAP_DASH` / `CAP_CLIP_PATH` / `CAP_PATH` / `CAP_LAYER` / `CAP_BACKDROP` / `CAP_IMAGE` | 支持（Extended 层允许降级近似） | 支持 |
| `CAP_SHADOW` | **不支持**（`drawShadow` 响亮失败） | 支持 |

`RECT` / `TEXT` / `SAVE` / `CLIP_RECT` 等原语所有后端无条件支持，不在掩码里。
`CustomPaint` 拿到画布时查一次 `capabilities()`，不在每次绘制时查。

★ **位只回答「能不能发起这个 op」，不回答画得像不像。** 三种语义必须分开：

| 语义 | 含义 | 位 |
|---|---|---|
| `exact` | 两后端同义 | `CAP_ELLIPSE` / `CAP_LINE` |
| `approx` | Raster **置位但产出是降级近似**：虚线退实线、硬边路径、层用 alpha 乘数、`blurBackdrop` 空实现、图像最近邻 blit | `CAP_GRADIENT` / `CAP_DASH` / `CAP_CLIP_PATH` / `CAP_PATH` / `CAP_LAYER` / `CAP_BACKDROP` / `CAP_IMAGE` |
| `optional` | Raster 缺位，由 `ShadowPainter` 降级形状 | `CAP_SHADOW` |

把「近似」当「支持」读，调用方会以为查过位两后端就等价 —— 这正是 golden 只跑
Raster 时验不出画质差异的病根。Qt `QPaintEngine::hasFeature()` 同样只回答
「引擎有没有」，不支持的由上层 best effort 模拟。逐位的两后端回答与语义登记在
`tests/Unit/Rendering/CanvasCapabilityContractTest.php` 的 `CONTRACT`，新增位不登记即红。

缺位时怎么处置**由调用方决定**：`ShadowPainter` 降级形状、`RenderImage` 跳过这一笔、
不查位直接发 Optional op 才 `unsupportedOp` 响亮失败。别把三者写成同一条规则。

★ 历史文档里的「19 op」是含 `GRADIENT` / `DASH` 两个 Paint 源属性的历史计数口径，
不是 `Canvas` 方法数；「14 op / 14 方法」为过期数字，以本节的常量表与 §6 的 `grep` 为准。

## 4. 静默失败闸门

- `DisplayList::record()` 拒绝未知 op（要求 `OP_*` 值域连续）。
- `DisplayList::replay()` 的 `else` 对未处理 op 响亮失败——新增 op 漏补分支不会静默丢像素。
- `DisplayList::assertBalanced()` 查 save / clip / layer 三种栈深；`LayerCache::endRecord()`
  在回放前调用，生产录制路径因此也有帧末兜底。
- `Canvas::assertFrameBalanced()` 由 `Frame::run()` 在 `endFrame()` 前调用，补上**直接画路径**
  没有 DisplayList 的那一半：`SkiaCanvas` 查变换栈 + Skia 保存栈镜像深度 + 设备模式，
  `RasterCanvas` 查变换/裁剪/层三条栈，`RecordingCanvas` 转发给 `DisplayList::assertBalanced()`。
  两个后端都要求帧末回到帧初基线，但内部栈数不同：漏弹的层在 Skia 侧由配对的
  `restore()` 提前收回，在 Raster 侧留到帧末报错。
- 静态对账判据 `tests/Unit/Rendering/DisplayListOpCoverageTest.php` 钉住「`OP_*` 集合 =
  `replay()` 分支集合 = `record()` 白名单」，新增 op 漏一处即红。
- `tests/Unit/Rendering/SkiaFrameBalanceTest.php` 钉住 Skia 单栈镜像：未配对场景必须
  响亮失败，配对的 `restore()` 必须把块内未闭合层退回。

### 4.1 为什么不引入「作用域块 / 回调式状态」（2026-11-15 裁决）

跨平台 RHI 文章提出「把状态提升为一级对象，一次声明一整组」。同理可问：
`save / pushClip / pushLayer` 全靠调用方显式配对，能否改成 `withClip(Rect, callable)`
或把作用域做成一条 op，从结构上消除漏 pop？**裁决：不做。**

1. **成熟框架不是这么用的**：Flutter `PaintingContext.pushClipRect(..., painter)` 的
   回调是为了**跨合成层换画布**（官方文档写明画子节点前后 canvas 可能变），不是防漏
   pop；同一份官方 `RenderParagraph.paint()` 仍裸用 `save() → clipRect() → restore()`。
   Skia 侧对应的是 `SkAutoCanvasRestore` 这类 RAII，PHP 没有等价的确定性析构。
2. **静默失败已被结构性堵住**：上面三道闸门 + `Canvas::assertFrameBalanced()` 帧末自证
   + `DisplayListOpCoverageTest` 静态对账，漏弹是**响亮失败**而非丢像素。
3. **改动面与收益不成比例**：新增 scope op 要同步 `DisplayList` 常量 / 白名单 /
   `replay()`、`PaintFingerprint::OP_NAMES`、`LayerCache`、golden 基准、三个 Canvas
   实现、二十余处生产配对以及十余条 `opAt()` 下标判据，合计 36–40 个文件；
   而 `callable` 在 AOT 下退化为 `php::Var`，回调式语法糖另有编译期风险。

替代落地：`DisplayListOpCoverageTest` 新增「`Canvas` 的 7 个栈方法 ↔ `record()` 的
7 个栈 op」对账，守的是「新增栈方法漏 op」这个真会静默失效的方向。
**复核条件**：增加第三个渲染后端，或命令流开始跨帧携带未配对状态时重新评估。

## 5. 确定性：录制-回放（**测试与预览路径**）

`RecordingCanvas` 把 `paint()` 的命令录进 `DisplayList`，再 `replay()` 到目标后端
（`RasterCanvas` 或 `SkiaCanvas`）。同一份命令两后端出相同像素（golden 可比性的基础）。

★ 录制层的能力位必须等于回放端：`RecordingCanvas` 默认取
`RasterCanvas::supportedCapabilities()`（离屏回放的典型端）；要"全录"的调用方显式传
`CanvasCapabilities::ALL_MASK`。显式全录会记下 `drawShadow`，回放端若是 Raster 就
`unsupportedOp` 响亮失败。

## 6. 验证口径

```bash
# Canvas 的 public 方法数（应为 19：18 绘制/状态 + 1 帧末自证）
grep -c "public function" src/Rendering/Canvas.php

# op 常量数（应为 17）
grep -c "const int OP_" src/Rendering/DisplayList.php

# 能力位数（应为 10）
grep -c "const int CAP_" src/Rendering/CanvasCapabilities.php

# 三个 Canvas 实现
grep -rln "implements Canvas" src/Rendering/

# 静态对账判据
php vendor/bin/phpunit -c phpunit.xml --filter DisplayListOpCoverage

# 能力位契约（每位的两后端回答 + 语义分类）
php vendor/bin/phpunit -c phpunit.xml --filter CanvasCapabilityContractTest

# 层缓存命中判据含回放端能力位
php vendor/bin/phpunit -c phpunit.xml --filter LayerCacheCapabilityTest
```
