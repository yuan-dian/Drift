## 0. 一句话

**Drift 的骨架不用换，要换的是三处"只有一个消费者时定下的形状"。**

这三处形状各自逼出了一整类补丁：

| 形状 | 当时唯一消费者 | 第二个消费者一来就崩 |
|---|---|---|
| 浮层 = 一个槽位 | 菜单 | 模态（已经互斥）→ Select 下拉 / Tooltip / DatePicker **无处安放** |
| 修饰 = 一个包装节点 | `Padding` | 每个修饰都要 1 个 Widget + 1 个 Element + 1 个 RenderBox + 1 遍 measure + 1 份 `intrinsic*` |
| 能力 = Skia 有就行 | 真机渲染 | Raster（preview/golden/smoke 全走它）画不出路径 → 控件自绘被锁死在 `drawRect/drawEllipse/drawLine` |

⇒ 本方案的全部内容，就是把这三处形状换成"第二个消费者已经存在"的形状。

## 1. 勘误：上一份报告的两条判断是错的

**必须写在最前面，因为它会改变优先级。**

上一份报告 `ARCH-REVIEW-2026-10-21.md` 提出 **B5（死命令 lint）** 与 **B7（lint 反例自检）**，
并据 G1「死命令可构建期校验」判定"自己的原则没兑现"。**这个判定是错的，两条都已经存在。**

### 1.1 事实

| 报告说 | 实际 |
|---|---|
| 「`tools/lint.php` 里 command/dead 零命中 ⇒ 规则从未实现」 | 规则在 `tools/Lint/Rules/DeadCommand.php`（209 行），**双向检查**：发出的名字必须在注册集、注册集里每条必须被发出 |
| 「反例自检是手工的，规则坏了没人知道」 | `tools/selftest.php` 就是双向自检：**该响会响 + 不该响不误响**，且额外检查"某条规则产出了发现但没配夹具断言" |
| 「lint 里零命中」 | `php tools/lint.php --list` = **15 条规则**；`--selftest` = **15/15 ok**（本轮实测） |

`DeadCommand` 甚至自己记了一次"规则空转"事故（`:181-183`）：

```
★ `=>` 是 **T_DOUBLE_ARROW 令牌**（不是两个原始字符）—— 2026-10-16 修：
  原先比原始字符串 `'=>'` ⇒ 恒假 ⇒ 整条 `commands()` 声明式注册的提取
  是**空转**的（`apps/users` 一落地就当场露馅：七条命令全被报"死命令"）。
```

⇒ **Drift 不但做了这条规则，还自己踩过"规则空转"并补了自检来防它。**
这比 v6 的 `spec/13` D-F1（`lint --self-check`）要求更严（v6 只要"该响会响"，
Drift 还要"不该响不误响"）。

### 1.2 我为什么会错

`grep -c -i "command" tools/lint.php` = 0。但 `tools/lint.php` 只有 1321 字节，
它只是引导器（`require autoload` + 分发 `--list/--selftest`），规则在 `tools/Lint/Rules/*.php`。

> **判据（新增，进 MEMORY）：** 对"某能力有没有实现"下结论前，
> **先 `ls` 那个目录**，再 grep。在引导文件里 grep 出 0 命中，只能证明引导文件里没有。

### 1.3 对方案的影响

| 原条目 | 处置 |
|---|---|
| **B5 死命令 lint** | **删除**（已存在，且比提案更完整） |
| **B7 lint 反例自检** | **删除**（已存在，且是双向的） |
| 报告 §2.5「修正二」的结论 | **撤回**。G1 已兑现，命令链的可检查性不缺 |
| 报告 §0 总账「该借未借 6 条」 | 降为 **5 条**（去掉 G1 那条） |

★ 但**新增一条真缺口**，是这次核实才发现的：
`DeadCommand` 只查"发出 ↔ 注册"的**配对**，不查"注册了但 handler 里没这个分支"。
`NavigationCommands::handleCommand()` 用 `str_starts_with($name, 'nav.')` 前缀分流
（`apps/users/src/Commands/NavigationCommands.php:23`），前缀**动态**路由，
静态不可判 —— 这是"宁漏不误响"的自觉取舍，记在 `07-可检查性.md` §4。

## 2. 原则（按优先级，冲突时上位压下行）

| # | 原则 | 落到什么 |
|---|---|---|
| **P1** | **形状优先于补丁** | 每一条改动都要回答"下一个消费者来了会不会再打补丁"；答不出就不做 |
| **P2** | **骨架不动** | 三棵树 / `settle→layout→paint→present` / 19 op / 双后端 / `int $kind`+`===` —— 全部保留 |
| **P3** | **单独可落地、单独可回滚** | 每一册对应一个提交序列，彼此不交叉；回滚 = revert 那一段 |
| **P4** | **出口判据必须机器可验** | 不写"手感更好"，写"`--selftest` 15/15 + smoke 936 + 真机 3 张图逐字节" |
| **P5** | **破坏兼容只用在"没有第三方"的地方** | 当前 0 个第三方应用；但 `apps/users` 必须始终可编译、可跑 |
| **P6** | **逃生口要难看** | 允许"全量重建"这类兜底，但要显式、难看、被 review 抓住（借 v6 01 §7） |

## 4. 与 v6 的关系：抄什么、不抄什么

v6.1（`Drift3/design-v6`，16 册 5699 行）是最成熟的一版。**它的方案层不能整体照搬**
（它是"从零重推"，Drift 是"演进"），但**它的判据层几乎全可抄**。

### 4.1 直接抄（判据 / 格式 / 事实）

| 抄什么 | 出处 | 落到 |
|---|---|---|
| **修饰是字段**（判据：*要不要自己的 `measure()`？*） | v6 `07` §3 / `11` D-05 | `02` 核心 |
| **`OverlayEntry` 九字段** + 四方向翻转 + anchor 消失自动弹 | v5 `design/08` §4.1 | `01` 核心 |

| **决策表格式**：决定了什么 / 否了什么 / **推翻条件** | v6 `11` | 每一册末尾 |

### 4.2 明确不抄（附理由）

| 不抄 | 理由 |
|---|---|
| **单树 `Node` + 无 rebuild**（v6 六个不变式之一） | 那是从零设计的红利；Drift 的三棵树 + 936 条 smoke 是资产。换成单树等于重写，收益是"少一层"，代价是全部验证作废 |
| **`ops` packed array 只写不读 + C++ 注册表** | 前提是"命令段长期住在节点上"（retained mode）。Drift 每帧重录，见 §5.2 |
| **`children` 用 `spl_object_id` 求最小操作序列** | 前提是"Node 可变、长期存在"。Drift 的 Widget 每次 build 新建，对象身份每帧都变 |
| **`#[\Native]` 几何对象** | Drift 已有 `final readonly class Size/BoxConstraints`。要不要改由 `08` §2 的实测决定，不凭文档改 |
| **`--nano` / Fiber 异步全套** | Drift 已选 `TaskHost`（进程）+ `SlicedJob` + `IoPoller` 三件，v6 的 Fiber 是另一条路。**判据抄（三问定位），机制不换** |
| **图标矢量路径 / 图片预算 / 字体子集** | 属资源域，与本次架构改造正交；记在 `05` §7 的"不碰" |

### 4.3 v6 自己承认的弱点（照抄时要知道）

v6 `11` §7「自我怀疑清单」自评最可能被推翻的七条，其中三条与我们要抄的判据直接相关：

1. **修饰是字段**：「一旦有人要"在任意节点上插入一个改变布局阶段的修饰"，字段方案就要开洞」。
   ⇒ 我们抄的时候必须同时抄它的开洞规则：**要自己 `measure()` 的才是节点**（`02` §2）。
2. **`Cell` 按类型分裂**：「真实代码里 `ObjCell` 用得最多，`IntCell`/`StrCell` 的收益可能
   不足以抵消"选哪个"的成本」。⇒ 我们先实测再分裂（`08` §3 V-3）。
3. **`ops` 只写不读**：调试路径变窄。⇒ 我们不抄（§5.2）。

## 5. 明确不做的（写下来免得再讨论）

| 提议 | 否决理由 | 出处 |
|---|---|---|
| **measure/place 两遍拆分** | 已判 no-op（`layout()` 位置无关）；要收益必须有尺寸缓存，缓存层判不做 | `EVAL-design-v7-2026-10-21.md` §7.1 |
| **retained 命令段 + 脏区光栅** | 3.14ms 端到端有 5.3× 余量；失效逻辑的复杂度正是 v6 要造自校验来兜的那一类。**等真有 60fps 压力再说**（触发条件写死：单帧 > 8ms 连续 10 帧） | `05` §8 |
| **命令改 int 派发** | 15 命令 / 52 处出现，按 `24` §5.3「30 以内不值得」判不做 | 既有裁决 |
| **GPUI 式 base/component 两层库** | 自绘单层、0 个第三方应用，没有"表现层可替换"的需求 | `ARCH-REVIEW` §5 |
| **Compose 式 `Modifier` 链** | AOT 下链式修饰退化为动态分派；且顺序有语义（`padding` 两次结果不同） | v6 `07` §3 |
| **把 `switch` 加回来** | C2440，不是口味 | 既有纪律 |
| **换单树（v6 形态）** | 见 §4.2 | — |

## 9. 取数口径

本册与后续九册引用的现状数字，全部可复算：

```bash
cd /d/TypePHP/Drift2

# 现状基线
find src -name '*.php' | wc -l                       # 223
grep -ro "★" src/ | wc -l                            # 974（每 27 行一条坑标记）
wc -l src/App/Application.php                        # 2192

# RenderBox 子类：20 个具体 + 1 个抽象（RenderProxyBox）
grep -rn "extends RenderBox\b\|extends RenderProxyBox" src/Layout/*.php | wc -l    # 21
grep -rln "extends RenderProxyBox" src/Layout/ | wc -l                              # 12 个代理盒

# 缺失的原语（Stack / Align / Wrap / Grid 全零）
ls src/Widget/ | grep -i "stack\|align\|wrap\|grid"   # 空

# readonly：187 处，其中几何/绘制值对象是 final readonly class
grep -rn "readonly" src/ | wc -l                     # 187
grep -rn "final readonly class" src/Geometry/ src/Rendering/

# 可空对象返回（v6 说会退化 Var）：9 处
grep -rn "): ?Size\|): ?RenderBox\|): ?RenderObject" src/ | wc -l                   # 9

# Cell 是 mixed
grep -n "mixed" src/State/Cell.php                   # :22 :32 :37 :49

# 每帧全量重录：beginFrame 每次 new Canvas
grep -n "function beginFrame" -A 8 src/Platform/Win32/Win32SkiaSurface.php

# 语义树每帧全量构建
sed -n '1199,1208p' src/App/Application.php

# lint：15 条规则 + 双向自检全绿
php tools/lint.php --list | wc -l                    # 15
php tools/lint.php --selftest                        # 15/15 ok

# C++ 仍写 using namespace php（v6 称为 Drift 的 D1 根因未修）
grep -rn "using namespace php" cpp-src/
```
