Drift —— TypePHP 声明式 GUI 框架 · 架构图

用 PHP 写界面，经 TypePHP AOT 编译为原生桌面应用。三树架构 + 自持布局与渲染 + 单 exe、无运行时。

三公理：编译器优先 · 绝不静默 · 确定性优先 PSR-4 分层 逻辑单位 DIP 全程 float Canvas 三后端 fluent + Seal-on-Mount 双缝：select 订阅 + CommandRouter 冒泡 UI 单线程亲和

01分层架构与依赖方向

依赖只能向下（实线箭头）。平台名只出现在每平台引导文件（组合根）——共享代码零平台引用；跨平台 = 同一份应用源码为每个 OS 各编译一次。

应用层（用户代码） 组合 / 主题 公共 API（稳定面） 引擎（可替换） 平台 / 应用宿主

02事件循环归属与线程模型

两条铁律：循环属于平台，派发属于框架；UI 单线程亲和，后台结果只能以事件回贴。

03三棵树与一帧生命周期

Widget 不可变描述 → Element 承载身份与 State → RenderObject 管几何与绘制。变更只在脏边界重建。

04UI 与业务隔离：两条缝

业务不认识 GUI；控件不认识业务。跨边界只有两条通道：值缝（数据→UI）与动作缝（UI→业务）。

05控件写法裁决：fluent-first + Seal-on-Mount

链式 ->title() 若 mutate + return $this 会让 Widget 可变，破坏三树 diff 的不可变前提。Seal-on-Mount：挂载即封存，封存后写入 ⇒ 响亮失败（G2）；封存幂等，同一实例复用到多处合法。

合法的 —— 不做 owner 校验（Widget 是纯描述，各处各有独立 Element） ③ lint 兜底：必填 modifier 未调用 / 死字段 / 命令无 handler / children 数组内重复同一根变量
可变窗口 不可变窗口 违规 ⇒ 响亮失败

06fluent 实现的实测裁决（不是推演）

探针 probes/fluent_cost/：N = 300,000 个「5 修饰」控件，-O2。结论：链式写法本身几乎免费，clone-with 贵 4.2× —— 所以采纳 mutate + 挂载即封存，并否决 ->build()。

clone-with（否决：4.2× 换掉一行 if） mutate + Seal-on-Mount（采纳） 纯构造器基线

为什么不加 ->build()

  • 名字硬冲突：StatelessWidget extends Widget 已声明 build(BuildContext $ctx): Widget。基类再加零参 build() = 不兼容覆盖 ⇒ PHP Fatal error
  • 要么到处都是、要么是装饰：强制则每节点一次；挂载自动则退化成 no-op，违反「要么不提供、要么必须生效」
  • 类型强制会翻倍类数：45 控件 × 2 类
  • 问题已有天然边界：「何时结束可变窗口」由挂载回答，不必再声明一次

替代品：->seal()，幂等且可选——不写也对，写了才省掉挂载时的封存判断。

类型化属性：手册旧记录已证伪

手册 §9.5/§9.15 记「属性进三元 ⇒ 推成 php::Variant ⇒ C2440」。探针 probes/typed_ternary/（--dry 查生成 C++）复核：

  • ✅ 五个探针函数返回类型全部保真，grep -c Variant = 0 —— 不再报错
  • ⚠️ 但属性读走 s.attr() → php::Var → 拆箱，不是原生字段直读；三元里同一属性读两次
  • ⇒ 是性能特征，不是正确性坑。热路径把属性读先落类型化局部变量

哨兵值（accent: -1）的理由随之改为「区分未设置 vs 合法值」的语义手段，不再是绕编译器。
