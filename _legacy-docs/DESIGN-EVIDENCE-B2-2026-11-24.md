# DESIGN-EVIDENCE-B2：S-live 该是什么

> 上一版把 S-live 写成「宿主常驻 + 面板按游标轮询」，判据三条。本页先证明那个描述**混了三件事**，再给一个能把成本与收益对上的形态。结论与论证分开写，便于逐条否证。

## 零、结论

1. **「实时」在成熟工具里是三件事**：接活体（Chrome DevTools）、放录像（Playwright trace）、自动重跑（nodemon）。三者成本差一个量级，而现有判据只覆盖第一件的皮毛。
2. **S-live 的实质是「驱动」与「观察」解耦**，不是「把帧跑快」或「热重载代码」。前者能落地，后两者在 PHP 下要么做不到、要么不省时间。
3. **宿主自走不破可判**。「从属」是可判的**手段**不是**原因**；只要帧的 `t` 仍然来自脚本，谁按什么节奏调用 `pump()` 不影响结果。现有文档把这两件事写成了一件事（`Host.php` 与 `debug-model.md` 各一处），这是本轮要修的第一处论证。
4. **改代码必须重启进程**（PHP share-nothing），所以「热重载」的诚实形态是「自动重启 + 观察者按地址恢复视图」，而不是「保留运行时状态」。
5. **长驻真正卡住的是两件事**（跨会话地址失效、窗口滚动成为常态），第三件（节点号重跑不归零）只在 `--loop` 下才咬人，本轮不做。

## 一、把「实时」拆开：三件事的成本差一个量级

| 形态 | 代表 | 被观测进程 | 时间来源 | 可重复 | 我们能不能做 |
|---|---|---|---|---|---|
| **接活体** | Chrome DevTools / Flutter DevTools | 本来就在跑 | 真实 vsync | 否 | 要动渲染循环，S2 才该做 |
| **放录像** | Playwright trace / Unity Profiler 的 Recorded | 已退出 | 录制时的时间戳 | 是 | **已有**（script 重放），只是不能边跑边看 |
| **自动重跑** | nodemon / Flutter 的 hot reload 兜底 | 重启进程 | 脚本 | 是 | 能做，但省下的不是「实时」而是「操作」 |

三者的分界线是**时间从哪来**，不是界面刷得多快。Unity Profiler 把这件事摆得最明白：同一次会话有 `Live` 与 `Recorded` 两种视图，且明确标注——因为两者的可比性不同。我们照抄这个划分，不发明第四种。

现有 S-live 判据（帧号连续无空洞 / 查询命中的帧与宿主当前帧同源 / 帧耗时增幅 < 5%）逐条看：

- 第一条只对「接活体」有意义，对「放录像」天然成立（脚本按序推进，没有空洞可产生）；
- 第二条三者都该有，且是最便宜的一条判据；
- 第三条只在「宿主自己也在跑」时才有量——现在的宿主根本不跑。

所以那三条判据默认了「接活体」，而「接活体」恰好是三者里最贵的。**判据比方案先落地，就会倒逼方案走最贵的那条路。**

## 二、四条物理约束（这些不是设计选择）

1. **PHP 是 share-nothing。** 类定义一旦加载不可替换。改一行 Widget 代码，常驻进程里的旧类还在，唯一的生效方式是换进程。任何「热重载」的说法在 PHP 下都必须先回答这一条。
2. **单线程。** 帧循环与 IO 不能同时进行。要么在帧间空档收消息（`stream_select` 零超时），要么不长驻。没有第三条。
3. **一个录制器只服务一个驱动者。** 两条驱动流交错 = 帧号与因果边互相串味，且**不会报错**——记录看起来完整，只是混了两次运行。多窗口隔离留到 S2，但多驱动者必须当场拒绝。
4. **帧号、节点号都是每会话重新发的。** 这一点决定了「观察者的游标」不能只是一个整数（见 §5.4）。

## 三、一处被混为一谈的论证

`tools/Debug/Host.php` 写着：

> 宿主自己不推帧、不读时钟、不做任何「定期」的事。每一次状态变化都来自客户端的一条消息。这不是懒，是**可判**的前提：异步驱动、后台定时器、后台预热都会让「这一帧什么时候发生的」取决于机器，而调试器要给的是同一份结果。

冒号前是**手段**，冒号后是**原因**。真正的危险是「这一帧何时发生取决于机器」，而它只有一条成立路径：**`t` 来自墙钟**。客户端发消息只是「让 `t` 来自脚本」的一种实现方式，不是唯一方式。

反例正是本轮要做的：宿主按脚本里的 `t` 自走（`pump($step->t)`），节奏由 `--speed` 决定，而 `--speed` **不影响任何记录内容**——`t` 是脚本里的常量，`cost` 是实测耗时（它本来就不进结构指纹）。所以：

```
自走 + 脚本时钟   ⇒ 可判，且观察者不占管道
自走 + 墙钟       ⇒ 不可判（动画位置、after() 到期判断都会变）
从属 + 脚本时钟   ⇒ 可判，但现在这样
```

`debug-model.md` 的「边界」表里有一条更直接的误归因：

> 实时 attach 一个正在跑的真窗口 | 要在一个忙着的帧循环里收消息…现在的传输是**子进程从属**的：它只在客户端发话时动

「传输是从属的」是**当前实现的属性**，不是「attach 真窗口」不可行的原因。真原因是另外两条：忙着的帧循环里没有空闲时隙、以及单线程下读记录会与写记录竞争。把原因写成「传输从属」，会让后来者以为「把传输改成非从属就能 attach」——而那条路走下去会撞上单线程，白走一趟。

**结论**：可判的判据是「时间来自脚本」，不是「谁发了消息」。这条要写进 `debug-model.md`，替换掉那两处混写。

## 四、推荐形态：宿主自走 + 多观察者

```
                    ┌──────────────────────────────┐
                    │  宿主（唯一持有 Recorder）      │
   session.json ───▶│  ├─ 自走：按脚本 pump($t)      │
   (pid/port/token) │  ├─ 帧间：select 零超时收消息   │
                    │  └─ 会话令牌 + 帧游标           │
                    └───────┬──────────┬───────────┘
                            │          │
                   观察者 A（人）  观察者 B（AI / CI）
                   只发 query     只发 query
```

三条要点：

- **宿主是唯一驱动者**，按脚本推进，`t` 取自脚本 → 可判性不减；
- **所有客户端都是观察者**，只发 `query`（含 `frames(since)` 游标），不发 `frame`；
- **`frame` 方法保留但语义降级**：只在宿主「暂停」时可用，等于单步（S6 的暂停才解锁它）。这是协议层唯一需要动语义的地方。

为什么是「宿主自走」而不是「驱动者客户端」：后者要多一跳代理、要多一份「驱动权」的租约状态，而它换来的只是「驱动者可以中途改主意」——脚本里没有中途改主意的表达，`Replay::apply` 已经是全序的。为不存在的自由度付状态机，不值。

### 与成熟框架的对应

| 工具 | 谁推进 | 观察者 | 我们照抄什么 | 我们不该照抄什么 |
|---|---|---|---|---|
| Chrome DevTools | 浏览器（真实 vsync） | CDP 客户端 | 「观察者不驱动」这条分工 | CDP 的 domain event 推送——已否决订阅 |
| Flutter DevTools | Flutter engine | VM Service 客户端 | 「连上去看同一个实例」 | hot reload 保留 State——PHP 做不到 |
| Playwright trace | 无（静态文件） | Trace Viewer | 可重复的录像形态 | trace 的「一次录制、多次查看」不能替代 live |
| Unity Profiler | 播放器 | Profiler 窗口 | **Live / Recorded 双模式且明确标注** | — |
| Jupyter kernel | kernel 自己 | 前端 | connection file 做发现（port + key + id） | ZMQ 的多通道 |
| Node inspector | 进程自己 | DevTools | `--inspect` 打印带 token 的 ws URL | 通过 ws 推事件 |

**Jupyter 的 connection file** 是本轮最值得抄的一件：kernel 启动后写一个 JSON（`transport` / `ip` / `port` / `key` / `signature_scheme`），客户端读它连上去。它解决的是「我怎么知道端口」这个看起来不值一提、实际会毁掉 DX 的问题——固定端口会撞、随机端口没法告诉别人、扫描端口是碰运气。

## 五、四个必须回答的形状

### 5.1 时间从哪来：脚本时钟，不是墙钟

`--speed` 是**节奏**参数，不是**时间源**参数：

| `--speed` | 行为 | 用途 |
|---|---|---|
| `0`（默认） | 全速跑完，停在最后一帧 | CI、报表：等它跑完 |
| `1` | 每帧之间按脚本 `t` 的差值 sleep | 人看：能看到「第 3 帧卡了一下」 |
| `N` | 按 `t` 差值 / N 放慢 | 慢放：一帧一帧看清 |

三种都喂同一个 `$step->t` 给 `pump()`，所以**三种产出的证据逐值相同**。这条本身就是一个判据（§7 第 4 条），而且它是我判断「自走不破可判」的实证方式。

### 5.2 谁推进：宿主，但可以停

宿主自走 → 需要一个暂停点，否则跑完就没事干了。三种情形要分开：

- `--at=N`：跑到第 N 帧**有意**停（人要看那里），停在 `paused`；
- 脚本跑完：停在 `finished`，会话保活，观察者还能继续问；
- 慢放中观察者连上来：不停，继续跑（「边跑边看」就是这个用例，此时状态一直是 `running`）。

状态形状是 `{state, reason}`，不是裸字符串：

```json
{"state":"paused","reason":"at"}
```

`reason` 现在就定，因为 S6 会加「客户端发起的暂停」，那时必须能区分「跑到 `--at` 自己停的」与「有人按了暂停」——两者对观察者的含义相反：前者是「你要看的就在这」，后者是「暂时停一下，一会儿还动」。S6 只填 `reason: "requested"`，形状不用改（§十二）。

前两种要能被观察到，所以进 `stats` 查询而不是 `open` 回执——`open` 只发生一次，而状态一直在变。把「跑完了」和「卡住了」混成一个「没有新帧」，是这一层最容易犯的错：观察者会一直等一个永远不会来的帧。

### 5.3 观察者怎么发现会话

`.drift/session.json`（cwd 相对，进 `.gitignore`）：

```json
{"protocol":1,"sessions":[
  {"id":"9f2c…","pid":12345,"port":51234,"token":"a71e…","target":"table","startedAt":"…"}
]}
```

**是数组，即使现在只有一个会话。** S2 的多窗口会让同一进程有多个窗口，那时「一个文件一个对象」必须变成「一个文件一个数组」——而格式变更的代价不在改代码，在「老版本写的文件新版本读不了」这类兼容尾巴。现在写成数组多花五分钟，S2 时省一次迁移（§十二）。

**文件里不放运行状态。** 活的 `state` / `reason` 只有 `state` 查询一个出口——写进文件就是两处真相，而文件那份必然滞后（只在启动与退出时写）。S2 多窗口时更糟：要么每次状态变化都重写文件（多进程并发写同一个文件，还得处理写坏），要么承认同名字段有两种时效（文件里是「启动时的快照」，查询里是「现在」）。后者是那种一年后没人敢删的坑。因此文件只回答一个问题：**怎么连上**。六个字段各就各位——`port` / `token` / `pid` / `id` 是连接所需（后两个用于诊断），`target` / `startedAt` 给人看。

- **token 必须有**：loopback 端口在本机对任何进程可见，没有 token 等于把调试面开给全机器。Jupyter 与 Node inspector 都带这个；
- **文件要能失效**：宿主退出时删除该条目（数组空了删文件）；观察者连不上时先看 `pid` 是否还活着，报「宿主已退出（pid 12345）」而不是「连接被拒绝」；
- **不用固定端口**：撞端口是概率事件，而它一旦发生，报错信息会指向完全无关的原因（「Address already in use」而不说「另有一个 drift 会话在跑」）。

### 5.4 长驻的三个新问题

这是本轮真正的成本，也是为什么不能只加一个循环就完事。

**(a) 节点号在重跑时不再从 1 开始。** `Element::$debugId` 的注释写得明确：

> 编号必须「每个会话从 1 开始、按首次出现顺序递增」，否则 `Digest` 的「两次重放逐值相同」判据永远红（它拿 id 序列当同一批控件的证据）。

而 `Recorder::reset()` 只清帧，**清 `$seq` 与换 `$tag` 这两件事都没做**。于是同一宿主里重跑一次，页面重新 mount 出来的新 `Element` 见 `debugSession !== tag`，拿到的是 `++$seq`——接着上一轮的号往下涨（364 之后从 365 开始）。两轮的节点号不同，结构指纹必然不同，而注释要求的正是它不该不同。

这里有个容易误判的分支：`reset()` 保留 `$nodes` 的注释理由是「描述的是树，不描述帧」，在「**树不重建**、只是重新开始记帧」的语义下它是对的（节点对象还是那批，号也没变）。但 S-live 的重跑是「**树被销毁并重建**」，那条理由就不成立了——旧号残留在表里、新号从 365 起，`stats.nodes` 会报一个越来越大、越来越假的数。

**但它不是 S-live 的阻塞项**，因为本轮 `drift debug serve` 每次是一个新进程：`$seq` 从 0 起、`$tag` 新分配，节点号天然从 1 开始。它只在「同一宿主里 `--loop` 反复重跑」时才咬人，而 `--loop` 本轮不做。所以它被降级为一条**应在做 `--loop` 之前修**的语义缺口（§九第 0 条），不是前置。

**(b) 跨会话的地址失效。** 节点号、帧号都是每会话重发的。观察者若把「我看到 frame=590, node=42」当游标，宿主重启后会拿到新会话的第 42 号节点——**同名不同物**。所以游标必须是二元组：

```php
final readonly class Cursor
{
    public function __construct(public string $session, public int $frame) {}
}
```

它住**消费者侧**（`tools/Debug/`），不进 `src/Debug/Session/`：它记的是「读到哪里」，不是采集到的事实。放进采集层会让「录制器知道谁在读它」这种反向依赖长出来。

`session` 来自 `open` 回执，一个进程内唯一、重启必变。观察者发现 `session` 变了 ⇒ 清空视图、从第 1 帧重来，并**明确显示「会话已重启」**。把两个会话的帧拼成一条连续时间线，正是「帧号连续无空洞」这条判据要防的反面。

**(c) 窗口滚动从异常变成常态——而这一层已经建好了。** 600 帧窗口在常驻下几分钟就滚满，所以「按游标取、落后就自报」必须在。查了 `Query::frames()`，它已经返回：

```php
return ['frames' => $out, 'window' => $window, 'dropped' => $dropped, 'since' => $since];
```

`window` 是 `{from, to, capacity, frames}`，`dropped` 用 `window.from - since - 1` 算出「中间那段真的没了」。`debug-model.md` 说「两件事的底座都已经有」，指的就是它。

所以这一段**不是新设计，是别造同义词**：我第一版在这里写了「返回 `{gapped: N, ...}`」——那是给已经叫 `dropped` 的东西换了个名字。项目纪律是「一份数一个名字」，同义异名比缺字段更难查（两个消费者各拿一个，聊起来以为在说同一件事）。

本轮真正要补的只有一处：`dropped` 只按帧号算，不知道「会话换了」。跨会话时必须先比 `session`，再谈 `dropped`——否则旧会话的 `since=590` 会在新会话上算出一个巨大的 `dropped`，看起来像「你落后了很多」，实际是「时间线换了」。这一条已经写进判据 6。

## 六、被否决的八个方案

| 方案 | 好处 | 否决理由 |
|---|---|---|
| 宿主自走 + **墙钟**时间 | 最像真实运行 | 动画位置、`after()` 到期判断随机器变 ⇒ 同一脚本两次结构指纹不同。这是唯一真正会毁掉可判性的做法，而它看起来最自然 |
| attach 到 dev 壳的真窗口 | Chrome 式体验 | 渲染循环里没有空档收消息，单线程下读完还会被下一帧覆盖。它不是「传输从属」的问题（§3），要等 S2 的常驻黑匣子一起解决 |
| 多个客户端共享一条管道 | 实现最省 | 一条管道没有「这条消息是谁发的」，帧响应会被另一个客户端的查询响应顶掉。TTL 与 seq 只能发现错，不能防止 |
| 驱动者客户端做代理（宿主不动） | 宿主零改动 | 代理自己也要 `select` 多路复用，成本与改宿主相同，还多一跳；且代理崩溃 = 会话没了 |
| 观察者 tail 一个追加文件 | 不需要 socket | 查询要活树（`props` / `pick` 要反射与命中测试），文件里只有记录。而且 `--from` 已经能做「读文件」，但它不能推进 |
| 起一个 HTTP / WebSocket 服务 | 现成、可浏览器直连 | 依赖一个 HTTP 栈（或手写最长前缀匹配），端口 + 跨域 + 静态资源全要自己管。S5 的 Web 视图需要它，但那是 S5 的实现选择，协议层不该绑 |
| 每帧把全量快照推给观察者 | 观察者实现最简单 | 直接违反「先摊平再物化视口」那条（`evidence-model.md` 的「投影」节）：600 帧 × 数百节点，推的量比它要省的多 |
| 用 `--from` 证据包当 live 数据源 | 已经能读 | 静态包不能推进。它能回答「上次那次运行」，不能回答「现在这一帧」 |

## 七、判据（八条，先写判据）

| # | 判据 | 防的是 |
|---|---|---|
| 1 | 三种 `--speed` 跑同一脚本，**帧时间序列与结构指纹都逐值相同** | 自走偷换时间源（墙钟混进 `t`） |
| 2 | 同一会话：观察者查 `frames()` 得到的末帧 = `stats().lastFrame`（停机后），且两者都带同一个 `session` 令牌 | 观察者连到了另一个会话 |
| 3 | 自走循环的帧耗时增幅 < 5%（对比从属模式同脚本） | 循环本身成了瓶颈，或者 `select` 用了阻塞超时 |
| 4 | 第二个驱动者（`frame` 在非 `paused` 时）被拒，错误码是 `NOT_PAUSED` 而不是静默排队 | 两套时间线交错 |
| 5 | 观察者落后到窗口外时，`frames(since)` 的 `dropped` 给出被裁掉的条数、`window` 给出当前窗口——**不返回空数组**（这两个键已经存在，见 §5.4(b) 的「别造同义词」） | 把「被裁掉」读成「那时没有」 |
| 6 | 会话重启后：`session` 变化被观察者检出（`frames` 响应带令牌，`Cursor` 据此归零重取），视图清空并显示「已重启」，**不拼接帧号** | 两个会话被拼成一条连续时间线 |
| 7 | 宿主退出后：观察者报「宿主已退出（pid=N）」，不是「连接被拒绝」 | 发现机制把最常见的失败说成最含糊的错误 |
| 8 | 没有令牌或令牌不对的连接在 `open` 阶段被拒（`unauthorized`），而正确令牌能接上 | loopback 端口对全机器可见 |

第 1 条是整套方案的立足点，也是最容易实现错的一条（`--speed` 想当然地写成「sleep 在 pump 前」就会把 `now()` 混进去）。**它必须同时比时间序列，只比指纹是无效判据**：`Digest` 刻意不含时间（它就是为跨进程比对设计的），实测把 `now()` 当 `t` 时，三种速度的指纹一个字节都没变，只有 `t` 序列全变了 —— 只比指纹的那一版会恒绿，而它本该防的正是这件事。第 3 条只能人工基准，不进 CI（它测机器）。**首次实测**（2026-11-24，同一脚本 30 帧）：自走 `cost` 均值 0.046ms / 最大 0.364ms，从属 0.204ms / 2.253ms —— 自走没有让帧耗时变差。`cost` 只量 `pump()` 内部，调度方式进不到这个数里，这正是这条判据能成立的前提（循环在 `pump()` 外面加的活，不会体现成 `cost` 上升；所以它还配了判据 1）。

### 两个令牌，不是同一个

实现时发现这里必须先分清，混用会让两件事变成一件：

| | 访问令牌 | 会话令牌 |
|---|---|---|
| 回答 | 这个进程的调试面开给谁 | 这是不是同一条时间线 |
| 存放 | 发现文件 `.drift/session.json` | `state` 查询、`frames` 响应、`open` 回执 |
| 何时变 | 宿主进程换一个变一次 | 每次 `open` 换一次 |
| 用途 | `open` 时校验（`unauthorized`） | 写进 `Cursor`，判跨会话的游标 |

合并成一个的话，"宿主重启"与"重新录制"就分不开了：读屏的人只想知道"我那个游标还算数吗"，而他不该因此被要求重新拿一次连接凭据。

## 八、DX

```bash
# 一条命令起宿主，跑完停在最后一帧，等人来看
drift debug serve --page=table --frames=1

# 另一个终端/另一个进程（人或 AI）连上去看
drift debug brief --attach
drift debug panel --attach

# 慢放看过程：边跑边看
drift debug serve --page=async-table --rows=6 --resolve --speed=1
drift debug brief --attach --follow        # 跟着游标翻页
```

三条约束：

- `--attach` 与 `--page` 互斥（会话已经在跑，不能再指定页面）——与 `--from` 同一条纪律；
- `--follow` 只在 `--attach` 下有意义（本地会话没有「别人在推进」这回事）；
- 找不到 `session.json` 时报「当前目录没有运行中的 drift 会话」，并给出「`drift debug serve` 起一个」的建议。只说 `ENOENT` 等于把用户扔在门口。

**关于「改代码后自动重跑」**：这一轮不做，但架子要留对。它的正确形态是「supervisor 监视 mtime → 重启宿主 → 观察者重连 → 按地址恢复选中/滚动」——其中「按地址恢复」依赖 A35「行键而非下标」，已经成立。这条留到 S-live-b，因为它的判据（「改一行不影响结构的代码，选中节点不变」）需要 S5 的 Web 视图才看看得出来，终端里看不出差别。

## 九、本轮落点

顺手修（与 S-live 解耦，5 行，但要在 `--loop` 之前做）：

0. `Recorder::reset()` 同时清 `$nodes` / `$boxless`、`$seq` 归零、换 `$tag`，让重跑后的节点号从 1 重新开始——`Element::$debugId` 的注释已经要求了这件事，`reset()` 没做到（§5.4(a)）。做完之后「重跑」这个词才名副其实。

本轮：

1. `Protocol\Server` / `Protocol\Channel` 接口（`Channel implements Transport`，`Server::wait()` + `canPoll()`）。**`wait()` 而不是 `accept()`**：宿主真正要问的是「有没有新连接，或者老连接上有没有新消息」合起来那一件事 —— 拆成两个方法的话，循环里就得用一次 `select` 的语义去凑两次调用。**接口进 `src/Debug/Protocol`，实现留 `tools/Debug`**——照 `Transport` / `StdioTransport` 的既有分层；S2 的 AOT 侧要能只依赖接口就接上（§十二）。
2. `Host` 的循环里加一个**可选的 tick 回调**，不要另写一个「自走宿主」：`serve(callable $open, ?callable $tick = null, ?Script $autoStart = null)`。`tick` 为 `null` 时行为与本轮之前**逐字节一致**（现有 `--remote` 测试要照旧全绿）。自走逻辑住 `tools/debug-serve.php`，由它传 tick。S2 没有脚本，传 `null`，因此不用拆 `Host`。
   **第三参是落地时才发现的必需项**：自走宿主没有客户端来发 `open`，会话只能由自己先建起来；少了它，`tick` 永远等不到会话，自走会安静地不推进任何一帧（不是报错，是看起来在跑）。同一条也决定了「跑完之后不退进程」：判断条件是 `$autoStart === null`。
3. 会话发现文件 `.drift/session.json`：`{protocol, sessions: [{id, pid, port, token, target, startedAt}]}`，token 校验走 `open` 的 `params`（不新增 `hello` 方法，见 §十二）。不放 `state`——活状态只有 `state` 查询一个出口（§5.3）。
4. `open` 回执加 `session`（令牌）；`stats` 查询加 `lastFrame` 与 `{state, reason}`——**放查询面而不是回执**，因为 `open` 只发生一次，而状态一直在变。
5. `Cursor` 值对象（住 `tools/Debug/`，消费者状态）。`frames(since)` 的 `dropped` / `window` **已经有了**，本轮只补「先比 `session` 再算 `dropped`」，不新增同义键。
6. `drift debug serve` 子命令 + `--attach` 挂 `brief` 一个出口先试（其余出口下一轮）。`serve` 跑完**不退进程**：它阻塞等人来查，退出的时机是「没有观察者了」——先退的话，下一个人看到的是「连接被拒绝」，而他什么都没做错。
7. `Source` 解析抽成一处（`Page` / `--remote` / `--from` / `--attach` 四选一），`brief` 与 `network` 里现在各有一份 `--from` 分支，加 `--attach` 就成三份（§十二）。落地时它收的是**意图**（`from` / `attach` / `remote` / `drive` / `out`），**不是 argv**：argv 里各出口有自己的词（`--request` / `--speed`），收 argv 等于把出口词表也塞进共用层，那样它就不再是「来源选择」，而是「又一个参数解析器」。
8. 判据 1–8，其中 3 人工基准、4 属 S6（本轮 `paused` 只是宿主自己的停机状态，客户端还发不了 `paused` 请求）。
9. `Replay::advance()`：把「推一步」从 `apply()` 里抽出来。自走是「没消息时推一步」，`apply()` 是「一口气跑完」——两者的**动作**必须只有一份，否则 `--at` 的边界、步号报错、效果参数剥离会在两条路径上各漂一次。

不做：`--watch` 自动重跑（S-live-b）；attach 真窗口（S2）；干预（高亮/暂停控制，S6——本轮的 `paused` 是宿主自己的停机状态，不是客户端发起的暂停）。

**本轮留下的欠账**（不改，但记下来）：驱动词表（`--page` / `--frames` / `--rows` / `--click` / `--hold` …）在 `brief` / `network` / `serve` 三处各有一份解析，约 40 行 × 3。它们必须逐词一致（同一个 `--click=` 在三个出口里语义相同），却没有任何判据钉住这件事 —— 判据在形态上根本够不着（那是 CLI 参数解析，不是可断言的形状）。正确形态是抽一个 `DriveOptions`：只认驱动词，把不认识的留给出口（`--request` / `--speed` 是各自的话）。放到下一轮：它是纯搬迁、不改变任何行为，而现在改会让"哪一处坏"难定位 —— 本轮已经动了四个出口与协议层，再加两个 CLI 的解析段，红了分不清是谁。

## 十、放弃与代价

| 放弃 | 代价 | 为什么值得 |
|---|---|---|
| Chrome 式的「手动点击、面板实时跟随」 | 开发期不能看真实鼠标操作产生的帧 | 需要 attach 真窗口 + 单线程下的帧内 IO，这是 S2 的范围；而 S2 之前先做，会为了一个不存在的能力改渲染循环 |
| 热重载保留运行时状态 | 改代码后滚动位置与选中靠「地址恢复」而非「状态保留」，改结构时只能退回最近祖先 | PHP 的物理限制。诚实做「重启 + 恢复」比假装能保留状态好 |
| 订阅推送 | 观察者要轮询，延迟上限 = 轮询间隔 | 漏一条之后每条都错（既有裁决）；游标是「再问一次」，可重试、可并行 |
| 多驱动者 | 不能两个脚本同时驱动一个会话 | 帧号与因果边会串味且不报错，这是最难发现的一类错 |

## 十一、这一轮修的两处文档欠账

1. `tools/Debug/Host.php` 的「从属 = 可判」：改成「`t` 来自脚本 = 可判」，从属只是当时的实现方式。
2. `docs/concepts/debug-model.md` 的「边界」表里「attach 真窗口不做，因为传输从属」：改成「不做，因为单线程下帧循环里没有收消息的时机」，把归因从「当前实现属性」拉回「物理约束」。

两条都不是润色：两条都会让后来者以为「改掉传输就能 attach」，而那条路撞的是单线程。

## 十二、全局前瞻：这些决定以后会被谁消费

分期表的原话是「S-live 先上，S2 可以复用同一套『常驻 + 窗口』的形状，避免做两遍」。所以 B2 不是一期独立的活，它是 S2 的部分前置。这一节把每个组件往后追一遍，只留下「现在不这么定、以后必然返工」的那些。

### 判断标准（避免把前瞻做成过度设计）

一个决定值得提前定，要同时满足三条：

1. 后续某一期**必然**触碰它（不是「可能会」）；
2. 触碰时改的是**持久化格式或公共接口**（改内部实现不算，那种返工很便宜）；
3. 现在定的成本接近零（多写一个数组括号、多一个字段）。

三条都满足才提前。所以下面这些**不提前定**，理由写清楚，免得后人以为是漏了：

- `--speed` 的三档语义：S2 没有脚本，这个参数不会传下去，返工成本为零；
- 流控 / 背压：S0 已有「先摊平再物化」，观察者按游标取不会被压垮，等真压垮了再说；
- 多观察者上限：先不设。设一个拍脑袋的数字比不设更糟——它会变成事实上的容量承诺。

### 逐组件前瞻

| 组件 | S-live | S5（Web 消费者） | S6（干预） | S2（常驻黑匣子） | 结论 |
|---|---|---|---|---|---|
| `Server` / `Channel` 接口 | 用 | 用（HTTP/WS 桥是**另一个** `Transport` 实现） | 用 | 用（AOT 侧用 PHP 写一个走 native socket 的实现，被编译进产物） | 接口进 `src/Debug/Protocol`，实现进 `tools/Debug` |
| PHP 版 socket 实现（`stream_socket_server`） | 用 | 不用（浏览器走 HTTP 桥） | 用 | **不用**（换 native 实现） | 一次性代码，别指望它复用 |
| 发现文件 | 用 | 用 | 用 | 用（多窗口） | **必须是数组**，见下 |
| `token` | 用 | 用 | 用 | 用（线上更必须） | 现在定 `random_bytes(16)`，够用到 S2 |
| `Cursor(session, frame)` | 用 | 用 | 用 | 用（多窗口时 session 隐含窗口） | 二元组够，不用三元组 |
| `state.reason` | 用 | 用 | **用**（客户端暂停 vs `--at`） | 用（崩溃后状态是 `crashed`） | **现在就要有 `reason`** |
| `Host` 的 tick 回调 | 用 | 不用 | 用 | **不用**（应用自己跑） | tick 可选，`Host` 不因它分叉 |
| `Methods` 只有六个 | 是 | 是 | **否**（加 pause / resume / highlight） | 是 | 注释改成「按角色分组」，别写「刻意只有六个」 |
| `frames(since)` 的 `dropped` / `window` | 用 | 用 | 用 | **必须**（窗口更小、跑得更久） | **已有**，只补跨会话判断 |
| `Source` 四选一解析 | 用 | 用 | 用 | 不用 | 现在抽，否则 8 个出口各写四份 |

读完这张表有个反直觉的结论值得单独说：**S2 复用的不是传输，是证据面。** 常驻黑匣子的价值在「跑很久之后仍能回答『第 3000 帧为什么慢』」，靠的是 `Cursor` 的跨会话语义、`dropped` 自报、窗口账、`state.reason`——全都不涉及 socket。传输层对 S2 是「如果将来要做线上 attach 就用得上」，不是必需品。

所以下面五件提前定的事，没有一件是**提前实现功能**：两件是持久化/协议形状（发现文件数组、`state.reason`），三件是代码结构与接线（`Server` 接口的位置、tick 作为 `Host` 的参数、`Source` 解析收口）。这个比例本身就是判断标准在起作用——功能改起来只是重写，形状改起来要背兼容尾巴，结构改起来会在仓库里留下两条并行的路。

### 五处「现在不定就要返工」的具体理由

**(1) 发现文件是数组。** S2 多窗口实现之后，同一进程会有多个会话。单对象格式那时必须变数组——而这不是改一行代码的事：老版本写的文件新版本读不了，或者要靠「有 `sessions` 键就当数组、否则当对象」这种兼容分支活着。后者会在仓库里留一辈子。

**(2) `state` 带 `reason`。** S6 要加客户端发起的暂停。裸字符串 `"paused"` 那时无法区分「`--at` 到点了」（去看吧，就是这里）和「有人按了暂停」（一会儿还动）。这两个含义对观察者相反，缺 `reason` 就只能靠「有没有第二个字段」这种隐式约定。S2 还要加 `crashed`——它和 `finished` 的区别正是「跑完了」与「炸了」，混一起等于把崩溃报成正常结束。

**(3) tick 是 `Host` 的参数，不是另一套循环。** 如果为了自走另写一个 `LiveHost`，S2 就面对「两份消息循环」——而 S2 恰好不需要自走。届时要么维护两份、要么合并回来，两种都是返工。tick 为 `null` 时行为不变，这条可以用现有 `--remote` 测试直接证明。

**(4) `Methods` 的注释要改。** 现在写着「刻意只有六个」。S6 必加干预方法（那是唯一反向流），六个变九个。注释不改，它就从「纪律」变成「过时的话」，下一个读到的人会以为加方法是违规的，或者反过来把纪律整个放弃。改成「按角色分组：会话 / 驱动 / 读 / 干预」，加方法时是往里填，不是破例。

**(5) `Source` 解析抽出来。** `brief` 与 `network` 现在各有一份 `--from` 分支（互斥检查、`hydrate`、标签取值，约 20 行）。加 `--attach` 就是第三份，而 8 个出口早晚都要有。三份之后，任何一处改动（比如新增「`--from` 与 `--out` 互斥」这条纪律，我本轮就改了两遍）都要改三处。抽成 `Source::resolve(argv): SessionQueries` 之后，出口只拿到「能查的东西」，不再关心它是页面、证据包还是远端会话。

### 四处已确认不用改（扩展点本来就在）

1. **域缺失 ≠ 域为空**：B1 的 `domains` 声明已经让「S2 的证据没有 `script` 域」可表达。实测 `script` 为 `null` 时 `counts.script = 0`、`digests.drive = ''`，读取侧接受——无脚本证据包能正常往返，不用改格式。
2. **`Transport` 抽象**：S5 的 HTTP/WS 桥只是第三个实现（前两个是 `StdioTransport` / `ProcessTransport`），协议层不动。
3. **`Cursor` 用 `session` 而不是窗口号**：多窗口实现时每个窗口一个 Recorder、一个会话令牌，所以「窗口」已经隐含在 `session` 里，不用升三元组。
4. **`frames(since)` 的 `dropped` / `window`**：已经实现了，而且 `window` 里带 `capacity` 与 `frames` 两个数，S2 更小的窗口也够用。这一条是本章唯一的「查了代码才发现不用做」，也说明**先读再设计**能省掉一整块工作。

### 一处仍不确定、但可控

**S5 到底是「离线包的 Web 查看器」还是「实时 Web 面板」**，现在没定（S5 的判据只要求「三端对同一证据给出同一根因」，没要求实时）。如果是前者，B2 的传输层只有 S-live 一个消费者；如果是后者，浏览器需要一条 WS 通道。

两种都不用改 B2：前者不连宿主，后者是「WS → 协议」的又一个 `Transport` 实现。这正是把「协议」与「通道」分开的用处——**这个不确定性不需要现在消除**。
