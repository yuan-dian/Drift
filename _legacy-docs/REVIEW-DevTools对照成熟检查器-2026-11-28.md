## 0. 总评

**一句话**：当前分支的**证据链已经和成熟工具打平、在可重放与 CI 断言上反超**；
真机检查器在"只做 Web 给不了的三件事"这条边界上完成度不错；但 Web 面板本质上仍是
**只读查看器**，属性编辑、源码跳转、真机悬停与生态是主要失分点。

按 26 项能力、权重合计 90 加权，**当前分支 7.2 / 10，成熟基线 8.75 / 10**。
差距不在"检查器做没做完"，而在"检查器是不是完整开发环境"—— 当前把它当成
**证据 + 可视化**做得很好，成熟工具把它当成**编辑 + 调试 + 分析工作台**做得更全。

**三个最值得记的判断：**

1. **强项被低估**：离线证据包、指纹、逐帧重放、`--verify` 断言、能力目录双向闭合，
   是 Chrome / Flutter 默认形态都没有的东西。成熟工具强在交互，本仓强在**结论可复算**。
   这是路线差异，不是功能缺失。
2. **弱项是真的**：Web 节点卡能读 `props`，但不能改；`source` 查询存在，但 Web 没有落点；
   `eval` 默认关且只读。离 Chrome 的 Styles 面板、Console、Flutter 的属性面板差一整层。
3. **真机的克制是对的，但有两处体感缺口**：hover follow 有意不做（每次 `mousemove`
   会污染被测应用），这条守住；HUD 不折叠、不避让，则是实现缺口，不是边界。

## 3. 优点（按对排查可信度的影响排序）

1. **证据链是可复算的，不是"看着像"**。指纹、逐帧因果、离线包、`--verify` 两次跑对照，
   让"这帧为什么慢"可以被 CI 判定。成熟 DevTools 大多是交互式取证，结论难以自动回归。
2. **真机与 Web 同源，且各自只做自己擅长的事**。HUD 与节点卡读同一份 `boxModel`，
   四边格式规则同一条；真机只上屏不进快照，Web 底图永远不带调试装饰。
3. **拾取形态已经对齐真实业务**。持续模式、命中链换层、吞整段点击避免"选中即触发按钮"、
   快捷键冲突让位 —— 这几条正是"只为简单做一次性拾取"会返工的地方。
4. **协议和 CLI 有单一真相**。`Capabilities` 双向闭合、`Registry` 生成帮助和分发、
   参数 schema 不写第二份；工具的可发现性不像手写脚本那样容易腐烂。
5. **数据表达在说人话**。`Hud` 把 `tight` / `0..∞` / `pumpIo` 翻成"宽锁定"、
   "尺寸由内容决定"、"布局 1.2ms"，并把全零间距写成"无间距"，不拿噪声占位。

## 4. 缺点与风险

1. **Web 是查看器，不是工作台**（最大缺口）。`props` 只读、`source` 不落点、`eval` 默认关。
   对习惯 Chrome Elements 的人，"为什么这个控件是这个尺寸"能回答，"把它改成 12 看看"不能。
2. **真机悬停与 HUD 自适应是两种不同性质的缺口**。悬停是有意不做（避免污染）；HUD 不能
   折叠、不避让是实现缺口 —— 后者该补，前者别补。
3. **覆盖面窄的几处容易被误读**：网络只统计经 Drift HTTP 客户端的请求；异步只覆盖后端
   调度 job；内存只有存活跨度。页面已明说"没开"与"没有"的区别，但能力边界仍要常记。
4. **源码位置断在最后一公里**。`source` 查询有，Web 没落点，AOT 没映射。dev 形态补一行
   反射的成本很低，现在不做属于明显低垂果实。
5. **多窗口只并列不 join、无插件生态、无 3D**。前两条影响复杂应用，第三条目前没有用例；
   都不该塞进当前检查器这一棒。

## 5. 路线图建议

| 优先级 | 事项 | 验收判据 | 风险 |
|---|---|---|---|
| P0 | dev 形态源码位置落到节点卡：`site` → 文件:行，点击跳编辑器；AOT 明确显示"无映射" | dev 页可跳、AOT 页不假装；与 `source` 查询逐值一致 | 低，不进证据 |
| P0 | 只读属性面板增强：列 Widget / State 配置摘要、类型、来源 `site` | 与 `props` 逐值相同，不新增第二份采集 | 低 |
| P1 | 网络 / 内存扩面：先明确"哪些请求可见"，再评估宿主钩子 | 页面区分"未采集"与"采集了但为空"；判据可咬红 | 中，涉及宿主钩子 |
| P1 | HUD 折叠与避让：输入钩子 + 命中测试 | 不进证据、不改变 `inspectorDrawn` 语义 | 中 |
| P2 | 多窗口 join（全局节点 id）、3D / 设计稿叠加、插件机制 | 先有真实用例与独立裁决，再开工 | 高，范围外 |

**前提**：属性实时编辑不能为了像 Chrome 直接做。Widget 不可变、AOT 无反射，dev 做会
造成两套行为；要先裁决"编辑只作用于 dev 预览，还是生成新代码"。

## 6. 明确保持的边界

- 不在真机里复制结构树、面板、搜索框、请求列表 —— Web 是唯一面板（evidence-model 边界表）。
- 不做悬停即高亮 —— `mousemove` 写 highlight 等于在被测应用里制造真实绘制。
- 不把检查器状态放进证据、指纹或重放；只进 `state` 的 operational 段供 Web 镜像。
- 不为了"图做得快"给 `boxModel` 加四个 rect 字段 —— 证据面不因渲染方便而膨胀。

## 7. 证据来源与局限

- 本评审为**只读分析**：未改产品代码，未新增裁决，未跑真机验证；评分依据是当前分支的
  实现、测试与既有设计文档，不是实测帧率或用户调研。
- "成熟基线"是跨工具综合能力分：例如离线重放断言成熟工具只给 5，是因为 Chrome / Flutter
  默认没有等价能力，不是它们"做得差"。
- 分值是**相对坐标**，用于排优先级；不同人按不同使用习惯可上下浮动 0.5–1 分，但分组结论
  （证据强、编辑弱、生态空）不随小幅调整改变。
