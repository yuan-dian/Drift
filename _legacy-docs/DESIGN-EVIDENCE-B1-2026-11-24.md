# B1 证据包：设计（2026-11-24）

S0 的落地。上一轮 `DESIGN-EVIDENCE-B0` 第三节只给了形状草案（单文件 JSON + 嵌套 `facts`），没实现。真正动手前把六种记录类、`Wire`、`Script` 编解码、`Recorder` 的私有状态读了一遍，**发现草案有三处会疼的地方**，先改形状再写代码。

## 一、先确认前提：现在做 S0 对不对

A47 把 S0 排在"事实定型之后"，理由是"格式定早了，每加一域破一次兼容"。现在的事实形状：S1 / S3a / S3b / S3c / S4 已落地，**S3d（绘制归因）未做，它会加一域**。

所以现在做 S0 只有一个前提成立才安全：**格式必须按域可扩展**——加一域是"加一个 domain 名 + 一类记录行"，不是"改 schema 版本"。

这一条直接否掉了草案的嵌套形状，见 §2.1。

## 二、四处形状，反着做都会静默出错

### 2.1 容器：NDJSON 记录流，不是嵌套 `facts` 对象

草案是：

```
{ "schema": "drift-evidence", "version": 1,
  "facts": { "frames": [...], "nodes": {...}, "geometry": [...] } }
```

三个问题：

**① 加域要改 schema。** `facts` 是一个固定键的对象，S3d 加 `paint` 就得让 `version: 1` 的读者遇到不认识的键——要么忽略（那就不知道自己漏了绘制域），要么报错（那就等于破兼容）。这正是 A47 想避免的那件事，草案自己踩了。

**② 中间态要三份。** 600 帧全量包几十 MB，`json_decode` 整包时内存里同时存在「整份文本 + 解码出的嵌套数组 + 再转成的对象」三份。实测（14560 节点 / 0.79 MB）：整包解码峰值是文件大小的 **12.97 倍**，逐行读是 **7.74 倍**。当前 `feature` 全量测试已经吃到 1.3 GB，加点余量就 OOM——而这条判据恰恰是 §6 里最重要的一条。

注意 7.74 倍**不是**小数字：`EvidenceBag` 必须全量驻留，PHP 对象本来就比 JSON 文本贵约 8 倍，这是对象模型的固有问题，不是实现能消掉的。逐行读真正消掉的是那份额外文本副本与嵌套数组（省 40%），**不是**"峰值与包大小无关"——那个说法是错的，第一版这么写过，实测推翻了（见 §6 判据 7）。

**③ 不可 diff、不可 grep。** 单行 30 MB 的 JSON，`git diff` 无意义；想查"第 41 帧重建了谁"只能写程序。

改成 **NDJSON**：首行 manifest，其余每行一条记录，`kind` 决定形状。

```
{"kind":"manifest","schema":"drift-evidence","version":1,"domains":["frames","nodes","geometry","network","script"],...}
{"kind":"node","id":1,"p":"-1","c":"PageShell","x":false}
{"kind":"frame","id":41,"t":656.0,"cost":12.34,"stageNs":{"settle":9876543},"rebuilt":[...],"causes":[...]}
{"kind":"geometry","frame":41,"node":11,"applied":{...},...}
{"kind":"network","request":1,...}
```

好处：读的时候不必先持有整份文本（峰值只剩"驻留 + 一行"）；`head -1` 看版本、`grep '"kind":"frame"'` 数帧、`diff` 两份证据按行对齐；加域只是多一种 `kind`，老读者遇到不认识的 `kind` **必须报错而不是跳过**（见 §2.4）。

代价：不是严格 JSON，第三方工具读不了。这个代价可以接受——证据包的第一消费者是我们自己的 `Query`，而"能被 shell 处理"比"能被 jq 处理"在这个场景里更值钱。

### 2.2 `encode()` 与 `toArray()` 是两个方法

六种记录类都有 `toArray()`，看起来可以直接拿来序列化。**不行**，它们是为投影服务的：

| 类 | `toArray()` 做了什么 | 往返后果 |
|---|---|---|
| `FrameRecord` | `stageNs` → `stageMs`（`round(…, 4)`）、加派生的 `unattributedMs` | 纳秒精度丢失；导入后再导出数值会漂 |
| `GeometryRecord` | `inset` 改名 `margin`、`border` 拆成 `{present, width}` | 解码要记一张改名表，而改名表会漂 |
| `Edge` | `fromId` 改名 `from` | 同上（这个可以接受，映射简单且已稳定） |
| `NetworkRecord` | 加派生的 `pendingFrames` | 多一个字段，无害但不算"逐值相同" |

所以每个记录类加一对 `encode(): array` / `static decode(array): self`，**无损**、字段名与构造器一致。`toArray()` 一律不动——它是协议面的形状，改它等于改查询输出。

这不是洁癖：`Script` / `Step` 已经是这个模式（`toArray` / `fromArray` 无损，因为脚本本来就要往返）。证据包只是把同一个模式推广到另外六个类。

命名上不叫 `toArray`/`fromArray`，是为了让"我要无损"和"我要给人看"在调用处就能分辨。

### 2.3 三指纹：External 只覆盖"外部给了什么"

草案写 `digest(External)` 覆盖"method + 脱敏 URL 模板 + 顺序 + **输入事件序列**"。**输入事件序列是重复计入**——它在 `Script::steps()` 里，已经进 `digest(Drive)` 了。

重复计入的后果不是"多算一遍"，而是**诊断价值归零**：两份证据的输入不同时，Drive 与 External 同时红，于是分不清"是我驱动得不一样"还是"外部条件不一样"。而这两件事的修复动作相反（改脚本 vs 等外部/改 mock）。

三条指纹的职责划清：

| 指纹 | 覆盖 | 不覆盖 |
|---|---|---|
| `drive` | 目标、视口、`meta`、`steps`（帧时间戳 / 输入 / 具名副作用） | 任何记录层事实 |
| `facts` | 节点表 + 逐帧因果与段结构（`Digest::ofFrame` 的输入） | 时间、耗时、外部条件 |
| `external` | 网络请求序列：`method` + 脱敏后的 host+path 模板 + `status` + 顺序 | 请求的帧号（"多久回来"）、`elapsedMs`、`bytes`、`landed` |

`external` 里**保留 `status`**：它是"外部给了什么"，不是"多久回来"。服务端从 200 变 500 而 Facts 没变，是有用信息（"错误被吞了"），不该被当成"同一份证据"。

`facts` 沿用现有 `Digest::of()` 的 `digest` 字段（`hash({frames, nodes})`）——它已经把节点表并进去了，这是对的：帧里只有 id，节点表不同则"重建集合相同"是假相同。

### 2.4 `domains` 声明：域缺失 ≠ 域为空

默认导出只带"窗口内慢帧 + 节点表 + 驱动"，几何 / 网络 / 属性可能整域没采。导入后若 `Query::boxes()` 发现几何是空的，它会照现有逻辑报"几何窗口 #0–#0 不含 #41"——**一个误导的 miss**：真相是"这一域根本没导出"。

这正是 B0 立的那条纪律（三类 miss 分开报）在证据包上的延伸。manifest 里显式声明：

```
"domains": ["frames","nodes","geometry","network","script"]
```

查询侧遇到缺失域报 `domain-absent`（并说明包里声明了哪些域），而不是"窗口外"或"空"。**`--all` 导出与默认导出因此可以用同一个 schema，只是 domains 不同。**

同时定一条硬规则：**遇到不认识的 `kind` 必须报错**。理由与"版本不认识就抛"同源——跳过它等于交出一份少一域却不自知的证据，而读者无法分辨"这份证据没有绘制域"和"这个版本不写绘制域"。

## 三、`hydrate()` 的形状

`Recorder::hydrate(iterable $records): self`，静态工厂，返回**游离实例**（不装 `Recorder::$current`）。

四条具体决定：

**① 节点表必须导出。** `pathOf()` / `typeOf()` / `isFlex()` 全依赖 `$nodes`。只导帧不导节点表，导入后所有路径都是空串——报告能跑，全是 `#0`。

**② `capacity` 取 `max(声明值, 实际帧数)`。** 导入的记录数可能超过导出时的窗口容量（全量包）。若照声明值建实例，`stats()['capacity']` 会说 600 而实际有 1200 帧——`window.capacity` 在自报说谎。取 max 之后，"当时能装多少"与"实际有多少"分开报，这是既有的 `from/to/count/capacity` 语义。

**③ `owns()` 对游离实例永远 false。** `$tag` 在构造时取自 `sessionSeq`，与任何活元素身上的号都不同，所以天然返回 false。**不加特判**——特判会让人以为"离线实例也能认领活元素"。

**④ 不重算派生量。** `Digest::ofFrame()` / `parentOf()` / `causeOf()` 都是从记录现算的纯函数，导入时不算、不存。存了就有两份真相。

`hydrate` 内部只做三件事：按 `kind` 建记录对象、按不变量校验（帧号升序、边两端在节点表里、`domains` 与内容一致）、填私有字段。

## 四、被否决的替代方案

| 方案 | 好处 | 否决理由 |
|---|---|---|
| 单 JSON（草案） | 严格 JSON，jq 可读 | 中间态三份（实测 12.97 倍包大小）；大包不可流式；diff 无用；加域要改 schema。见 §2.1 |
| 单 JSON + 手写 `[` 逐条 `fwrite` | 能流式**写** | 读仍要全量 `json_decode`，省掉的一半正是最贵的那一半 |
| 目录包（manifest + 多文件） | 大对象可外置 | 我们最大的对象就是帧数组本身，没有可外置的；多文件让"一份证据"变成"一个目录"，拷贝/上传/贴 issue 都变麻烦 |
| 复用 `Debug\Protocol` 的消息形状 | 一套编码纪律 | 协议是"一问一答"（`{id, method, params}` / `{id, result}`），证据是"一段记录"。硬套会得到"一条消息装一整个帧"的怪东西，且查询侧要假装自己是请求 |
| protobuf / MessagePack | 体积小、解析快 | 零依赖、可 diff、可 grep 三条全丢；体积不是当前痛点（默认包几十帧） |
| 集中式 `EvidenceCodec`（一个大 switch） | 一眼看全 | 加字段必漏——B0 刚吃过"版本表凭记忆写全错"的亏。编解码住在记录类里，加字段时改的是同一个文件 |
| 只导 `digest` 不导事实（"证据"= 指纹） | 极小 | 指纹只能回答"是否相同"，回答不了"哪里不同"。而后者才是要解决的问题 |

## 五、判据（先写判据，再写实现）

| # | 判据 | 防的是 |
|---|---|---|
| 1 | 逐记录往返逐值相同（六种 `kind` 各一条，含 `INF` 约束、`null` 帧时间戳、负 id 父标记） | 编码丢精度 / 类型漂移（`400.0` ↔ `400`） |
| 2 | 整包往返：导出 → 导入 → 再导出，两份字节相同 | 字段顺序不稳定、派生量被写进包 |
| 3 | 导出 → 导入 → **简报逐字节相同**（含指纹与裁剪账） | "导入后能查但结论不同"——这是证据可携带的最终检验 |
| 4 | 三指纹分离：只改驱动 / 只改网络 / 只改引擎，各自只红一条 | 指纹重叠（诊断价值归零，见 §2.3） |
| 5 | 域缺失报 `domain-absent`，且列出包里声明了哪些域 | 把"没导出"读成"窗口外" |
| 6 | 版本不认识 / 未知 `kind` / 文件尾巴截断 → 报错，不给半份 | 半份证据（读者无法分辨"没有"与"没写"） |
| 7 | 读包时「峰值 − 驻留」远小于包大小（一半以内；20000 行小记录的包实测溢出 0.05 MB / 1.10 MB） | 逐行读是否真的逐行（而不是偷偷 `file_get_contents`） |

第 7 条要单独说，因为它**改过一次**。第一版写的是"峰值增幅 < 包大小的 3 倍"，实测直接推翻：14560 个节点 / 0.79 MB 的包，逐行读是 7.74 倍，整包解码是 12.97 倍。3 倍这个数在任何实现下都达不到，因为 `EvidenceBag` 是全量驻留的，PHP 对象比 JSON 文本贵约 8 倍——判据写错了，不是实现错了。

改成看 `峰值 − 驻留`，才对准了它真正想守的东西：**实现方式**。逐行读时这个差约等于一行（几百字节）；一旦有人先 `file_get_contents` 再切分，这个差就至少是一整份文本。自检过：把 `read()` 换成整包读，用例立刻红（溢出 2.26 MB，因为文本副本和 `php://memory` 副本各一份）。

代价是这个判据不测"倍率"，只测"有没有多一份包"。倍率随记录类型变化（`node` 记录 54 字节、`body` 记录可达 64 KB），本来就没有可比性。

## 六、DX：`--out` / `--from` 挂在现有出口上

不加新子命令。"导出"不是一个独立的观察动作，它是"这次观察顺便存下来"。

```bash
drift debug brief --page=table --frames=1 --out=case.evidence
drift debug brief --from=case.evidence            # 离线复算，不需要 --page
drift debug network --from=case.evidence          # 换一个角度问同一份证据
```

两条约束：

- `--from` 与 `--page` 互斥（同时给就报错，不猜"以哪个为准"）。
- `--from` 时不需要活应用、不需要 `--frames`（帧已经在包里）；给了 `--frames` 报错而不是忽略——忽略会让"我明明要跑 3 帧"变成静默失败。

## 七、本轮落点

1. 六个记录类加 `encode()` / `decode()`（`Edge` / `FrameRecord` / `GeometryRecord` / `NetworkRecord` / `NetworkBodyRecord` / `PropSnapshot`）。
2. `Evidence` 编解码器：写（manifest + 记录流）、读（逐行建 `Recorder`）。
3. `Recorder::hydrate()`。
4. 判据 1–3、5、6（4 与 7 视时间）。
5. `--out` / `--from` 挂 `brief` 与 `network` 两个出口先试，其余下一轮。

不做：`drift debug diff`（两份证据的差异视图）。它是基线回归的入口，但形状依赖 S5 的消费者，现在定会返工。
