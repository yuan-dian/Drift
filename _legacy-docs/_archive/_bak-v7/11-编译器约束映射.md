# 11 编译器约束映射

> 本册是**唯一一册"每条设计都由编译器事实支撑"的对照表**。
> 用途：任何人想改设计，先在这里找到对应行；找不到 ⇒ 说明他引入了一条没有依据的决策。

---

## 1. 硬约束 → 设计律

| # | TypePHP 事实 | 设计律 | 违反的症状 |
|---|---|---|---|
| **C1** | `#[Native]` 对象**没有 `zend_class_entry`**：不能进 PHP 数组 / **普通对象属性** / `mixed` / `Box`；不能 `get_class()` / 反射 / `serialize` / `json_encode` | **L1** **节点是普通 class**；`#[Native]` 只给不进容器的小值对象（`BoxConstraints` / `Color`） | 运行时"对象消失"或直接崩；`get_class()` 编译期就报错 |
| **C2** | `?T` / `union` / `callable` / `iterable` **退化 `php::Var`** | **L1** 热路径零可空；"没有"用 `-1` / `''` / `count()==0` | 能跑，但每帧多几十万次装箱 ⇒ 帧时间翻倍且**找不到热点**（因为慢在装箱不在代码） |
| **C3** | 固定值属性**不能 `unset()` 也不能赋 `null`** | **L1** 需要空值就声明 `?T`（并接受 C2 的代价），否则用哨兵 | `PHP Fatal: cannot assign null to int` |
| **C4** | `readonly` 与 Property Hook 是**运行时 Hook**，密集访问慢 **10×+** | 值对象用 `private` + `#[Getter]` + `#[Immutable]` | 能跑，只是慢；profiling 显示在属性访问上 |
| **C5** | Property Hook **不支持间接写入 / 复合写入 / 取引用** | 写入口是**显式 setter**（`setText()`），不用 `$obj->text = x` 的 Hook | `$obj->text .= 'x'` 静默无效或编译期拒绝 |
| **C6** | 虚方法在**静态类型已知时会被去虚化**，静默走基类实现 | **L3** 节点行为用 `int $kind` + `switch`；虚方法只在"静态类型即具体类型"时用 | **最难查的一类**：声明了覆写、编译通过、运行走基类——"看起来生效、实际没生效" |
| **C7** | `callable` 属性退化 `php::Var`；`Closure::bind/call/bindTo` 不支持；闭包不能按引用返回 | **L2** 交互 = 命令 ID（int）+ 参数数组；闭包只作**函数参数**，不存属性 | 能跑但慢；或编译期报 `bind` 不存在 |
| **C8** | `global` / `$GLOBALS` / 未标注 static 的静态属性 ⇒ 擦除类型、丢 Native Call | 全局状态用**带类型的静态属性**或参数注入 | 能跑，但拿到的对象退化为 `Var`，方法调用全动态 |
| **C9** | 所有代码必须在 `function` 内，入口是 `main()`；无游离代码、无内嵌 HTML | 应用入口 `main()`；模板不用（自绘框架不需要） | 编译期拒绝 |
| **C10** | 不支持 `$$` / `extract()` / 隐式 `func_get_args()` / `isset($undefinedVar)` | 不用动态变量；参数显式声明 | 编译期拒绝 |
| **C11** | Native 的 `Iterator`/`ArrayAccess` 支持，但**不支持元素间接修改**（`$a['x']++`） | 写入口唯一：`$node->setX()`；不要 `$list[$i]->setX()` 这类间接写入 | 编译期拒绝或静默无效 |
| **C12** | Native 的 tracing GC 只在**两个安全点**回收；`unset` 不保证析构 | 后端资源实现 `close()`，destroy 时显式调用 | **帧间泄漏**：每次重建漏一点，几小时后爆；且堆栈看不出是哪 |
| **C13** | Trait 只在编译期可见（`trait_exists()` 返回 false） | 用 Trait 做**代码复用**，不做运行期能力探测 | 运行期 `trait_exists` 恒 false |
| **C14** | AOT **只编译可达代码** | 扩用法面必须真机构建；不能只看"编译通过" | 某个分支从未被构建进去 ⇒ 真机走到就崩；本地 `php.exe` 跑得好好的 |
| **C15** | 命名空间内**非限定函数调用不回退全局** | 内置函数必须 `\` 限定（`\mb_substr` / `\strlen`） | 能跑（`php.exe` 下）但 AOT 后 Fatal：`Call to undefined function` |
| **C16** | 没有 `$argv` | 用 `$_SERVER['argv']` | 命令行参数读不到 |
| **C17** | `tpc` 比 PHP 严：可选参数排在必选前 ⇒ Fatal；类常量与同类方法同名 ⇒ C2872 | 参数顺序纪律；常量名与同名方法共存时改名 | 本地能跑，tpc 编译失败 |
| **C18** | `project.yml` 的 `sources` 支持 `if`（`PHP_OS_FAMILY`） | **平台源文件选择用原生条件**，不写构建脚本 hack | 每平台复制粘贴一份 project.yml |
| **C19** | `-m lib` 导出的库与消费方必须 OS/架构/ZTS/PHPX/TypePHP 版本一致 | SDK 形态只在版本锁定场景用；默认**框架随应用编译**（见 V2） | ABI 不匹配 ⇒ 链接期或运行期崩，错误信息不可读 |
| **C20** | Windows 桌面要 `-m bin` + `--no-console` | 桌面产物必须带 `--no-console` | 双击弹黑框 |
| **C21** | Std 容器**不能嵌入原生类属性**；赋给属性会被 `toArray()` **拷贝成 PHP 数组**（v6 探针）；普通 array 不能存 Native 对象 | **L1b** 孩子与 op 段用 packed PHP array；Std 容器只做函数局部或 `#[StdVector]` 参数 | 以为建了持久结构，实际每次赋值都拷贝 ⇒ 性能崩塌 + 行为诡异（最坏的一类 bug） |

## 2. 为什么 L2（命令 ID）是本方案的支点

C7 是"最讨厌的约束"：它让"回调"这条路走不通。三种应对：

| 应对 | 代价 |
|---|---|
| 用 `php::Var` 存闭包 | 每次调用动态分派；且闭包捕获的变量不受订阅表管理 |
| 用字符串方法名 + 动态调用 | 字符串拼错要运行时才发现；`call_user_func` 不支持 Native 对象 |
| **用 int 命令 ID + 静态路由表** | 多写一个常量；但换来编译期可检查、可序列化、可回放 |

★ 第三条不只是"最不坏"，它**顺带解决了三个本来要单独设计的问题**：
撤销栈、回归夹具、AI 驱动。**约束与特性在这里是同一件事。**

## 3. 待验证的未知数（P0 第一件事）

| # | 未知数 | 怎么验 | 影响 | 不成立时的退路 |
|---|---|---|---|---|
| **V1** | `#[Native]` 值对象（`BoxConstraints`）传参，是否真比 4 个 float 参数快 | 微基准：5000 次 `layout()` 调用 | 约束模型 | 退回 4 个 float 参数 |
| **V2** | `#[Native]` 类能否跨 `-m lib` 边界（SDK 形态） | 编一个含 Native 类的 lib，再让应用消费 | 框架编一次 vs 每应用重编 | 每应用重编（可接受，Drift 现状） |
| **V3** | `toObject(Node::class)` 在 5000 节点 × 5 阶段遍历中的实际成本 | 微基准 + 看生成代码是 `php_*` 还是动态调用 | 孩子遍历 | 父持索引 + 类型化 accessor 方法 |
| **V4** | 闭包作为**参数**（不存属性）的开销 | 微基准：1000 次调用 | `Repeater` 是否可用闭包构建器 | 数据驱动 `CellSpec` + 对象构建器 |
| **V5** | `int` 位域运算（`$f & 0x3`）是否保持原生 | 看生成代码 | 脏位成本 | 多个 `bool` 字段（多几个字节，无性能差） |
| **V6** | `#[Getter]` + `#[Immutable]` 在 Native 类上的实际开销 | 微基准 vs `public` 字段 | 值对象设计 | 直接用 `public`（但失去只读保护） |
| **V7** | 每平台 ZTS 构建可行性 | 按上游文档编一次 | `Async::thread` 前提 | 子进程池 |
| **V8** | `enum` 在 Native 语境下是否可用 | 写一个带 `enum` 参数的 Native 类 | 命令/角色常量形态 | `final class` + `public const`（已按此设计） |
| **V9** | ~~op 流容器选型~~ **已由约束解掉**（段是属性 ⇒ 只能 packed array） | — | — | 只剩"追加开销"可优化（预分配 + 游标） |

★ **V1–V6 决定的是"性能上限"，V7 决定"能不能并行"，V9 决定"绘制快慢"**。
**它们都不影响架构形状**——这是本方案相对 design-v6 的改进：
v6 有 7 条未知数会动摇架构（比如 `?int` 是否退化决定整个约束模型），
本方案把未知数都推到了"可替换实现"的层面。

## 4. 一条自我约束

**任何新增的"便利 API"必须先回答：它在生成代码里是什么？**

如果答案是"一次动态调用"或"一个 `php::Var`"，那它就不能进热路径
（`layout` / `paint` / `dispatch`），只能进建树期或冷路径。

★ 这条规则的作用不是限制功能，是**限制功能的位置**。
便利 API 可以存在，但要放在对的地方——这是 TypePHP 项目最容易犯的错。

## 5. 编译器事实补遗（实测与踩坑记录）

> 这一节全是"试出来的"，不是文档写的。每条都附症状，因为它们的共同点是**静默或错位**。

### 5.1 tpc 比 PHP 严的地方

| 事实 | 症状 | 对策 |
|---|---|---|
| `switch` 的每个 `case` 必须以 `return`/`break`/`continue`/`exit`/`throw` 结尾（**`default` 也是**） | 编译报错，且指向下一行 | 每个 case 都显式收尾 |
| `catch (\Throwable $e)` 与前面 `$e = []` 同名 | **编译拒绝** | 变量名不跨语义域复用 |
| 可选参数排在必选参数之前 | Fatal | 必选在前 |
| 类常量与同类方法同名 | `C2872`（歧义符号） | 常量加前缀 |
| **变参在循环里累积** | 编译器 bug，结果不可预测 | 用 `->children(array)`（[19](19-控件API语法.md) §1.1） |

### 5.2 命名空间内的函数调用

★★ **非限定函数调用不回退全局** ⇒ 内置函数必须写 `\mb_substr(...)` 或先 `use function`。
症状是"函数不存在"，而代码在解释模式下明明能跑。

★ **没有 `$argv`** ⇒ 用 `$_SERVER['argv']`。

### 5.3 属性与注解的作用域

| 注解 | 能用在 | 不能用在 |
|---|---|---|
| `#[Immutable]` | 方法 / 属性 hook / 函数参数 | **类**（编译期报错） |
| `#[MethodsFor]` | **类**（Provider 类） | 函数（编译期报错） |

★ **常量覆盖是整体替换**（不是合并）⇒ 子类要加字段，字段表必须**运行时合并**
（`BASE_FIELDS + FIELDS`），不能靠 `const` 覆盖。

### 5.4 路径与资源

★ `__FILE__` / `__DIR__` **编译期固化** ⇒ 资源路径必须走 `Platform::assetDir()`（[08](08-平台与能力矩阵.md) §2）。
★ `--nano` 不支持 Fiber ⇒ 走 `-m bin`。
★ `--no-console` 无 stdout ⇒ 日志只能走文件。

### 5.5 异常跨语言边界

★★ 生成的代码里，PHP 异常在 C++ 层是 **`throw zend_object*`**，
C++ 侧要写 `catch (zend_object *)`。phpx 没有 `Exception` 类。

★ **异常绝不能穿过 C++ 栈**（[08](08-平台与能力矩阵.md) §9.6 第 2 条）：
桥函数失败必须返回值，不抛异常。

### 5.6 资源释放的时序陷阱

★ `proc_terminate()` 之后 `fclose()` 资源 ⇒ **TypeError**。
判据：任何"先终止、后清理"的组合，清理前必须 `is_resource()` 保护。

### 5.7 一条元规则

★ **AOT 只编译可达代码** ⇒ 扩了用法面（新增一个分支、新的命令处理）就必须真机构建。
增量缓存可能不重编 `Bootstrap.php` ⇒ grep 生成物里的新符号，或删 `.cc` + `.obj` 重编。

★ **解释模式过了不算完**：类型钉死、闭包元数、多字节堆损坏三类问题只在编译后暴露
（[12](12-工程与工具.md) §9.3）。
