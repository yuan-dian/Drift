# 评估：示例应用该不该有测试用例与验证工具？

> 2026-11-13 · 只读评估，未改任何 `src/` / `tests/` / `tools/` 文件。
> 提问：「`tools` 和 PHPUnit 里是否有示例应用的测试和验证工具？示例应用是不是不应该有
> 测试用例和验证工具，验证与测试应该只针对核心框架吧？」

## 0. 结论

**提案的事实前提不成立，整体判死；但其中「应用内容不该被框架判据绑住」这一条关切成立，
且有一个比删测试更优的落点。**

一句话分辨：这些测试**不是「测示例应用」，而是「用示例应用当场景测框架」**。
`apps/` 下 0 个测试用例；284 个测试与 13 个真机探针全部住在框架仓，断言主语绝大多数是
框架行为。真正按提案删下去，删掉的不是示例应用的测试，而是框架的判据输入、变异史，
以及唯一能抓 AOT 编译期语义的 T2 层。

## 1. 事实盘点（重核 HEAD `4142687`）

| 项 | 数量 | 说明 |
|---|---|---|
| `apps/` 演示应用 | 8 | `hello` / `showcase` / `users` / `watermark` / `bench` / `dev` / `pacing` / `tutorial` |
| `tools/Smoke/App/` 夹具应用 | 78 | 判据输入 / 场景定义，不是产品 |
| `tools/probe-*.py` 真机探针 | 13 | 起 `<app>.exe`，验窗口 / 像素 / UIA / 退出码 |
| `tests/` | 284 | Feature 190 / Unit 84 / Support 10 |
| 引用 `Smoke\App` 的测试 | 82 | 夹具当输入 |

| `golden/` 基线 | 34 整页 + 9 原语 | RGBA 像素 md5，不是命令序列 |
| `apps/**/tests/**` 被 git 追踪 | **1** | `apps/users/tests/fixtures/memory_source.php`，是数据夹具 |

**`apps/` 下没有任何 `*Test.php`、没有 phpunit 配置、没有验证脚本。**
唯一那 1 个文件是 `drift-preview --fixture` 的离线数据源，而且它放在 `tests/` 下是
**故意的、不能挪进应用源码**：文件头注释写明夹具必须写顶层 `return`，而 AOT 编译器
不认 `Stmt_Return`，一旦落进 `project.yml` 的 `sources` 扫描范围，构建当场
`Fatal error: Unsupported statement: Stmt_Return`。
⇒ 「示例应用不该有 tests 目录」这条洁癖若真去执行，第一脚就踩 AOT 构建中止。
它该改的是**命名/归属说明**，不是删除。

## 2. 概念辨析：三种「应用」、两种「测」

提案把三个不同的东西并成了一个词：

1. **演示应用 `apps/*`** —— 给用户看框架能做什么，同时是「框架能跑真应用」的最小证据；
2. **夹具应用 `tools/Smoke/App/*`** —— 78 个，是**判据输入**。`ComboBoxApplication.php:49-56`
   刻意放 4 个城市、其中 2 项含「北」，只为区分「过滤后取第一项」与「取全部」；
   `onChanged` 回写 `setState` 而非直接 `update()`，编码的是 2026-10-24
   「同步重建 ⇒ 跳过 layout ⇒ 第二次点击打不开面板」的修复。**删夹具 = 删场景定义**；
3. **测试替身 `tools/fakes/{skia,win32}.php`** —— 故意与真 C++ 桥**不同源**的反同源资产，
   由 `tools/abi-check.php:99` 做变异牙检（改 `float $opacity` ⇒ 必须红）。
   它让「解释器面没有真桥」这件事保持可见。

两种「测」：

- **测应用**：断言应用自身文案 / 业务内容。全仓极少，见 §4；
- **用应用测框架**：应用只负责把框架推到一个可观察状态，断言落在布局、绘制、状态机、
  输入链、帧边界、像素确定性上。这是主体。

例：`tests/Feature/App/HelloAppTest.php:22-33` 的注释把判据定义为
「表面是**注入**的 ⇒ 无平台也能挂载」「`drawParagraph` 曾直接用传入坐标（不跟变换）
⇒ `Center` 算出的偏移在 paint 时被丢掉 ⇒ 文字贴左上角，**而墨点数一模一样**」。
它看似在测 hello 页面，实际守的是一个「几何对了但没画出来」的框架缺陷。
`tools/smoke.php:3532-3546` 的「22 个导航项都上了字」也不是文案断言：
注释写明判据是 `drawOpCount(OP_DRAW_PARAGRAPH) >= 22`（少画一项就少一条命令，
可证伪），而 `inkCount() > 0` 只要有一个字就恒真 —— 是**绘制覆盖度量具**。

## 3. 为什么「验证与测试应该只针对核心框架」在本框架不成立

### 3.1 核心框架纯类没有可观察输出

GUI 框架的输出是**像素、窗口、UIA 树、帧命令流**，这些只在有消费者场景时才存在。
`tests/Unit/` 84 个文件里也有 3 个引用 `Smoke\App/worker.php`
（`JobProgressTest` / `JobTimeoutTest` / `PrewarmTest`）——因为 Job / 超时 / 预热必须
在真子进程里跑一个夹具才有状态可断；`SpinnerTest.php:165-168` 甚至要 `Frame::run()`
才能看到「前后两代树」。**「只测核心框架」在物理上等价于「只测不产生输出的那部分」**，
剩下的能力全部失守。

### 3.2 T2 是 AOT 编译期语义的唯一入口，它只能跑真 exe

`DESIGN.md` §7：T0 无头、T1 dev 真机、**T2 AOT 真机 = 唯一能抓 AOT 编译期语义**；
`docs/architecture/12-工程与工具.md:46`：「T0 与 T1 都不编译业务 PHP ⇒ 都看不见
AOT 编译期语义」。

仓内反复吃过这个亏，且全部是「解释器 + phpunit + smoke 全绿、真机炸/静默失效」：

- enum 内非 case 常量 ⇒ AOT 启动 `0xC0000005`（`PITFALLS.md:4986`）；
- AOT 校验闭包实参个数、解释器不校验 ⇒ 真机 `Fatal: {closure}() expects exactly 0 arguments`；
- `int / int` 在 AOT 下整数除法，静默截断（`PITFALLS.md:5261-5266`）；
- 跨实例读 `private` / 可空 `?->m()` ⇒ 读成 null 只静默；
- `docs/AOT-CONSTRAINTS.md:819`：「**不能用『解释器绿』代替**」。

`CheckRegistry.php` 里 `pages` / `smoke` / `m2` / `tick` / `scale` / `unit` / `feature` /
`genversion` / `devshell` 这些判据，本身就以应用或应用清单为输入；
`golden-raster.php:610` 直接 `glob('apps/showcase/src/Pages/*.php')` 拿 27 个真实页当分母，
`aot-equivalence.php` / `dual-mode-equivalence.php` 用同一份 `Fingerprint::snapshot()`
做解释器↔AOT/dev 壳逐值等价。**没有应用，就没有「真实页」这个分母。**

> **勘误（2026-11-13，见 `DESIGN-EXAMPLES-TESTING-TARGET-2026-11-13.md` §8）**：
> 上句把 `golden-raster.php:610` 的活 `glob` 与 AOT 等价量具的「27 页分母」并列表述，
> 容易被读成后者也是活引用。实际后者来自 `tools/Bench/ShowcasePages.php` 的**固化清单**
> （27 页，只收构造器无必填参数的页），而 `golden-raster.php` 的活 `glob` 覆盖 34 页，
> 且 `tools/frame-tax-probe.php` 判据⑤ 已对这份固化清单做双向比对（只是不进 gate）。
> 「删掉真应用验证会失去 T2 入口」的结论不变；「27 页是活引用」这一具体描述作废。

### 3.3 删判据会让 gate 更绿 —— 全绿不是验收线

这是最容易被忽略的一点：按提案删完之后 `composer check` 必然更快更绿，
但这个绿是**假绿**。项目已有的裁决（`PITFALLS.md:5731-5748` 下沉节 C）逐字写明：
> 78 个夹具应用是**判据输入 / 场景定义**，不是 harness。
> 3459 条判据的**变异史**作废（重写后即使逐字等价也没有「被咬红过」的证明）。

并给了「才允许删」的可证伪条件：逐条对齐、每条改写后能被变异咬红、`abi-check` 对
fakes/stub 仍咬红、`composer check` 全绿 + T2 探针 5/5、golden/pages 基线哈希不变。
其中第 ② 条成本 >> 收益 ⇒ **不删**。

## 4. 提案里站得住的那一小块

诚实地说，有一小撮断言确实在测「应用自己的东西」：

| 位置 | 内容 | 判断 |
|---|---|---|
| `tools/smoke.php:3332` / `:3532` | `title() === 'Drift 教程'` / `'Drift 示例台'` | 纯文案。改标题就红，但守的是 §4.5「应用只写 `buildRoot/title/commands`」这一**框架契约面**，不是文案审美 |
| `tools/smoke.php:3603` / `:3611` | Feedback 页标题 / 「打开对话框」按钮 | 注释自述是「`Modal` 有应用侧消费者」——**零消费者探测**，仍是框架契约 |
| `tests/Feature/Watermark/` 11 文件 | `ApiClientParseTest` / `SignInfoTest` / `TaskResultTest` 3 个纯值对象 | **唯一真正不碰框架类的一族**，约 284 的 1%；另 8 个测的是 `WatermarkStore` + `Job` + `Future`/`AsyncValue` 异步链路，属框架 |

但这 3 个也不是「随手可删的 demo 测试」：它们的注释各自写明了**错了会静默**
（`extractTaskId` 兜底缺失 ⇒ 建任务成功但永远转圈；`SignInfo::isExpired()` 把秒级
时间戳当毫秒 ⇒ 无限重签、永远传不完；`TaskResult` 未知状态不算终点 ⇒ 每 10 秒重试
一个不认识的状态码）和**变异会咬红**（`SignInfoTest` 头注直接给出变异体）。
它们符合本仓「判据不与实现同源 + 变异自证」的准入门槛。

## 5. 更优方案：不删测试，把被测代码放到对的位置

用户真正想要的「验证只针对核心框架」，正确落地方式不是删，而是**分层**：

**A. 上移，而不是删除。** 那 3 个纯函数（`extractTaskId` / `SignInfo` / `TaskResult`）
本质是 SDK 级解析与状态机契约，不是 demo 文案。把它们从 `apps/watermark/src/Api/`
上移到框架的共享契约层（或明确标注为 `apps/watermark` 的公开契约面），
测试自然就从「测示例应用」变成「测框架」——**主语没变，位置对了**。
这比删掉 3 个带变异史的判据代价小得多。

**B. 内容断言与结构断言分离。** 若担心改 demo 文案就撞红：
把 `title() === '字面量'` 改成结构性判据（「`title()` 非空 / `buildRoot()` 返回 Widget」
+ 「应用没有覆写框架生命周期方法」），并在 `smoke.php` 里显式标注
「本节是应用内容哨兵，改应用时同步更新」。这样 §4.5 契约仍被守着，
文案不再是判据。**注意：`golden/page` 34 张整页基线刷不刷是另一回事**——
`golden-raster.php` 已注入确定性字体/主题/Scale（`REVIEW-ARCH-DX-2026-11-08.md:116`
判「不脆弱」），改页面视觉本就该刷基线，这是能抓渲染回归的**特性不是债**；
原语 9 张与整页 34 张已经分层，不必再动。

**C. `apps/users/tests/fixtures/` 只改说明不改位置。** 在文件头或
`docs/architecture/12-工程与工具.md` 补一句「这是 `drift-preview` 的离线数据夹具，
不是应用自测；因 AOT 不认 `Stmt_Return` 必须留在 `sources` 扫描范围外」，
消除观感歧义即可。搬走会踩 §1 那个构建中止。

## 6. 若仍要按原提案执行：停止线

按 V2 纪律，「答不出怎样的变异能让它报红」的能力不上仓；同理，
「拿不出被删判据仍能抓到缺陷的证据」就不许删。必须逐条满足：

1. 把 284 个测试 + `smoke.php` 473 条 `check()` 按**断言主语**分类，只有主语确为
   「应用内容」的条目进入候选，其余一律不动；
2. 对每个候选，**先做变异证明它曾咬红**；咬不红的先当死判据单独处理，不要混在
   「删示例应用测试」里一并冲掉；
3. 构造一个「只有被删的那条能抓到」的缺陷变体，证明删完后仍有别的层报红；
   做不到 ⇒ 说明它是唯一守门人，不许删；
4. `golden/pages` 34 张基线哈希不变、`composer check:full` 21 项、T2 探针全绿、
   `docref` 0 FAIL —— **这是必要条件，不是通过条件**（见 §3.3）。

## 7. 五维评估

| 维度 | 按原提案删 | 按 §5 分层 |
|---|---|---|
| 结构 | 破坏「应用 = 判据输入」的分层，T2 无载体 | 保持三层，只调整契约归属 |
| 实现 | 失去 AOT/真机唯一入口，静默缺陷回归 | 零行为改动 |
| 扩展性 | 新平台（Android / Headless）失去现成真机判据模板 | 探针可复制到新后端 |
| DX | 短期「gate 更快」，长期改框架不敢验证 | 改 demo 不再撞无谓红 |
| 维护性 | 3459 条判据的变异史作废，且假绿 | 变异史保留，仅新增标注 |
