# 设计证据 B10：基线只在可复现的度量上断言

日期：2026-11-25 ｜ 上接 P5 第一项（规则注册表）与 B9（手册接线）

## 1. 先证伪推荐

`debugger-roadmap.md` 把「基线回归」的未做原因写成一句：「依赖规则 id 稳定，现在有了」。
实测这句只说了半个前提。同一个页面、同一份脚本、连跑五次：

```
slow-frame    38.47  36.98  41.18  42.42  39.43     ← ±7%
stage-dominance 29.01 27.00 30.43 30.54 28.42      ← ±6%
fanout        360    360    360    360    360       ← 逐值相同
unvirtualized 12     12     12     12     12        ← 逐值相同
constraint-tightened 558.4 / 290.4 ×5               ← 逐值相同
```

所以「规则 id 稳定」不足以保证基线能用：**耗时不可复现**。若把 `slow-frame` 的
42ms 写进基线，下一次 38ms 报"修好"、42.4ms 报"变差 1%"，容差 5% 挡不住 ±7%
的抖动 —— 这份报告每天都会红一次，而每次都是假的。假红三次之后，没人再读它。

这不是实现问题，是**判据该建在哪种度量上**的问题。

## 2. 候选方案

| 方案 | 做法 | 优点 | 代价 / 坑 |
|---|---|---|---|
| A 整份 `--json` 当基线 | 存 60 行 JSON，逐字段比 | 实现最省事 | 进版本控制后 diff 不可读；阈值一改全量"变化"；耗时抖动同上 |
| B 只存度量清单 + 全量比较 | `(rule,address,value)` 三元组，耗时也计入回归 | 简单 | 同上假红，且更隐蔽——报告看起来"很专业" |
| C 度量清单 + 确定性分级（选） | 基线存精简清单；规则声明 `deterministic`；断言只数确定性回归，耗时类照列不计 | 断言可复现、无假红；耗时仍在报告里，只是不冒充结论 | 多一个规则属性；"变慢了"不能直接卡 CI |
| D 不做基线，只做 `--assert` 阈值 | 断言"回归数 ≤ N" | 更少概念 | N 从哪来仍是手填，等于把基线换成魔数 |

C 的取舍要说清：**P5 的判据「回归能红在度量变差」依然成立** —— 重建数、重画帧数、
约束收紧 px 都是度量，而且它们才是"改了代码之后到底好没好"的主证据。耗时类不是
不能进 CI，而是要用多轮取中位数（B5 `loop` 已有这个能力），那是另一件事，
写进未做清单，不在这里用单次采样冒充。

## 3. 裁决

1. **基线是一份精简清单**，不是一份证据：
   `{version, label, digest, thresholds, selection, excluded, findings:[{rule,version,severity,address,title,metric,value}]}`。
   只有对比需要的身份与数值；可以进版本控制、可以手改、可以按行 review。
2. **写与读分开**：`--baseline=<文件>` 读，`--save-baseline=<文件>` 写。不做"文件不
   存在就写"——那会让一次 CI 跑的副作用改掉基线，而报告还会说"通过"。
3. **确定性分级**：`Rule::deterministic()` 默认 `true`；`slow-frame` / `stage-dominance`
   覆盖为 `false`。对比时两类都算状态、都列行，但只有确定性规则计入 `regressions`。
   非确定性的行首标 `~`，段尾自报"不计入断言"。
4. **兜底发现不进基线**：`clean` / `inconclusive` / `suppressed` 的 `value` 为 `null`，
   它们不是度量而是结论。`--save-baseline` 时过滤并记 `excluded`（解释"干净应用的
   基线为什么是空数组"）。对比时两侧都 `null` 判 `same`（结论相同），只有一侧 `null`
   才 `uncomparable`。
5. **口径变化只报不平，不改状态**：阈值、规则选择、指纹三项与基线不同时，头部各写
   一句。不阻断、不改变行状态 —— 那三项变了之后 new/fixed 本来就该出现，
   再叠加一层"整体不可比"会让读者两个信号都读不懂。
6. **退出码 3**，与 `loop --assert` 一致（跑通了，但结论是否定）。
   `--assert` 不给 `--baseline` 直接报错：没有期望值就无从断言。
7. **同 `(规则, 地址)` 重复要计数带出**，不能静默保留第一条。原先 `Baseline::index()`
   的注释写了"把重复数带出去"而代码没带 —— 注释说了做不到的事，本轮补上。
   地址撞车本来就是真 bug（约束改写的宽/高），这个计数是那条不变量的监视器。
8. **Web 不接基线**：观察台看的是"现在什么样"，基线是 CI 的事。`--json` 带
   `baseline` 顶层键，机器消费者拿得到。

## 4. 判据与变异

正向：七种状态各一条、容差边界（等于容差不报、略超就报）、0 → 正数算变差、
耗时类不计入 `regressions`、变差排最前且按幅度降序、重复键计数、
基线与当前同源时零回归、`--save-baseline` 写出的文件能被 `--baseline` 读回、
文件缺失 / 版本不认识 / 结构不对各自报错且不当空基线、`--assert` 无 `--baseline` 报错、
有回归退出 3 无回归退出 0。

反向变异至少六组：把耗时类算进回归、容差写成 >=、0 基线走除法、去掉重复计数、
文件缺失当空基线、兜底发现进基线、断言只看总数不看确定性。

验收链：PHPUnit（Debug + 全量）、`verify --full`、`tools/doccheck.php`、`tools/lint.php`。
