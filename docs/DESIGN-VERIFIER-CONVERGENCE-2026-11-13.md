# 验证体系 V2：全删重建裁决（2026-11-13）

> 本文替代同日上午的「收敛」方案。用户裁决：**不再一轮轮修工具，全部删除，按标准验证流程重新设计重写**。
> 本文只加一个前置条件：**删之前先建缺陷题库**。理由不是保守，是逻辑 —— 删完 gate 必然全绿，没有对照组就无法证明新体系不比旧的差。

## 0. 决断

**同意全删重建。** 成熟 GUI 框架没有这么复杂，是因为它们没有 Drift 长出来的这一层：

- `tooling` 组 12 条里 **6 条是「判据的自证」**（`abiself` / `cppbridgeself` / `dxself` / `staleself` / `errself` / `scenesetself`），另有 `selftest`（lint 自检）、`probe`（探针骨架审计）、`sym` / `decode` / `m2` 的 `--selftest`。这是一层**元判据递归**：历史上出过「判据静默失效」，于是给每条判据再配一条判据。
- 6 份静态对账脚本 1,370 行，本质是用 PHP 文本扫描**模拟编译期保证**（tpc/AOT 没有静态分析器）。成熟框架的 analyzer / 编译器替它们做了这件事。
- 21 项判据无差别全跑，改一行 `src/` 也等 150.7s；`--fast` 只是把 3 项标 slow，没有真正的分层与增量。

**标准流程的答案不是「给每条判据配自证」，是「一个 mutation testing 运行器统一回答判据有没有牙」。** 这就是 V2 的核心：把 N 条元判据压成 1 份题库 + 1 个量具。

## 1. 删之前先有的那一件东西（本轮已落地）

`tests/Contracts/DefectCorpus.php`（纯数据）+ `tests/Contracts/run-corpus.php`（量具），**2 个文件，放在 `tests/` 不在 `tools/`**。每条缺陷是历史上真实修过的事故 + 把它复原到工作树的最小操作；判据不写进题库，由量具对每套体系跑覆盖率矩阵来比较。注入一律 `try/finally` 还原，锚点不唯一直接抛（不静默测错东西）。

## 3. V2 目标形态（标准验证流程）

参考 Flutter（一个 `flutter test` + `dev/bots` 分片 + golden 独立服务）、Chromium（`PRESUBMIT.py` 的 `AffectedFiles()` + gtest）、Qt（`tests/auto/<module>` 每模块一个 target）的共同点：**一个运行器、语言级静态检查、少量真实端到端、CI 分片**；没有元判据递归。

```
bin/drift verify                     ← 唯一入口（复用已有 CLI，不新增顶层脚本）
 ├─ static    lint（保留 32 规则；编译器没有的能力）
 ├─ behavior  PHPUnit(unit+feature) + golden + smoke，按目录分片，可增量选跑
 ├─ device    AOT 构建 + 少量端到端探针（T2 / 发版，人工触发）
 └─ corpus    缺陷题库验收（一次性，取代 12 条元判据）
```

判据可信度由 `run-corpus.php` 统一回答「每个缺陷至少有一条判据变红」，**不再给每条判据配一个 `--selftest`**。V1 的 6 对自证、`gate --list` 里的元判据项整体消失。

速度 SLA：`verify` 日常 ≤ 15s、`verify --full` ≤ 150s、CI 只认 `--full`；本地 `--affected` 默认关闭且不作为验收线（动态删判据 = 静默变绿，这条红线不因重建而放宽）。

### 7.2 通道选型：为什么是这 9 条

判据不能按「21 项 gate 全跑」来选：`feature` 一条就 63s，23 条缺陷乘上去是 40 分钟。
选型标准是**每类缺陷至少有一条代表通道**，且通道之间**判据不同源**。

| 通道 | 守什么 | 实测 | 层级 |
|---|---|---|---|
| `sceneset` | 场景集合三向封闭（冻结清单 / 磁盘 / 基线） | 0.9s | core |
| `docref` | 文档引用的文件 / 链接 / 章节 / 项目名存在吗 | 2.9s | core |
| `apidoc` | `API-SURFACE.md` 是不是最新的 | 1.2s | core |
| `theme` | 语义 token 有没有真实消费者（feature 切片） | 1.2s | core |
| `lint` | 32 条静态规则（模拟编译期保证） | 8.0s | core |
| `pages` | 34 份整页像素基线（**独立把 RGBA 算出来**） | 9.0s | core |
| `unit` | 纯单元（621 条） | 16.2s | core |
| `smoke` | 行为（渲染 / 布局 / 输入 / 异步，1217 条） | 22.4s | core |
| `feature` | 场景测试全量（900 条） | 62.9s | **full** |

并发后单缺陷墙钟 = 最慢那条：`core` ≈ 24s、`full` ≈ 65s。串行会是求和（63s / 125s）。
并发的前提是**通道之间不共享可变状态**（缺陷注入本身仍是串行的，每个都要改工作树）。

### 7.3 两条纪律（写进题库 docblock，量具会执行）

1. **`aot === false` 的条目必须至少被一条通道抓到**。抓不到就是题库或通道在骗自己 ——
   量具直接 `exit 1` 并列出 `blind` 名单，不许「记录一下就算了」。
2. **`aot === true` 的条目不计入覆盖率分母**。它们在解释器侧**本来就全绿**（这是已知缺口，
   不是假绿），如实记录、单列输出。把它算进分母会让 V2 的对比自己骗自己。

### 7.5 六个结论

1. **`feature` 不可删。** `U3`（`after()` 基准）/ `B1`（两相位叠色）/ `B2`（重建换盒先归零）
   三条在 core 的 8 条通道上**全绿**，只有 `feature` 抓得到。它是行为判据里最贵的一条
   （63s），也是最不可替代的一条 —— 「把贵的砍掉」会直接砍掉一半交互语义。

2. **`sceneset` 与 `pages` 在集合类上完全重合**（D1/D2/D3 三行两列同时红），
   但 `pages` 另有 G1/G2 两行独占 ⇒ `pages` 是 `sceneset` 的超集。
   `sceneset` 剩下的价值只有「0.9s 的快速反馈」；V2 里它可以降级成 `pages` 的一个子模式。

3. **`lint` 对静态缺陷 5/5，但边界必须诚实**：最初把 `new Size(` 改成 `new SizeX(`
   （全仓不存在的短名）时规则**故意不报** —— 静态无从区分「漏 use」与「就用全局类」。
   换成 `Paint`（Rendering 的真类、Geometry 没 `use`）才红。这不是规则缺陷，是它的设计边界。

4. **有些缺陷「一处改动不成立」。** §13.1 的双重扣减必须同时「弹性子第一遍照量」+
   「扣减不过滤弹性子」；只改后者是**空操作**（弹性子的占位值本来就是 `0.0`）。
   第一轮跑出 `blind` 就是这么来的。⇒ 题库需要 `replace-set`，而
   **「变异必须真能改行为」本身要写成量具的判据**（否则盲区会被当成"判据没牙"）。

5. **`apidoc` 需要自己的缺陷。** 第一轮 20 条可评分缺陷它一条没抓到 —— 不是通道无用，是题库漏了一类：
   「新增 `@api` 却不重生成清单」，而 `api-doc-check.php` 的 docblock 里就记着真事故
   （`FrameStage` 没进文档）。补 `L6` 后 1/1。**没有缺陷的通道，等于没被验收过。**

6. **`aot-only` 两条在 9 条通道上全绿**，这正是单列它们的原因：`A1`（enum 非 case 常量）
   与 `A2`（`self` 当静态属性类型）在解释器侧完全正常，只有 AOT 产物崩。
   它们不是「V1 抓不到」的缺口，而是「任何解释器侧通道都抓不到」的已知边界 ——
   V2 若要覆盖，只能靠 AOT 构建 + 启动烟测，不能靠加判据。

## 8. S2 开工前的三项裁决（2026-11-13）

### 8.1 「文档检查可以直接删吗」—— 可以，但要显式退役，不能悄悄删

**撤回本节上一版「不能删」的裁决。** 用户补充的前提改变了结论：当前 `docs/` 是开发
过程中迭代出来的产物，正式发布前会整体重构。于是 `docref` 的四条检查
（`file-line-refs` / `section-refs` / `markdown-links` / `project-name`）与 `apidoc`
守的是一套**即将被替换**的文档：跨册 § 编号、`file:line` 引用、章节结构、行号派生
的 API 清单，重构后全部失效。守一个马上要拆的对象没有价值；成熟框架也不写独立
文档验证器（Rust 把 `broken_intra_doc_links` 并进 rustdoc lint、Chromium 并进
PRESUBMIT），方向一致。

⇒ **裁决**：V2 目标形态里**不给文档验证留位置**；`docref` / `apidoc` /
`DocRef/Checks/` / `API-SURFACE.md` 随 S4 一起删。上一版指出的 `static` 层缺位自动消失。

⇒ 但「直接删」有三个必须同步的交接动作，否则精确复现「删判据让 gate 更绿」：

1. **题库显式退役 4 条**。`R1` / `R2` / `R3` 只有 `docref` 抓到，`L6` 只有 `apidoc`
   抓到；它们描述的是旧文档体系的引用完整性事故，重构后不再是同一种缺陷形态。
   不能从题库里悄悄抹掉 —— 标 `retired` + 理由 + 日期，`graded` 从 21 降为 17。
2. **分母与基线在 S2-1 第一步同步重算**（不是等 S4）——已落地：从 `v1-full.json`
   派生 `v1-postdocs-full.json`（17 条），`--suite=v2` 的 `regress` 对照指向新基线；
   **旧基线保持 21 条原样**作历史真值，不就地改。若不换基线，V2 会被这 4 条永远顶红。
3. **文档重构那一棒自己承接验收**。新文档体系把「引用完整性 + API 面清单」内建进
   生成器 / 发布脚本，不另起验证脚本。`project-name` 是命名纪律不是文档内容检查，
   成本近零，并入 `lint` 保留。

⇒ **删除时机**：文档重构尚未发生，此刻物理删会让中间这段时间的引用烂了没人知道，
且 `run-corpus.php` 立刻 `exit 1`（4 条 `blind`）。所以**设计上现在就删（V2 不建），

### 8.2 IR 时序死结 —— 拆成 S2-1 / S2-2

`ANALYSIS-IR-VERIFICATION` §5 要 V2-1（IR 快照主面）进 S2、V2-5（IR 层缺陷）并进题库；
§7.6 却说 IR 缺陷「本轮故意不加」。两者不是矛盾，是顺序没写清：V1 没有 IR 通道，
现在把 IR 缺陷加进题库必然 `blind`，污染「非 aot 必须被抓到」纪律；而 S2 若先建 IR
快照判据却不配缺陷，又撞 §7.5 ⑤「没有缺陷的通道 = 没被验收过」。

⇒ **裁决**：S2-1 先建 `bin/drift verify` 三层骨架 + 分片，通道集合覆盖退役后的 17 条，
跑通 `--suite=v2 --tier=full` 且 `regress=[]`；S2-2 再加 IR 快照通道，**同批**把
4 类 IR 层缺陷写进题库并逐条给出「IR 快照能报红」的反证。
不引入 `since: v2` 之类的新分母语义 —— 那会让覆盖率口径变复杂，收益不抵风险。

⇒ **S2-1 已落地**：`bin/drift verify`（四层 + 34 个分片 + `--list` 唯一事实源）、
题库 `--suite=v2` 从 `VerifyPlan` 生成 7 条通道；4 条文档缺陷显式退役，对照基线
换成 `v1-postdocs-full.json`（17 条）。S3 的 `--tier=full` 全量矩阵仍需实跑。

⇒ **S2-2 已落地**：`ir` 通道（`tests/Verify/ir-snapshot.php`）渲染固定夹具
（`tests/Verify/IrFixture.php`，`CustomPainter` 直接发 4 类命令）→ `PaintFingerprint`
逐命令序列化 → 与入库基线 `tests/Verify/baseline/ir.txt` 逐字节比对。同批把 4 类
IR 层缺陷写进题库（`I1` op 顺序 / `I2` 裁剪没弹 / `I3` 两色传反 / `I4` 平移与变换分叉），
逐条实证「注入 ⇒ `ir` 红、还原 ⇒ 绿、零残留」。`ir` 在 `behavior` 层 `fast` 档，
不进 `device`；判据与实现不同源（序列化走 `PaintFingerprint`，与录制器两套代码）。

### 8.3 `--suite` 从标签升格为路由

此前 `$suite` 只是报告字段，`$probes` 写死 9 条 V1 通道 ⇒ `--suite=v2` 会把 V1 结果
贴成 v2 标签。现改为显式套件表（`v1` 有效 / `v2` 未注册即 `exit 2`），并在非 v1 套件下
自动对照入库基线输出 `regress` / `gain`；裁剪矩阵（`--defect` / `--probe`）不许当
验收报告，直接 `exit 2`。基线文件同时从 `_build/` 搬进 `tests/Contracts/baseline/`，
S4「删前删后对照报告入库」才有落点。
