# 23 桌面集成

> 本册回答：**文件对话框、托盘、拖放、剪贴板、单实例——这五件"框架外的事"怎么接进帧循环。**
> 它们的共同特征：**由 OS 发起、可能阻塞、可能改变窗口存在性**，
> 所以不能当普通控件写（普通控件不会挂起 PHP 主循环）。

---

## 0. 一句话

**五件事都在"帧的边界"上进出：进来前先 present，出去后强制全刷 + 重置帧钟。**

---

## 1. 文件对话框

### 1.1 为什么不能直接调

Win32 的 `GetOpenFileName` / `SHBrowseForFolder` 会跑**自己的消息循环**
⇒ PHP 主循环被挂起（Drift2 踩过，见 [08](08-平台与能力矩阵.md) §9.1 的"生命周期倒置"）。

症状（都很具体）：
- 对话框打开期间主窗口不重绘 ⇒ 被别的窗口盖住后留下"白块"；
- 关闭后**残留旧像素**（对话框覆盖区域没重画）；
- 动画在回来后**一次跳完**（`dt` 是对话框停留的秒数）。

### 1.2 三条顺序（缺一就出上面的症状）

```
① present 当前帧 —— 把"要弹对话框"这件事先画出来（否则用户看到的是上一帧）
② 进模态循环（阻塞）
③ 回来后：清脏区 → 强制全刷 → **重置帧钟**
```

★★ **③ 的"重置帧钟"是最容易漏的一条**：不重置的话，回来第一帧的 `dt` 是对话框停留的几秒
⇒ 所有基于 `dt` 的动画一次跳完、滚动惯性一次滑到底。

### 1.3 返回值用哨兵，不用可空

```php
public function openFile(string $title, string $filter): string;   // '' = 取消
public function saveFile(string $title, string $filter): string;   // '' = 取消
public function pickFolder(string $title): string;                 // '' = 取消
public function message(string $title, string $body, int $buttons): int;  // 返回按钮位
```

★ `?string` 退化 `php::Var`（C2）。**空串是哨兵**：文件路径不可能是空串（`""` 不是合法路径）。
★ `message` 返回 int 位（1=OK / 2=Cancel / 4=Yes / 8=No），调用方自己判——比返回字符串可测。

### 1.4 首版阻塞，接口留口

非阻塞（回调式）要额外维护"对话框开着"的状态机 + 帧循环照跑 + 焦点归还。
**首版阻塞**：代价是"对话框打开时应用不刷新"——但这正是用户对模态的预期。

★ 接口不变（返回 `string` / `int`），所以将来改非阻塞**不改调用方**——
但那时要新增一个"对话框开着"的标志（`wantsFrame` 要考虑它）。

## 2. 托盘

### 2.1 生命周期

```
install(icon, tooltip) → 常驻 → 左键（激活主窗口）/ 右键（菜单）→ uninstall
```

★★ **托盘图标不是窗口**：它没有 `Surface`，**不能自绘**。
⇒ 托盘菜单**必须原生**（[19](19-控件API语法.md) §4.3：给托盘的菜单只能收声明式数组）。
⇒ 托盘图标的像素由壳提供（读资源 → 转 `HICON`），**框架不创建图标资源**（[08](08-平台与能力矩阵.md) §7）。

### 2.2 "无主窗口"模式

托盘应用的常见形态：**关窗口 = 隐藏，不退出**。

```php
$win->onClose(fn() => $this->hide());     // 不是 close()
```

★ **必须显式区分 `hide` 与 `close`**：
- `close` 走退出路径（`WM_CLOSE` 同步 `DestroyWindow` ⇒ 窗口已死，见 [08](08-平台与能力矩阵.md) §9.1）；
- `hide` 只 `ShowWindow(SW_HIDE)`，**`Surface` 与几何都保留**，恢复时不需要重建。

★ 判据：**"这个窗口还会回来吗？"** 会 ⇒ `hide`；不会 ⇒ `close`。

### 2.3 退出路径

托盘菜单的"退出"必须是 `Application::quit()`（走正常收尾：`dispose` → 卸载托盘 → 退出码），
**不是 `exit()`**。

★ `exit()` 会跳过 `Owner` 释放（[18](18-生命周期与所有权.md) §3）⇒ **托盘图标残留在系统里**，
直到用户把鼠标划过那个位置——用户看到的是"这个程序已经关了但图标还在"。

### 2.4 能力三态

| 平台 | 级别 | reason |
|---|---|---|
| Win32 | `Full` | `Shell_NotifyIcon` |
| macOS | `Full` | `NSStatusItem` |
| Linux | **`Partial`** | 需要 StatusNotifierItem；GNOME 默认不支持 |

★★ Linux 的 `PARTIAL` **必须能被应用查询到**：否则用户"关掉窗口后找不到程序"（没有托盘可点）。
应用据此决定"没有托盘时怎么退出"——通常是"关窗口就退出"。

## 3. 拖放

### 3.1 四个事件

```
DragEnter(位置, 载荷类型) → DragOver(位置) × N → Drop(位置, 载荷)
                                     ↘ DragLeave（拖出窗口 / 按 Esc）
```

★ 与指针事件**共用同一套坐标**（[07](07-输入与焦点.md) §1）：拖放位置是客户区逻辑像素，
**不另立坐标系**。否则命中测试要写两遍。

### 3.2 拖放期间必须起帧

`DragOver` 要画"可以放这里"的高亮 ⇒ **它是 `wantsFrame()` 的一个源**（[09](09-帧与异步.md) §3）。

★ 不起帧的症状：**高亮只在鼠标停下时出现**（因为要等下一个 OS 事件才重绘）。
用户看到的是"拖过来没反应，停下来才亮"。

### 3.3 `DropTarget` 是字段不是节点

判据（[03](03-树与身份.md) §1 三条：纯修饰 · 不改孩子列表 · 不产生 op）：
拖放高亮由**节点自己**在 paint 里画（读 `$node->dropActive`），**不引入新节点**。

```php
public int  $dropMask  = 0;      // 位域：1=files 2=text 4=image
public bool $dropActive = false; // 由 DragOver 置，paint 读
```

★ `dropActive` 变化打 `DIRTY_PAINT`（只重录自己那段），不打 `LAYOUT`。

### 3.4 载荷

```php
final class DropPayload
{
    public int    $kind  = 0;      // 0=files 1=text 2=image
    public array  $paths = [];     // kind=0：packed string array
    public string $text  = '';     // kind=1
    public int    $image = -1;     // kind=2：资源句柄（见 15 §4）
}
```

★★ **路径必须当场拷出来**：拖放结束后 OS 的 `HDROP` 就失效了。
延迟读取（比如在异步任务里读路径）会拿到空——这是"拖进来没反应"的经典原因。

★ `kind` 与 `dropMask` 位要对应：`dropMask` 里没有的 kind ⇒ `DragEnter` 就拒绝（光标变"禁止"），
不要等到 `Drop` 才报错。

## 4. 剪贴板

### 4.1 三种能力

| 能力 | 用途 |
|---|---|
| `readText()` / `writeText()` | 文本编辑（[06](06-文本.md) §8.7） |
| `readImage()` / `writeImage()` | 截图粘贴 |
| **`hasFormat(int $kind): bool`** | **粘贴按钮的启用态** |

★★ 第三条最容易被忘：**"能粘贴"和"知道能不能粘贴"是两件事**。
没有 `hasFormat`，粘贴按钮永远亮着，点了没反应——这是最常见的体验缺陷之一。

### 4.2 变化通知：不做实时

Windows 的剪贴板**没有可靠的"内容变了"通知**：
`AddClipboardFormatListener` 要绑一个窗口，且其他进程写入时不一定触发；
轮询 `GetClipboardSequenceNumber` 又要定时器。

**不做实时监听**，只在两个时机各查一次：
- `settle` 里（如果界面上有依赖剪贴板的控件）
- 窗口激活时（`WM_ACTIVATE`）

★ 代价：别的应用复制后，**切回来才更新按钮态**。这是可接受的滞后（用户感知不到）。
★ 判据：**这个"实时"值不值得一个常驻定时器？** 不值得。

### 4.3 换行

`\n` ↔ `\r\n` 的转换**只在剪贴板边界做**（[06](06-文本.md) §8.7），框架内部统一 `\n`。

## 5. 单实例

```php
$token = Platform::acquireSingleInstance('myapp');   // 0 = 首个实例；>0 = 已有实例的 pid
if ($token > 0) {
    Platform::activateInstance($token);   // 还原 + 置前
    return;                                // 自己不建窗口
}
```

★★ **判据：第二个实例必须"激活第一个"然后自己退出**，而不是：
- "两个都开"（用户会同时编辑同一个文件）；
- "弹个框说已运行"（多一次点击，且框在后台时用户看不到）。

★ 实现要点：
- Win32：命名 Mutex（`CreateMutex` 拿 `ERROR_ALREADY_EXISTS`）+ `FindWindow` + `SetForegroundWindow`；
- 第一个实例若最小化 ⇒ **先 `restore` 再激活**（否则 `SetForegroundWindow` 只闪任务栏）；
- **必须在 `Application::run()` 之前**做：拿不到 token 就不要建窗口（建了再退会有闪一下的白框）。

## 6. 反模式

| 反模式 | 症状 | 正解 |
|---|---|---|
| 直接调 `GetOpenFileName` | 关掉后残留旧像素、动画一次跳完 | 三条顺序 + 重置帧钟（§1.2） |
| 对话框返回 `?string` | 退化 `Var` | 空串哨兵（§1.3） |
| 托盘菜单用自绘 | 托盘没有 `Surface`，画不出来 | 原生菜单（§2.1） |
| 关窗口用 `close()` 做"最小化到托盘" | 窗口已死，点托盘无法恢复 | `hide()`（§2.2） |
| 托盘"退出"用 `exit()` | 托盘图标残留 | `Application::quit()`（§2.3） |
| 拖放高亮不起帧 | 高亮滞后一拍 | `wantsFrame` 加拖放源（§3.2） |
| 异步读 `HDROP` 路径 | 拖进来没反应（句柄已失效） | 当场拷出（§3.4） |
| 实时监听剪贴板 | 平台不可靠、耗电、要常驻定时器 | 两个时机各查一次（§4.2） |
| 单实例在 `run()` 之后判 | 已经建了窗口，闪一下白框 | `run()` 之前（§5） |
