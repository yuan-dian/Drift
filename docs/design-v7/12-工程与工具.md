# 12 工程与工具

> 本册回答：**怎么在没窗口的情况下把框架跑起来、怎么分层验证、怎么让错误自己暴露。**

---

## 1. P0：无头管线（第一件事，先于任何窗口代码）

```
php bin/drift-render.php scene.json  →  out.png  +  ops.hash  +  semantics.json
```

`scene.json` 描述一棵节点树 + 一次事件序列 + 视口尺寸。整条管线（settle → layout → paint → raster）**在 `php.exe` 里跑完**，不建窗、不碰 OS。

★ **为什么这是 P0 而不是 P3**：
1. 90% 的 bug 在布局/绘制/配对，与窗口无关；有窗口时每次验证要编译 + 启动 + 截图，一轮 2 分钟；
   无头一轮 50ms。**迭代速度差 40 倍。**
2. golden 需要一个**确定性入口**；有窗口就有 DPI/字体/主题三个不确定源。
3. 真机探针很贵（启动进程、抓图、OCR 断言），只能覆盖"窗口相关的 10%"。

★ 判据：**P0 完成的标准是"能用 JSON 画出一个带文字、按钮、滚动的页面，并输出 PNG 与 op 哈希"**。
这一步做完，后面所有功能都能先无头验证，再真机确认。

## 2. 四层验证

| 层 | 覆盖 | 怎么跑 | 耗时 | 抓什么 |
|---|---|---|---|---|
| **L1 纯函数** | `layout` / `paint` / `reconcile` / `shape` | `php bin/test-unit.php` | < 1s | 算法错误、边界条件 |
| **L2 夹具** | 建树 → 喂事件 → 断言几何/语义/命令日志 | 同上 | ~2s | 装配错误、脏位传播、订阅漏 |
| **L3 golden** | op 哈希 + 像素 md5 | `php bin/test-golden.php` | ~5s | 视觉回归 |
| **L4 真机探针** | 窗口、IME、无障碍、拖动 resize、滚动条 | 启动 exe + 抓图/枚举 | ~30s | 平台层错误 |

★ **金字塔必须真的呈金字塔**：L1+L2 占 90% 的用例数，L4 只覆盖"只有真机能测"的少数几条。
反过来的症状是"改一行要跑 3 分钟"——那时就没人跑测试了。

★ **每条 L4 探针必须带反例自检**：先构造一个必然失败的输入，确认探针会红。
否则"探针全绿"可能只是探针没接上（这类假绿比没测更危险）。

## 3. golden 两层

| 层 | 产物 | 抓什么 | 稳定性要求 |
|---|---|---|---|
| **op golden** | `md5(codes . nums)` | 布局、绘制顺序、裁剪、颜色、op 数量 | 资源索引必须确定（按创建顺序，不按地址） |
| **像素 golden** | PNG md5 | 光栅器、字形、抗锯齿 | 字体文件必须随包固定 |

★ **先 op 后像素**：op 不同 ⇒ 是框架 bug；op 相同但像素不同 ⇒ 是光栅器 bug。
**这个顺序把 90% 的回归定位从"看图找差异"变成"看哈希"**。

★ **golden 更新必须显式**（`--update`），且 diff 要能看：`--diff-golden` 输出"哪个节点多了哪条 op"。

## 4. lint（编译期抓"静默错误"）

| 规则 | 抓什么 | 为什么必须有 |
|---|---|---|
| `instanceof-missing-use` | 短名 `instanceof` 解析不到 `use` ⇒ **恒 false** | 不报错、不警告，分支永不进入（本项目咬过 3 次） |
| `unqualified-builtin` | 命名空间内 `strlen()` 未加 `\` | `php.exe` 下能跑，AOT 后 `Call to undefined function` |
| `closure-in-property` | 把闭包存进类型化属性 | 退化 `php::Var`，每帧动态分派 |
| `native-in-property` | Native 对象进普通对象属性 / 数组 | 直接写法编译器会拒；间接写法（先塞进 `mixed`）会静默崩 |
| `container-in-property` | Std 容器声明成属性 | 每次赋值被 `toArray()` 拷贝，持久结构不存在 |
| `nullable-in-hotpath` | `layout`/`paint`/`dispatch` 路径上的 `?T` | 退化 `php::Var` |
| `missing-key-in-repeater` | `Repeater` 子项无 `key` | 删除中间项 ⇒ 身份漂移 ⇒ 输入框串位 |
| `virtual-override-hotpath` | 在热路径依赖虚方法覆写 | 去虚化 ⇒ 覆写被静默吞掉 |
| `global-usage` | `global` / 未标注 static | 类型擦除 |
| `read-outside-settle` | 在 `place` / `paint` 路径上读共享态 | 依赖集漏登记 ⇒ 增量失效；**读即订阅之后"读了没订阅"已不可能，真正会犯的是"在错的阶段读"**（[02](02-状态与命令.md) §3.2） |
| `api-shape` | 控件构造违反 `19` §2 的命名参数规则 | 同一件事两种拼法 ⇒ 读代码要猜；且 `make()` 收多个本质输入会掩盖设计问题 |

★ **lint 的价值不在"规范"，在"抓静默"**。上表每一条的特征都是：**代码能跑、编译通过、行为错**。
凡是会响亮报错的错误，不需要 lint。

## 5. 诊断

### 5.1 标准中止序列

```
① 写 errors.log（含最近 100 条 Diagnostic 环形缓冲）
② 走 Platform::fatalBox() 弹原生错误框（不依赖渲染栈——渲染栈可能正是崩掉的那环）
③ exit(3)
```

★ 第 ② 步**不能**用自己的渲染栈画错误页：如果是光栅器崩了，错误页也画不出来。

### 5.2 错误消息格式（强制）

```
<现象>：<哪个容器/节点> 的 <哪一维> 不够/冲突。

  <数值1>   <数值2>
  <差额>

修法一：<具体动作>
修法二：<具体动作>
```

★ **不写内部编号、不写术语**（不写"条轨""自然主轴""C5"）。
用户不会读设计文档，但一定会读崩溃消息——**这是框架唯一必须自己写的文档**。

### 5.3 `FrameStats` 与 `--trace-frame`

见 [09](09-帧与异步.md) §6。`--trace-frame` 导出单帧 JSON：
op 流 + 语义快照 + 订阅表 + 每阶段耗时。**同一个产物给测试、给 agent、给人看。**

---

### 5.4 `diag-codes.json`：code 的唯一真相

`E-*` / `W-*` / `I-*` 现在散在各册（`05` / `09` / `15` / `17` / `19` / `20` / `22`）。
**散着写的问题是查不了重，也查不了"有没有 code 只出现在文档里、代码里没人用"。**

⇒ 建 `docs/design-v7/diag-codes.json`（构建期拷进 `build/`，运行期只读），每条五个字段：

| 字段 | 用途 |
|---|---|
| `level` | 五级（fatal/error/warn/info/trace）；决定"记不记、弹不弹框、算不算 CI 失败" |
| `phase` | lint / build / settle / paint / frame / runtime；决定它在哪一层被触发 |
| `msg` | 消息模板（`{name}` 占位）；**日志格式只在这里定义一次** |
| `source` | 设计出处（册 + 小节）；改语义时知道该回去看哪 |
| `fixture` | 触发它的测试文件；空串 = 只统计、不单独测 |

**CI 三查（缺一条这机制就退化）**：
1. 文档里出现的每个 `E-/W-/I-` 都在 json 里 ⇒ 否则报"未登记的 code"；
2. json 里每条至少在文档里出现一次 ⇒ 否则是幽灵条目（设计时想加、后来没做）；
3. `level ∈ {fatal, error}` 必须有 `fixture` 或真机 probe ⇒ 否则是"没有反例的判据"。

★ 第 3 条与项目那条老教训同源：**量具必须带反例自检**。
★ **新增 code 必须先登记再用**：运行期遇到未登记的 code 直接 Fatal（不静默接受）——
它意味着有人绕过了登记册，而那正是"日志里出现一个查不到的 code"的来源。

## 6. 应用结构与构建

```
apps/<app>/
  src/            ← 页面、状态、命令（零平台引用）
  bin/
    win32/Bootstrap.php    ← 组合根（唯一出现平台类名的地方）
    macos/Bootstrap.php
  assets/fonts/
  app.yml         ← 名称、图标、最小尺寸、能力需求
```

组合根五步（顺序固定）：

```php
$platform = new \Drift\Platform\Win32\Win32Platform();
$app      = new App();                       // 建树（此时读状态）
$handle   = $platform->window()->create(...);
$app->installFatalBox($platform);            // ① 先装失败路径
$app->show($handle);                         // ② 显示
$app->attach($platform->surface($handle));   // ③ 接表面
$app->resize($platform->screen()->viewport()); // ④ 首帧尺寸
$app->pace($platform->now());                // ⑤ 帧钟起跳
while ($platform->pump()) { $app->frame($platform->now()); }
```

★ **顺序不能换**：失败路径必须最先装（后面的每一步都可能失败）；
`pace()` 必须在首帧前（否则第一帧的时间戳是 0，动画相位错）。

构建：`drift-build` 读 `app.yml` + `build/<os>/platform.ini`，生成 `project.yml`。
Windows 必须 `-m bin` + `--no-console`。

## 8. 提交前闸门（分级）

| 档 | 何时 | 内容 | 耗时 |
|---|---|---|---|
| **T0** | 只改文档/示例 | lint + 无头渲染一页 | ~5s |
| **T1** | 日常迭代（改了 `src/`） | T0 + L1 + L2 | ~10s |
| **T2** | 提交前 | T1 + golden + 真机构建一个应用 | ~3min |
| **T3** | 发版前 | T2 + 全平台构建 + L4 全探针 | ~30min |

★ **T1 必须快到"改完就想跑"**。超过 15s 的闸门，人就会跳过它。

## 9. 快速重启与状态快照（v6 补齐）

### 9.1 快速重启（E1）

```
改代码 → 杀进程 → 起进程 → 回填状态 → 重放路由      ≈ 600ms
```

★ **AOT 没有热重载**（代码已编译进 exe），所以这是唯一的替代品。
判据：**"改一行样式要看效果"的时间**。600ms 与"重启 + 手点三层菜单"（10s）差 16 倍。

组成：
1. 文件监听（`--watch`）⇒ 检测到变更就杀进程；
2. 新进程启动时读快照（§9.2）；
3. 回填 `Cell` 值 + 重放路由栈（**不是重放命令**，只恢复"在哪一页"）。

### 9.2 快照纪律（E2）

| 规则 | 理由 |
|---|---|
| **只存数据，不存结构** | 结构由代码决定；存了结构等于存了旧代码的形状 |
| 版本不匹配 ⇒ **丢弃快照冷启动** | 半恢复的状态比冷启动更难查 |
| 只存 `Cell` 与路由栈 | `local` 是渲染态，恢复它没有意义 |

★★ **"绝不尽力恢复"**：快照里少一个字段就整份丢弃。
半恢复的症状是"某个值莫名是旧的"——这类 bug 会让你怀疑自己的代码，实际是快照。

★ 快照格式 = JSON（可读、可 diff、可手工改）。**不用二进制**：调试价值 ≫ 体积。

### 9.3 CI 必须有一次 `build`（E3）

★ 解释模式过了不算完。AOT 专属问题**只在编译后暴露**：
- 类型钉死（可选参数顺序、类常量与方法同名 ⇒ C2872）
- 闭包元数（静态分析得到的最少参数个数与实际不符）
- 多字节堆损坏（`substr_replace` 类 O(n) 操作在生成代码里的行为）

★ 所以 §8 的 T2 闸门里 `--build` 不是可选项。
**判据：本次改动是否碰了"类型 / 闭包 / 字符串处理"** —— 碰了就必须 build，哪怕只改一行。

## 10. 应用级测试（`TestApp`，v6 补齐）

> §2 的四层金字塔全是**框架出口判据**：读像素、比 op 哈希、枚举无障碍树。
> 它不认识你的 `TaskStore`、你的页面、你的文案。
> 所以"应用开发者给自己的界面写测试"这件事，v7 第一版是空的。

### 10.1 两者都要，分工不是替代

> 不能只有 smoke：它不认识你的 `TaskStore`、你的页面、你的文案。
> 也不能只有 TestApp：AOT 专属问题（类型钉死、闭包元数、多字节堆损坏）在解释模式下根本不出现。

| | smoke（§2 的 L1–L4） | TestApp |
|---|---|---|
| 跑在哪 | AOT 产物 + 子进程 | 解释模式 |
| 测什么 | 框架出口：op 序列、像素、ABI、退出码 | 应用行为：点这个按钮，列表少一行 |
| 谁写 | 框架作者 | 应用开发者 |
| 断言粒度 | 字节 / 像素 | 语义 / 几何 |
| 何时跑 | CI 全量 | 每次改代码 |

★★ **AOT 测框架，解释模式测应用。**

### 10.2 形状

```php
TestApp::mount(fn() => TasksPage::make(store: $store));   // 只挂页面，不起真窗口

$t->findByText('保存')->tap();
$t->pump();
$t->expect($t->findAllByRole(Role::ROW))->toHaveCount(2);
$t->expect($t->findByKey('row-3'))->toHaveSize(w: 320, h: 48);
```

| 能力 | API |
|---|---|
| 查语义 | `byText` / `byLabel` / `byRole` / `byKey` |
| 交互 | `tap` / `tapAt` / `doubleTap` / `longPress` / `type` / `pressKey` / `scroll` / `drag` / `hover` / `focus` |
| 时间 | `pump()` / `pump(5)` / `pumpAndSettle()` |
| 断言 | `toBeVisible` / `toBeExists` / `toBeEnabled` / `toBeChecked` / `toHaveText` / `toHaveCount` / `toHaveSize` / `toHaveOffset` / `toHaveSemantics` |

### 10.3 六条纪律（每条对应一类 flaky）

| # | 纪律 | 不这么做的后果 |
|---|---|---|
| 1 | **默认要求唯一匹配**（匹配到 2 个直接报错；要第一个必须显式 `->first()`） | 模糊 finder 是 flaky 测试的第一来源 |
| 2 | **`key` 只给测试用，不进无障碍树** | 测试专用属性泄漏成用户能听到的名字 |
| 3 | **`type()` 逐字符派发**，走完整编辑模型 | 直写 value 绕开编辑模型 ⇒ 光标/过滤/IME 整类 bug 测不到 |
| 4 | **显式 `pump`，不做隐式** | 隐式 pump 让"改一行多跑一帧"变成静默行为变化 |
| 5 | **几何断言是一等公民**（`toHaveSize` / `toHaveOffset`） | 布局 bug 只能靠几何抓，语义断言永远绿 |
| 6 | **golden 用 SVG 不是 PNG** | 与 `preview` 共用管线 ⇒ diff 可读、跨 DPI 稳定 |

★★ 第 3 条最重要：**测试要走用户走的那条路，否则测的是另一套代码。**
`setText('牛奶')` 直写看起来更简单，但它跳过了"逐字符输入"才会触发的光标、组字、过滤三条路径。

★ 第 1 条是刻意的严格：`findByText('保存')` 匹配到两个时**报错而不是取第一个**。
方便取第一个会让"页面上多了一个同名按钮"这类回归静默通过。

### 10.4 与 AOT 的衔接

★ TestApp 测试默认只在解释模式跑。要给 AOT 用，得**显式标 `@smoke`**，只有标了的才进 AOT 产物。
理由：AOT 构建一次几十秒，全量 TestApp 进去会让 CI 从 5 分钟变成 30 分钟。
