# 04 布局

> 本册回答：**约束怎么传、尺寸怎么回、什么时候要两遍、滚动为什么是布局的一部分。**

---

## 1. 契约

```php
// 每个节点由框架的**两个静态入口**处理（不是虚方法，理由见 §1.1）
//
//   Layout::measure(Node $n, BoxConstraints $c): void
//     输入：节点 + 父给的约束
//     输出：写 $n 的 w/h（尺寸）
//     可递归 measure 孩子 —— 这一步是 O(子树)
//
//   Layout::place(Node $n, float $x, float $y): void
//     输入：节点 + 父给的位置
//     输出：写 $n 的 x/y，并按**已定的尺寸**摆孩子 —— 这一步是 O(子数)，纯加法
Layout::measure($n, $c);
Layout::place($n, $x, $y);
```

★★ **两步分离是本册最重要的结构决定**（v6 §3 的洞察，v7 第一版漏了）：

> **定位是 O(子数) 的加法，重量是 O(子树)。这个区分是增量布局的全部秘密。**

| 变化 | 跑哪一步 | 成本 |
|---|---|---|
| 滚动（`offset` 变、可见区间不变） | 只跑 `place` 链 | O(可见孩子数) |
| 改一个字的文本 | `measure` 该文本 + 沿祖先链 `place` | O(路径长) |
| `translate` / `opacity` | 都不跑，只改合成矩阵（`DIRTY_COMPOSE`） | O(1) |
| 窗口 resize | 全量 `measure` + `place` | O(树) |

★ **揉成一个 `layout()` 的代价**（v7 第一版就是这么写的）：滚动被迫走完整重排；布局边界只能省"重量"、
省不掉"重定位"；动画改位移也只能走 `DIRTY_LAYOUT`。三件事被一个签名同时堵死。

**约束**：`minW ≤ w ≤ maxW`，`minH ≤ h ≤ maxH`；`maxW = INF` 表示无界（只在滚动轴上出现）。

★ `BoxConstraints` 是 `#[Native]` 值对象（不进数组、不持容器、整帧复用同一个实例）。
★ **无界用 `INF` 而不是 `null`**：`?float` 退化 `php::Var`，而 `INF` 在比较里天然正确
（`$w <= INF` 恒真，`min(INF, x) === x`）——用哨兵比用可空更省也更不容易错。

★ **`x/y` 是相对父的局部坐标**。全局坐标只在两处需要：命中测试与语义快照——都在遍历时累加，不存字段。

★ **`x/y/w/h` 是 `float`**（逻辑像素）。物理像素只在 `RenderSurface::resize()` 里出现一次（DPI 量化单点）。

### 1.1 为什么布局方法不用虚方法

虚方法在**静态类型已知时会被去虚化**，静默走基类实现（L3）。
布局是每帧每节点都跑的路径，一旦某个容器的 `measure` 被静默吞掉，症状是"这个容器永远用默认尺寸"——
**看起来能跑，只是位置不对**，最难查。

⇒ 与命令分派同策略：`switch ($node->kind)` 调具体类型的静态方法。
`measure` / `place` 是框架内部的闭集（23 种），switch 完全够用。

★ 注意 `measure` 与 `place` **必须成对分派**：只分派 `measure` 而让 `place` 走基类，症状是"尺寸对、位置全在原点"。

★ **所以 §1 的契约是 `Layout::measure($node, $c)` 而不是 `$node->measure($c)`** ——
后者在 `$node` 静态类型为 `Node` 时**必然**被去虚化，正是本节要避开的那个 bug。

## 2. 三种策略，按需升级

| 策略 | 何时用 | 成本 | 例子 |
|---|---|---|---|
| **S1 单遍** | 孩子尺寸可由约束直接决定 | 1× | `Column` `Row`（无弹性子）`Box`（`padding`/`align` 是字段） |
| **S2 固有尺寸** | 需要"孩子想多大"才能分配 | 2× | `Grid`（等宽列）`Row` 含 `IntrinsicWidth` |
| **S3 仲裁** | 约束互相矛盾（孩子 min > 父 max，或弹性总和超界） | ≤3× | 嵌套 `Expanded` + 固定宽子 |

★ **默认 S1，只有显式声明才升级**。`Node::$measureHint` 字段：`0=单遍 1=需固有 2=可仲裁`。
框架在布局前扫一遍子树，只要有一个 `1` 就走 S2；有一个 `2` 且冲突就走 S3。

★ **S3 上限 3 轮**：第 4 轮仍不收敛 ⇒ Fatal（消息见 §6）。无上限迭代是"界面偶尔卡死"的经典来源。

## 3. 内边距：必须在布局期进子盒 offset

这是 Drift2 用血换来的一条（P13）：

### 3.1 有内边距的盒子

```php
// ✅ 正确：measure 期 deflate 子约束，place 期加 inset
//    ★ 静态方法、首参是节点 —— 不是虚方法（§1.1）；
//    ★ 单孩子走 children[0]，**没有 `$this->child` 字段**（可空会退化 php::Var）
final class BoxLayout
{
    public static function measure(Node $n, BoxConstraints $c): void
    {
        $child = $n->children[0]->toObject(Node::class);
        Layout::measure($child, $c->deflate($n->padL, $n->padT, $n->padR, $n->padB));
        $n->setSize($child->w + $n->padL + $n->padR,
                    $child->h + $n->padT + $n->padB);
    }

    public static function place(Node $n, float $x, float $y): void
    {
        $n->setPos($x, $y);
        Layout::place($n->children[0]->toObject(Node::class),
                      $x + $n->padL, $y + $n->padT);   // ★ inset 只在这里加
    }
}
```

★ **内边距是字段，不是节点**（v7 第一版把它当节点，见 [03](03-树与身份.md) §1）：
所以 `padL/padT/padR/padB` 在同一个节点的 `measure` 与 `place` 里各出现一次，**不产生额外节点、不产生额外 `depth`**。

★ **两条必须同时做**：只 deflate 不加 offset ⇒ 孩子贴在左上角、右边多出空白；
只加 offset 不 deflate ⇒ 孩子溢出、被裁剪。

### 3.2 有内边距的盒子必须覆写 `intrinsicWidth/Height` 加回 insets

```php
public static function intrinsicWidth(Node $n, float $h): float
{
    $child = $n->children[0]->toObject(Node::class);
    return Layout::intrinsicWidth($child, $h - $n->padT - $n->padB)
         + $n->padL + $n->padR;                   // ★ 忘了这两项 ⇒ Grid 列宽永远偏小
}
```

★ 症状：**Grid 的列宽总是差一点，看起来像字体度量错了**。实际是 intrinsic 漏了内边距。

## 4. 滚动：`offset` 属于 `place`，不属于 `measure`

```php
#[Native]
final class ScrollConstraints
{
    public BoxConstraints $box;      // 视口给孩子的宽高约束
    public float $viewport    = 0.0; // 视口主轴尺寸
    public float $cacheExtent = 0.0; // 视口外预建距离
    // ★ 没有 offset：offset 只影响"摆在哪"，不影响"多大" ⇒ 它属于 place，不属于 measure
}
```

★ **`ScrollConstraints` 只做参数/局部，永不成为节点字段**（Native 对象不能进普通对象属性）。
它自己持有 `BoxConstraints`（Native 持有 Native 是允许的），但它本身只活在 `measure()` 调用栈上。

★ **`offset` 是 `Scroll` 节点的私有 `float` 字段**，只在 `place()` 里被读一次：

```php
final class ScrollNode extends Node
{
    private float $offset   = 0.0;    // 逻辑像素
    private float $velocity = 0.0;    // ★ 为触屏/触控板留的（桌面滚轮恒 0，见 §4.2）
    private int   $physics  = 0;      // 0=clamp 1=bounce 2=inertia（能力矩阵标 Partial）
}
```

带来三个直接好处：

| 好处 | 说明 |
|---|---|
| **`measure` 不读 offset** | 尺寸与滚动位置无关 ⇒ 滚动不会让任何节点的 `w/h` 失效 ⇒ 滚动永远不进 `measure` |
| 虚拟化归 `settle` | 可见区间变了才重建孩子（`DIRTY_STRUCT`）；区间没变就只 `DIRTY_PLACE` |
| 滚动不改结构 | 绝大多数滚动帧只打 `DIRTY_PLACE`，不打 `DIRTY_STRUCT` |

★ 第三条尤其重要：Drift2 的滚动是"改 `ScrollViewState::offset`，下一帧布局才同步"（P-滚动条拖动），
中间有一帧的滞后。**`place` 是纯加法之后，"滚动"就是"重跑一条 place 链"**——滞后消失，
而且比"重排"便宜一个数量级。

★ **一次滚动的完整路径**（`ScrollNode::scrollBy(float $d)`）：

```
① $this->offset = clamp($this->offset + $d, 0, maxScroll);
② 二分 Fenwick 前缀和，算新的可见区间 [i0, i1)        ← O(log n)
③ 区间没变 ⇒ flags |= DIRTY_PLACE                     （99% 的滚动帧）
   区间变了 ⇒ flags |= DIRTY_STRUCT | DIRTY_PLACE      （每 ~10 帧一次）
④ place 期：孩子 y = 前缀和[i] - offset
```

★ **可见区间的二分是唯一允许"每帧都跑"的 O(log n)**：n 是总项数（可能 10 万），log n ≈ 17。
用节点遍历找可见区间是 O(n)，那正是 Drift2 长列表卡顿的来源。

### 4.1 无界主轴

| 情形 | 行为 |
|---|---|
| `Repeater` 在无界主轴上，且外层**有**滚动视口 | 合法（外层视口提供可见区间，虚拟化生效） |
| `Repeater` 在无界主轴上，且外层**无**滚动视口 | **Fatal**（"列表要算自然尺寸，但主轴无界"） |
| `Row`/`Column` 在无界主轴上 | 合法（按孩子自然尺寸排） |

★ 判据不是"有没有 Repeater"，而是**"谁提供可见区间"**。这是 Drift2 那条 `LazyColumn` Fatal 的准确版本。

### 4.2 滚动物理：桌面不做惯性，触屏必须做

| 输入源 | 有速度吗 | 做法 |
|---|---|---|
| 鼠标滚轮（Win32 `WM_MOUSEWHEEL`） | **没有**。离散档位，系统不提供速度 | 一格 = 固定像素（`WHEEL_NOTCH_PX`），**不做物理惯性** |
| 精确式触控板（Windows） | 有，但被系统合成成 `WM_MOUSEWHEEL` | 同上 —— 框架**拿不到** momentum（见 [08](08-平台与能力矩阵.md) §9.5） |
| 触屏 / 直接操作（未来） | **有** | 必须做：`offset += v·dt`，`v *= exp(-k·dt)`，打断时 `v = 0` 但**不动 offset** |

★ **桌面不做 fling 是裁决，不是偷懒**：伪造速度会滑过头 / 刹不住，与 Windows、Qt、Flutter 桌面全部相反。

★ **但抽象里必须留 `$velocity` 与 `$physics`** —— 否则接触屏那天要改 `Scroll` 节点的形状、所有夹具、所有 golden。
这是"首版只做 Win32，但抽象现在就要对"的直接体现。

★ 判据写进能力矩阵：`scrollPhysics` = `Full`（有真惯性）/ `Partial`（只有离散档位）/ `Unsupported`。
Win32 首版 = **`Partial`**。

## 5. 布局边界

```php
final class LayoutBoundary extends Node
{
    private float $lastMinW = 0.0, $lastMaxW = 0.0;    // 上次的约束拆成 4 个标量
    private float $lastMinH = 0.0, $lastMaxH = 0.0;    // （避免 ?对象 ⇒ 退化 Var）
    private bool $dirtySubtree = true;
}
```

**跳过条件**（三个都满足才跳）：
1. 约束与上次**完全相同**（`minW/maxW/minH/maxH` 四个 float 全等）；
2. 子树内无 `DIRTY_LAYOUT`（有 `DIRTY_PLACE` 不算——只跳过 `measure`，`place` 照跑）；
3. 自身无 `DIRTY_STRUCT`。

★ 用途：**侧边栏、工具栏、状态栏**这些"窗口变了但自己尺寸没变"的区域。
不加边界时，改一个输入框的文本会触发**全树**重排（因为脏集合沿父链向上扩散）。

★ **不要滥加**：边界会切断"父的约束变化向下传播"的优化机会。
判据：**这块子树的约束在一帧内变化次数远小于内容变化次数**，才值得。

## 6. 失败消息（必须说人话）

三条铁律：**现象 + 数值/差额 + 两条修法**，不写内部编号。

```
布局失败：Row 的横向空间不够。

  可用宽度  200.0
  子项需求  248.5（4 个子项，其中 1 个是固定宽 120.0）
  超出       48.5

修法一：把那个固定宽 120.0 的子项包进 Expanded，让它跟着窗口缩放。
修法二：把 Row 换成 Scroll（横向可滚动），或给 Row 设 overflow: clip。
```

★ 为什么值得为错误消息花这么多字：**这是框架唯一"必须自己写"的文档**。
用户不会读设计文档，但一定会读崩溃消息。

## 7. 溢出策略

| 容器类型 | 默认策略 | 理由 |
|---|---|---|
| 尺寸随窗口变化的 chrome（`AppBar` / `Dock` / `StatusBar`） | **`Clip`** | 用户拖窄窗口不该弹 Fatal（Drift2 实测：可用 322 / 自然 327） |
| 内容容器（`Column` 里的卡片） | **`Report`** | 内容溢出是**真 bug**，要响亮 |
| 拖动预览期（`LayoutTolerance::$previewing`） | **全部降级为 `Clip`** | 松手后的正式帧仍然响亮失败 |

★ **`previewing` 是一个显式的 try/finally 作用域**，不是全局开关。
拖动 resize 期间置位，松手立即复位——否则真 bug 会被永久静默。

## 8. 自校验（每 16 帧一次，仅 debug）

校验四条：
1. 每个节点的 `w/h` 落在它收到的约束区间内；
2. 每个孩子的 `x/y + w/h` 在父的内容盒内（除非父声明 `overflow: visible`）；
3. `depth` 与实际父子关系一致；
4. 脏位在帧末全部为 0（有残留说明清位点错了）。

★ 失败时**打印节点路径**（`App > Dock > Column > Row > Text "保存"`），不是只打印 id。
id 只在日志里，路径在消息里。

## 9. 性能预算（首版目标，Win32 / Skia 后端）

| 场景 | 节点数 | 目标 |
|---|---|---|
| 静态页首帧 | 500 | < 8ms |
| 输入框打字（单字符） | 500 | < 2ms（只重排该行 + 祖先链） |
| 列表滚动一帧 | 2000（视口内 60） | < 4ms |
| 窗口拖动 resize 一帧 | 500 | < 10ms（可以掉帧，但不能错位） |
| 主题切换（全树重建） | 500 | < 30ms（可接受一次卡顿） |

★ 这些数字是**待实测的目标**，不是承诺。P1 阶段第一件事就是量出来，然后改设计或改预算。

## 10. 增量布局的实现细节（v6 补齐）

> 前面九节是"契约与边界"，这一节是"算法怎么写"。
> v7 第一版只有 S1/S2/S3 三个词，具体到"哪个字段驱动哪个算法""缓存哪几个值"是空的——
> 那是实现阶段必然卡住的地方。

### 10.1 意图字段在子节点，框架定义一套（v6-L1）

| 字段 | 类型 | 谁读 | 含义 |
|---|---|---|---|
| `grow` | float | `Row` / `Column` | 主轴弹性系数（0 = 不弹） |
| `shrink` | float | `Row` / `Column` | 空间不足时的收缩权重 |
| `basis` | float | `Row` / `Column` | 主轴基准尺寸（`-1` = 用自然尺寸） |
| `alignSelf` | int | `Row` / `Column` / `Stack` | 覆写父的交叉轴对齐（`-1` = 继承） |
| `order` | int | 所有容器 | 绘制/布局顺序（默认按数组顺序） |
| `absolute` | bool | `Stack` | 脱离常规流，按 `x/y` 定位 |

★ **一套字段，所有容器读同一套**。这是 v6 删掉 Flutter `ParentData` 相的原因：
`ParentData` 让"子节点携带父类型专属数据"，于是每个新容器要新增一种 `ParentData`，
子节点在被挂接时必须被强制转换——那是**结构耦合**，且每次读都要类型检查。

★ 代价：每个节点多 6 个字段（≈ 40 字节）。5000 节点 = 200KB。
**换掉一整套运行时类型转换，值得。**

### 10.2 十一个算法，按"信息可得性"归属（v6-L2）

| # | 算法 | 必须两遍？ | 依据 |
|---|---|---|---|
| 1 | `leaf` | 否 | 尺寸 = 固有尺寸 ∩ 约束 |
| 2 | `column` | 仅当有 `grow` 且主轴有界 | 要先知道非弹性子的总高 |
| 3 | `row` | 同上 | 同上 |
| 4 | `stack` | 否 | 尺寸 = 孩子最大值 |
| 5 | `scroll` | 否（但需可见区间） | 视口尺寸已知 |
| 6 | `wrap` | **是** | 换行位置依赖行长 |
| 7 | `grid` | **是** | 列宽 = 各列自然宽的最大值 |
| 8 | `table` | **是** | 列宽与行高互相影响 |
| 9 | `virtual` | 否（需前缀和） | 项高可估 |
| 10 | `aspect` | 否 | 一边定则另一边定 |
| 11 | `baseline` | **是**（S2/S3） | 要先知道各子基线 |

★★ **决定"要不要两遍"的不是控件，是信息可得性**：
"分配主轴空间"必须先知道"非弹性子占多少"⇒ 要先量；"按最大孩子定尺寸"⇒ 一遍就够。
这条判据能挡住 90% 的"随手加一次 layout"。

### 10.3 布局缓存四个值（v6-L3）

```php
final class LayoutBoundary extends Node
{
    private float $lastMinW = 0.0, $lastMaxW = 0.0;   // 上次的约束（拆成 4 个标量）
    private float $lastMinH = 0.0, $lastMaxH = 0.0;
    private int   $layoutVersion = 0;                 // 上次 measure 时的全局版本
    private int   $doneVersion   = 0;                 // 上次 place 时的全局版本
    private float $boxW = 0.0, $boxH = 0.0;           // 上次的结果（自校验用）
}
```

★ 四个值各司其职：`lastC` 判"约束变了没"，`layoutVersion` 判"子树脏了没"，
`doneVersion` 判"这一帧已经摆过没"，`box` 是上次结果（用于 §8 自校验）。

★ **`doneVersion` 单独存在的理由**：一帧内一个边界可能被 `place` 两次（父重排 + 滚动），
第二次必须能早退。少了这个值，滚动会让整棵子树重复摆两遍。

### 10.4 边界判据表（v6-L4）

| 该加边界 | 理由 |
|---|---|
| 自身有固定宽高（工具栏、状态栏） | 窗口变了它不变 |
| `Scroll` 视口 | 视口尺寸变才需要重排内容 |
| `Virtual` 内容 | "项数变化"与"视口变化"是两件事 |
| `Surface` 根 | 整帧的唯一入口 |

| **不该加** | 理由 |
|---|---|
| 每个 `Row` / `Column` | 边界会切断"父约束变化向下传播"的优化机会 |
| 叶子节点 | 没有子树可省 |

★ 判据：**这块子树的约束在一帧内变化次数 ≪ 内容变化次数**，才值得。

### 10.5 baseline（v6-L5）

```
Text  基线 = 第一行 ascent（不是盒底）
Image 无基线 ⇒ 按底边
其他容器 = 第一个有基线的孩子的基线（相对自己的 y）
```

★ 一行里大小字号混排必须按基线对齐，否则**视觉错位**（大字下沿与小字下沿不在一条线上）。
这是 S2/S3 的第三个用途：`baseline` 必须先量孩子才能对齐。

★ 实现：`measure` 期间把基线缓存在节点上（`$baseline`，`-1` = 无），`place` 时直接用。

### 10.6 `Virtual`：Fenwick + 锚点保持（v6-L6 / v6-L7）

```
① Fenwick 前缀和：O(log n) 求"第 i 项起点"与"offset 落在第几项"
② 二分找可见区间 [i0, i1)
③ 预估 extent：未量过的项用平均高估（不是 0）
④ ★ 锚点保持：重建后让"重建前在视口顶部的项"仍在视口顶部
⑤ 回收池：离屏节点不 dispose，进池复用（省 create/mount 开销）
```

★★ **没有锚点保持 ⇒ 用户往下滚时，一旦某项比估算高，内容整体上跳**。
症状是"滚到一半突然跳一下"，且只在"项高不均"时出现——最难复现的一类 bug。
做法：重建前记 `anchorIndex`（视口顶部那一项）与 `anchorDelta`（它顶部到视口顶的距离）；
重建后 `offset = 前缀和[anchorIndex] - anchorDelta`。

★ **`Repeater::all` vs `Repeater::virtual` 的判据**（v6-L7）：
*滚动一屏之后，用户回头还能不能指望某项的展开态还在？*
能 ⇒ `all`（全建，状态在节点里）；不能 ⇒ `virtual`（回收，状态必须搬进 `CellSpec`）。

★ 用错方向的症状：该 `all` 却用 `virtual` ⇒ 状态莫名丢失；该 `virtual` 却用 `all` ⇒ 内存爆。

### 10.7 嵌套滚动（v6-L8）

```
外层视口先吃 delta；吃不完的**剩余 delta** 传给内层
```

| 规则 | 说明 |
|---|---|
| **按剩余 delta 传递** | 整次传递会让内容多滚一个档位（90px 时尤其明显） |
| `lockAxis` | 该 `Scroll` 只吃一个轴（水平列表嵌在垂直页面里必须设） |
| `noScroll` | 该 `Scroll` 不参与手势（但仍可编程滚动） |
| 横纵同时可滚 | 按**主方向**（位移大的那个轴）一次只驱动一个轴 |

★ 判据：**"这次滚轮事件最终由谁消费"必须可观测**（进 `FrameStats`），
否则"滚不动"永远查不出是哪一个视口吃掉了。

### 10.8 `scrollTo` 三层次（v6-L9）

| API | 输入 | 用途 |
|---|---|---|
| `to(float $offset)` | 绝对偏移 | 恢复上次位置 |
| `toIndex(int $i, int $align)` | 索引 + 对齐 | 列表跳转 |
| `ensureVisible(Node $n)` | 节点 | **Tab 键与"搜索命中"的必需品** |

★ **边距 8px**：滚到边缘时留 8px，否则目标项贴着视口边，看起来像被裁掉。
★ **元素比视口大时顶部对齐**（不是居中）——居中会让用户看不到开头。
★ `ensureVisible` 是**焦点系统的一部分**：Tab 走到视口外的控件必须自动滚进来（[07](07-输入与焦点.md) §5）。

### 10.9 滚动条不占布局（v6-L10）

★ **6px 悬浮，不占布局空间**。否则"滚动条出现 ⇒ 内容宽少 6px ⇒ 换行变了 ⇒ 内容变高 ⇒ 又需要滚动条"，
经典的正反馈循环。

★ **滚动条走 `DIRTY_COMPOSE`**：它只是一个矩形 + 一个变换，不参与 `measure`。
拖动滚动条只改 `offset`（`DIRTY_PLACE`）+ 滚动条自己的位置（`COMPOSE`）。

★ Drift2 的教训保留：**thumb 是 paint 期画的、不是子盒** ⇒ 命中必须在 `dispatchPointer` 里
先于内容接管，几何只在 `thumbRect()` 一处算（paint 与命中复用）。

### 10.10 `absolute` 与 z 序（v6-L11）

★ **z 序 = 数组顺序，不引入 `zIndex`**。两套顺序（数组 + `zIndex`）必然打架，
而"打架"的表现是"偶尔某个弹层被盖住"——不可复现。

★ `absolute` 只影响**定位方式**（脱离常规流，按 `x/y`），不影响 z 序。
需要置顶 ⇒ 放到数组末尾，或放进 `Overlay`。
