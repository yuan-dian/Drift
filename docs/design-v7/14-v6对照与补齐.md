## 0. 一句话

**v6 深在运行时（脏位分级、布局两步、滚动、虚拟化、资源、诊断、错误边界）；v7 新在通道（命令 ID、能力分级、扁平语义、可移植抽象）。**
两者不是替代关系——**v7 的骨架要保留，v6 的机制要搬回来**。下面 5 条结论冲突必须当场改，17 条机制缺口要补册。

## 1. 结论冲突（v7 做错了，已改）

| # | 议题 | v6 的做法 | v7 原做法 | 判定 | 处置 |
|---|---|---|---|---|---|
| **X1** | 滚动偏移放哪 | 放 `local`，滚动 = 改一个 float + 重定位孩子（**不重排**） | 放进 `ScrollConstraints`，滚动 = `DIRTY_LAYOUT` | **v6 对**。滚动时孩子尺寸不变，只有位置变 ⇒ 重排是纯浪费 | **布局拆成 measure/place 两步**（见 X1 详述） |
| **X2** | 订阅怎么建立 | **读即订阅**：`Tracker` 栈顶登记依赖，`set()` 只置脏不回调 | 手写 `subscribe()` + 读时断言 | **v6 对**。而且它不是黑盒——`Tracker::$stack` 是带类型的静态属性，可 dump | 改成读即订阅 |
| **X3** | 事件回调形态 | 闭包（存在 `mixed` 袋里，用户速度，不逐帧） | **禁止闭包**，一律命令 ID | **都不完整**。v7 的"可序列化/可回放"是真收益，但把每个按钮都变成"常量 + switch 分支"是重税 | **混合**：闭包做常规交互，命令 ID 只给"必须可序列化"的路径（菜单/快捷键/AI/撤销） |
| **X4** | `padding` / `align` 是节点还是字段 | **字段**（基类 `measure()` 统一处理）⇒ v5 的 `Padding`/`Align` 两个节点被删掉 | 当成节点（26 种里有 `Padding`/`Align`） | **v6 对**。10 层修饰 = 10 个节点 = 10 次 measure；字段方案是 1 次 | 从节点表删掉，改成字段 |
| **X5** | 桌面滚轮惯性 | 物理积分（`offset += v·dt`，`v *= exp(-k·dt)`），打断时 `v=0` 但不动 offset | "物理 fling 不做"（Drift2 桌面结论） | **两者都对，看输入源**。桌面滚轮是离散事件无速度 ⇒ 不做；触屏/触控板有速度 ⇒ 必须做 | 桌面 v1 不做，但**抽象里留 `velocity` 字段**，并在能力矩阵标 `scrollPhysics: Partial` |

### X1 详述：布局必须拆成两步

v6 §3 有一句关键的话，v7 完全没有：

> **定位是 O(子数) 的加法，重量是 O(子树)。这个区分是增量布局的全部秘密。**

v7 的 `layout(BoxConstraints)` 把"量尺寸"和"摆位置"揉在一个调用里，于是：

- 滚动（只改位置）被迫走完整 `layout`；
- 布局边界只能省"重量"，省不掉"重定位"；
- 动画改 `translate` 也只能走 `D_LAYOUT`。

**改成两步**：

```php
public function measure(BoxConstraints $c): void;  // 定自己的 w/h；可递归量孩子
public function place(float $x, float $y): void;   // 按已定尺寸摆自己与孩子（纯加法）
```

| 变化 | 走哪一步 | 成本 |
|---|---|---|
| 滚动（offset 变） | 只跑 `place` 链 | O(可见孩子数) |
| 改一个字的文本 | `measure` 该文本 + 沿祖先链 `place` | O(路径长) |
| `translate` / `opacity` | 都不跑，只改合成矩阵（`D_COMPOSE`） | O(1) |
| 窗口 resize | 全量 `measure` + `place` | O(树) |

★ 这同时解释了 v6 的 `D_COMPOSE` 为什么值钱（§2 #1）：
**有 `D_COMPOSE` 才能让动画不进 measure/place；有 measure/place 分离才能让滚动不进 measure。两者缺一，另一个就白搭。**

## 2. 机制缺口（v7 完全没写，按册归类）

### 2.1 绘制（05）

| # | v6 的机制 | 为什么重要 | v7 现状 |
|---|---|---|---|
| **v6-P1** | **`D_COMPOSE` 一等脏位**：`translate`/`scale`/`rotate`/`opacity` 只改矩阵，**不重排、不重录、不光栅** | 200ms 位移动画 60 帧：`D_COMPOSE` ~3µs/帧，走 `D_LAYOUT` ~300µs/帧，**差 100 倍** | 只有 STRUCT/LAYOUT/PAINT/SEMANTICS 四位，动画全部走 LAYOUT |
| **v6-P2** | **层的开关判据表**：`opacity<1` 开、非矩形裁剪开、混合模式开；**变换不开**、**阴影不开** | "变换不开层"是最值钱的一条：500 节点子树整体位移的成本 = 位移一个矩形 | 只有 `RepaintBoundary` 一个概念，无开层判据 |
| **v6-P3** | **脏区 damage**：`∪(旧 bounds, 新 bounds)` 经变换 → 屏幕矩形 → 外扩（阴影/模糊/AA/描边）→ ∩ 视口；**>40% 视口就全刷** | 没有脏区就只能全刷；且"元素缩小后留残影"是必踩的坑 | 完全没有 |
| **v6-P4** | **脏区在 C++ 算**（需要 op 级精确 bounds，PHP 只有节点级） | 用节点 bounds 算脏区过于保守（大节点里改一个小字也整块重画） | 无 |
| **v6-P5** | **扁平化 `drawList` + `transformIndex`**（矩阵栈索引，不是每节点一个矩阵） | 滚 1000 项不是 1000 次矩阵乘法；`D_PAINT` 只换段，`drawList` 不动 | 只有"段属于节点" |
| **v6-P6** | **动画三档成本**（compose 3µs / paint 60µs / layout 300µs）+ Tween 按字段静态类型分派，**不做 `interface Tween{lerp(mixed)}`** | `mixed` 在 AOT 下是 `Var`，每字段每帧一次装箱 | 无动画模型 |
| **v6-P7** | **七条绘制不变量**（段局部坐标 / 只有属主能重录 / `ops` 只写不读 / **帧内不分配** / 录制中不改状态 / `opacity<1` 必有层 / 段生命周期跟随节点） | "帧内不分配"靠 `Recorder` 预分配缓冲覆写实现，是 60fps 的前提 | 无 |
| **v6-P8** | **分数量化在光栅前**（相邻盒共享像素边） | 否则两盒交界处各亮半行，出现接缝 | 只提了"量化单点" |

### 2.3 树与生命周期（03）

| # | v6 的机制 | 为什么重要 | v7 现状 |
|---|---|---|---|
| **v6-T1** | **七个态**：`create → mount → attach → active → deactivate → detach → dispose` | 每阶段有"必须做"和"不能做" | 只有 create/update/move/destroy |
