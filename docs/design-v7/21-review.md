## 1. A 类：会让人写出错代码的矛盾（必须改）

### A1 ★★★ 布局/绘制的契约签名，与 §1.1 自己的论证相反

**证据**

| 位置 | 内容 |
|---|---|
| `04:20` | `public function measure(BoxConstraints $c): void;`（虚方法契约） |
| `04:52` | 「⇒ 与命令分派同策略：`switch ($node->kind)` 调**具体类型的静态方法**」 |
| `04:84` | `public function measure(...)` —— 直接覆写示例 |
| `03:52` | `$child->measure($sub);` |
| `05:108` | `node->paint($painter)` |
| `11:17` (C6) | 静态类型已知时虚方法被去虚化，**静默走基类实现** |

**为什么这是硬伤**：`$child` 的静态类型是 `Node`（`toObject(Node::class)` 的返回值），
所以 `$child->measure()` **必然**被去虚化成 `Node::measure()`。§1.1 用一整节论证了"这条路走不通"，
然后 §1 的契约、§3 的示例、`03` 的遍历示例、`05` 的 paint 伪代码**全部走这条路**。

后果不是"慢"，是**每个容器都用基类的默认 measure** —— 尺寸全错，但编译通过、不报错。
这正是 C6 描述的最难查的一类。

**推荐修法**（改 5 处，不动架构）：

```php
final class Layout
{
    public static function measure(Node $n, BoxConstraints $c): void
    {
        switch ($n->kind) {
            case Kind::BOX:    BoxLayout::measure($n, $c);  return;
            case Kind::ROW:    RowLayout::measure($n, $c);  return;
            // … 24 种
            default:           throw new \Error('unknown kind ' . $n->kind);
        }
    }
    public static function place(Node $n, float $x, float $y): void { /* 同构 */ }
}
```

- `04:20-21` 契约改为 `Layout::measure(Node, BoxConstraints)` / `Layout::place(Node, float, float)`
- `04:84/91` 覆写示例改为 `BoxLayout::measure(Node $n, BoxConstraints $c)`（静态方法，首参是节点）
- `03:52` 改 `Layout::measure($child, $sub)`
- `05:108` 改 `Paint::record($node, $painter)`

**代价**：每节点多一次静态调用（可内联）；**收益**：与 §1.1 一致，覆写不可能被吞。

> 替代方案（不推荐）：删掉 §1.1，承认布局路径上接受去虚化风险。那等于把 C6 这条约束作废一半。

### A3 ★★ `OpBuffer` 存在性：三处口径互相否证

| 位置 | 说法 |
|---|---|
| `05:61` | 「**容器只能是 packed PHP array**：op 段是**节点的属性**」 |
| `05:33` | `public function draw(OpBuffer $buf, int $count): void;` |
| `05:103` | 「每个节点持有自己的 `OpBuffer $seg`」 |
| `05:130` | `private OpBuffer $cached;` |
| `01:94` | 把 `OpBuffer` 列为「要装 op 数组 ⇒ **不能是 Native**」的反例 |
| `03:38` | 「就一个 packed array，**没有容器类**」 |

**为什么是硬伤**：`05:61` 与 `03:38` 都断言"没有容器类"，而 `05:33/103/130` 三处都在用 `OpBuffer`。
读者无法判断：到底要不要写这个类？写它是普通 class（可以，但违反 §2 结论）还是不存在（那签名全要改）？

**推荐修法**：**统一成 `array` + 游标**，`OpBuffer` 从方案里消失。

```php
// 节点上（03 §1 的字段表补两行）
public array $ops  = [];    // packed：8 槽/op
public int   $opCount = 0;  // 有效 op 数（游标）

// 后端
public function draw(array $buf, int $count): void;

// RepaintBoundary
private array $cached = [];
```

★ 顺带解决 §9.5 第 4 条「帧内不分配」的落地问题：`$ops` 首次 paint 时
`array_fill(0, 8 * CAP, 0)` 预分配，之后 `$ops[$base + $i] = $v` 覆写，`$opCount` 重置。
**预分配发生在"节点第一次被 paint"，不是每帧**——这一句现在没写，是实现者最容易踩空的地方。

10⁴ 字快照 ×100 层 = 3MB，而文档本身限 1MB —— 两者不矛盾（前者是单文档，后者是撤销栈总量），
但读者会误以为"3MB > 1MB 所以矛盾"。
**修法**：`06:228` 加一句「文档上限 1MB（§5），10⁴ 字约 30KB，占上限 3%」。

### B9 `00` §6 与 `11` §3 两份未知数表（重复维护）

两份 V1–V9 表内容一致，但已经开始漂移（`00:154` 的 V7 已改，`11:61` 没改）。
**修法**：`00` §6 只留 3 行摘要 + 「权威表见 [11](11-编译器约束映射.md) §3」。
