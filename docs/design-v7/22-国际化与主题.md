# 22 国际化与主题

> 本册回答：**UI 文本从哪来、切语言为什么会重排、颜色为什么不能写死、切主题该打哪个脏位。**
> 为什么合成一册：两者都是"把字面量从控件里赶出去"，而且**都必须在 `settle` 期解析**——
> 放进布局期就会撞 [02](02-状态与命令.md) §3.2 的 Fatal。它们是同一个问题的两面。

---

## 0. 一句话

**文本与颜色都是"配置"，必须在 `settle` 里解析成节点的普通字段；布局期与绘制期只读字段。**

---

## 1. 为什么不能"用到时再查语言包"

`02` §3.2 定了一条硬规矩：**共享态只能在 `settle` 里读**，否则 `Tracker` 栈已空 ⇒ 依赖漏登记 ⇒ 直接 Fatal。

如果 `Text` 在 `measure` 里做 `L::t($key)`，两条路都死：

| 做法 | 结果 |
|---|---|
| 读的是 `Cell`（语言是共享态） | 非 settle 期读共享态 ⇒ **Fatal**（这正是那条规矩要挡的） |
| 绕开 `Cell`，直接读静态语言包数组 | 切语言时**没有任何脏位** ⇒ 界面保持旧语言，且无报错 |

⇒ 只剩一条路：**`settle` 里把字符串算好，写进 `$node->text`**。
布局期读 `$node->text`（普通字段），绘制期读同一个字段。**语言包的读取点只有一个，且在 settle。**

```php
// settle 期（节点的 build/update 里）
$node->setText(L::t('dialog.save.title'));      // ★ 读语言包 + 插值，一次算完
```

★ 这与"写即置脏"是同构的：`setText()` 顺带置 `DIRTY_LAYOUT`（文本可能变长）。

---

## 2. 一个 key 的三种命运

| 场景 | 结果 |
|---|---|
| key 存在 | 插值后写进字段 |
| key 缺失（dev） | 显示 `⟦missing:dialog.save.title⟧` + 一条 `E-I18N-KEY` 诊断 |
| key 缺失（prod） | 显示 **key 本身**（不是空串） |

★ **缺 key 不能显示空白**：空白的症状是"按钮变成一个空框"，用户以为是控件坏了，
开发也看不出是哪条漏了。显示 key 至少让两边都能定位。
★ dev 用 `⟦⟧` 包起来是为了**肉眼可辨**（不会被误当成正常文案）。

## 3. 插值与复数：只做两种

```
Hello, {name}                    ← 具名插值
{n, plural, one{# item} other{# items}}   ← 两分支复数
```

★★ **不引 ICU MessageFormat 全量**。它要一个 parser + 一整套 locale 规则，
而中英日韩都不需要"两分支复数"之外的东西（中文没有复数，英文只有 one/other）。

★ 升级判据：**出现"两分支复数表达不了"的语言**（阿拉伯语有 zero/one/two/few/many/other 六种，
俄语有三种）。那时再换 parser，且**只换这一个函数**——接口是 `L::t(string $key, array $args): string`，不变。

★ 占位符缺失时**不静默留 `{name}`**：显示 `⟦missing-arg:name⟧`。理由同上——静默的占位符会被发布出去。

## 4. 切语言 = 一次命令 + 全树 `DIRTY_LAYOUT`

```php
$node->command(Command::SET_LOCALE)->onTap(fn() => $this->setLocale('en'));
```

★★ **必须打 `DIRTY_LAYOUT`，不能只打 `DIRTY_PAINT`**：
文本长度变了 ⇒ 断行、行数、行高、容器自然宽全变。
只打 PAINT 的症状很具体：**英文文案溢出被裁、按钮宽度不够、行高错位**（因为行数是按旧文本算的）。

★ 代价：这是本册唯一一处"必须全树重排"的操作。可接受——切语言是低频动作（一次会话最多几次）。
★ 但**不能顺手把 `DIRTY_LAYOUT` 用在"只换颜色"上**：那会让主题切换变成全树重排（见 §7.3）。

---

## 5. 字体：语言可能换字体族

同一汉字在中日字形不同（`直`、`骨`、`步`），所以**切到日语可能要换字体族**。
字体族一变，度量全变 ⇒ 这条也打 `DIRTY_LAYOUT`。

★ **首版不做"运行时换字体族"**：语言包与字体族在**启动时绑定**，切语言只切文案。
理由：换字体族会让所有已缓存的字形表（[06](06-文本.md) §7）失效，代价远超收益。
★ 如果真要做，接口不变（`L::setLocale()` 内部判断是否需要换族），但必须重新走一遍"字形表预热"。

## 6. 方向：只留结构，不实现镜像

```php
public int $dir = 0;   // 0 = LTR / 1 = RTL（进语义快照，不进布局）
```

★ 首版**所有布局按 LTR**，`dir` 只用于两处：语义快照（读屏软件需要知道方向）、
以及"为将来留位"。

★★ **明确不做的理由**：RTL 要镜像 padding、对齐、滚动条位置、图标方向、进度条方向 ——
那是"把布局再写一遍"，不是"加个开关"。**做了再砍比不做更贵。**

## 7. 主题：语义槽，不是色值

```php
// ❌ 写死
Box::make()->background(0xFFFFFFFF);
// ✅ 语义槽
Box::make()->background(Theme::SURFACE);
```

★ **为什么不能写死**：切主题时要改**所有**颜色，而 `Paint` 表（[05](05-绘制.md) §2）里存的是具体色值——
应用代码里的 `0xFFFFFFFF` 散在几十处，改不到。语义槽让"切主题 = 换一张 `Paint` 表"。

### 7.1 最小槽位集合（15 个）

```
SURFACE          SURFACE_RAISED   ON_SURFACE      ON_SURFACE_MUTED
PRIMARY          ON_PRIMARY       SECONDARY       ERROR
ON_ERROR         OUTLINE          FOCUS_RING      SELECTION
DISABLED_FG      DISABLED_BG      SHADOW
```

★★ **不要给每个控件一个槽**（`BUTTON_BG` / `BUTTON_BG_HOVER` / `BUTTON_BG_PRESSED`…）。
那会变成"每个控件一套主题"：切主题时要改 N×M 个值，且新增控件必须同时改所有主题。
**控件用 `(槽, 状态)` 组合出颜色**——状态是 `Paint` 表的另一个维度，不是槽的另一个名字。

### 7.2 暗色不是反色

| 项 | 亮色 | 暗色 | 为什么不能靠推导 |
|---|---|---|---|
| 背景 | `#FFFFFF` | `#1E1E1E`（**不是** `#000000`） | 纯黑在 OLED 上边缘发灰，且对比过强刺眼 |
| 文字 | `#1A1A1A` | `#E6E6E6`（**不是** `#FFFFFF`） | 纯白在暗底上"发光"，长时间阅读疲劳 |
| 阴影 | 有（浅灰） | **几乎不用**，改用亮边框 | 暗底上阴影看不见 ⇒ "靠阴影表达层级"整个失效 |
| 图片 / 图标 | 原色 | **可能降亮度** | 亮色图标在暗底上刺眼 |

⇒ 暗色是**另一套配色**，不是同一套配色的变换。**两套都要人工定，不能算。**

### 7.3 切主题打什么脏位

| 变化 | 脏位 | 理由 |
|---|---|---|
| 只换颜色 | `DIRTY_PAINT` | `Paint` 表整体换，段重录；几何不变 |
| 换字体族 / 字号 / 行高 | `DIRTY_LAYOUT` | 度量变了 |
| 换圆角半径 | `DIRTY_PAINT` | 圆角是绘制参数，不进布局 |
| 换图标 | `DIRTY_PAINT` | 图标是 op 的资源索引 |
| 换控件密度（padding） | `DIRTY_LAYOUT` | padding 是布局字段 |

★ 判据统一成一句：**"这次变化会不会改变任何节点的 w/h"** —— 会 ⇒ LAYOUT，不会 ⇒ PAINT。

★★ **不做主题切换动画**：那会让全树每帧重录（PAINT 档 ~60µs × 节点数），收益只是"1 秒的渐变"。
局部可以用 `ColorTween`（[20](20-动画与过渡.md)），**全局直接切**。

### 7.4 高对比度是系统级强制，不是可选主题

Windows 的高对比度模式（`SystemParametersInfo(SPI_GETHIGHCONTRAST)`）是**无障碍合规项**。
- 检测到 ⇒ **强制用高对比度主题表**，不跟随应用自选主题
- **语义槽不变** ⇒ 应用代码零改动（这正是 §7 用槽而不用色值的回报）
- 高对比度下**忽略应用传的具体色值**：`Theme::SURFACE` 直接映射到系统色

| 平台 | 级别 | 说明 |
|---|---|---|
| Win32 | `Full` | `SPI_GETHIGHCONTRAST` + 系统色 |
| macOS | `Partial` | 有"增强对比度"，但不是同一机制 |
| Linux | `Partial` | 依赖 DE |

### 7.5 主题是一个对象，不是一堆常量

```php
final class Theme
{
    public string $name = 'light';
    public array  $paints = [];    // slot*state → paintId（packed，见 05 §2）
    public float  $radius = 4.0;   // 圆角基准
    public int    $fontFamily = 0; // 字体族索引
}
```

★ `Theme` 是**普通 class**（它要装 `paints` 数组 ⇒ 不能是 `#[Native]`，[01](01-心智模型.md) §3.1）。
★ `paints` 是 packed array（`slot * STATE_COUNT + state` 直接索引），不是 map——热路径不查字符串键。

## 8. 两条交汇：文本 × 主题

| 组合 | 脏位 |
|---|---|
| 切语言（文本变长） | `LAYOUT` |
| 切语言 + 字体族变 | `LAYOUT` |
| 切主题（只换色） | `PAINT` |
| 切主题 + 字号 / 密度变 | `LAYOUT` |
| 系统高对比度切换 | `PAINT`（槽映射变，几何不变） |

★ 两者共用同一条判据（§7.3 末），所以不需要两套规则。

## 9. 反模式

| 反模式 | 症状 | 正解 |
|---|---|---|
| 在 `measure` 里 `L::t()` | Fatal（非 settle 期读共享态） | settle 里算好写字段（§1） |
| 缺 key 显示空串 | 按钮变空框，两边都定位不到 | 显示 key / `⟦⟧`（§2） |
| 颜色写死 `0xFF...` | 切主题不变 | 语义槽（§7） |
| 切语言只打 `PAINT` | 文案溢出、行高错位 | `LAYOUT`（§4） |
| 每个控件一个主题槽 | 切主题改 N×M 个值 | 15 个槽 × 状态（§7.1） |
| 暗色用反色推导 | 纯黑纯白刺眼、阴影失效 | 两套人工定（§7.2） |
| 主题切换加过渡动画 | 全树每帧重录 | 直接切（§7.3） |
| 把 RTL 当开关做 | 等于重写一遍布局 | 首版只留结构（§6） |
