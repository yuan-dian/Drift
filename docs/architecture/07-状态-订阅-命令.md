# 07 · 状态、订阅与命令

> 对应 design-v7 [02-状态与命令](../design-v7/02-状态与命令.md)。本文描述**实现**，并标出与
> design-v7 的一处实质偏离。

## 1. 一句话

三条缝分离：**UI 状态**住 `State`（有 `markDirty()` 标脏、帧末重建）；**业务数据广播**住
`Subject`（手动 `notifyChanged()` + 异常隔离订阅）；**命令**走**字符串名**的派发链
（`CommandRouter`）。★ 与 design-v7 不同：实现里命令是**字符串名**（`nav.users` / `doc.save`），
不是 design-v7 主张的 **int 命令 ID**——"命令 ID = 阿基米德点"那条律在代码里让位了（见 §5 与
[13](13-与-v7-设计对照.md)）。

## 2. 状态（UI 局部状态）

- `StatefulWidget`（`src/Widget/StatefulWidget.php:15`）/`State`（`src/Widget/State.php:21`）/
  `StatefulElement`（`src/Widget/StatefulElement.php:14`）：标准组合。
- `State::markDirty()`（`src/Widget/State.php:81`）是唯一写副作用；`State::tickFrame()` /
  `tickFrameStamped()`（`src/Widget/State.php:101`/`:116`）被帧时钟驱动动画。
- `StatefulElement::onMount()` 在首次 `build()` 前跑 `initState()`（订阅必须先到位，否则首帧读不到值）。

## 3. 订阅（业务数据 → UI，跨层）

- `Subject`（`src/State/Subject.php:20`，`abstract`）：广播端，**不认识 GUI**（子类 `Store` 只依赖本类
  ⇒ "业务层零 GUI 依赖"是结构事实）。`notifyChanged()`（`:37`）手动调一次；**每个订阅者异常隔离**
  （`:37` 注释：先记账、通知完再报，避免第一个炸后面全收不到）。
- `Subscription`（`src/State/Subscription.php:21`）：按自增 id 退订，遍历中退订不出错。
- `SubjectBuilder`（`src/State/SubjectBuilder.php:35`，`StatefulWidget` + `SubscribingWidget`）：
  在 `build()` 里声明订阅，`SubjectBuilderState`（`:126`）持有它们。
- `Cell`（`src/State/Cell.php:20`）：单值容器，`setIfChanged()` 设同值不触发重建（"设同值不重建"的精确门控点）。
- `SubscribingWidget`（`src/State/SubscribingWidget.php:19`）：**空标记接口**——给 lint 与读代码的人看，
  订阅责任只能落在这类控件上（`dead-subscription` 判据的抓手，`src/State/SubscribingWidget.php:6` 注释）。

## 4. 命令（字符串名 + 派发链）

- `CommandRouter`（`src/Commands/CommandRouter.php:22`，`final`）：应用级注册表，`on(string $name, CommandHandler)`（`:47`）+ `dispatch(string $name, CommandArg)`（`:71`）。`array<string, CommandHandler>`——**字符串名**，非 int。
- `CommandHandler`（`src/Commands/CommandHandler.php:20`，`interface`）：具名类实例（可枚举/可单测/静态可达）。
- **派发链**（§11.4.3 第 ③ 环）：State → 祖先 State → 本注册表 → 都没接 ⇒ Diagnostic 级上报
  （不静默：菜单项亮了但点了没反应是最难查的 bug 之一，`src/Commands/CommandRouter.php:77`）。
- 死命令 lint（R5）：`names()`（`:87`）是静态输入，未注册命令名会被 lint 抓到。

## 5. 为什么是字符串名而不是 int ID（与 v7 的偏离）

- design-v7 把"命令 ID（int）+ 可回放"当阿基米德点；本实现选择**字符串名**为主。代价：字符串名
  不如 int 紧凑、不可直接序列化进回放帧；收益：可读性 + 免维护常量表 + 与 `CommandRouter` 的
  "页面就近接管 + 应用级注册"链天然契合（跨树复用、一个 handler 管一列命令）。
- 可回放路径（菜单/快捷键/AI 驱动）当前**没有**独立的 int 通道——这是已知的实现欠债，列在
  [13](13-与-v7-设计对照.md) 的"设计让位"清单。

## 6. 验证口径

```bash
# 状态 / 订阅 / 命令 三类都在
grep -rn "abstract class State\b\|abstract class Subject\|interface SubscribingWidget\|final class CommandRouter" src/

# 命令是字符串名（不是 int 路由）
grep -n "array<string, CommandHandler>\|public function on(\|public function dispatch(" src/Commands/CommandRouter.php

# 订阅异常隔离
grep -n "异常隔离\|foreach (\$failures" src/State/Subject.php

# 受控控件：只回调新值、不自持状态
grep -n "function activate\|onChanged" src/Widget/ToggleBase.php
```
