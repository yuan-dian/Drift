## 2. design-v7 里**实现让位/没落成**的判据

| v7 判据 | 实现现状 | 说明 |
|---|---|---|
| **命令 ID（int）= 阿基米德点** | **字符串名命令 + 派发链** | 实现选了 `CommandRouter::on(名, handler)`（`src/Commands/CommandRouter.php`），int 回放通道**未做**。可读性 + 免常量表换可读性；可回放路径是已知欠债 |
| **`measure`/`place` 两步分离** | **单遍 `layout()`** | `RenderBox::layout()` 是 `final`（`src/Layout/RenderBox.php:88`），`measure/place` 分离判定为 no-op（布局位置无关、缓存层不做） |
| **行为走 `int $kind` + `switch`** | **`int $kind` + `===` 链，控制流 `switch` 零处** | AOT 硬坑逼的：tpc 的 `switch` 生成 C2440（[11](11-编译器约束与-AOT-坑.md) A1）。v7 的"switch"写法在实现里被证伪 |
| 虚拟方法分派 | 去虚化 ⇒ 一律 `int $kind` | v7 的 L3 从"建议"变成"硬必需"——`ToggleBase`/`RenderToggle` 单盒按 `kind` 分支 |

## 3. design-v7 提出但**首版未启动**的能力

- **GPU 加速**：`GpuContext` 接口已留（`src/Rendering/GpuContext.php:20`），未实现。
- **原生控件**：一律自绘；菜单是数据（已实现），系统强制处才渲染原生 `HMENU`（未做）。
- **多窗口**、**富文本编辑**（首版单行 + 多行纯文本 + 选区）、**移动端**（抽象留口，实现不做）。
- **int 命令回放通道**（见 §2）。
- design-v7 的 `23-桌面集成`（文件对话框/托盘/拖放不起帧）中，拖放/托盘接口已留
  （`Tray`/`DragController`），文件对话框 `Dialog` 接口已留但未接系统实现。

## 4. 一句话总结

**v7 的设计意图 ≈ 实现的主干**（三层树 / 写脏 / Canvas 接口 / 手势 arena / 语义推拉 / 虚拟化）；
**三处实质偏离**是 AOT 编译器把"建议律"逼成了"硬纪律"（命令字符串化、`switch` 消失、去虚化走 `kind`），
**首版非目标**（GPU / 原生控件 / 多窗口 / 富文本 / 移动端）按计划未做。读 v7 时，把 §2 的三处当
"设计稿已被实现推翻"，其余当"蓝图已兑现"。
