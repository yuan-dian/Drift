# 03 · 布局与渲染盒

> 对应 design-v7 [04-布局](../../design-v7/04-布局.md)。本文描述**实现**。

## 1. 一句话

布局是**单遍**的：`RenderBox::layout()` 是 `final`，子类只实现 `performLayout(BoxConstraints): Size`，
约束 → 尺寸 + 子节点相对位置，是纯函数；C1–C6 六条契约里唯一响亮失败的是"画到盒外"（C6）。
**没有 `measure`/`place` 两步分离**——design-v7 主张的分离在本实现里判定为 no-op（布局位置无关，缓存层不做）。

## 2. `layout()` 为什么是 final

`RenderBox::layout()`（`src/Layout/RenderBox.php:88`）：
- 调 `$this->performLayout($constraints)` 拿到测量尺寸；
- C6 检查：**只有超出上界**才算违反**（`$measured->width > $constraints->maxWidth || height > maxHeight`）**——下界提升不是违反（`tight()` 父把尺寸定死是本职工作）；
- 预览期（`LayoutTolerance::$previewing`）把瞬时违规降级为裁剪，否则拖动 resize 会弹 Fatal 打断拖动；
- `$this->size = $constraints->constrain($measured)` 钳回约束内。

子类只实现 `performLayout()`（`src/Layout/RenderBox.php:120`，`abstract`）。容器在这里给子节点 `layout()` 并 `setOffset()`（C1 单向数据流：子不自定位）。

## 3. C1–C6 六条契约（实现侧）

| # | 契约 | 落实 |
|---|---|---|
| C1 | 父管挂接，子不自定位 | `RenderBox::setOffset()`（`src/Layout/RenderBox.php:52`）只有父写；`Element::adoptBoxes()` 把子盒收进父盒 |
| C2 | `layout()` 纯函数（同输入同输出） | 由调用方决定何时重排；Render 层全树重排（§13.3，无脏边界） |
| C3 | 内禀测量 | `intrinsicWidth(float $height)` / `intrinsicHeight(float $width)`（`src/Layout/RenderBox.php:128`）带另一轴 |
| C4 | 主轴弹性份额 | `flex(): int`（`src/Layout/RenderBox.php:137`），默认 0；`RenderFlex` 读它 |
| C5 | 溢出策略 | `overflow(): Overflow`（`src/Layout/RenderBox.php:148`），默认 `Clip`；会超的容器必须覆写 |
| C6 | 画到盒外即 Fatal | `layout()` 里的 `Errors::report(...)`（`src/Layout/RenderBox.php:96`） |

## 4. 渲染盒家族（27 个 Layout 类）

- 抽象基类：`RenderObject`（`:21`）、`RenderBox`（`:25`）、`RenderProxyBox`（`:16`，单子透传）。
- 单子/叶子：`RenderPadding`、`RenderSizedBox`、`RenderCenter`、`RenderCard`、`RenderButton`、
  `RenderDivider`、`RenderProgress`、`RenderSpinner`、`RenderToggle`、`RenderText`、
  `RenderTextField`、`RenderCustomPaint`、`RenderMenuItem`、`RenderAppBar`(extends `RenderFlex`)。
- 容器：`RenderFlex`（Row/Column/Each 的盒，`src/Layout/RenderFlex.php:33`）、`RenderProxyBox`
  子类链、`RenderScrollView`、`RenderModalHost`、`RenderPopupPanel`、`RenderDock`、
  `RenderErrorBoundary`、`RenderFlexible`。

★ `RenderText::performLayout()`（`src/Layout/RenderText.php:58`）**会调两次**：一次自然尺寸、
一次被夹紧后的最终尺寸（文本度量要按可用宽重排）。

## 5. 命中测试：一次命中、三方消费

`RenderBox::hitTest(float $x, float $y)`（`src/Layout/RenderBox.php:169`）：
- 越界 ⇒ `null`；
- 子节点**逆序**问（后画的在上，与 `paint()` 顺序相反）；
- 子都不中 ⇒ **返回自己**（容器吞掉事件，"禁用 ≠ 穿透"的基础）；
- `Offstage` 无需特判：它跳过 layout ⇒ `size` 为 null ⇒ 这里直接 `null`。

调用方（输入路由 / 语义 / 光标形状）只走一次树，三方各取所需。

## 6. 绝对原点单一出处

`RenderBox::absoluteOrigin()`（`src/Layout/RenderBox.php:69`）沿父链累加 `offsetX/offsetY`
（Element 不持有 offset，盒才持）。命中测试 / IME 候选框 / 菜单锚点 / 语义几何全部走这里——
自己沿 Element 链累加会**重复累加**。

## 7. 验证口径

```bash
# layout 是 final、performLayout 是 abstract
grep -n "final public function layout\|abstract protected function performLayout" src/Layout/RenderBox.php

# 哪些盒子覆写了 performLayout（= 真实参与布局的节点）
grep -rln "protected function performLayout" src/Layout/

# C6 的"画到盒外"报错
grep -n "画出的尺寸超出父容器" src/Layout/RenderBox.php

# 确认没有 measure/place 两步分离
grep -rn "function measure\|function place\b" src/Layout/ || echo "no measure/place split"
```
