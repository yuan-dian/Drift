## 3. 布局/组合族

`Row`（`src/Widget/Row.php:15`）/`Column`（`:15`）/`Each`（`:30`，带 Key 必填的列表）/ `Spacer`（`:17`）/
`Expanded`（`:18`，弹性项）/ `Padding`（`:19`）/`Center`（`:18`）/`SizedBox`（`:33`）/
`Offstage`（`:22`，跳过 layout ⇒ 尺寸 null ⇒ 命中测试自动 null）/ **`TabView`**（`:74`，
多页签容器：页签条复用 `SegmentedControl`，每页套 `Offstage` ⇒ **切走再切回状态保活**）。
★ `TabView` 与路由侧的 `PageHost` 是同一套保活机制的两个入口（键：序号 vs 页名；谁来选：
受控 vs 订阅 `Subject`），两者刻意不共用代码 —— 共同部分只是那个三行的 `Offstage` 循环。

★ `SizedBox::height()` 小于子内容会触发 C6 Fatal（"画出的尺寸超出父容器给的可用空间"）把整帧拖垮——
定尺寸只给 `width`、高度让给内容是实测纪律（`src/Widget/SizedBox.php:56`）。

**`TreeView`**（`src/Widget/TreeView.php:72`，层级数据树：递归的 `TreeNode` 在
`visibleRows()` 里展平成 `list<TreeRow>` 交给 `LazyColumn` ⇒ 虚拟化 + 按 `id` 锚点）。
展开集合（`expanded()`）与选中值（`selected()`）都是**受控**的，与 `TabView::selected`
同族；`onSelected()` 不给 ⇒ 标签按钮连 Tab 站都不占。

★ 这是"组合优于自建容器"的第三个落点（前两个是 `TabView` 的 `Offstage` 保活与
`LazyGrid` 的 `LazyColumn` 虚拟化）：它 `extends StatelessWidget`，**零新增
Element / RenderBox**。代价是行高下限被箭头按钮钉住 —— `IconButton` 的天然边长 42
也是 `ARROW_SLOT`，所以 `rowHeight()` 只有**一条**守卫（`< ARROW_SLOT` ⇒ 响亮失败，
理由：小于它时行内容被 `LazyColumn` 的 `SizedBox` 静默裁掉）。

★ 行标签用 `Button::alignLeft()`（`src/Widget/Button.php`）而不是 `NavButton`：
标签被 `Expanded` 撑满整行剩余宽度（点行的空白也算点这一行），默认居中会让整棵树
看着像一段居中文字。`NavButton` 是"这类按钮天生左对齐"，借它会把"树行"和"导航项"
焊在一起。★ 这一条是 **AOT 真机取证**抓出来的 —— 几何判据测的是 Button 盒的起点，
盒看着对、字却在中间。

**`CalendarView`**（`src/Widget/CalendarView.php`，月历网格：7 列 × 5~6 行，
日期格是 `Button` + `Button::compact()`，前导/尾随留白）。
月份（`month()` + `onMonthChange()`）与选中日期（`selected()` + `onSelected()`）
都**受控**，两个值对象是 `YearMonth` / `LocalDate`（不碰 `\DateTimeImmutable`：
日历只要"这月几天 / 一号周几"，而时区与夏令时是它唯一用不上又必须先钉住的两样）。

★ **三档视图**（2026-10-29 补）：点标题在「日 → 月 → 年」之间循环，跨年翻月从
"按 17 次箭头"变成三次点击。视图粒度（`CalendarViewState::$mode`）是**纯 UI 态**、
住 State；受控值仍是 `month` / `selected`，切视图不动值。月/年格走**同一条**
`onMonthChange` 通道 —— 翻页、选月、选年都是"我想看别的月份"。
★ **标题可点 ⇔ 有 `onMonthChange`**：能切过去却一格都点不动，比"不能切"更糟。
★ **越界那侧不挂回调**（`YearMonth::tryPlusMonths()` 返回 `null`）：翻到头了就该
点了没反应，而不是上报一个"跟当前一样"的月份；更不能因为构造越界 `YearMonth`
把进程打死。

★ 行数随月份形状变（`firstWeekday() + daysInMonth()` 向上取整，最少 5 行）：
28 天且 1 号是周一的月份只需 4 行，视觉上太扁。

★ **别月日期留空、不画灰色数字**：框架没有"禁用态"，而灰且可点的格子会让用户
以为能选 —— 空白是唯一诚实的表达。这也是"点别月自动跳"没做的原因：
那需要控件替应用决定翻月，与受控纪律相反。

★ 日期格全部 `skipFocus()`：31 个 Tab 站是可用性灾难。`skipFocus()` 只挡 Tab 序 ——
方向键在格间移动由 `FocusManager` 的几何导航提供（2026-11-05，见 [06](06-输入-手势与焦点.md) §4）。

### 4.0 修饰的接收者必须是盒（2026-10-25：加静态前置）

**修饰是盒的属性**：`Element::syncBox()` 拿到盒之后才 `setMods()`。所以不产盒的控件
（`StatelessWidget`、不覆写 `createRenderObjectFromState()` 的 `StatefulWidget`、
`Offstage` / `ThemeScope` / `ScrollView`）套 `padding` / `width` / `background` / `shadow`…
**修 silent 失效**，直到运行期撞 §11.7 守卫才 Fatal。

**这不是"偶尔写错"，是反复踩**：2026-10-23 那次"`Card::make(ScrollView::make(...))`
让示例台 7 个页面一点就炸"（当时的绕法是让 `Card` 先套一层代理盒，见
[`REVIEW-2026-10-28.md`](../REVIEW-2026-10-28.md) §11.9 末尾的"Card 归位"）；
2026-10-25 又添一例 —— 示例台第 21 页「图标」写成 `ScrollView::make(...)->paddingAll(24)`，
`lint` 全绿、`smoke` 全绿、AOT 编译通过，**用户点开那一页才 Fatal**。

**根因不是"没守卫"，是"守卫发现点太晚"**：它是运行期的，只在那一页真被 build 时才触发；
而 `showcase` 有 21 页，只有被点到的那页才会暴露。

**两道闸门，分工不同**：

| 闸门 | 时机 | 形态 |
|---|---|---|
| `Element::syncBox()` 的守卫（§11.7） | 运行期（build 到） | Fatal，最后保险；负向用例见 `smoke` 的 `modstateful` |
| lint `nonbox-decoration` | 提交前 | error，静态前置（判据见下） |

静态判据（三条同时成立才报）：① 出现修饰方法调用；② 接收者的静态类型是本仓的
`Drift\Widget\Widget` 子类（`Modifier` 自己的同名方法不算）；③ 该类型不产盒 ——
继承 `RenderBoxWidget` 的产盒；**类自己声明了这个修饰方法也算产盒**（`Card` 是
`StatelessWidget`，但它把 `padding/shadow/background/…` 转发给内部代理盒 `SizedBox`）；
`StatefulWidget` 子类声明了 `createRenderObjectFromState()` 也算。

修法：`Padding::make(8)->child($x)`（`Padding extends RenderBoxWidget`，所以它自己不会
被这条规则报），或用控件自己的样式参数。

★ **为什么不做"让写不出来"**（把修饰方法从 `Widget` 下移到 `BoxWidget`，不产盒的类
干脆没有这些方法）：代价是搬 20 个方法 + `mods()` 字段（`Element` 要读它，搬走等于
拆掉 §11.7 那道运行期保险），而 `Card` 这类"覆写转发"的组合控件仍需要在子类里同名声明
（PHP 允许父类没有的方法）⇒ 类型层只能拦住"直接调"，拦不住"覆写"。
收益（IDE 不提示）已被 lint 覆盖，不值这个改动量。

### 4.1 交互状态层：悬停反馈（2026-10-25）

**问题**：`ColorToken::Hover` / `Pressed` 早有值（`src/Rendering/ColorToken.php:41`），但
**零消费者**（`grep "ColorToken::Hover" src/` 只命中枚举自身）。悬停毫无视觉反馈，是
"精致感"的第一道缺口。

**为什么不是"在 `Button` 里 if/else 换底色"**：
- `Button extends BoxWidget`（**不是** `StatefulWidget`），改继承会牵动
  `NavButton` / `Menu` / `MenuItem` 三条子链，且 `RenderButton` 创建路径要重写。
- 每个控件各写一遍 ⇒ 加新控件必漏，`Card` / `MenuItem` 还要复制同一段。

**为什么不是"渲染层反查 Element"**：`RenderObject` **没有** `element` 引用（只有
Element → Box 的正向），渲染层读不到"我是否被悬停"。

**采用：状态推进盒 + 能力方法**

| 层 | 改动 |
|---|---|
| `RenderObject` | `acceptsHover(): bool`（默认 `false`，与 `panelRect()` 同形的能力方法）、`setHovered(bool)`、`hovered(): bool` |
| `RenderButton` | 覆写 `acceptsHover()`（声明了状态色才接）、构造加 `?Color $hoverOverlay = null`、`paintContent()` 在背景之后叠一层 |
| `Button::createRenderObject()` | 按变体解析状态色（Default/Flat → `ColorToken::Hover`；Primary/Danger → 白色 12%）—— **Layout 仍不依赖 Theme** |
| `FocusManager::hoverTo()` | 沿**盒父链**找第一个 `acceptsHover()` 的盒：旧的 `setHovered(false)`、新的 `setHovered(true)` |

**为什么状态推进盒、而不是推进 Element**：`RenderObject` 自带 `parent()`（盒父链），起点由
`Element::effectiveBox()` 给；而 `App` 层问"接受吗"走能力方法 ⇒ **零 `instanceof`**（I2 闸门）。

**为什么不需要"请求一帧"**：`RenderBox` 没有脏标记（`RenderObject` 类头写明"Render 层没有
脏边界"，每帧全量 paint）；且 hover 由 `WM_MOUSEMOVE` 驱动 —— 同一条消息的那一轮循环里
`FrameClock::tick()` 紧接着就重绘。

**`Pressed` 为什么本轮不做**：按钮**按下即激活**（`Button` 类头的既有裁决），down 之后命令型
按钮通常已 `setState` 重建、盒被换掉 ⇒ pressed 态可见窗口极短。等有"需要按住反馈"的真实
消费者再接（通道已就绪：`setPressed()` + `pressedOverlay`，形状与 hover 完全相同）。

**兼容性**：`RenderButton` 构造加**可选**参数（唯一创建点是 `Button::createRenderObject`）；
`RenderObject` 加三个方法（默认不表态）。静态截图不变（hover 只在交互时出现）。

#### 4.1-落地（2026-10-25）

- `RenderObject`：`acceptsHover()`（默认 `false`）/ `setHovered()` / `hovered()` + `protected bool $hovered`。
- `RenderButton`：覆写 `acceptsHover()`（`hoverOverlay !== null` 才接）、构造第 7 参
  `?Color $hoverOverlay = null`、`paintContent()` 在底色/边框之后、标签之前叠一层。
- `Button::createRenderObject()`：`Default`/`Flat` → `ColorToken::Hover`；
  `Primary`/`Danger` → `new Color(255,255,255,40)`（实心强调底上叠 Hover 色会被染灰）。
- `FocusManager`：`?RenderObject $hoverBox` + `applyHoverState()`，`hoverTo()` 开头推状态；
  沿**盒父链**找第一个 `acceptsHover()` 的盒（零 `instanceof`）。

**验证**
- `smoke` **1443 / 0**（+4：`acceptsHover`、`hoverTo` 置位、悬停容器不复位、离开复位）。
- `lint` 524 / 0-0；`docref` 69/0。
- **像素（`_build/hover-probe.php`，软光栅两帧对比按钮边缘 `+6,+6`）**：
  `Default` `243,243,243 → 236,240,245`（**恰为 `ColorToken::Hover` = `0xECF0F5`**）；
  `Primary` `9,105,218 → 48,129,224`（白色 40 提亮）。两枚按钮都变，PASS。
- AOT：`showcase.exe` 增量编译通过。

#### 4.1-自绘控件（2026-11-05）

上面那节的实现后来整体搬进了 `RenderObject`（两相位 `setInteraction()` +
`RenderBox::paintInteraction()`，见 `DESIGN-INTERACTION-FEEDBACK-2026-11-05.md`）。
**但那只覆盖"形状就是盒矩形"的控件** —— 开关 / 分段 / 滑杆各自画自己的几何，
`acceptsHover()` 从没被声明过，指针压上去**逐像素静默**。

本轮把状态层切成**原语 + 形状**两半：

| 层 | 职责 |
|---|---|
| `RenderBox::paintStateLayer(Shape, radius)`（`final`） | **层次**：hover 在下、press 在上、进度淡入、两色皆 `null` 时零命令 |
| `RenderBox::paintInteraction(?Size)`（`protected` 可覆写） | **形状**：默认整盒矩形；自绘控件换成自己的几何 |

★ 层序由 `final paint()` 钉死（`装饰 → 状态层 → 内容`），覆写只能换形状、换不了
层次。所以"状态层必须压在某块图元之上"时，**把那块图元挪进 `paintOwnChrome()`**：
分段控件的选中药丸、滑杆的轨道与已选段都因此各挪一格（静止时零像素变化 ——
27 页整页 golden 不刷基线仍逐绿）。

三个控件的形状与配色：

| 控件 | 状态层形状 | 为什么 |
|---|---|---|
| `RenderToggle` | 本体外扩 `0.4×boxSize` 的光晕（圆 / 胶囊） | 整行铺色会像一条列表高亮；点标签与点方框是同一件事，不该有两种"选中感" |
| `RenderSegment` | 四边内缩 `inset` 的药丸 | 段盒比药丸大一圈，铺满会让反馈跑到轨道上 |
| `RenderSlider` | 拇指外扩 `0.6×thumbRadius` 的圆 | 整盒 = 整条轨道，那是在说"这条滑杆被指着"，而不是"拇指被指着" |

配色跟着**底色**走（与 `Button` 的变体同一条判据）：未选中段压在轨道灰上 ⇒ 主题
`Hover`/`Pressed`；选中段是 `Accent` 实底 ⇒ 叠白 40/70。禁用态两个色都给 `null`
⇒ `acceptsHover()` 为假 ⇒ 连状态都不推进（零成本）。

#### 4.1-输入域：状态层的第二种形状（2026-11-05）

输入井是 `Pane` 底，与主题 `Hover` 只差 3/5/6 级 —— 把上面的**填充叠色**照搬过来，
亮主题下几乎看不见，而且 hover 变亮、press 变暗，与按钮的递进方向相反。所以输入域
不是"第五个自绘控件"，是**同一种状态的另一种形状**：

| 控件 | 层次 | 形状（笔） |
|---|---|---|
| 按钮 / 开关 / 段 / 滑杆 | `paintStateLayer()`（`final`，只此一份） | `Paint::fill` 填充 |
| `TextField` / `TextArea` | 同上 | `Paint::stroke` 沿边框描边 |

`paintStateLayer()` 多一个 `float $strokeWidth = 0.0`：`> 0` 用描边笔、`0` 用填充笔。
淡入、两相位层序、零成本早退仍只写一份，既有四个调用方零改动。

- 两个渲染盒覆写 `paintInteraction()`，把**自持 `BoxStyle`** 的 `radius` / `borderWidth`
  传进去 —— `mods` 那份是 0，直接套基类会画成方角填充（`interactionRadius()` 只认 mods）。
- 两档色 = 当前边框色朝 `Text` 混 0.28 / 0.50：亮主题变深、暗主题变亮，方向由主题
  自己给，无分支；`error()` 态从 `Danger` 起混 ⇒ 红信号不会被指针状态盖成灰。
- 静止态进度为 0 ⇒ 一条命令都不发 ⇒ 整页 golden 零刷新。

★ 判据必须钉「**变在哪**」：盒心一个像素都不变、直角顶点不吃色、圆角弧上有色。
只断「变了没有」的测试，把描边退回整盒填充也全绿。

### 4.2 图标：矢量 `Path`，不碰字体也不碰位图（2026-10-25）

**问题**：全仓没有 `Icon` —— 工具栏 / 导航 / 按钮全靠文字堆，是"不精致"的大头。

**三条路的取舍**

| 方案 | 为什么不选 / 选 |
|---|---|
| 位图（`Image` + PNG） | 12/16/20/24/32 多尺寸上糊（DPI 缩放） |
| 图标字体（私有区码点 + `Text`） | 软光栅靠**预生成字模**，而字模脚本扫的是源码里的中文字面量 ⇒ **扫不到图标码点** ⇒ 真机**零宽隐形**（不画 tofu、不报错） |
| **矢量 `Path`**（选） | `Path` + `drawPath` 已有，`CAP_PATH` 是 Extended（**两后端都有**）；纯新增、零框架改动 |

**形状**

| 层 | 职责 |
|---|---|
| `IconName`（enum，10 个） | 只有名字；拼错是静态可查的（字符串 `'serach'` 会静默画不出东西） |
| `IconSet::path(IconName, float $size): Path` | **归一化 0..1 坐标 × size**；加图标只改这里 |
| `Icon`（`RenderBoxWidget`） | `size` / `color` / `strokeWidth`；`color` 默认 `ColorToken::Muted` |
| `RenderIcon`（`RenderBox` 叶子） | 固定正方形布局 + `drawPath(Paint::stroke(...))` |

**两个必须知道的约束**

1. **`Canvas` 没有 `scale`**（只有 `save`/`translate`/`restore`）⇒ 缩放只能在几何层做：
   `IconSet` 直接生成"已乘 `size`"的 `Path`，`RenderIcon` 收到什么就画什么。
2. **`RenderBox` 已有非 readonly 的 `$size`**（盒尺寸，布局期写）⇒ `RenderIcon` 的字段
   必须叫 `$iconSize`，否则 Fatal（"Cannot redeclare non-readonly property as readonly"）。

**不进语义树**：图标是装饰（`Icon` 不调 `semantics()`）—— 可访问名由包住它的按钮给，
与 `Text` 同一条纪律（`SemanticsRole` 类注释："叶子内容不给角色"）。

**已知差异**：`drawPath` 在 Raster 上是**硬边无抗锯齿**（`CAP_PATH` 的既有取舍），
Skia 是真矢量 —— 小尺寸下 Raster 会有锯齿，这是测试后端换确定性的代价。

### 4.3 图标接进控件：`IconButton` / `NavButton(icon)`（2026-10-25）

`Icon` 只出现在展示页等于没做 —— 「工具栏 / 导航全靠文字堆」这个问题要**控件**解决。

**为什么是"同一个盒"，不是 `Row(图标, 文字)`**：`Flex::createRenderObject()` 只建
`RenderFlex` 空壳，子盒由 Element 层挂 —— 在 Widget 层手工拼 `Row` 会得到一个
**没有孩子**的 `RenderFlex`（布局出 0×0，不报错）。所以图标做成 `RenderButton` 的
字段（`?Path $iconPath` + `iconSize` + `iconGap` + `iconStrokeWidth`），与标签在
同一个盒里排；`label` 仍是 `RenderText` 孩子（保住断行口径）。

| 层 | 改动 |
|---|---|
| `RenderButton` | 加 4 个图标字段 + `bool $centerContent`；布局把「图标 + 间距 + 标签」当**一个整体**；`label === ''` 时**不建** `RenderText`（空串会占一行行高，把正方形撑成竖条） |
| `Button` | `->icon(IconName)`；抽出 `resolveBoxStyle()` / `resolveForeground()` / `resolveHoverOverlay()`（子类复用，不复制 40 行 match）；`labelVisible = false` 时内边距改四边等距 ⇒ **正方形** |
| `IconButton` | `IconButton::of($icon, $label)`：`label` **不进视觉**，只作可访问名（纯图标没有可读文本，不传名等于对读屏隐形） |
| `NavButton` | 构造置 `centerLabel = false`：菜单项左对齐（见下） |
| `IconSet` | 10 → 20 个图标（`Grid` / `TextLines` / `Square` / `ListBullets` / `Bell` / `Play` / `Image` / `Sliders` / `Info` / `Brush`）—— 21 个导航项共用 10 个图标就没了区分度 |
| `ShowcaseRoot` | `[名称, 工厂]` 二元数组 → `NavEntry`（图标 + 名称 + 工厂）：加字段不用改 `[0]`/`[1]` 魔数，"图标和名字写反"也从静默变成编译错误 |

**为什么 `IconButton` 用 `of()` 不是 `make()`**：`Button::make(string): self` 是父类签名，
子类改成"图标 + 名字"会 **Fatal**（`Declaration ... must be compatible`）—— PHP 对静态
方法同样查 LSP。`Size::of()` / `TextStyle::of()` 是同款先例。

**对齐开关（`centerLabel`）**：按钮语义是居中（Material 也是这样），但**菜单 / 导航项
必须左对齐** —— 实测三种长度标签的 label offset 是 49 / 59.5 / 33.5，一列图标参差不齐。
`NavButton` 构造置 `false` 后三个都是 26。这是字段不是虚方法覆写（tpc 去虚化那条纪律）。

### 4.4 顺手修掉的两个既有 bug（都是加图标时才暴露）

1. **`RenderButton::performLayout()` 用父给的 `maxWidth` 居中**，而不是盒的实际宽度：
   松约束下 `maxWidth` 可能是 400，把内容推到盒子**右边外面**（图标直接飞出按钮）。
   改成先 `constrain()` 出盒尺寸、再按盒宽算内容区。
2. **`setOffset()` 的偏移从未被 `paintContent()` 使用**（那里只 `translate($insets)`）——
   "标签在内容区居中"这句注释从来没生效过，一直靠"盒宽 = 内容宽"掩盖成
   "贴左上也不算太怪"。加图标后立刻变成"图标压在首字上"。修法：paint 时
   `translate($insets + $child->offset)`（`RenderProxyBox::paintContent()` 本来就是这么写的）。

★ 这两条都有回归判据：**像素级**（紧约束 200 宽下左右留白差 ≤ 3px，抓"算了偏移但没画"）
+ **几何级**（`NavButton` 三种长度标签 offset 相同）。变异验证：把 paint 退回只用
`insets` ⇒ 前一条 FAIL（`ink=[17,86] left=17 right=113`）；把纯图标内边距退回两倍
⇒ 正方形用例 FAIL（`50.0 × 34.0`）。

### 5.1 日期与时刻（2026-10-29）

一个入口、两个可复用件 —— 日期与时刻**不是**同一个类里的两个分支：

| 件 | 值 | 是什么 | 知道自己在浮层里吗 |
|---|---|---|---|
| `CalendarView`（`:59`） | `LocalDate` / `YearMonth` | 7 列月历 + 日/月/年三档视图（点标题循环） | **不知道** |
| `TimeView`（`:46`） | `LocalTime` | 时 / 分（`withSeconds()` 出秒）三列 `LazyColumn` | **不知道** |
| `DatePicker`（`:53`） | `LocalDate` | 触发框 + `overlayPanel` 浮层，面板里就是 `CalendarView` | 是（唯一知道的那个） |
| `DateTimePicker`（`:49`） | `LocalDateTime` | 同上，面板里是 `Row[CalendarView, TimeView]` | 是 |

★ **为什么不合成一个 `DateTimePicker` 带 `type` 分支**：① `time-only` 的表单（"每天 02:00 跑批"）
用不上一张 7×6 月历，合成后只能靠 `type` 写两套布局；② `CalendarView::onSelected(LocalDate)` 的
签名会被迫改成"一天 + 也许还有个时间"；③ 组合是本仓既有纪律（`TreeView` / `TabView` 同款）。
★ **两者唯一的行为分叉**：`DatePicker` 选完**立即收面板**（只有一个交互面），`DateTimePicker`
**不收**（两个面，选一半就收会让另一半得重新打开）。
★ 三者都不读系统时间（`make()` 不要求月份、值为空时退到 `initialMonth()`）—— 一读时钟，
golden 基线就每天不一样。
★ 与 `Select` 同一条裁决：**不写新的渲染盒**。触发框是一个 `Button`（`Default` 变体），
面板是 `PopupPanel` + `OptionPanel`（复用它的跨树订阅）。
★ 面板宽上限默认 320（`Application::PANEL_MAX_WIDTH`，一列选项的口径）；并排两块的选择器
自报更宽（`overlayPanel($f, $maxWidth)`）—— 否则 `Row` 会在 304 可用宽里要 416（2026-10-29 实测崩过）。
★ **滚动条要占位**：`TimeView` 的列盒 = 内容 56 + 条留白 12（`ScrollBarGeometry::THICKNESS + 2×MARGIN`）。
条是**画在视口里**的（`thumbRect()` 按渲染盒宽定位），`->padding()` 只把内容挤窄、挪不动它 ——
第一版就是这么错的：按钮声明 56 宽塞进 51 的视口，条照样切在色块右边缘上。所以留白必须算进**盒宽**，
并排宽度也随之走 `TimeView::widthOf(bool $withSeconds)`（`DateTimePicker::panelMinWidth()` 用它），
不能拿 `COLUMN_WIDTH × 列数` 估 —— 估出来的面板会刚好短一截。

### 5.2 禁用态（`disabled()`，2026-10-29）

**一个声明、四处消费** —— 这是它住 `Modifier` 而不是控件字段的全部理由：

| 消费方 | 位置 | 表现 |
|---|---|---|
| 命中测试 | `RenderBox::hitTest()` / `RenderTable::hitTest()` | 返回**自己**（不是 `null`）⇒ 父容器不再问下一个兄弟；`InputRouter` 见 `isDisabled()` 直接吞掉本次按下 |
| 焦点 | `FocusManager::walk()` | 子树既不进 `order`（Tab 序）也不进 `byId`（可聚焦表）⇒ 正在聚焦的元素被禁用时，`collect()` 末尾那条"focused 不在 byId ⇒ `leave()`"自动移焦 |
| 无障碍 | `SemanticsBuilder` | `enabled = semanticsEnabled() && !disabled`（**子树级**）⇒ UIA `IsEnabled=false`；C++ 侧 `drift_win32.cc` 的 `UIA_IsEnabledPropertyId` 早就读这个字段，缺的一直是 PHP 侧没人写 |
| 绘制 | `RenderBox::setMods()` | 合成 alpha 乘 `RenderBox::DISABLED_ALPHA`（0.38），`pushLayer` 整棵子树一起变淡 —— 零新增绘制代码 |

★ **`hitTest()` 返回自己而不是 `null`**：返回 `null` 等于"这一层不存在"，父容器会继续问下一个兄弟
⇒ 事件落到被盖住的那层，**那就是穿透**。夹具里 `Stack[under, over(禁用)]` 第一版点 `over`
时 `pressed = ["under"]`。注释里"禁用 ≠ 穿透"说的是**容器兜底**（子都不中 ⇒ 容器返回自己），
不是"某一层子被禁用"。

★ **与 `skipFocus()` 的分工**（两者都动 Tab 序，不能互相替代）：`skipFocus()` 只挡 Tab 序、
**仍然点得动**（导航意图，如 TreeView 的行箭头 / AppBar 按钮组）；`disabled()` 连"点得动"一起取消，
并改语义与外观（业务状态，如表单校验未过、无权限、提交中、`min/max` 之外）。

★ **四份 `enabled()` 已收敛（2026-10-29）**。`ToggleBase` / `Slider` / `Segment` /
`SegmentedControl` 上的 `enabled(bool)` 现在只是 `disabled(!$enabled)` 的**别名** ——
没有 `$enabled` 字段，状态只有 `Modifier::$disabled` 一份。随之统一的行为：**不进 Tab 序**
（旧注写的"仍在 Tab 序 —— 与 Win32 一致"是错的，`WS_DISABLED` 的控件 `SetFocus` 直接失败）、
不响应指针、语义 `enabled=false`。像素外观**一个字没变**：收敛当次 golden 三页整页即字节一致
（"收敛 ≠ 改外观"的证据）；本件收尾的 caption 文案改写（"仍在 Tab 序"→"不进 Tab 序"）让三页整页
golden 变化，已重刷基线。

★ **两个可能的灰化来源不能叠加**：框架默认"整棵子树乘 0.38"（通用、零成本），而这四个控件
有更好的表达 —— 标签/轨道换 `ColorToken::Muted`（**灰**而不是**淡**）。两者叠加会二次衰减，
深灰字在浅底上几乎看不见。裁决方式是控件**声明** `paintsDisabledLook(): bool`（与
`paintsBoxChrome()` 逐字同构，声明在控件 → 落实在 `Element::syncBox()` 的 `withoutDim()`
→ 消费在 `RenderBox::setMods()`），声明为真 ⇒ 框架不再叠 alpha。`SegmentedControl` 自己
不画任何禁用外观，但照样声明：禁用要下发给每个 `Segment`，容器再乘一层同样会衰减子树的灰。

★ **`RenderToggle` 不再收 `bool $enabled` 构造参数**（`RenderBoxWidget` 同理不存字段）：
"禁用"的唯一来源是 `Modifier` → `RenderBox::setMods()` 落成 `$this->disabled` →
`isDisabled()` 读口。控件另存一份就是两份真相，而那正是这轮要删掉的东西。

★ **有意边界**：不做 `readOnly`（只读能选中、能复制，与禁用是两种状态）；不禁用"已经开始的交互"
（拖到一半的 `Slider` 会拖到底 —— 框架没有取消进行中手势的原语）；**未**单独做
`ColorToken::disabled` 槽 —— 现有四个控件用 `Muted` 已经够，加槽要连主题/预览/对比度
三处一起调，等真有"禁用色 ≠ 次级文字色"的需求再说。

### 7.1 滚轮**平滑**：`Scrollable::glideByAxis()`（2026-10-29）

`Scrollable` 有**三条**入口，分工是**语义**而不是"快慢"：

| 入口 | 语义 | 谁在用 |
|---|---|---|
| `scrollBy(Δ)` | **立即**改偏移（原语） | `ensureVisible()`、State 内部 |
| `scrollByAxis(轴, Δ)` | **立即**、带轴判定 | 滚动条 thumb 拖动（必须 1:1 跟手） |
| `glideByAxis(轴, Δ)` | **摊成若干帧** | 滚轮（`ScrollInputRouter::scrollAt()`） |

★ **为什么不把 `scrollByAxis()` 直接改成动画**：全仓 **81 处**调用依赖"调完就到"
（21 个测试文件）。thumb 拖动若变成动画就"不跟手"；`ensureVisible()` 若变成动画，
键盘翻页会追不上按键。

★★ **动画 = 把一次大增量拆成多次小增量**，每帧仍交给现成的 `scrollBy()` ——
于是夹取（`maxScroll`）、换窗（`markDirty`）、锚点（`rememberAnchor`）、
提交编辑（`commitIfUserScrolled`）**一条都没被重写**。

节律住在 `ScrollMotion`（`src/Widget/ScrollMotion.php`，三份实现共用一份曲线），
**不住盒上**：盒每帧重造（`scrollOffset` 是 readonly 构造参数）⇒ 住盒上的进度
每帧清零、动画永远走不完。与 `ScrollBarFade` 同源理由。

三处**静默**坑（都有测试钉住）：

1. **收口帧必须交付**：`AnimatedValue::tick()` 收敛时把值精确落到 target，但那一帧
   返回 `false`。若跟着不交付，最后一小段（< `EPSILON` = 0.01px）永不施加 ⇒
   停在 `-47.99…` 而不是 `-48.0`。对 alpha 无感，对**位置**是硬伤。
2. **动画中再滚一格必须累加目标**（不能 `snapTo(当前偏移)`）：对齐会丢掉第一格
   还没走完的距离 ⇒ "快滚时越滚越慢"。单格测试全绿。
3. **到边界要就地收口**：指数衰减保证终会停，但不收口要多转一百多帧
   （实测 81 帧 vs 190 帧）—— 每帧白跑一次 `tickFrame` + 一次全量 paint。

★ **不做 fling（惯性）**：`ScrollEvent` 只有 `delta`，**没有 velocity**，也没有
拖拽滚动；滚轮是离散事件（一格就是一格），触控板惯性由 Win32 折进连续的
`WM_MOUSEHWHEEL`。**没有消费者的物理不是特性。** 将来真接触摸，fling 只是
"给同一个 `AnimatedValue` 一个非零初速 + 换衰减曲线"，`ScrollMotion` 不用改形状。

### 7.1.1 三份实现收成一份：`ScrollLane`（2026-10-31）

`ScrollViewState` / `LazyListState` / `TableState` 是三个 `Scrollable` 实现。
`ScrollMotion`（节律）与 `ScrollBarFade`（淡出）早已共用，但**把两者串起来的那段
管道**仍是三份：偏移字段、懒建、夹下界 0、推给盒、回写夹过的值、到边界收口、
先亮条后推盒。

代价不是行数，是**同一条契约要改三处**：

| 提交 | 同一件契约 | 必须同时改 |
|---|---|---|
| `b7257bf` 滚动不重建 | 回写盒夹过的值 / 首帧不夹 | 三个 State |
| `58305af` 滚轮平滑 | 起飞对齐 / 累加目标 / 到边界收口 | 三个 State |

而漏一处**不报错**：漏回写 ⇒ 真机"拖着条，画面不动"；漏收口 ⇒ 每帧白跑一次全量
paint（实测 81 帧 vs 190 帧）。

`ScrollLane`（`src/Widget/ScrollLane.php`）＝**一根轴**的（偏移 + 动画 + 淡出）：

```text
move(Δ, push)  ──▶ 夹下界 0 ──▶ push 推给盒 ──▶ 回写盒夹过的值      ← 立即
glide(Δ)       ──▶ 起飞对齐（不在跑时）+ 目标 += Δ + 点亮条          ← 滚轮
tick(ts, apply)──▶ 本帧该到哪 ──▶ apply(差值) ──▶ 推不动就 snapTo   ← 每帧
```

★ **只收"每根轴都一样"的那部分**。三个 State 仍各自拥有**策略**，用两个回调交回去：
轴怎么判、改完还要做什么（`rememberAnchor` / `markDirty` / `commitIfUserScrolled`）、
用哪个盒。回调是**单一签名**（`float → float` / `float → void`），不做混签名回调表
——AOT 严格校验实参个数，混签名只有走到那条分支才炸。

★ **组合而不是基类**：`TableState` 要**两根**轴，且两根**共用一份** `ScrollBarFade`
（横条竖条提示的是同一件事，分两套节律会"一根亮一根暗"）⇒ 两个 lane + 注入同一份
fade。基类表达不了"一个 State 有两根轴"。

★ **`set()` 不夹取**：它只服务"播种 / 锚点还原 / build 期回夹"三个入口，三者的值
都由调用方算好（`TableGeometry` 回夹的已是盒夹过的值）。在那里再夹一次是**第二个
真相**；下界 0 只在 `move()`（用户增量）里夹。

★ 闸门：`ScrollLaneTest::testScrollableStatesDoNotOwnTheMachinery()` 扫
`src/Widget/*.php` 里 `implements Scrollable` 的类，**不许**出现 `ScrollMotion`
或直接调 `noteScroll` / `snapTo` / `glideBy`。`ScrollBarFade` 字段**允许**留在
State 上 —— 它是跨轴共享的资源，所有者只能是 State（两类东西的所有权不同，
不是白名单）。

### 7.2 隐式动画：`Opacity` / `AnimatedOpacity`（2026-10-29）

两个新控件，一条纪律：**合成参数不是布局输入**。

| 控件 | 语义 | 谁在用 |
|---|---|---|
| `Opacity`（`src/Widget/Opacity.php`） | **静态**不透明度包装（自己的盒） | 应用直接写 `Opacity::make(0.5, $kid)` |
| `AnimatedOpacity`（`src/Widget/AnimatedOpacity.php`） | 只写**目标值**，控件自己追过去 | `MotionPage` 的"淡出/淡入" |

★ **为什么需要 `Opacity` 控件，而不是 `->opacity()` 修饰符**：修饰写的是**盒上的合成槽**，
一个盒只有一个槽 ⇒ `->opacity(0.5)->opacity(0.5)` 是**后写覆盖先写**（效果 0.5，不是 0.25）。
`Opacity` 每次包装产自己的盒 ⇒ 嵌套时相乘。判据落在命令流上：两层各一条
`DisplayList::OP_LAYER_PUSH`（`AnimatedOpacityTest::testNestedOpacityMultipliesInsteadOfOverwriting`）。

★★ **`tickFrame()` 只写盒的合成槽，不 `setState`、不 `markNeedsLayout`**：

```text
一帧 = tickFrame()（写盒 compose）→ Frame::run()（settle → layout → paint）
```

① 不重建子树；② 合成参数不是布局输入 ⇒ 不重排（`Frame` 的"纯动画帧跳过 layout"
本来就认这个）。代价只是一次 `pushLayer()`。判据是**计数器**：整段动画
`LayoutCountBox::layoutCalls` 一次不涨，`paintCalls` 每帧都涨 —— 画面上"每帧全量重建"
与"只改合成槽"**逐像素一样**，只有计数分得出来。

★★ **`build()` 交的是"当前动画值"，不是目标值**：`Element::update()` 的顺序是
`syncBox()`（`setMods()` 重置合成槽）**先于** `rebuild()` ⇒ 声明目标值的话，
"动画跑到一半时父控件重建"会让画面**瞬间跳到终点**、下一帧再被拉回中间值。
一次肉眼可见的闪烁，**没有任何报错**。

★ **首次挂载不播**：初值 = 目标值。隐式动画的语义是"追目标"，不是"入场效果"；
要淡入就让它先以 `0.0` 挂载再改成目标值。

★ **曲线与收口帧交付下沉到 `AnimatedScalar`**（`src/Widget/AnimatedScalar.php`）：
`ScrollMotion` / `ScrollBarFade` / `AnimatedOpacity` 三处都要"指数趋近 + 值变了才交付"，
各写一份迟早漂成"这个控件比那个慢一点"（不报错，也没人会查）。与
`AnimationController` 的分工是**语义**：本类追目标（无总时长、可随时改向），
那个放定时动画（0..1 + `Curve` + 可反向 + `onCompleted`）。

★ **层合成原语早就存在**（`Canvas::pushLayer()` / `RenderBox::setCompose()` /
`paintComposed()` / `LayerCache` / `OP_LAYER_PUSH`，`ComposeSkipLayoutTest` 钉着
"纯动画帧不重排"）⇒ 这一件的实质是**接线**，不是造层。`AnimationController` 类注释里
"`Opacity` 的前提是层合成语义"那句已按此更正（`Transform` 仍缺，前置是仿射光栅器）。

## 8. 自绘 / 模态 / 进度 / 错误边界

- `CustomPaint`（`:36`，`extends RenderBoxWidget`）+ `CustomPainter`（抽象）：用户画任意 op。
- `Modal`（`:41`）+ `ModalHost`（`:23`）/ `RenderModalHost`：模态层。
- `Progress`（`:36`）+ `ProgressBox` / `Spinner`（`:27`）+ `SpinnerBox` + `SpinnerState`
  （动画驱动：`SpinnerState::tickFrame()` 让 `wantsFrame()` 恒真 ⇒ 自转让，卸载自动停）。
- `ErrorBoundary`（`:39`）+ `ErrorPlaceholder` + `ErrorBoundaryElement` / `RenderErrorBoundary`：
  **节点级兜底**——一个控件坏了不拖垮整页。
