# Drift2 发布就绪度评估 —— 对照成熟 GUI 框架（2026-11-10）

> 基线 `14e3e83`（§75 之后）。**只读评估**：未改一行产品代码、未跑 gate、未做构建。
> 方法：① 代码实测量规模与能力面 ② 112 份文档交叉核对 ③ 对照 7 个成熟 GUI 框架逐维比较

> 不照抄 `DEBT` 与推进计划（本仓已多次证明清单会腐烂：§73/§74 都是把计划推荐判错后改选）。

## 0. 结论先行

**能发布，但不能以「通用 1.0 框架」发布。** 分三档：

| 发布形态 | 判定 | 还差什么 | 门数量 |
|---|---|---|---|
| **A. 内部生产使用** | **✅ 已可用** | 无阻断项 | 0 |
| **B. 技术预览（v0.1-preview，Windows-only，source-available）** | **⚠️ 补 3 项即可** | 根 README + 可复现构建指引、CI、版本与发布流程 | 3 |
| **C. 通用正式版（1.0，可被第三方依赖）** | **❌ 差 7 项** | 再加：第二个平台后端、ABI 握手、增量构建判据、生态/包管理、i18n、稳定 API 承诺、安装器与签名 | 7 |

**一句话**：能力面已经到了「能写真实业务应用」的程度，工程质量明显超过多数个人项目；
卡住对外发布的是**「别人装不起来」**和**「只有 Windows」**，不是控件不够。

**给决策者的三句话**

1. 作为**框架作者自己用**：现在就能交付（`apps/watermark` 是一条真实业务闭环，18 项闸门常态绿）。
2. 作为**给别人看的技术预览**：只需 2–3 周补「文档 → CI → 发版」这条链，不必碰渲染地基。
3. 作为**别人能依赖的 1.0**：至少还要一个平台后端 + ABI 契约 + 生态，是「半年量级」而不是「几周」。

## 1. 评估口径

### 1.1 对比对象

| 框架 | 为什么选它 |
|---|---|
| **Flutter** | 同为「声明式 + 自绘 + 单语言 AOT」，是最近邻；差别只在语言与运行时 |
| **SwiftUI** | 声明式 + 原生控件，对照「自绘 vs 系统控件」的取舍 |
| **Jetpack Compose** | 声明式 + 组合/重组模型，对照状态与重组语义 |
| **WPF / .NET** | Windows 桌面工业级基线，对照「保留模式 + 依赖属性 + XAML」 |
| **Qt 6（Widgets/QML）** | C++ 桌面长期工业基线，对照信号槽、i18n、可访问性 |
| **Electron / Tauri** | Web 技术栈桌面，对照「分发体积与生态换开发速度」 |
| **Avalonia** | .NET 跨平台 XAML，对照「同一套 UI 代码多平台」的可达性 |

### 1.2 评级定义

| 符号 | 含义 |
|---|---|
| **★** | 在本维度**领先**参照组（有可指认的机制优势） |
| **●** | **追平**：机制等价，差距只在成熟度/覆盖面 |
| **○** | **落后**：机制在，但有可指认的天花板或缺口 |
| **×** | **缺失**：该维度没有对应能力 |

★ 评级只对「本维度是否够用」负责，不做总分行情的加权 —— 加权会掩盖「一票否决项」。

本仓已有 `docs/REVIEW-ARCH-DX-2026-11-08.md` 做过架构与 DX 深挖，本稿**不重复它的取证**，

## 4. 五个维度的深入判断

### 4.1 架构：追平，且比多数同规模框架更干净

三层树（Widget / Element / RenderObject）+ 单向下行 + 组合根注入，与 Flutter 同构；
`src/` 在 `src/Platform/Win32/` 之外**零 Win32 类型引用**（`docs/ANALYSIS-ANDROID-PLATFORM-2026-11-09.md`
逐文件重算过）—— 这条比多数「先写死再谈跨平台」的项目强。

扣分项是 `REVIEW-ARCH-DX` 已指出的两处**结构性盲区**，不是设计错误：
`Core` 不在分层 lint 的 `LAYERS` 表里（于是 `Pipeline` 的进程级单例双向免检）、
`Application` 仍是 5 个 Host 接口全实现 + 1928 行的组合根。
（2026-11-10 后订正：第一项已修 —— `Core` 入层表且分层 lint 改为 fail-closed；
此处保留评估当时的快照。）

**对外发布影响**：中。第三方要扩展时会撞上「组合根太大、扩展点标了 `@internal`」。
`BuildContext` 是 `final readonly` 五字段、无 `of()/find()`，`ThemeScope` 已实现父链解析却
不能复用 —— 这是**现成扩展点被锁死**，比「没有扩展点」更可惜。

### 4.2 渲染与性能：落后一档，但有尺子

无 `RelayoutBoundary`、无 damage rect、命中测试每次全树 DFS —— 三项都是主动裁决
（`DESIGN-INCREMENTAL-LAYOUT-VERDICT-2026-11-04.md` 明确「不立项」，触发条件未成立）。
12k 节点实测对拍显示余量 4.8×，所以**今天不疼**。

但它决定**性能天花板**：一旦出现「10 万节点 + 高频动画」的真实场景，没有补丁路径，
只能重做这三项。成熟框架里 Flutter 的 `RelayoutBoundary` + damage rect 是标配。

**对外发布影响**：低（桌面工具类应用很少撞到），**但要在 README 里明说**，
否则用户按 Flutter 的直觉写大列表会失望。

### 4.3 工程纪律：这一栏领先，是整个项目最值钱的资产

- **18 项闸门**；`--fast` / 全量两档；`gate.php --json` 为 CI 预留。
- **变异四律**：每条判据必须能被变异咬红，打空先自查，不造假证据。
- **判据三态**（该响 / 不该响 / 诚实边界 SKIP），`docref --selftest` 双向自检。
- **金样不脆**：注入确定性字体/主题/Scale，不跨后端比像素。
- **T0/T1/T2 分层**：dev 绿 ≠ AOT 绿，这一条把「三绿一炸」的风险显式化了。
- **真机探针**：起窗/尺寸/非白像素/DPI/退出码 5 判据，脚本自关窗。

对照：这六条里任何一条，在多数开源 GUI 框架的首发版本里都找不到。

**对外发布影响**：**正**。它是「值得被看」的理由 —— 但前提是别人能跑起来。
现在这些能力全锁在本机，`gate.php` 没有 CI 消费方。

### 4.4 无障碍：单平台满配，跨平台为零

Windows 侧做得相当完整：UIA provider、Fragment 树导航、结构变化事件、焦点变化事件，
并且**判据走客户端订阅**（`DESIGN-UIA-EVENT-PROBE-2026-11-07.md` §70）——
这是「不是自己说自己无障碍，而是外部观察者能看见」的做法，成熟框架里也算讲究。

但 UIA 是 Windows 专有。一旦上第二个平台，无障碍要**整套重做**（macOS AX / Android
AccessibilityNodeInfo / Linux AT-SPI）。这也解释了为什么「跨平台」是 1.0 的一票否决项：
无障碍不是「加个适配器」，是每个平台一套语义树投影。

### 4.5 分发链：最大短板，也是三档判定的分水岭

| 环节 | 现状 | 后果 |
|---|---|---|
| 根 README | **无** | clone 下来不知道从哪开始 |
| 一键 setup | **无**（`doctor.php` 只检查不安装） | 新人门槛高 |
| 构建依赖 | MSVC **特定版本** + Windows SDK **特定版本** + `PHPX_HOME` + `tpc` 源码树 + Skia 预编译包（已 vendored 在 `cpp/skia/`） | 环境一错就是 LNK2019 / 静默行为不对 |
| CI | **无** | 「本机能跑」无法成为对外承诺 |
| 版本 | `project.yml` 里 `0.1.0`，无 CHANGELOG | 无法说清「这次改了什么、会不会破坏」 |
| 安装器 / 签名 / 自动更新 | **无** | 用户拿到的是个裸 `.exe` |
| 崩溃上报 | 有本地 `Errors.log` + `rva2sym` 符号化，**无远程收集** | 用户崩了你看不到 |

**结论**：A/B 两档的差别几乎全在这一列。补 README + CI + 版本三件事，
就能从「作者的私仓」变成「可被别人运行的技术预览」。

## 5. 阻断级缺口（对外发布前必须闭合）

> 判据沿用本仓 `DEBT §40.1`：① 有消费者 ② 错了是静默的 ③ 决定能不能交付。
> 这一节每条都**决定「别人能不能用起来」**，属 ③。

| # | 缺口 | 证据 | 为什么是阻断 | 成本 |
|---|---|---|---|---|
| **B1** | 无根 README / 无构建指引 | 根目录无 `README*`；`doctor.php` 只报告不修复 | 别人 clone 后无从下手；这是所有其它问题的前置 | S |
| **B2** | 无 CI | 无 `.github/`；`gate.php --json` 无消费方 | 无法对外承诺「main 分支是绿的」；发版靠人手跑 | S |
| **B3** | 无版本/变更日志/发布流程 | 无 `CHANGELOG` / `VERSION` / tag 规范 | 用户无法判断「升级会不会坏」；出问题无法定位版本 | S |
| **B4** | 壳 ↔ PHP ABI 无握手 | `cpp-src/drift_win32.stub.php` 自承「改一边必须同步另一边…**静默失败**」 | 错配表现为「行为不对」而非报错 —— 这是最贵的故障形态 | S |
| **B5** | AOT 增量构建 stale 无判据 | `drift-build.php` 的 `--full` 靠「怀疑」触发；无「类集合变化」失效条件 | 出包时可能 `0xC0000005`，且只在发版暴露一次 | S |
| **B6** | 只有一个平台后端 | `src/Platform/` 仅 `Win32/` | 1.0 的「通用」定义不成立；无障碍也要整套重做 | L |
| **B7** | 无生态与组件分发 | 无组件注册表；`composer.json` 只声明 `php>=8.4` | 「框架」与「一个应用底座」的分野就在这里 | L |

**B1–B5 是 S 级（各 1–3 天）**，B6/B7 是 L 级（月/季度）。
⇒ **技术预览只需 B1–B3；正式 1.0 需要全部 7 项。**

## 6. 非阻断缺口（发布后可补，不影响首批用户）

| 类别 | 具体项 | 判据 |
|---|---|---|
| 结构 | `Core` 未入层表（2026-11-10 已修）；`Application` 上帝类；`didUpdateWidget()` 缺失（父重建换 `select` 闭包是静默错配）；订阅/任务生命周期兜底不对称 | `docs/REVIEW-ARCH-DX-2026-11-08.md` §1.1 / §2.1–2.3 |
| 可诊断 | 静默失败未进 `Errors`；错误到 UI 一律压成 string（分不清 404/鉴权/超时）；进度是 Future 旁路 | 同上 §1.2 / §2.4–2.5 |
| API | 无 `Future::timeout`；`object` 槽位模式复制 4 处未抽象；`BuildContext` 扩展点锁死 | 同上 §2.6 / §3 |
| DX | 无统一 CLI / 脚手架；无 DevTools（组件树检查器）；热更状态全丢 | 同上 §3 / §4 |
| 国际化 | 无 i18n | 若目标用户非中文母语，**这项会升级为阻断** |

## 7. 三档发布路径

### A. 内部生产（现在）

**条件**：无。
**使用边界**：Windows only；单团队；接受「改一行 PHP 有时要 T2 3 分钟」。
**已具备的交付证明**：`apps/watermark` 是完整业务闭环（选图 → OSS 直传 → 建任务 → 轮询 → 出图），
18 项闸门常态绿，AOT 产物 13.9 MB 有真机 5 判据。

### B. 技术预览 v0.1-preview（补 B1–B3）

1. `README.md`：一句话定位 + 30 秒截图 + 「五分钟跑起来」（`doctor` → 装依赖 → `drift-build hello` → `probe-window`）。
2. 明确标注 **Windows-only / alpha / API 不保证兼容**。
3. CI 接 `gate.php --fast --json`（PR 必跑；nightly 跑全量）。
4. `CHANGELOG.md` + tag 规范（`v0.1.0-preview.N`）。
5. 把 `.workbuddy-ai/memory/` 里被引为「项目级真值」的结论**沉淀进 `docs/`**（该目录不进 git，
   对任何 clone / 第二开发者 / CI 都是断链）。

**验收判据**：一台干净 Windows 机器，按 README 从零到 `probe-window hello` 5/5，**不超过 30 分钟**。

### C. 通用正式版 1.0（再加 B4–B7）

1. ABI `abiVersion + schemaHash`，错配**响亮失败**。
2. 增量构建把「类集合变化」纳入失效条件（或默认 `--full`，增量 opt-in）。
3. 第二个平台后端（macOS 或 Linux）—— 这条会强制把「无障碍投影」「多显示器」「字体栈」都泛化。
4. 组件分发方案（哪怕只是「约定目录 + composer 源」）。
5. i18n 框架（locale 解析 + 格式化 + 复数）。
6. 安装器 / 代码签名 / 自动更新 / 崩溃上报。
7. 稳定 API 承诺：`@api` 面从 991 行清单升级为带签名与示例的参考文档。

**验收判据**：一个外部开发者在**没有作者指导**的情况下，写出一个带网络请求与后台任务的应用，
并跑通自己的 CI —— 全程不需要问一句「为什么我这里是红的」。

## 8. 诚实边界

- 全程只读：未跑 `gate`、未做构建、未验证任何修复方案；§7 的成本是静态判断。
