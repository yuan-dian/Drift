# 10 无障碍与语义

> 本册回答：**语义树从哪来、怎么同时喂"推"和"拉"两种平台模型、三档推送怎么降级。**

---

## 1. 语义是节点的一部分，不是第二棵树

```php
// 普通类（同 01 §3.1：Native 节点装不下孩子）
abstract class Node
{
    public int    $role  = SemanticsRole::NONE;   // 0 = 不参与语义
    public string $label = '';
    public int    $state = 0;                     // 位域：选中/禁用/展开/焦点
    public int    $value = 0;                     // 数值控件用
}
```

★ **角色在"构造/设值处"赋值**，不靠虚方法覆写。
理由：Native 类的虚方法在静态类型已知时会被去虚化，**覆写会被静默吞掉**（L3）。
一个"看起来声明了、实际没生效"的语义角色，等于无障碍完全失效且无从发现。

★ **`role == NONE` 的节点不进语义树**：纯布局容器（`Row`/`Column`/`Padding`）默认不进。
否则读屏软件会念一堆"分组、分组、分组"。

---

## 2. 扁平快照：同时满足推和拉

```php
// 每帧末（或有语义脏位时）生成
$flat = [
  // [id, parentId, role, label, state, x, y, w, h, childrenCount]
  [0, -1, Role::WINDOW, 'Drift', 0, 0, 0, 800, 600, 3],
  [1,  0, Role::BUTTON, '保存', 0, 20, 20, 80, 32, 0],
  ...
];
```

| 平台模型 | 怎么用这个数组 |
|---|---|
| **推**（Win32 UIA） | 我们主动 push 快照 ⇒ 平台侧缓存 ⇒ OS 回调来查时按索引回答 |
| **拉**（macOS NSAccessibility） | 平台侧持有快照 ⇒ OS 问"节点 X 的孩子"⇒ 按 parent 索引查 |
| **拉 + 跨进程**（Linux AT-SPI） | 同上，但要 D-Bus + 独立事件循环（首版不做） |

★ **关键洞察**：两种模型的差异在**谁发起**，不在**数据结构**。
一个前序扁平的快照数组两边都能吃——**这是本方案不加新端口、不加第二棵树的原因**。

★ **`parentId` 必须是索引而不是指针**：跨语言边界只能传 POD（`int`）。
这也是为什么扁平数组里存的是 `parentId`（索引）而不是对象引用。

## 3. 三档推送

| 档 | 触发 | 数据量 | 用在哪 |
|---|---|---|---|
| **full** | 树结构变化 / 首次 | 全量快照 | 启动、切换页面 |
| **delta** | 少量节点属性变 | `[id, 变更字段位, 新值]` | 打字、勾选 |
| **coalesce** | 高频变（滚动、动画） | 只推最终状态 + 合并窗口 200ms | 滚动列表 |

★ **降档是自动的，但可观测**：`FrameStats` 里记 `语义 delta(12)` / `coalesce(3)`。
超预算时自动降档，且**降档原因进日志**——否则"为什么读屏延迟"无从查。

---

## 4. 事件三件套

| 事件 | 何时发 | 平台对应 |
|---|---|---|
| **结构变化** | 节点增删/换序（快照条数变） | UIA `StructureChanged`（**专用函数**，不是普通事件） |
| **焦点变化** | `focused` 节点索引变 | UIA `FocusChanged` / macOS `AXFocusedUIElementChanged` |
| **属性变化** | label/state/value 变 | UIA `PropertyChanged` / macOS `AXValueChanged` |

★ **结构变化必须用专用 API**：Drift 实测——用通用的 `UiaRaiseAutomationEvent` 发结构变化，
**探针 hits = 0**（事件发了，读屏不认）。必须用 `UiaRaiseStructureChangedEvent`。
这是"看起来发了、实际没生效"的典型，只能靠探针抓。

★ **焦点事件不能靠轮询**：必须比较"上一帧焦点节点索引"与"本帧"，
变化才发。每帧都发会让读屏软件疯狂念。

## 5. 平台侧纪律

| 纪律 | 理由 |
|---|---|
| **不得回调进 PHP** | 跨语言回调会破坏"一帧一次跨界"；且 PHP 侧可能在布局中，重入即崩 |
| **必须保留快照** | 拉模型要它；推模型也要它算 diff |
| **provider 按索引持有** | 不持对象引用，避免生命周期纠缠 |
| **接口消歧用 adapter** | UIA 的 `IRawElementProviderFragmentRoot` 与 `Simple` 都继承 `IUnknown`，同一对象实现两者会有二义性 ⇒ 主类 + adapter，`QueryInterface` 分派 |

★ 最后一条是 Drift 用真机撞出来的：两个接口都继承 `IUnknown`，
`QueryInterface` 返回哪个 `this` 决定引用计数怎么算。**用 adapter 把 `IUnknown` 委托给主对象**是唯一干净的解法。

---

## 6. 首版范围

| 做 | 不做 |
|---|---|
| 窗口 / 按钮 / 文本 / 输入框 / 勾选 / 列表项 的角色与标签 | 表格网格语义（`GridItem` 行列索引） |
| 焦点 / 结构 / 属性三类事件 | 文本范围语义（`ITextProvider`） |
| 扁平快照 + 三档推送 | AT-SPI（Linux） |
| 真机探针（枚举 + 遍历 + 事件计数） | 读屏软件兼容性矩阵 |

★ **`ITextProvider` 不做**：它要求暴露"文本范围 → 屏幕矩形"的完整映射，
是无障碍里最贵的一块（Flutter 也长期补这个坑）。首版输入框只暴露"值 + 标签"。

---

## 7. 语义也是测试与 AI 的入口

语义树不只给读屏用。它是**唯一一份"人类可读的界面结构"**：

```php
$tree = $app->semanticsSnapshot();     // 扁平数组
// 测试：断言"有一个按钮叫保存"
// agent：找到 label='保存' 的节点 id ⇒ dispatch(CLICK, ['id' => 7])
// 诊断：--dump-semantics 导出 JSON
```

★ **一条通道的第三个收益**（前两个是测试与撤销）：
**语义快照 + 命令 ID = 界面对程序完全可操作**，不需要截图理解（MoUI 的"为 Agent 设计"）。
这不是额外功能，是前面设计决策的自然结果。
