# 03 树与身份

> 本册回答：**节点长什么样、身份怎么定、结构怎么改、动态列表怎么办。**

---

## 1. 节点类型（首版 24 种）

节点是**机制**，不是**控件**。控件 = 节点 + 样式 + 命令的组合，用工厂函数拼，不新增类。

| 组 | kind | 说明 |
|---|---|---|
| **结构 6** | `Fragment` `Slot` `If` `Repeater` `Overlay` `Portal` | 不画东西，只组织孩子 |
| **布局 6** | `Row` `Column` `Stack` `Grid` `Dock` `Scroll` | 约束分配 |
| **绘制 4** | `Box` `Text` `Image` `CustomPaint` | 产出 op |
| **交互 6** | `Button` `TextField` `Toggle` `Slider` `Select` `ScrollBar` | 声明命令 + 焦点 |
| **边界 2** | `LayoutBoundary` `RepaintBoundary` | 缓存与隔离 |

★ **`Padding` / `Align` 是字段，不是节点**（v7 第一版把它们算进 26 种，是错的）。
`Node` 基类带 `padL/padT/padR/padB` 与 `alignX/alignY` 六个 `float`，`measure`/`place` 统一处理（见 [04](04-布局.md) §3）。

**判据（三条都要满足才是字段）**：纯修饰 · 不改变孩子列表 · 不产生 op。
- 10 层修饰若各占一个节点 ⇒ 10 次 `measure` 穿透 + 10 个 `depth` + 10 条语义路径，**全是纯开销**。
- 反例 1：`RepaintBoundary` 必须是节点，因为它要存自己的 op 段。
- 反例 2：`If` 必须是节点，因为它要**占位**（见下条）。

★ **`If` 是节点而不是 PHP `if`**：因为"条件分支"会改变**位置**，进而改变身份。
把它显式化成节点，才能在 `false` 时**保留位置占位**（否则兄弟节点的位置会漂移，身份全乱）。

★ **`RepaintBoundary` 是节点而不是 flag**：它要参与结构配对（有自己的孩子列表）。
作为 flag 的话，子树 op 段的边界就没地方存了。

## 2. 孩子列表：唯一容器

```php
// 就一个 packed array，没有容器类
public array $children = [];     // array<int, Node>
```

★ **为什么不是 Std 容器**：Std 容器不能嵌入属性，赋给属性会被 `toArray()` **拷贝成 PHP 数组**
（design-v6 探针实测）⇒ "用 StdVector 做节点的长期子节点表"这条路根本不存在。
**packed array 是唯一能长期持有的形态。**

★ **遍历时必须恢复类型**：`$this->children[$i]` 读出来是 `php::Var`，
直接 `->measure()` 会退化成动态调用。正确写法：

```php
foreach ($this->children as $c) {
    $child = $c->toObject(Node::class);   // 一次 is-a 检查 + 定型
    $child->measure($sub);
}
```

★ 这一次 `toObject()` 是**每帧每节点一次**，是热路径上唯一允许的"类型恢复"（V3 待实测成本）。

★ **不要用 `ArrayAccess` 包一层**：多一次方法调用，换不来任何好处；且它会诱使人在 `layout` 里
`$node->children[$i]->setX()`，而那是间接修改（TypePHP 不支持）。

## 3. 结构变更的唯一入口

```php
// 容器节点上唯一能改孩子的方法
public function children(array $next): void;
```

内部算法（`Reconciler`，O(n)）：

```
输入：old[0..m), new[0..n)  +  每个 new 项的 (kind, key)

① 建索引：若 new 里存在非空 key ⇒ map{ key → 下标 }；否则走位置匹配
② 逐个配对 new[i]：
     key 非空 且 map 命中 且 kind 相同  ⇒ 复用（move）
     key 非空 且 未命中                ⇒ 新建
     key 为空 且 i < m 且 kind 相同     ⇒ 复用（位置匹配）
     否则                              ⇒ 新建
③ old 里未被复用的 ⇒ destroy（显式 close）
④ 更新 parentId / depth / 顺序；打 DIRTY_STRUCT | DIRTY_LAYOUT
```

### 3.1 身份规则（只有两条）

| 情况 | 身份 |
|---|---|
| 有 `key` | `key` 决定身份（同 key 必复用，位置可变） |
| 无 `key` | **位置**决定身份（第 i 个孩子 ↔ 第 i 个孩子） |

★ **没有 `runtimeType` 比较**。`get_class()` 能用，但它在热路径上是一次动态查找，
且会让身份判断依赖类型字符串（L3）。
`kind` 是显式 `int` 字段，比较它即可——这也让"型别"可被日志打印、可被测试断言。

★ **没有 `equals`**。身份由位置/key 决定，内容变化不影响身份。
这就是 I2 的直接收益：**改内容 ≠ 改结构**，两者完全解耦。

### 3.2 key 什么时候必须给

| 场景 | 必须给 key？ | 不给的后果 |
|---|---|---|
| 静态孩子（固定几个） | 不必 | 无 |
| 列表（`Repeater` 产出） | **必须** | 删除中间一项 ⇒ 后面所有项的身份漂移 ⇒ 输入框内容串位 |
| 条件分支（`If`） | 不必（`If` 自己占位） | 无 |
| 可排序 / 可拖拽 | **必须** | 拖拽后状态错位 |

★ "输入框内容串位"是这个 bug 的**经典症状**，也是 Flutter/Vue/React 共同的坑。
我们的差异是：**`Repeater` 强制要求 key**（编译期 lint：`Repeater` 的子项若无 key 直接报错），
而不是靠文档提醒。

## 4. 动态列表：数据驱动 + 逃生舱

### 4.1 为什么不用 `Each(items, fn($item) => Widget)`

闭包作为**参数**是允许的（V4），但作为**每项构建器**有三个问题：
1. 每帧每项调用一次闭包 ⇒ 动态调用开销（且无法内联）；
2. 闭包捕获的变量不受订阅表管理 ⇒ 漏订阅无从检查；
3. 不可序列化 ⇒ 列表结构无法被测试/agent 重建。

### 4.2 主路径：`CellSpec`（数据）

```php
final class CellSpec
{
    public string $key    = '';     // ★ 必填
    public string $title  = '';
    public string $sub    = '';
    public int    $icon   = 0;      // 图标 id（资源表索引）
    public int    $badge  = 0;      // 0 = 无
    public int    $command = 0;     // 点击时派发的命令
    public int    $payload = 0;     // 命令参数（列表场景几乎总是"某条记录的 id"）
    public bool   $enabled = true;
}

$list->cells($specs);   // 列表节点持有 CellSpec[]，自己生成 Text/Box 子节点
```

★ `CellSpec` 是**纯数据**：可序列化、可 diff（`key` 对得上就复用子节点）、可被测试直接断言。

### 4.3 逃生舱：`CellBuilder` 对象（不是闭包）

```php
interface CellBuilder { public function build(Node $host, int $index, mixed $row): Node; }
```

注册在 `ListKind` 上（`kind => builder` 表，冷路径）。
★ 只用于"格子长得完全不像标准样式"的少数场景；**主路径永远是 `CellSpec`**。

## 5. 后端资源挂接

节点若持有 C++ 侧资源（字体、纹理、图层缓存），必须实现：

```php
public function close(): void;    // 释放后端资源，幂等
```

★ **destroy 时显式调用**，不靠析构：TypePHP 的 tracing GC 只在两个安全点回收，
`unset` 不保证时机。靠析构释放句柄的症状是**帧间泄漏**——每次重建列表漏一点，几小时后爆。
（Drift 的 `adoptBoxes()` 就是这件事的前身：新盒子必须被登记，否则后端永远不知道它存在。）

## 6. 树的规模上限与纪律

| 指标 | 首版目标 | 超了怎么办 |
|---|---|---|
| 节点总数 | 5,000 | 用 `Repeater` 虚拟化（只建视口内） |
| 单帧重建节点数 | 200 | 检查是不是 `DIRTY_STRUCT` 泛滥（通常是 `If` 用错或 key 缺失） |
| 树深 | 32 | 超过时 `depth` 桶排序退化为 `sort`（仍然正确，只是慢） |
| 命令数/秒 | 200 | 超过说明把动画写成了命令（应该用帧回调） |

★ **这些数字是预算，不是限制**。超过不报错，但 `FrameStats` 会标红——**让它可见，而不是让它崩**。

## 7. `Overlay`：栈的语义（v6 补齐）

`Overlay` 在 v7 第一版只是一个节点名。它承载菜单、对话框、Toast、拖放会话四样东西，
所以栈的语义必须定死，否则每样东西各写一套。

### 7.1 形状

```
每个 Surface 根下有一个 Overlay 栈
entry = 一个独立子树 + 锚点 + 关闭策略
```

★ **挂 Surface 根，不挂页面**。这一条决定了"切页时浮层怎么办"：
锚点节点随页面卸载 ⇒ 浮层自动关闭（靠 anchor 绑定，不需要路由层配合）。

### 7.2 四条判断

| # | 判断 | 说明 |
|---|---|---|
| 1 | **锚点 + 首选方向 + 四方向翻转 + 夹取** | **不做通用自动避让**——避让结果依赖精确尺寸，不可 golden |
| 2 | **`barrier` 与 `scrim` 是两个参数** | 合成一个 ⇒ 菜单被迫变暗（只想挡点击）或 Toast 挡住点击 |
| 3 | **关闭四源**：点外面 / `Esc` / **锚点节点卸载** / 显式关闭 | 第 3 条最常漏 ⇒ 切页后浮层飘在那里 |
| 4 | **窗口失焦不关闭浮层** | 点别的应用不算"点外面" |

★ 第 1 条的"不做自动避让"是刻意的：自动避让会让同一个浮层在不同 DPI / 不同文案下位置不同，
golden 无法稳定。**方向翻转 + 夹取**覆盖 95% 的真实场景，且结果可复现。

### 7.3 与 z 序的关系

★ Overlay 栈的顺序 = z 序（[04](04-布局.md) §10.10：**不引入 `zIndex`**）。
栈内后进先出，没有"置顶" API——需要置顶就重新 push。

### 7.4 菜单在 Overlay 上的三个额外约束

| 约束 | 理由 |
|---|---|
| 菜单是**数据**不是 View 树 | 原生 `HMENU` / `NSMenu` 没有 View 概念（[19](19-控件API语法.md) §4） |
| `custom` 项必须显式声明 | 让"这个菜单能不能给托盘用"可判定 |
| 锚点来自修饰器，不由调用方算 | 调用方拿不到几何 |
