# 07 输入与焦点

> 本册回答：**事件在哪归一化、手势怎么消歧、焦点怎么走、那些"paint 期画的东西怎么点"怎么办。**

---

## 1. 归一化：唯一翻译点

```
OS 消息（MSG / NSEvent / XEvent）
   │   ← ★ 只有壳层碰这些常量
   ▼
Drift 事件（PointerEvent / KeyEvent / ScrollEvent / ThemeChanged / DpiChanged / TextCommit）
   │   ← 框架只认这些
   ▼
dispatch(命令 ID, 参数)
```

★ **壳层是唯一的翻译点**，框架内不得出现任何平台常量、位运算、键码。

### 1.1 事件类型（首版 6 种）

| 事件 | 字段 | 备注 |
|---|---|---|
| `PointerEvent` | `x y button phase device` | `phase ∈ {Down, Move, Up, Leave}`；`device ∈ {Mouse, Touch, Pen}` |
| `ScrollEvent` | `x y dx dy` | `dy > 0` = 内容上移（框架语义，与平台无关） |
| `KeyEvent` | `code mods phase` | `phase ∈ {Down, Up, Repeat}` |
| `TextCommit` | `text` | IME 提交串 / 普通字符输入 |
| `ThemeChanged` | `dark` | 系统深色模式 |
| `DpiChanged` | `scale` | ★ 触发**全树重建**（字号/间距 token 都变），不是 relayout |

★ **`device` 现在就要有**（哪怕首版只用鼠标）：触摸端一旦上线，
"hover 在触摸上不该存在""右键在触摸上不该有"这类 bug 会成片出现。加一个带默认值的字段几乎免费。

★ **滚轮方向约定在壳层完成，且只在一个地方**（Drift 裁决）：
回拉（朝自己）⇒ 内容上移看到下面；前推 ⇒ 看到上面。框架语义永远 `dy > 0 = 内容上移`。
**翻译只此一处**——两处就会互相抵消。

## 2. 命中测试

```
hitTest(node, px, py) → 最内层命中的节点
  ① 先看是否在自己的裁剪矩形内（不在 ⇒ 早退，不测孩子）
  ② 孩子**从后往前**（绘制顺序的逆序 = 层叠顺序）
  ③ 自己在孩子之上（如按钮背景）时，孩子没命中就命中自己
```

★ **逆序 + 裁剪早退**是两条必须：正序会让底层吃掉点击；不裁剪会让"滚出视口的项"仍能点中。

★ **paint 期画的东西没有节点 ⇒ 命中测试看不见**。这是 Drift 的滚动条 thumb 教训：
thumb 是 `paint` 里画的，不是子节点，`hitTest` 完全不知道它存在。
**解法：`dispatchPointer` 里先于内容做"虚拟命中"**：

```php
// 先问"有没有不占节点的可交互区域"（thumb / 分割条 / resize 边）
if ($scrollbar->hitThumb($px, $py)) { $scrollbar->beginDrag(); return; }
if ($splitter->hit($px, $py))       { $splitter->beginDrag(); return; }
// 再走正常命中
```

★ **纪律**：任何"画出来但不占节点"的交互区，必须在 `dispatchPointer` 里**显式登记**，
并且几何只有一处来源（`thumbRect()` 同时给 paint 和命中用）。**别在两处各算一遍**。

## 3. 手势消歧：Arena

```php
final class GestureArena
{
    public const DRAG_THRESHOLD = 6.0;   // 逻辑像素，单一出处
    private array $members = [];         // 声明者，按加入顺序
}
```

规则四条：

| 规则 | 理由 |
|---|---|
| 只有当命中链上存在 `Draggable` 声明者时才开 arena | 普通点击不需要竞争，开了反而多一跳 |
| **`Tap` 必须第一个加入** | 默认胜者是 `members[0]`；Tap 在后会被 Drag 抢走（Drift 实测） |
| `Drag` 必须过 `DRAG_THRESHOLD` 才 `claim()` | 否则轻微抖动就被判成拖拽，点击全失效 |
| `Up` 时无人 claim ⇒ `members[0]` 胜 | 保底，避免"点了没反应" |

★ **阈值只有一个常量**：`DRAG_THRESHOLD` 在两处出现（判定与测试）就是 bug 温床。

## 4. 焦点

```php
// 普通类：它是节点的字段（Native 对象不能进普通对象属性）
final class FocusNode
{
    public int    $id = 0;
    public int    $order = 0;        // Tab 顺序（建树时按结构顺序分配）
    public bool   $focusable = true;
    public bool   $focused = false;
}
```

| 行为 | 规则 |
|---|---|
| 点击可聚焦节点 | 焦点转移（先 blur 旧的，再 focus 新的） |
| `Tab` / `Shift+Tab` | 按 `order` 环状遍历，跳过 `focusable=false` |
| 焦点丢失（节点销毁） | 焦点交给最近的祖先可聚焦节点；没有则清空 |
| 窗口失活 | 保留焦点但 `focused=false`（回来后恢复） |
| 焦点环 | 只在**键盘导航**时显示；鼠标点击不显示（平台惯例） |

★ **`focused` 必须进语义树**：无障碍的焦点变化事件靠它（§10）。

★ **焦点与命令的关系**：命令派发顺序是「应用级 → 焦点链 → 命中链」。
`Ctrl+S` 属于应用级，`Enter` 属于焦点链，`Delete` 属于命中链——**顺序固定且可观测**。

---

### 4.1 焦点 = 路径 + `FocusScope`

v7 第一版的模型是"每节点一个 `$focused` bool"。它有两个问题：

| 问题 | 症状 |
|---|---|
| 每个节点都维护一个 bool | 焦点变化要"先清旧、再置新"，中间状态可被观察到 |
| 没有"作用域"概念 | 弹层 / 菜单打开后，`Tab` 会走到背后的页面上 |

**改成路径 + 作用域**：

```php
final class FocusScope
{
    public int $focusedId = 0;      // ★ 每个 scope 只存一个焦点 id
    public int $parentId  = 0;
}
```

| 规则 | 说明 |
|---|---|
| 焦点是**一条从根到叶的路径** | `root > dialog > field`；不在路径上的节点就是未聚焦 |
| **每个 scope 存一个焦点 id**，不是每节点一个 bool | 切焦点 = 改一个 int，不需要遍历清位 |
| `Tab` 在**当前 scope 内按树序 DFS** | 不跨 scope ⇒ 弹层里的 `Tab` 不会跑到背后页面 |
| scope 卸载 ⇒ 焦点回到父 scope 上次的 id | 关弹层自动回到"打开它的那个按钮" |
| **焦点不用 `Cell`** | 否则每次 `Tab` 触发一次重建（焦点是渲染态，不是共享态） |

★ 落地为两个修饰器，**不新增第九种原语**：`->focusable()` / `->focusScope()`。

★ **菜单键盘导航是 `FocusScope` 的第一个真实用户**（上下走树序、左右压/弹栈、打开 autofocus、关闭恢复）——
这是这个机制存在的理由，不是"以后可能有用"。

★ 焦点**必须**进语义树（[10](10-无障碍与语义.md)）：UIA / NSAccessibility 的焦点变化事件靠它。
但焦点**路径**不进语义快照——快照里只有"这个节点是否聚焦"这一位。

## 5. 键盘与快捷键

```php
final class KeyChord
{
    public int $code = 0;        // 归一化后的键码（不是 VK_ / keyCode）
    public int $mods = 0;        // Ctrl / Shift / Alt / Meta 位域
}
```

★ **键码必须归一化**：`VK_*`（Win32）、`keyCode`（macOS）、`keysym`（X11）三套编码。
壳层映射到 Drift 的键码表（约 120 个常用键 + 字母数字直接用 ASCII）。

★ **`Meta` 键的平台语义不同**（Win = Win 键，mac = Command）。
**不做"自动把 Ctrl 映射成 Command"**——事件层只报"按了什么"（物理位，四位各一位）。
（Qt 在这里做过**事件级**自动映射，结果是"同一个快捷键在两个平台行为不同"，更难查。）

★ 但框架提供一个**声明期**的归一常量 `Modifier::Primary`（Win32/Linux ⇒ Ctrl，macOS ⇒ Cmd），
解析发生在 `KeyChord` 匹配处，一处。**归一"声明"，不归一"事件"**（见 [08](08-平台与能力矩阵.md) §9.2）。

## 6. 文本输入的完整链路

```
按键 → KeyEvent(Down)
  ↓
IME 拦截？（组字中）
  ├─ 是 → 平台处理组字 → 提交时发 TextCommit(串)  → EditState 插入
  └─ 否 → 可打印字符 → TextCommit(单字符)        → EditState 插入
  ↓
EditState 变 → DIRTY_LAYOUT | DIRTY_PAINT | DIRTY_SEMANTICS
  ↓
下一帧：布局重排该行 → 绘制 → 上报新的 caret 矩形给平台
```

★ **IME 只走提交串**（§06）：组字过程不经过框架，框架只收到"最终这几个字"。
这让三平台的 IME 代码路径**完全相同**。

## 7. 悬停 / 离开 / 光标

| 事件 | 触发 | 动作 |
|---|---|---|
| `Move` | 指针移动 | 命中变化 ⇒ 旧节点 `Leave` + 新节点 `Hover`；更新光标形状 |
| `Leave` | 指针离开窗口 | 全链 `Leave`；取消进行中的拖拽（**诚实边界**：拖出窗口即取消，不卡死） |
| `Up` | 抬起 | 结束拖拽 / 派发点击命令 |

★ **`Leave` 取消拖拽**而不是"捕获鼠标继续拖"：Win32 的 `SetCapture` 能做，
但拖出窗口后松手的事件流在各平台不一致。**取消是确定的行为，捕获是不确定的行为。**

★ **光标形状**：`CursorShape` 是 int 枚举，壳层映射到平台光标。
**不要在框架里创建光标资源**——那是平台能力。

## 8. 输入侧的失败消息

```
输入派发失败：命令 1001（SAVE）没有任何处理者。

  派发路径：应用级（无）→ 焦点链（焦点在 TextField#12，未声明）→ 命中链（Button#7，未声明）

修法一：在目标节点上声明命令：$node->command = Command::SAVE;
修法二：在 App::command() 里处理它（应用级命令，快捷键也能触发）。
```

★ **打印派发路径**，不是只打印"未处理"。用户需要知道"我以为它会走这条链"为什么没走。
