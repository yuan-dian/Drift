## 2. 判据表：约束 → 被否掉的候选 → 采用的形态

格式抄 v6 `13` §10。每条三列：**约束是什么 / 因此否掉了什么 / 因此采用了什么**。

### 2.1 类型退化

| 约束 | 否掉了 | 采用了 |
|---|---|---|
| `?Obj` / `A\|B` / `mixed` / `callable` 退化成 `php::Var`（动态分派） | 用 `?RenderBox` 做**热路径**字段 | `RenderBox $child` + `bool $hasChild`（`RenderProxyBox` 的形态） |
| 同上 | `?float $virtualExtent` 做**每帧读**的字段 | `float $virtualExtent = \NAN` 哨兵（`RenderScrollView` 的形态；`02` §3.2 的 `Modifier::$width` 同法） |
| 同上 | `Cell::$owner` 用 `?State` | `State $owner` + `bool $bound`（`03` §3.2） |
| `?int` / `?string` **推断**不退化（**未实测**，v6 V-1） | 依赖它做设计 | 一律不用（用 `NAN` / `-1` 哨兵） |

★ 第三行是 `03` 的核心改动之一，**它的依据就是这张表的第一行**。
若 M0-2 实测发现 `?Obj` **不**退化（即 tpc 能静态分派），那 `Cell::$owner` 的改动
就没有收益 —— 但**仍然要做**（因为 `?` 会强迫每个读点写 `?->`，那是**人因**问题，
不是性能问题）。⇒ 这条要写清：**M0-2 只影响"性能理由"，不影响"人因理由"。**

> **2026-10-21 M0-2 已跑完（结论在 `docs/AOT-CONSTRAINTS.md` §2.2），上面这段要改口**：
> 实测是"**形参层退化、字段层不退化**"—— `?Obj` 在形参/返回值上确实变成 `php::Var`，
> 但**字段存储层 `?State` 与 `State` 同形态**（tpc 不给普通类生成 C++ 结构体字段），
> 读点层各付一次比较，**无量级差**；且非空字段上的属性访问**不是静态偏移读**。
> ⇒ `Cell::$owner` 的改动**没有性能收益**，人因收益成立 ⇒ 仍然做，但理由从
> "消掉动态分派"改成"读点不写 `?->`"。

### 2.2 语法

| 约束 | 否掉了 | 采用了 |
|---|---|---|
| `switch ($this->intProp)` 生成 `php::Int tmp = this_.attr(...)` ⇒ **C2440** | `switch` 语句（**全仓零使用**，所以从未验过） | `int $kind` + `===` 比较链（`ToggleBase::activate()` / `Curve::map()`） |
| `?:` 两支类型不同 ⇒ **C2678** | `$cond ? $a : $b` 里两支不同型 | 拆 `if/else`（`ToggleBase.php:189-210` 两个 `?:` 拆开） |
| `match` 已用 **15 处**且 T2 通过 | —（`match` 可用） | 继续用（但**没测过它是否生成跳转表**，见 §4 V-4） |
| 可选参数排必选前 ⇒ Fatal（比 PHP 严） | `function f($a = 1, $b)` | 必选在前（`RenderScrollView::__construct` 注释写明） |
| 类常量与同类方法同名 ⇒ **C2872** | 同名 | 改名 |
| 常量链 `A = B \| C` 而 `B = X \| Y` ⇒ **C2065** | 嵌套常量表达式 | 平铺成一次 `\|`（`CanvasCapabilities::ALL_MASK`） |
| 命名空间内非限定函数**不回退全局** ⇒ `C2653` | 裸 `strlen()` | 写 `\strlen()` |
| 函数外不能有语句（探针 P-4） | 文件级初始化 | 静态方法 |

### 2.3 对象模型

| 约束 | 否掉了 | 采用了 |
|---|---|---|
| 父类 `private` **不进子类属性表** ⇒ 子类实例上访问报 `Undefined property` | 基类用 `private` 给子类共享字段 | `protected`（`Element` 的 `$box`/`$mounted` 注释写明"语义不变，仅可见性放宽"） |
| `#[\Native]` 类**不能**进 PHP 数组 / 不能持容器 / 不能作 Fiber 参数 | `#[\Native]` 做树节点 | 纯 PHP 类做节点；`#[\Native]` 只做叶子值对象 |
| 被继承的类，字段不能是 `private`（tpc 按运行时类型查属性表） | `RenderFlex` 的字段用 `private` | `protected readonly`（`RenderFlex.php:46-51` 注释：2026-10-16 真机跑 `users.exe` 当场暴露） |
| `readonly` 属性**不能**在构造之外赋值 | 可变值对象 | 可变字段用 `private`（`RenderBox::$composeOpacity`，`05` §5.4） |
| `readonly` **慢 10×+**（v6 断言，**未实测**） | 热路径字段用 `readonly` | `private` + getter（`Modifier` 的字段，`02` §3.1） |

★ 第三行是最值钱的一条：`RenderAppBar extends RenderFlex`，而 `RenderFlex` 的
`$vertical` 如果是 `private`，子类实例上访问会**动态创建属性**并得到 `NULL` ⇒
布局拿到错值。**只在真机上暴露，解释器与 smoke 全绿。**

### 2.4 标准库

| 约束 | 否掉了 | 采用了 |
|---|---|---|
| std 容器赋给对象属性会被 `toArray()` **拷成 PHP 数组** | `private array $kids` 用 `std::vector` | 用 PHP `array`（`RenderFlex::$kids`）；`Element::$children` 同 |
| 二进制串禁在循环里 `.=` 累加（含 `\0` 与高位） | `pack()` 结果逐段拼接 | 数组 + `implode`（lint `str-concat-loop` 守） |
| `Closure::call` / `bindTo` 不可用 | 用闭包换绑定 | 显式传参 |
| `global` 擦除类型 | `global $app` | 构造注入 |
| `__FILE__` / `__DIR__` 编译期固化 | 用它找运行时资源 | `Paths` 类（`src/App/Paths.php`） |
| 无 `$argv` | 命令行参数 | 环境变量 / 文件（`build/m4.on` 文件开关） |
| `getenv` / `putenv` / `eval` / `include` 动态路径被 `nano-hygiene` 禁 | 运行时配置 | 文件开关（`build/*.on`） |

### 2.5 性能

| 约束 | 否掉了 | 采用了 |
|---|---|---|
| `readonly` 慢 10×+（**未实测**） | `final readonly class` 做热路径 | 只给几何值对象用（`Size`/`BoxConstraints`/`EdgeInsets`/`Rect`/`Point`/`Scale` 六个） |
| 临时构造立即调用无法优化 | `(new Foo())->bar()` | 先落局部变量 |
| `#[\Native]` 值对象省装箱（**未实测**） | — | 现在用 `final readonly class`（32 个） |

★ 注意 `readonly` 的用量：**187 处**，其中 **32 个 `final readonly class`**（`grep` 实测）。
如果 M0-1 证明 `readonly` 真的慢 10×，那 32 个类的**每一次字段读**都慢 10× ——
而 `Size::$width` 在 `layout()` 里每帧被读几十次。

⇒ **M0-1 是三条里影响面最大的**：它可能要求把 6 个几何类全部改成 `private` + getter。

### 2.6 缺一条 lint：`variant-arg`（本册提议）

五处 `C2440` 的形状完全相同：**属性读直接当实参**。

```php
// 坏
$f($this->box->maxWidth);
// 好
$v = $this->box->maxWidth;
$f($v);
```

但这条**不能靠 lint 判**（"哪个形参是 `float`"要跨类类型推导，PHP 没有静态类型）。
⇒ 只能靠**纪律**（写进 §6 的第 6 条）+ **T2 构建**。

★ 这是"编译约束里唯一一条只能靠 T2 兜的"。写在这里免得有人提议加 lint。

## 3. M0 三条实测

### 3.1 为什么要先测

`00` §7 第 0 步：**M0 排最前**，理由是"v6 的三条待实测如果结论不同，`02` 的 `Modifier`
值对象与 `03` 的 `Cell` 分型**形状会变**。先测再写，不把未知数埋进地基。"

三条与方案的耦合点：

| 实测 | 决定什么 |
|---|---|
| **M0-1** `readonly` 成本 | `02` 的 `Modifier` 字段用 `private` + getter 还是 `public readonly` |
| **M0-2** `?Obj` 是否退化 | `03` 的 `Cell::$owner` 用 `?State` 还是 `State` + `bool` |
| **M0-3** `mixed` 装箱成本 | `03` 的 `Cell` 要不要分裂五类 |

### 3.2 量具：`apps/bench`

**已有的量具**（`apps/bench`，v7 阶段 0 的三个微基准）：

```bash
# 从仓库根（cwd 决定 exe 落点与所有相对路径）
php tools/drift-build.php bench
./bench.exe
cat build/bench-out.txt
```

★ `apps/bench/README.md` 自己写明：**"必须跑 AOT 产物，不要用 `php.exe` 跑 `main.php`。
解释执行与 AOT 的开销分布不同（本项目踩过'解释模式过了不算完'）。"**

⇒ M0 三条**必须加进 `apps/bench`**，不新建量具。理由：它已经有"GUI 子系统、无 stdout、
写 `build/bench-out.txt`"的完整形状，且 `drift-build` 只认 `apps/<name>/project.yml`。

### 3.3 M0-1：`readonly` 成本

**测什么**：同一份逻辑，字段分别用 `public readonly float` 与 `private float` + getter，
各跑 1000 万次读，比总耗时。

```php
// apps/bench/src/M0Readonly.php
final readonly class RO   { public function __construct(public float $v) {} }
final class PV            { public function __construct(private float $v) {}
                            public function v(): float { return $this->v; } }

// 各跑 N 次读，分别计时
```

| 输出 | 判据 |
|---|---|
| `m0.readonly_ns_per_read` | 与 `m0.private_ns_per_read` 比 |
| 比值 | **> 3×** ⇒ `02` 的 `Modifier` 用 `private` + getter；**≤ 3×** ⇒ 可以用 `public readonly`（更简洁） |

★ 为什么阈值是 3× 而不是 10×：v6 说"慢 10×+"，但那是它的量级；
我们的判据应该问"**这个差在我们的热路径上值不值得为它牺牲简洁**"。
`Modifier` 的字段每次 `layout()` 被读 5–10 次，一次布局 5.7–12.4µs ⇒
若差 10ns/读，10 次读 = 100ns = 布局的 **1–2%** ⇒ 不值得改。
⇒ 阈值定在"差值的绝对值 > 100ns/次读"才算显著。

**修正判据**（更准）：

```
若 (readonly_ns - private_ns) × 每帧读次数 × 60 < 1ms/秒  ⇒ 用 readonly（简洁优先）
```

### 3.4 M0-2：`?Obj` 是否退化（★ 用 grep，不用计时）

> **★ 2026-10-21 增补（`10` §2 A2）：这一条的答案官方文档已经给了 ——
> `null`/`callable`/`iterable`/联合/`?A`/交叉在编译期退化为 `php::Var`。
> 所以 M0-2 从"实测"降为"一次 grep 确认"，**半小时 → 十分钟**，
> 且 `02` §3.1 的 `Modifier` 已按"会退化"改掉（`?Color` → `Color` + `bool`）。
> 下面保留原始测法，用于"本仓生成物确实如此"的确认。**

**这是三条里唯一能"看死"的** —— 不需要测时间，直接看生成的 C++。

```bash
# 1) 在 apps/bench 里加两个类
#    A: private ?RO $maybe;    B: private RO $always;  + bool $has
# 2) 生成 C++
php tools/drift-build.php bench
# 3) 看生成物
grep -n "maybe\|always" apps/bench/build/src/*.cc | head -40
```

| 观察 | 结论 |
|---|---|
| `A` 的字段声明是 `php::Var` 或 `php::Variant` | **退化**（动态分派） |
| `A` 的字段声明是 `php::Obj` / 具体类型 | 未退化（但可空性要另判） |
| `B` 的字段声明是具体类型，且 `B->v()` 的调用是**静态**（无 `php::call_method`） | 非空引用可静态分派 ✅ |

> **2026-10-21 M0-2 跑完，这张表的三行预期只对了一半**（详见 `docs/AOT-CONSTRAINTS.md` §2.2）：
> - 第 1、2 行**问错了层**：tpc 不给普通类生成 C++ 结构体字段，`?RO` 与 `RO`
>   都走 `this_.attr(persistent_prop)` 的 PHP 属性表 ⇒ **字段存储层同形态**，
>    grep 字段声明类型看不出任何差别。
> - 第 3 行**不成立**：`RO $always` 上的 `->v` 是 `typephp_read_property_cached`
>   （带 `PropertyCacheId` 的单态内联缓存），**不是静态偏移读**。
> - 真正的退化在**形参/返回值层**，且是铁证：`Frame::run` 同一签名里
>   `Element $root` → `php::Object`、`?Element $popup` → `php::Var`。
> ⇒ 判据要从"grep 字段声明"改成"**grep 函数签名 + 读点比较次数**"。

★ **为什么用 grep 不用计时**：计时会被"内联""分支预测""缓存"干扰，
而生成物的类型名是**二值答案**。这是"先看死、再测快"的正确顺序。

★ 生成物位置（实测）：`apps/bench/build/main.cc` + `apps/bench/build/src/*.cc`。

### 3.5 M0-3：`mixed` 装箱成本

**测什么**：`Cell` 的 `private mixed $value` 读写一次 vs `private int $value` 读写一次。

| 输出 | 判据 |

| `m0.mixed_ns_per_rw` / `m0.int_ns_per_rw` | 见 `03` §3.4 的公式 |

```

```

## 6. 代码纪律 14 条

抄 v6 `13` §7，按本仓的实测补充：

| # | 纪律 | 依据 |
|---|---|---|
| 1 | 热路径禁 `switch`，用 `int` + `===` 链 | C2440（`Curve.php:92`） |

| 4 | 禁 `(new Foo())->bar()` | 临时构造不能优化 |
| 5 | 父子类不声明同名 `private` | 父类 `private` 不进子类属性表 |
| 6 | **属性读不当实参**：先落局部标量 | C2440 ×5（本仓最高频） |
| 7 | 常量链平铺成一次 `\|` | C2065（`CanvasCapabilities`） |
| 8 | 类常量不与同类方法同名 | C2872 |
| 9 | 命名空间内调全局函数写 `\` | C2653 |
| 10 | 循环内禁 `.=` 累加二进制串 | lint `str-concat-loop` |
| 11 | 可空对象字段优先用"非空 + `bool` 哨兵"或 `NAN` | `?Obj` 退化 |
| 12 | 二进制复合数据过桥只走打包字节串 | 桥 ABI 只认标量 + string |
| 13 | **内置编译期注解必须写 `#[\X]`**（或 `use \X;`）—— 命名空间内写 `#[X]` 解析成 `当前命名空间\X`，**静默无效** | `10` §2 A0 + lint `attribute-unqualified` |
| 14 | **运行时路径禁 `__DIR__`/`__FILE__`**（编译期常量）；用 `getcwd()` / 环境变量 / 显式参数 | `10` §2 A8 + `best_practice.md` §3 |

★ 第 6 条是**本仓新增的**（v6 没有，因为它的代码量小）。它是 5 次 C2440 的共同形状。

★ 第 12 条来自 `Path` / `ImageHandle` 的实测（`05` 相关的 P4 工作）。

★ 第 13/14 条来自 `best_practice.md` 的逐条对齐（`10` 册）。两条的共同形状是**"不报错、
只是没效果"** —— 与第 5 条（父类 `private` 静默不生效）、MEMORY 的 `instanceof` 漏 `use`

## 12. 备选方案与否决

| 备选 | 否决理由 |
|---|---|
| **新建一个 `apps/m0` 量具** | `apps/bench` 已有完整形状（GUI 子系统 / 无 stdout / 写文件）；`drift-build` 只认 `apps/<name>/project.yml` |

| **用计时判 `?Obj` 退化** | 计时被内联/缓存干扰；生成物类型名是二值答案（§3.4） |
| **给"属性读当实参"加 lint** | 要跨类类型推导，PHP 没有静态类型 ⇒ 只能靠 T2（§2.6） |
| **把 v6 `13` 册直接搬进本仓** | 它的口径是"从零设计"（`#[\Native]` 几何、Fiber、单树），与本仓现状不符；搬进来会产生"文档说该这样、代码是那样"的第二重腐烂 |

### 推翻条件

| 裁决 | 什么情况下推翻 |
|---|---|
| `apps/bench` 加基准 | 基准需要真实窗口（M0 三条都不需要）⇒ 那时才新建 |

| 纪律 6 靠 T2 | 若出现"T2 构建太慢，一天只能跑一次"的情况 ⇒ 那时才考虑给 tpc 加类型注解检查 |
