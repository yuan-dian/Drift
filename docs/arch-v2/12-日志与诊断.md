# 12 · 日志与诊断系统（方案）

> 触发：现状只有一个 `Errors`（193 行、三级、默认 Fatal）。问「是不是缺一个真正的日志系统」。
> 本文先回答"缺什么、不缺什么"，再对照四个成熟框架的做法，最后给一个**可分期落地**的方案。
> 结论先行：**缺的不是"把 Errors 扩到五级"，而是一条独立的轨迹管道**。`Errors` 该保持现在的样子。

---

## 1. 现状：`Errors` 是**判决器**，不是日志

先把它现在做的事说清楚（`src/Errors.php`，129 处调用）：

| 维度 | 现状 |
|---|---|
| 分级 | 三级：`FATAL`(3) / `RECOVERABLE`(2) / `DIAGNOSTIC`(1) |
| 默认级别 | **FATAL**（单参 = 最响的一档，G2 要求"忘了写级别应当太吵"） |
| Fatal 行为 | 写 `Errors.log`（错误 + 栈 + 最近 100 条 Diagnostic）→ 原生错误框 → `exit(3)` |
| Recoverable | debug 中止、release 只落盘 |
| Diagnostic | **只进内存环形缓冲**（100 条），不落盘、不带时间/分类 |
| 可观测面 | `recentDiagnostics()`（devtools / 测试） |
| 落盘 | 单文件 `Errors.log`，追加，无轮转、无大小上限 |

**它解决的是「绝不静默」（G2）**：每个机制要么生效、要么响亮失败。129 处调用里绝大多数是
"契约被破坏"（例如 `Paint` 描边宽度 ≤ 0、`Option` 空键），把它当**断言**用是**正确**的定位。

它**没有**解决的是「看见发生了什么」：

- 业务/框架无法记 `info` / `debug`（"搜索发了 3 个请求""布局重排了 42 个节点"）；
- 没有分类 ⇒ 无法只开 `layout` 的日志；
- 消息是**已经拼好的字符串** ⇒ 调用点先付了格式化成本，即使这条不会输出；
- 没有 sink 概念 ⇒ 只能写同一个文件，应用想接 Sentry 无门；
- Diagnostic 不带时间戳/分类/级别 ⇒ Fatal 报告里的"最近 100 条"是一串无结构文本。

⇒ **结论：确实缺一条日志管道。但不要把它塞进 `Errors`** —— 那会让"判决"和"记录"
共用一个类，而它们的生命周期、性能要求、失败语义都不同（日志写失败必须**不能**触发中止）。

## 2. 成熟框架怎么做（四个样本）

### 2.1 Qt：`QLoggingCategory` + `qInstallMessageHandler`

- **分类**：点分命名（`driver.usb.events`），每个分类独立 4 级（debug/info/warning/critical）。
- **规则**：文本规则 `*.debug=false;driver.usb.debug=true`，可从 `QT_LOGGING_RULES` 环境变量、
  `qtlogging.ini`、`setFilterRules()` 三处配置，**后者覆盖前者**。
- **惰性求值**：`qCDebug(cat) << expensive()` 是宏 —— 未启用时**参数根本不求值**。
- **唯一接管点**：`qInstallMessageHandler(fn)`，应用把日志转去文件/网络/UI。
- **fatal 永远启用**（不受规则关掉）。

### 2.2 Flutter：`FlutterErrorDetails` + `onError`

- `FlutterError.onError` 可整体替换；默认 `presentError` 打到设备日志，IDE 里 inspector
  再接管一层（路由到 console）。
- `FlutterErrorDetails` 的字段值得抄：
  - `informationCollector`：**惰性**产出上下文（`ErrorDescription` / `ErrorHint`），
    "只在真要打印时才收集"，且明确要求调用方缓存（回调可能很贵）；
  - `silent`：某些错误（如 HTTP 404）在 release 下**默认不打印**，但自定义 handler 仍能看到；
  - `library` / `context`：错误属于哪个库、哪个节点。
- `ErrorWidget.builder`：build 失败时**换一个 UI**（debug 红屏 / release 灰底）——错误不只能
  写日志，还能在界面上**就地**表达。

### 2.3 .NET `ILogger`（另一 UI 框架 GUI.cs 的落地案例）

- **默认 null logger（opt-in）**：不配置日志就零开销。
- 五级（Trace/Debug/Information/Warning/Error）+ **分类**（logger 名 = 类名/模块）。
- **结构化**：消息是模板 + 参数，不是拼字符串；`BeginScope` 提供"一段时间的上下文"。
- **多 provider**（sink）：Console / File / ETW / 第三方，一个 logger 广播给所有 provider。
- 高频事件**采样**（如每帧渲染）——避免日志爆炸。

### 2.4 GPUI / tracing（现代 Rust GUI 的做法）

- `tracing` 的 **span**（name + category + 归属元素 + 深度 + 起止）而不是纯文本行。
- **编译期剥离**：`#[cfg(feature = "flamegraph")]` —— 关掉时二进制里不存在这段代码。
- **运行时开关**：`CAPTURE_ENABLED` 一个原子 load + 分支，未录制时几乎零成本。
- 环形缓冲**有界**（`max_frames`），长时间录制不会无限涨。

### 2.5 六条共性（方案的地基）

| # | 共性 | 为什么重要 |
|---|---|---|
| 1 | **分级**（4–5 级） | 无级别就只能全开或全关 |
| 2 | **分类 + 可配置规则** | 无分类就只能"全量刷屏"，一个模块的日志淹没其他 |
| 3 | **惰性求值 / 编译期剥离** | 不输出时不该付格式化成本 |
| 4 | **可接管 + 多 sink** | 框架不该决定日志去哪（文件/UI/Sentry） |
| 5 | **有界缓冲** | 崩溃时要能"回放最近 N 条"，且不能无限涨 |
| 6 | **结构化 + 上下文** | 纯文本行无法聚合；错误要带"当时的状态" |

## 3. 差距表

| 共性 | Drift2 现状 | 缺口 |
|---|---|---|
| 分级 | 3 级且都是"错误语义" | 缺 info/debug（轨迹），也缺独立的 warn |
| 分类 | 无 | 全缺 |
| 惰性 | 无（先拼字符串） | 全缺 |
| 可接管 | 无（只有 `installFatalBox`） | 缺 sink |
| 有界缓冲 | 有（100 条，仅 Diagnostic） | 需扩成"全级别 + 分类" |
| 结构化 | 无（纯文本） | 全缺 |

## 4. 方案

### 4.0 职责切分（这是整个方案最重要的一条）

```
业务/框架 ──► Errors::report()   判决：破坏了不变式？（中止 / 降级 / 记一条）
           └► Log::info/debug()  轨迹：发生了什么（永不中止、永不抛）
```

- **`Errors` 不动**：三级、默认 Fatal、中止序列全保留。它是 G2 的落地。
- **`Log` 是新类**：只写、不判决。**写失败也不许抛**（日志系统把自己搞崩是最糟的失败形态）。
- **桥只有两处**：
  1. `Errors::report(DIAGNOSTIC)` **同时**写 `Errors::$ring`（原样保留，78 处测试断言依赖它）
     与一条 `Log::warn('framework', ...)`（有了时间/级别/分类）；
  2. `Errors` 中止时 dump **两个环**：`Errors::$ring`（原样）+ `Log` 的环（`WARN` 及以上，
     避免把 debug 噪音塞进崩溃报告）。
  ★ **不是"转成"**：`Errors` 的环是测试契约（"这一帧没有 diagnostic"），不能被 Log 的全级别
  环替代 —— 详见 §4.6。

### 4.1 数据模型

```php
final readonly class LogEntry
{
    public function __construct(
        public int $seq,        // 单调序号（可判"中途丢了几条"）
        public int $timeMs,     // 相对**启动**的毫秒（不调 date()，见 §4.5）
        public int $level,      // Log::TRACE / DEBUG / INFO / WARN / ERROR
        public string $category, // 'layout' / 'input' / 'net'
        public string $message,
        public array $fields,   // 只允许 scalar（string|int|float|bool）
    ) {}
}
```

★ `fields` 只允许 scalar：嵌套数组会让"格式化 sink"与 AOT 都变复杂，且日志字段的真实需求
几乎都是扁平键值。

### 4.2 API

```php
Log::debug('layout', 'measure', ['node' => 'Column#12', 'h' => 320.0]);
Log::info('net', 'search done', ['n' => 3]);
Log::warn('theme', 'unknown token', ['token' => 'foo']);
Log::error('input', 'capture leaked', ['node' => 'Slider#3']);
```

- **消息与字段分开**：`message` 是**常量**（便于聚合），变量全进 `fields`。不做 `sprintf`。
- **不做可变参数**（`...$args`）：tpc 对 variadic 的支持没有实测过，不值得赌。
- 作用域（省重复写分类）留给 P1：

  ```php
  Log::scope('layout', function (): void {
      Log::debug('measure', [...]);
  });
  ```

### 4.3 门槛与规则

```php
Log::configure([
    'min' => Log::WARN,                 // 全局门槛
    'categories' => [                   // 按分类覆盖（覆盖 > 全局）
        'layout' => Log::DEBUG,
        'net'    => Log::INFO,
    ],
    'ring' => 2000,                     // 环形缓冲容量
]);
```

- 判据：`level >= categories[cat] ?? min` 才写。**一次数组查找 + 一次比较**。
- 组合根可从环境变量读（`DRIFT_LOG=layout:debug,net:info`）——P1。

### 4.4 输出：sink 接口

```php
interface LogSink
{
    public function write(LogEntry $entry): void;
}
```

内置三个：

| sink | 用途 | 说明 |
|---|---|---|
| `RingSink` | devtools / Fatal dump | 默认启用，有界（2000 条），O(1) 覆盖写 |
| `StreamSink` | 文件 | P1：大小上限 + 单份轮转（`.1`），**不引入日志库** |
| `StderrSink` | 开发期控制台 | `error_log()`；release 关闭 |

`write()` 收的是 `LogEntry`（结构），**不是字符串** —— 格式化归 `LogFormatter`（§4.7）：
内置 sink 走自己的 formatter，自定义 sink 想怎么序列化都行（JSON、二进制、直接转发对象）。

★ 一条硬约定（§4.7 第 1 条）：**sink 自己产出字符串 = 接管格式化**，此后 framework 的
pattern 不再参与。想"既走 sink 又改格式"，改的是 formatter 而不是 sink。

应用侧：`Log::addSink(new SentrySink(...))` —— 框架不认 Sentry，只认接口。

### 4.5 性能纪律

1. **门槛在最前**：`if (!self::enabled($level, $category)) return;` —— 一次比较。
2. **不每帧 `date()`**：`timeMs` 用 `hrtime` 相对启动（一次减法）；需要墙钟时间的 sink
   自己在**输出时**补（文件 sink 每行一个 `date()` 可接受，环形缓冲不需要）。
3. **不 `debug_backtrace`**：日志不带调用栈（`Errors` 才带）。要定位靠 `category` + `message`。
4. **环形缓冲复用**：预分配 2000 槽，`$seq % cap` 覆盖写（不 `array_shift`）。
5. **release 剥离**：`Log::disable()` 让 `enabled()` 恒 false。AOT 下这是一次静态读 —— 与
   GPUI 的 `CAPTURE_ENABLED` 同一形态（做不到 Rust 的 `#[cfg]` 真剥离，但成本等价）。

### 4.6 与现有设施的关系

- **`SurfaceProfile`（帧分段计时）保留**：它是"计数器"不是"文本日志"，两者不重叠。
  将来可以让它把每帧摘要**以 `Log::info('perf', ...)` 输出**（P2），而不是合并。
- **`FramePhase`（trace 名）保留**：它给 `frameCostMs` 用。
- **`Errors` 的 `recentDiagnostics()`**：**保持现状**（只读 `Errors::$ring`，只装 Diagnostic）。
  ★ 这里踩过一个差点写错的判断：全仓有 **78 处**调用它（绝大多数是 smoke 在每个用例后
  断言"没有 diagnostic"）。若把它改成"读 Log 的全级别环"，78 条断言会因为闻到 debug 日志
  而集体变红。⇒ **两环并存**：`Errors::$ring`（Diagnostic，测试契约）与 `Log` 自己的环
  （全级别），互不替代。

### 4.7 格式与扩展（三层模型）

先说结论：**原方案只有第 ③ 层（`LogSink` 完全接管），缺了前两层**。而"改一下输出格式"是
用户最常见的需求 —— 为此写一个 sink 类太重。

成熟框架普遍是三层，从轻到重：

| 层 | 机制 | 例子 | 谁用 |
|---|---|---|---|
| ① 格式字符串 | pattern / output template | Qt `qSetMessagePattern`、spdlog `set_pattern`、Serilog output template | 只想改样式的用户，零代码 |
| ② 格式化器对象 | formatter 接口 | spdlog `set_formatter`、.NET `ILoggerFormatter` | 需要条件/对齐等逻辑 |
| ③ 完全接管 | handler / sink | Qt `qInstallMessageHandler`、Flutter `FlutterError.onError`、`LogSink` | 改变**去向**（文件/网络/UI） |

两条硬结论（都是从实现里读出来的，不是推测）：

1. **① 与 ③ 在语义上互斥**：Qt 文档明写 `qSetMessagePattern()` 在装了自定义 handler 后
   **不生效** —— 因为 handler 接管后框架不再格式化。⇒ Drift2 也要立这条：`LogSink` 一旦自己
   产出字符串，framework 的 pattern 就不再参与；想两者兼得，用 `LogFormatter`（②）而不是 sink。
2. **pattern 必须在配置时"编译"，不能每条日志解析**：spdlog 的 `set_pattern()` 会把字符串
   预编译成内部表示。⇒ `PatternFormatter::compile()` 在 `configure()` 时跑一次，
   `format()` 只做拼接。

#### 4.7.1 新增一层 `LogFormatter`

```php
interface LogFormatter
{
    public function format(LogEntry $entry): string;
}

final class PatternFormatter implements LogFormatter
{
    /** @param list<string> $parts 已编译片段：字面量或占位符名 */
    private function __construct(private readonly array $parts) {}

    public static function compile(string $pattern): self;   // 一次解析，失败即 Fatal
    public function format(LogEntry $e): string;             // 只拼接，不解析
}
```

#### 4.7.2 占位符（极简子集）

| 占位符 | 含义 | 示例 |
|---|---|---|
| `%T` | 墙钟 `HH:MM:SS`（**只在 sink 输出时**取，环里不存） | `18:20:03` |
| `%t` | 相对启动的毫秒 | `12345` |
| `%l` | 级别名 | `INFO` / `WARN` |
| `%c` | 分类 | `layout` |
| `%m` | 消息（常量，不带字段） | `measure` |
| `%f` | 字段串 `k=v k=v`（按插入序） | `node=Column#12 h=320` |
| `%s` | 序号 | `42` |
| `%%` | 字面 `%` | `%` |

默认两套：

- 文件 sink：`[%T] %l %c: %m %f`
- stderr sink：`%l %c: %m`（开发期不要时间戳噪音）

**为什么不做 `%{...}` 长占位符**：Qt 那种 `%{time yyyyMMdd}` 需要一个带参数的 tokenizer，
而 Drift2 的时间格式需求只有"时分秒"；需要别的格式就写 formatter 类（②）。单字符解析
30 行，带参数解析要 100+ 行 —— 不值得。

#### 4.7.3 粒度：每 sink 一个 formatter

```php
$file = new StreamSink('app.log');
$file->setFormatter(PatternFormatter::compile('[%T] %l %c %m %f'));

$console = new StderrSink();
$console->setFormatter(PatternFormatter::compile('%l %c: %m'));
```

学 spdlog 的"单个 sink 独立 formatter"：文件要时间戳、控制台不要，这是真实差异。

#### 4.7.4 用户自定义的三条路（按侵入度）

| 需求 | 做法 | 代码量 |
|---|---|---|
| 改格式 | `Log::configure(['format' => '[%t] %l %c %m'])` 或 `$sink->setFormatter(PatternFormatter::compile(...))` | 0 行 |
| 格式带逻辑（条件、对齐、字段排序） | 实现 `LogFormatter`（`format()` 返回字符串） | ~20 行 |
| 改去向（文件/网络/UI/剪贴板） | 实现 `LogSink`（`write(LogEntry)`） | ~15 行 |

★ **不做 spdlog 的 `add_flag` 注册机制**：PHP 里自定义 formatter 就是一个类，不需要注册表；
多一层反而多一个失败点。

#### 4.7.5 与 `LogEntry` 的关系

`LogEntry::$fields` 是 `array<string, scalar>` ⇒ 自定义 formatter 拿得到全部字段，
可以任意重排、过滤、序列化成 JSON。**这是"格式自由"的兜底**：pattern 不够用就写 formatter，
formatter 不够用就写 sink。

| 不做 | 理由 |
|---|---|
| 把 `Errors` 改成五级 | 会毁掉"默认 Fatal"这条 G2 安全网；轨迹与判决是两种东西 |
| 结构化字段支持嵌套 | 无真实需求，且 AOT/格式化都变复杂 |
| 采样 / 限流 | Drift2 日志量小；高频路径已有 `SurfaceProfile` 聚合，不需要逐条记 |
| 远程上报 | 框架不该有网络依赖；留给应用写 sink |
| `__FUNCTION__` 自动定位 | AOT 下不可靠；且"哪个模块"由 category 表达更准 |
| 日志库（Monolog 等） | 引入依赖与 AOT 面；核心 300 行足够 |

## 6. 分期

### P0（最小可用，约 300 行 + 夹具）

- `Log` 类：5 级 + 分类门槛 + 环形缓冲（2000）+ `StderrSink`；
- `LogEntry`；
- **`LogFormatter` + `PatternFormatter`**（§4.7）——"改格式"是最常见诉求，
  留到 P1 会让 P0 出来就欠一次接口破坏；且 `LogSink::write()` 的签名从第一天起
  就该是"收 `LogEntry`、自己决定格式化"，② 层只是把默认格式化路径立住。
  占位符只做单字符 8 个（`%T %t %l %c %m %f %s %%`），不做 `%{...}`；
- `Errors` 两处桥：`DIAGNOSTIC` **同时**写 `Errors::$ring`（测试契约，不动）与 `Log`（WARN 级）、
  `abort()` 的 dump 追加 `Log` 环；
- `recentDiagnostics()` **不动**（见 §4.6）。

验收（smoke，全部可 head 侧断言）：

1. 未达门槛**不写**（环里没有）；
2. 分类覆盖生效（`layout=DEBUG` 时 layout 写、其他不写）；
3. 环满**丢最旧**（写 2001 条，第一条不在）；
4. `seq` 单调递增（中间不跳）；
5. `Errors::report(DIAGNOSTIC)` 落到 Log（`recentDiagnostics()` 能看到）；
6. Fatal dump 里含"最近 N 条"（构造一个会中止的路径，读临时 `Errors.log`）；
7. `Log::disable()` 后零写入；
8. **pattern 编译一次**：`compile()` 未知占位符 ⇒ Fatal（契约不静默）；
   同一 pattern 的 1000 次 `format()` 输出逐字节相同（证明不再解析）；
9. **每 sink 独立 formatter**：两个 sink 各设不同 pattern，一条日志两边各自成型。

### P1（**已完成**，2026-10-24，`14cbd34`）

- ✅ `StreamSink`（文件 + 大小上限 + `.1` 轮转）；
- ✅ `LogSink` 的 `flush()` / `close()`（进程退出时收口）；
- ❌ ~~`Log::scope()`~~ —— **否决**：`Log` 是全静态门面，全局 + 嵌套 scope 在协作式
  交错的 `Job`/`SlicedJob` 下必然串。做对需要 `scopeId` 进 `LogEntry`，是事后破坏
  接口。.NET `BeginScope` 成立是因为 logger 是**注入实例**、作用域跟着 DI 走。
- ❌ ~~环境变量配置（`DRIFT_LOG`）~~ —— **否决**：`nano-hygiene`（§16.7）在编译期
  禁用 `getenv`/`putenv`（为将来切 `--nano` 保留可选性）。规则意图写在
  `Platform::configDir()` 注释里：**环境变量是平台能力，只能由平台实现回答**。
  要可配置走 API（组合根传进来，同 `Paths::userConfig($baseDir, ...)` 的判断）。
- ⏸ `Log::configure(['format' => ...])` 的全局默认 pattern 糖 —— 推迟：
  每个 sink 已有 `setFormatter()`，全局糖只是省一行，而它要引入"默认 formatter 从哪来"
  的第二个来源（与 `recentDiagnostics` 双环并存是同一类麻烦）。

**`StreamSink` 的三个决定**（实现时定的）：

1. **轮转检查在 `write()` 开头**（不在结尾）⇒ 单条永远不被劈成两半，
   一条超过上限的长消息也整条落进新文件；
2. **单份轮转（`.1`）够用** —— 多份是运维需求，不是 GUI 框架的需求（§5 同判断）；
3. **append + 每条一次 `file_put_contents`，不持句柄** ⇒ `close()` 无事可做、
   崩溃时也不会丢没 flush 的缓冲（§2.4 纪律 2 同 `Errors::appendLog`）。
   ★ 写失败**不抛**（丢这条），但**配置错误要响亮**（G2）；轮转失败也不响 ——
   磁盘满时最不该做的就是再写一份日志说明"我写不进日志"。

### P2（按需）

- devtools 面板：showcase 加一页"日志"（实时读 ring，按分类过滤，颜色分级）；
- Fatal 报告带**分类统计**（"最近 2000 条里 layout 占 70%"）；
- `SurfaceProfile` 每帧摘要走 `Log::info('perf')`。

## 7. 开放问题

1. **`Log` 是否 `@api`**？`Errors` 是（组合根要调 `installFatalBox`）。`Log` 同理需要
   `configure()` 与 `addSink()` 给组合根 ⇒ 建议 `Log` 整体 `@api`，但**写方法**（`debug` 等）
   允许框架内部自由调用。
2. **`Log::warn` 与 `Errors::RECOVERABLE` 的边界**：前者是"值得注意的正常事件"，后者是
   "契约被破坏但能降级"。文档要在两处 docblock 互相指认，否则会有人把可恢复错误写成 warn
   （被阈值吞掉）。
3. **环形缓冲的 `seq` 与覆盖率**：`seq` 超过容量后，`recent()` 返回的是"最近 cap 条"，
   但调用方可能想知道"总共写了多少条" ⇒ 需要 `Log::total()`（一个 int）。
4. **多线程/多进程**：`ProcessTaskHost` 的 worker 是独立进程，日志是否要回传主进程？
   当前回答：**不回传**（worker 的 stderr 已由 `Errors`/`TaskHost` 单独收集）。
   若将来要，走 `TaskHost` 的结果通道，不另开日志 IPC。
