# 11 · W8 控件与能力增补（arch-v2 之后）

> arch-v2 43 步 / 8 波次把**地基**做完并真机验收（flex 布局、渲染管线、状态/动画、语义、浮层栈、路由、主题+暗色、IME 文本、自绘）。本册是**方案外**的后续：补"标准控件目录 + 少数跨切面能力"的广度。
> 判据基线（2026-10-23 能力对照，见当日日志）：**地基全、控件目录薄**。缺的不是架构，是广度。

## 0. 缺口总表（按"补齐需要动多深"分层）

| 层 | 能力 | 深度 / 风险 |
|---|---|---|
| 叶子控件 | Slider / Select / Tooltip / Snackbar / TabBar(SegmentedControl) / DatePicker / Badge / Chip | 低（地基已解锁；`OverlayStack` W3 后浮层类全可安放） |
| 跨切面 | **Image 资源管线**（decode + 双后端 `drawImage` + `Image`/`Icon` 控件） | 中高（要动 Raster 后端 + 资源层 + 双端等价） |
| 跨切面 | 布局广度：Grid / Wrap / AspectRatio / LazyRow / GridView | 中（布局引擎加原语） |
| 跨切面 | 手势：long-press / pinch(多 pointer) / hover 回调 | 中（碰 `Application::dispatchInput` 中央派发，最 delicado） |
| 跨切面 | RichText 多样式 span | 中（文本整形/布局引擎） |
| 较深 | RTL / 双向文本、l10n 本地化框架 | 高（i18n 全链） |
| 较深 | 语义 → 平台（Windows UI Automation）桥接 | 高（平台集成） |

## 1. 建议执行序与出口判据

**顺序原则**：先"解锁且低风险"的叶子控件建立 W8 控件范式 + 双端测试 harness，再攻跨切面（Image 优先，它是唯一卡真应用的），最后 i18n/平台集成按产品需要排。

### W8-1 · Image 资源管线（最高优先，卡真应用）
- 资源源：文件路径加载（PNG 起）；后续再议嵌入/网络。
- 解码：**本机无 GD / 无 PIL** ⇒ Raster 侧要一份纯 PHP PNG 解码（`_build/pnglook.php` 的纯 PHP 解码可提炼进 `src/`）；Skia 侧走原生 codec。
- `RasterCanvas::drawImage` 落地（当前 `unsupportedOp`）+ Skia 桥已支持（`drawImageRect` 4/6 参）⇒ **双端能力等价**（G 判据）。
- 控件：`Image`（RenderBoxWidget，受控源）+ `Icon`（字体/矢量图标体系）。
- 出口：smoke 断言 Raster 与 Skia 同图逐字节相同（golden 扩一条 image 基线）；真机一图；`grep -c unsupportedOp src/Rendering/RasterCanvas.php` 下降（drawImage 不再响亮失败）。

### W8-2 · 叶子控件（解锁、低风险，建立范式）
逐控件：Widget(+State) + RenderBox + 语义 + smoke（含反例自检）+ 真机一图。顺序：
1. **TabBar / SegmentedControl**（tap + 受控选中，复用 focus/activate，无浮层）—— 先立范式。
2. **Slider**（受控值 + drag；drag 复用/最小扩展 `Application` 派发，**改前先出方案**）。
   - **2026-10-23 裁决（已落地 `7f0b536`）**：**否掉"复用 `Draggable`"**。三个硬理由：
     ① 点轨道不跳值（arena 把激活推迟到 up、拖动推迟到 6px 阈值，而 Slider 的标准语义是
     "按下即跳到该位置"）；② `DragController::drop()` 会派发 `DragTarget::onAccept`
     ⇒ 拖放区里的 Slider 松手会被当成"投放"；③ 拖动中 `hoverTo` 会刷新拖放区高亮。
   - 改走 **两条输入缝**（`Widget::pointer($h, ownsPress: true)` / `Widget::keyboard($h)`），
     见下节。**新控件一律走这两条缝，不要再往 `Application::activateFocusedWidget()` 的
     `instanceof` 塔里加分支。**
3. **Tooltip**（hover 回调 + `OverlayStack`；无新手势）。
   - **2026-10-23 裁决（已落地）**：**否掉"应用写 hover 回调 + 自己 `showTooltip()`"**，
     改走 **`Widget::tooltip(string)` 声明 + 框架托管浮层**。三个硬理由：
     ① **hover 回调拿不到锚点**（签名 `\Closure(bool)`），加第二个参数在 PHP 侧无害，但
     tpc 生成的 C++ 侧闭包 arity **没有验证过** —— 不值得为一个可选能力赌编译器；
     ② 应用侧代码量：回调式每个控件 3 行（记 entry / show / hide）+ 自己写对"相邻控件
     先关再开"的时序，声明式一行，时序只在一处；
     ③ 同族一致性：`semantics()` / `pointer()` / `keyboard()` 都是"控件属性"，Tooltip
     **不产生布局、不产生绘制** ⇒ 做成包裹 Widget 反而要透明 `RenderProxy` +
     `expandChildren()`（纯开销），还会插进 `hoverOwner()` 的父链判定。
   - **顺带补掉的三处结构性缺口**（都是"承诺了没实现"）：
     - `Application::after(ms, cb): int` / `cancelAfter()` —— **通用一次性延时**，
       全仓此前没有（`TimerHost` 只有周期定时器且只给帧时钟用）。走**帧时钟轮询**
       （`FRAME_MS=15`），不新增 `TimerHost` id：15ms 精度对"人的反应时间"无感，
       换来零平台改动。**Snackbar 的定时消失会复用同一条**。
     - `wantsFrame()` 第 5 条判据"有定时器待触发" —— **结构前提**，不是优化：
       消息泵是阻塞的，没人叫醒定时器永远不响。反面代价是停留期帧时钟保持上膛
       （500ms ≈ 33 帧空转），可接受。
     - `FramePhase::ALL` 加 `pumpTimers`（组 A，settle 之前）。
   - **`OverlayEntry` 三处新增**：
     - `hitTest = true`（`false` = 指针看不见这一层，对应 Win32 `WS_EX_TRANSPARENT`）。
       ★★ **没有它就会闪烁死循环**：提示面板一出现在指针附近 ⇒ `dispatchPointer()` 的
       浮层段命中它 ⇒ `hoverTo(面板里的元素)` ⇒ 锚点悬停丢失 ⇒ 隐藏 ⇒ 指针又命中锚点
       ⇒ 再显示。`barrier=false` 只解决"没命中时穿透"，解决不了"命中了就不放"。
       真实后果还有一条：提示盖住某个按钮时，`barrier=false` 的命中分支会**吞掉那次
       down** ⇒ 用户点不动下面的按钮。
     - `maxWidth`（`INF` = 不限）—— `placeEntry()` 给非居中层的是**无界**约束，而
       `RenderPopupPanel` 只在约束有界时才夹宽，⑤ 的夹紧**只挪 x 不改宽** ⇒ 长文案
       右边溢出。Tooltip 设 320。
     - `BELOW_CENTER = 6` / `ABOVE_CENTER = 7` —— 锚点中心对齐。落位算法在
       `originFor()` 里（应用拿不到夹紧后的 `maxW`），所以方向必须是**语义**而非坐标。
   - **`FocusManager::onHoverChanged(\Closure(?Element))`** —— 悬停**原始命中**的变化口。
     与 `hoverHandler` **不同源**：那个找"有 `hover()` 的控件"，Tooltip 的声明者可能
     没有 `hover()`。收原始命中而不在这里解析，是为了不把"Tooltip 是什么"的知识漏进
     焦点层。默认 `null` ⇒ 逐字节不变。
   - ★ **`OverlayEntry::$owner` 此前零消费**（`01` §7 承诺"owner unmount ⇒ 自动 pop"）
     —— 本次在 `placeOverlays()` 里补上。死字段比缺失更贵：读代码的人会以为防线已在。
   - ★ `pushOverlay()` 会快照 `restoreFocus`（菜单/模态要的"焦点回锚"）⇒ Tooltip 必须
     **在 push 之后**把 `restoreFocus` 覆盖成 `null`，否则关闭提示会把焦点从用户刚点的
     地方抢走。
   - ★ 时序：进入 ⇒ `after(500)`；离开 ⇒ cancel + 立即 hide；**已显示时移到相邻声明者
     ⇒ 立即换**（Windows 手感：一排图标不该每个都等 500ms）。
   - ★★★ **AOT 坑（2026-10-23 真机抓到的，解释器侧全绿）**：`BoxConstraints::INFINITY`
     作为**外部类常量引用**（`new BoxConstraints(0, $w, 0, BoxConstraints::INFINITY)`）
     在 tpc 生成的 C++ 里求值成 **0** ⇒ `maxHeight = 0` ⇒ 面板 `w=h=0`。
     现象极具欺骗性：`showTooltip` 被调、文字正确、`placeEntry` 的 `x/y` **完全正确**
     （`x=268 y=161.6`）、`ink_all_pct` 只从 9.4 变 9.5（一个 88×30 的面板占整窗
     0.13%，而墨量精度是 0.1% ⇒ **单看墨量会误判成"没变"**），画面一丝不变。
     ⇒ 修法：**走类内工厂** `BoxConstraints::capWidth($w)`（内部用 `self::INFINITY`，
     与 `unbounded()` / `loose()` 同一条已被验证的路径）。
     **判据纪律**：AOT 特有的静默失败，smoke 一条都抓不到 ⇒ 这类改动只能靠
     T2 真机图；且真机判据要**看 md5 与图**，不要只看墨量百分比。
4. **Snackbar**（`OverlayStack` + 定时消失 —— 复用上面那条 `after()`）。
   - **2026-10-23 裁决（已落地）**：**`Snackbar` 是纯描述对象（`final class`），不是
     Widget**。三条理由：
     ① **动作按钮要能关掉自己**，而 Widget 一旦 seal 就拿不到 `Application`
     （§4.3 禁 `Widget → App`）⇒ 只能由 `Application` 组面板时把 dismiss 闭包
     **注入**进去（`SnackbarPanel::make($snackbar, $onDismiss)`）；
     ② **生命周期一次性**（显示 → 消失 → 丢弃），没有 diff 复用需求 —— `Modal` 做
     Widget 是因为"内容变了要复用盒"，Snackbar 不会；
     ③ **队列里排着的那几条还没挂载**，本来就不该是 Widget。
     ⇒ 与 `OverlayEntry`（也是纯描述 `final class`）同形。
   - **`Application::showSnackbar()` / `dismissSnackbar()` / `hasSnackbar()` /
     `snackbarQueueLength()` / `snackbarEntry()`**：第一条立即显示、其余 **FIFO 排队**
     （不排队的话"连续保存三次"只看得到最后一次 —— 那正是通知最容易失职的场景）。
     `duration(0)` = **永不自动消失**（错误提示要用户确认），走哨兵三档定则。
   - **`OverlayEntry` 两处新增**：`BOTTOM_CENTER = 8`（贴底居中，**不做翻转** ——
     通知没有"上面放不下就翻到下面"这种语义）+ `inset`（离底留白，Snackbar 用 24）。
     落位 `x=(maxW−w)/2`、`y=maxH−h−inset`，放不下由 `placeEntry()` ⑤ 的夹取兜住。
   - ★★ **`hitTest` 与 Tooltip 相反**：Snackbar 保持 `true`（动作按钮要能点），
     Tooltip 是 `false`（指针看不见它）。**这两个需求正好相反**，改任何一个之前
     先想清楚是哪一类。
   - ★★ **`MIN_WIDTH = 220` 不是审美，是必须的**：`RenderPopupPanel` 用
     `max(minWidth, child->intrinsicWidth(INF))` 定内容宽，而 `Button` 在**无界高度**
     下的 `intrinsicWidth()` 会失真（返回远小于实际）⇒ 内容宽被算成正文那行字的宽
     （42），布局时动作按钮要 50 ⇒ `RenderFlex 放不下：子项共需 50.0，可用只有 42.0`
     **直接中止**（smoke 退出码 3、零输出，`Errors.log` 里才有那句话）。
     长文案不受影响：`max(220, 全文宽)` 后被 `MAX_WIDTH=480` 夹住 ⇒ 正文换行。
   - ★★★ **示例台接线踩到的坑（2026-10-23，真机进程直接崩、smoke 全绿）**：
     `$this->application()` **不存在** —— `State` / `Widget` 上都没有这个访问器。
     我在 `Application::showSnackbar()` / `Modal.php` / `Snackbar.php` 的 docblock
     和示例台里都写成了那个形态（`docs/examples.md` 更早就写着），**照抄即崩**。
     后果：真机点一下按钮 → 未定义方法 → AOT 侧直接退出、5 秒内进程消失、**没有
     `Errors.log`**（那不是 `Errors::abort` 的路径）。
     ★ 两条连带教训：
     - **tpc 不校验 `$this->不存在的方法()`** ⇒ `drift-build` 照样成功（9.4 MB，
       0 error）⇒ **AOT 构建本身不是这条的闸门**；
     - **smoke 的夹具拿着 `Application`**，走的是另一条路 ⇒ 全绿。
       **示例台是这条 API 唯一的真实消费者** ⇒ 凡"只给应用用的 API"，判据必须在
       示例台上做。
     ⇒ 合规写法只有两条：**组合根接线**（`ShowcaseApplication::buildRoot()` 把
     `fn(Snackbar $s) => $this->showSnackbar($s)` 递进 `ShowcaseRoot` → 页面，
     `Menu::onOpen` 同款）或**框架托管**（`Widget::tooltip()` 那种声明式）。
     ★ 闭包参数**不可空**（`?\Closure` 在 AOT 侧退化 `php::Var`）。
   - ★ 真机五档判据（`_build/probe-snackbar.php`）：`sb-page` = `sb-gone`（**逐字节
     相同** `9e06ac88…` ⇒ 4s 到点真的自动走了）、`sb-on` 不同（通知出现）、
     `sb-act` 不同（带「撤销」按钮 ⇒ **AOT 侧注入的闭包被接受、面板建起来了**）、
     `sb-undo` 不同（点完通知收掉 + 页面「已撤销 0 次」→「1 次」）。
   - ★★ **起窗探针的子进程 stdout/stderr 必须落文件**（`['file', ...]`）：
     `stream_set_blocking()` 对 Windows 管道**无效**，想在运行中抽干管道会永久阻塞
     （探针只打印了 `pid=` 就卡死，看着像"起窗卡住"）；而崩溃信息是唯一线索。
5. **Select/Dropdown**（tap + `OverlayStack` + 列表 + 受控选中）。
   - **2026-10-23 裁决（已落地）**：**不写 `RenderSelect`，用 `Button` + 一条
     声明式浮层缝组合出来**。理由：新渲染盒是本仓最贵的改动面（内禀失真 /
     offset 双重平移 / AOT 常量折叠，每一条都出过真机 bug），而"一个有边框的、
     点了浮面板的按钮"用现成 `Button` **完全表达得出来** —— 焦点、激活、光标、
     语义、命中全白送。真机实测 `Button` 被 `width()` 定宽后标签**靠左**（与示例台
     侧栏导航同一条路径）⇒ 正好是选择框的形态，连对齐都不用额外处理。
   - ★★★ **新增第三条声明式缝 `Widget::overlayPanel(\Closure $factory)`** ——
     形参是"收掉这一层"的 `dismiss` 闭包，返回面板内容。三个关键点：
     - **为什么需要它**：`pointer()` / `keyboard()` 这两条输入缝把事件交给**控件
       自己的闭包**，而"开浮层"要 `Application`（§4.3 禁 `Widget → App`）⇒
       闭包够不着。声明式让框架在**激活**那一个入口统一处理。
     - **为什么工厂只收一个参数**：tpc 生成的 C++ 侧**闭包 arity 没有系统验证过**
       （`Menu::onOpen` 的 2 参形态至今没被示例台消费过）。要往工厂里塞"锚点宽度"
       这类信息，宁可给 `OverlayEntry` 加字段，**不要加形参**。
     - **为什么由 `Application` 注入 dismiss**：与 `SnackbarPanel::make($s, $onDismiss)`
       是**同一条**已被真机验证过的路（`119cfd7`）。
   - ★★ **`activateFocusedWidget()` 里只有一条按"能力"判的通用分支**
     （`$widget->overlayPanelValue() !== null`），**排在最前**、**没有 `instanceof`**
     ⇒ 以后 DatePicker / ComboBox 不用再改这里一行。优先级：声明了面板 ⇒ 开面板，
     不走 `onPressed` / 命令（"浮一个面板"比"按一下"更具体）。
   - ★★ **面板参数三处最容易搞反的**：
     | 字段 | 值 | 为什么 |
     |---|---|---|
     | `barrier` | **true** | 这是 `dismissOnTapOutside` **唯一**生效的路径 —— `dispatchPointer()` 里"点在条目盒外"整支包在 `if ($e->barrier)` 里，`false` 的条目直接穿透 |
     | `owner` | **锚点自身** | 页面走了没关下拉 ⇒ `placeOverlays()` 的 owner 清扫收尸 |
     | `restoreFocus` | **保留快照**（不置 null） | 与 Tooltip / Snackbar **相反**：那两个是悬停 / 定时器触发的，打开时焦点不在锚点上，快照下来是错的；这里打开它的就是锚点自己 ⇒ 快照天然正确，收面板时焦点回到控件上（否则"选完一项焦点就丢了"） |
   - ★ **不靠字段记"谁开着"**：直接扫栈里 `owner === $anchor` 的条目。字段会在
     `dismissOnTapOutside` / `closeMenu()` / owner 清扫这些**不经过本类**的移除路径上
     变陈旧（Snackbar 的 `snackEntry` 就是靠 `closeMenu()` 手动复位兜的）。
   - **`Option` 值对象**（`label` + `value`）：`label` 是给人看的字，`value` 是**身份**。
     ★ 与 `SegmentedControl`（`list<string>` + 下标）**刻意不同**：分段控件的段是
     "几个平级的视图"，位置本身就是语义；Select 的列表会被重排 / 过滤 / 分页，
     下标就不是身份了。两条纪律各自的理由都写在这两处，**别为了统一而统一**。
   - ★ **能力边界（v1 刻意不做）**：方向键换值（要"面板随控件重建"，否则选中高亮会
     停在旧值上 —— 宁可不做也不做自相矛盾的）/ 下拉箭头（`Button` 标签位只收字符串）/
     滚动（与 `Menu::panel()` 一致）/ 可编辑 / 多选 / 面板与控件等宽（要 `placeEntry()`
     加最小宽约束）。
   - ★ 真机三档判据：`sel-page` `f2db7ca0…` → `sel-open` `e0ca36df…`（下拉出现，
     4 项、选中项强调色底）→ `sel-picked` `87147a28…`（触发框换字、`当前值：110000`、
     面板收掉）。
- 出口：每个控件 smoke 几何/交互断言 + 反例；T2 建 `showcase` 增演示页；真机逐控件一图。

#### W8-2 附 · 两条输入缝（2026-10-23，Slider 立的范式）

| 声明 | down 归谁 | 说明 |
|---|---|---|
| `pointer($h, ownsPress: true)` | **本控件** | 框架捕获它、把 `down` 交过去、**跳过** `activateFocusedWidget()`；焦点照旧落上去（键盘可达）|
| `pointer($h)`（默认） | 框架激活 | 只在捕获期被调（`OverlayLab` 的锚点按钮就是这个用法）|
| `Draggable` | GestureArena 裁决 | 过阈值才算拖 |
| 都没有 | 框架激活 | A15 行为 |

- `keyboard(\Closure(KeyEvent): bool)`：返回 `true` = 吃掉。只对**焦点控件**调
  （Tab/Shift+Tab 之后、`TextFieldState` 之前）。方向键调值 / 上下选 / 翻页都走它。
- ★ 两者都是**加性**（默认 `false` / `null` ⇒ 既有控件逐字节不变）。
- ★★ `ownsPress` 复用 `$captureNode` ⇒ **不引入第六个手势状态**，四条收口路径
  （抬起 / 卸载 / 失焦 / 浮层外按下）全部现成。**不要**给控件再写一套手写拖动状态
  （`$thumbDrag` 已是第二套，第三套必然走样）。
- ★ `pointer()` 分支必须排在 `Draggable` **之前**：它是"我自己处理指针"的最深声明，
  比祖先的拖放更具体（否则"可排序列表里放一个 Slider"会被祖先抢走按下）。
- ★ 命名是 `keyboard()` 不是 `key()` —— 后者已被 diff 身份 `key(Key)` 占用。

### W8-3 · 布局广度
- `Grid` / `LazyVGrid`、`Wrap`/流式（`Overflow::Wrap` 已声明未实现）、`AspectRatio`、`LazyRow`。
- 出口：smoke 几何断言（数字按公式推，不拟合）；golden 各一条。

### W8-4 · 手势（碰中央派发，最谨慎）
- long-press、pinch/双指、hover 进出回调。
- ★ 每加一条先过"五个手势状态"（`$captureNode`/`$gestureArena`/`$drag`/`$textSelect`/`$thumbDrag`）的收口对账，别引入第六个卡死点。
- 出口：headless 夹具驱动合成指针 + 真机（缩放带 `--cursor`）。

### W8-5 · RichText 多样式 span
- `Text` 从单样式到 span 列表；文本整形/布局支持多样式断行。
- 出口：golden 一条混排基线；真机一图。

### W8-6 · i18n / 平台集成（按产品需要）
- RTL/双向、l10n、语义→UIA 桥。
- 出口：视具体消费者定。

## 2. 通用纪律（承 arch-v2，不因是新功能而松）
- 每控件一次 T2（建 `showcase`，它有 `CustomPaintPage`/`Stack` 演示；`users` 缺控件消费者）。
- **smoke 全绿 ≠ 真机正确**：每个交互控件必须真机看图/驱动。
- 新增"产 `RenderProxy` 的单子控件"必须同时加 `Widget::expandChildren()`（漏了 = 子不挂载、静默空白）。
- 有态+有盒+无子走 `createRenderObjectFromState()` 叶子路径；有子的走 `build()`+`*Box`。
- 受控值（值住应用 State，控件只回调），不自持"任务语义"。
- 双后端能力必须等价（都支持或都响亮失败）；新 draw op 过 T2。
