# 01 · 覆盖层

> 关联：[00 总纲](00-总纲.md) · [06 帧管线](06-帧管线.md) · [07 可检查性](07-可检查性.md)
>
> 本册位置：解 **R1「没有覆盖层模型」**。它是做 `Select` / `DatePicker` / `Tooltip`
> 的**硬前置** —— 不做它，每加一个浮层控件就再打一次补丁，而现在的补丁已经打不动了。

---

## 1. 现状：一个槽位两用

### 1.1 证据

```php
// src/App/Application.php:173-218
protected ?Widget  $menu = null;
protected ?Element $menuElement = null;
protected float    $menuAnchorX = 0.0;
protected float    $menuAnchorY = 0.0;
protected float    $menuX = 0.0;        // 面板左上角落点（placeMenu 每帧算）
protected float    $menuY = 0.0;
protected ?Modal   $modal = null;       // ← "O-20「一槽位两用」的判别位"
```

```php
// src/App/Application.php:628   showModal() 的第一句
$this->closeMenu(); // 互斥：先清槽位（`closeMenu()` 幂等）
```

```php
// src/App/Frame.php:52-59   一帧只能收一个浮层
public function run(
    Element $root, BoxConstraints $constraints, float $timestampMs,
    ?Element $popup = null, float $popupX = 0.0, float $popupY = 0.0,
): void
```

`isMenuOpen()` 还要额外判 `$modal === null` 才能回答"菜单开没开"（`:588-591`）——
**两个问题共用一份状态时，答案必须互相打折**。这是槽位复用最典型的症状。

### 1.2 后果链（推演到具体控件）

| 场景 | 现在会发生什么 | 为什么 |
|---|---|---|
| `Select` 下拉 + 页面上已有打开的菜单 | 下拉 `showMenu()` ⇒ 菜单被顶掉 | 同一个 `$menuElement` |
| `Select` 下拉里再弹 `Tooltip` | Tooltip 无处安放 | 只有一个槽位 |
| `DatePicker` 弹层 + 输入框获得焦点 | 弹层在，但 IME 候选框算的坐标不含弹层原点 | `absoluteOrigin` 到浮层根就断了 |
| `Modal` 里放一个 `Select` | 打开下拉 ⇒ `showMenu()` **不会**关模态（只有 `showModal` 会 `closeMenu`）⇒ `placeMenu()` 走 `$modal !== null` 分支 ⇒ **下拉被当成模态盖满全屏** | `placeMenu():710-714` 的分支 |
| 菜单里的子菜单（多级菜单） | 不可能实现 | 一个槽位 |

★ 最后一行是判定"这个补丁已经打不动了"的关键：
**多级菜单不是新需求，是菜单本身就该有的能力**，而现在它需要第二个槽位 —— 没有。

## 2. 目标形状

### 2.1 两个类

```php
namespace Drift\App;

/**
 * 一个浮层条目。**普通 class**（不进 PHP 数组以外的容器、不做节点）。
 *
 * ★ 为什么不是 Widget：Widget 是**不可变描述**（挂载即 seal），而条目要每帧被写
 *   （`x` / `y` 由定位算法算、`alive` 由生命周期改）。放进 Widget 会立刻撞
 *   `mutate()` 的封存守卫。
 */
final class OverlayEntry
{
    /** @var int 进程内唯一，调试与 trace 用 */
    public int $id;

    /** @var Widget 面板描述。★ 是 Widget 不是 Closure：Drift 的面板可以是
     *  StatefulWidget，自己订阅状态自己重建 —— 不需要 builder 闭包这一层。 */
    public Widget $panel;

    /** @var Element|null 锚节点；null ⇒ 无锚（模态 / Toast） */
    public ?Element $anchor;

    /** @var int 首选方向，OVERLAY_* 常量 */
    public int $prefer;

    /** @var bool 是否拦截浮层外的指针（**与 scrim 是两个参数**，见 §4） */
    public bool $barrier;

    /** @var bool 是否画遮罩（变暗） */
    public bool $scrim;

    /** @var bool 点浮层外是否关闭 */
    public bool $dismissOnTapOutside;

    /** @var bool Esc 是否关闭 */
    public bool $dismissOnEsc;

    /** @var bool Tab 是否被限制在浮层内 */
    public bool $focusTrap;

    /** @var Element|null 归属者：它 unmount 时本条目自动 pop（§7 的结构性防线） */
    public ?Element $owner;

    /** @var Element|null 挂载后的根 Element（框架写） */
    public ?Element $element;

    /** @var float 面板左上角在客户区的落点（框架每帧写） */
    public float $x = 0.0;
    public float $y = 0.0;

    /** @var Element|null 关闭后焦点回到哪（push 时快照，§6） */
    public ?Element $restoreFocus;
}
```

```php
namespace Drift\App;

/**
 * 覆盖层栈。**每个 Surface 一个**（多窗口时对话框不会跑到另一个窗口 —— v6 `08` §1.1）。
 *
 * ★ 只有五个操作：push / pop / popTo / remove / top。
 *   **没有"改顺序"**：栈顺序就是绘制顺序，改顺序要 pop 再 push。
 */
final class OverlayStack
{
    /** @var list<OverlayEntry> */
    private array $entries = [];

    public function push(OverlayEntry $e): void;
    public function pop(): ?OverlayEntry;            // 关最上面一个
    public function popTo(?OverlayEntry $e): void;   // 关掉 $e 之上的全部（null ⇒ 全清）
    public function remove(OverlayEntry $e): void;   // 精确移除（owner 卸载时用）
    public function top(): ?OverlayEntry;
    public function count(): int;
    public function at(int $i): ?OverlayEntry;
    /** @return list<OverlayEntry> */
    public function all(): array;
}
```

### 2.2 方向常量

```php
public const OVERLAY_BELOW  = 0;   // 锚下方（菜单 / 下拉）
public const OVERLAY_ABOVE  = 1;   // 锚上方
public const OVERLAY_RIGHT  = 2;   // 锚右侧（子菜单）
public const OVERLAY_LEFT   = 3;
public const OVERLAY_CENTER = 4;   // 客户区居中（模态）
public const OVERLAY_AT_POINTER = 5;  // 最近一次命中的指针位置（右键菜单）
```

★ 用 `int` + `===` 链，不用 enum：Drift 全域是 `int $kind` + `===`
（`ToggleBase` / `Curve::map()` 同形）。理由不是口味 —— tpc 对 `switch` 生成 C2440。

## 3. 九字段逐个推演

v5 的 `OverlayEntry` 是九字段（`Drift3/design/08` §4.1）。Drift 版是 **13 个**
（九字段 + `id` + `owner` + `element` + `restoreFocus`）。逐个说清"为什么这个字段必须独立存在"。

| # | 字段 | 为什么不能省 / 不能合并 |
|---|---|---|
| 1 | `panel: Widget` | 面板描述。**不用 Closure**：Drift 的 StatefulWidget 自己会重建，闭包是多余一层 |
| 2 | `anchor: ?Element` | 每帧重算 rect（跟随滚动 + 锚点消失检测都要它）。**不能存 rect 快照** —— 存了就不跟随 |
| 3 | `prefer: int` | 首选方向。**必须与"实际方向"分开**：实际方向每帧算，首选是声明 |
| 4 | `barrier: bool` | 拦截点击。**不能从 scrim 推出**（见 §4） |
| 5 | `scrim: bool` | 画遮罩。**不能从 barrier 推出**（Tooltip: barrier=false, scrim=false；Toast: barrier=false, scrim=false） |
| 6 | `dismissOnTapOutside` | 点外面关。菜单 true；模态看 `Modal::isDismissible()`；Tooltip false |
| 7 | `dismissOnEsc` | Esc 关。**与 6 分开**：`Modal(dismissible: false)` 是"吞掉 Esc 但不关"（现有语义，`:1487-1496`） |
| 8 | `focusTrap: bool` | Tab 限制。模态 true、菜单 false（菜单要能 Tab 出去） |
| 9 | `owner: ?Element` | 归属者卸载 ⇒ 自动 pop。**结构性防线**，比 lint 可靠（§7） |
| 10 | `element: ?Element` | 挂载结果。框架写、应用只读 |
| 11-12 | `x, y: float` | 定位结果。框架每帧写 |
| 13 | `restoreFocus: ?Element` | 关闭后焦点回哪。**v5 没有**，因为 v5 的焦点模型不同 |

### 3.1 `barrier` 与 `scrim` 为什么必须是两个

合成一个 `modal: bool` 会逼出两个都错的组合：

| 想要的形态 | 合成 `modal` 后的结果 |
|---|---|
| **菜单**：挡住外面点击（否则点菜单外会顺手点到下面的按钮）、**但不要变暗** | `modal=true` ⇒ 菜单背后整片变暗，视觉上像对话框 |
| **Toast**：不变暗、**也不挡**（Toast 不该吃点击） | `modal=false` ⇒ 正确；但 `modal=true` 的菜单就错了 |
| **模态对话框**：挡 + 变暗 | 正确 |

⇒ 三者需要三种组合，一个布尔只有两态。**这不是"参数太多"，是它们本来就是两件事**：
`barrier` 是**输入路由**属性，`scrim` 是**绘制**属性。

★ 非法组合：`barrier=false && scrim=true` ⇒ 构造时响亮失败。
理由：画了遮罩却不挡点击，用户会以为挡住了 —— 这是"界面在撒谎"，属 G2 级。

### 3.2 `anchor` 存 Element 不存 Rect

存 Rect 快照的三种坏法：

1. **不跟随滚动**：锚点在 `ScrollView` 里，滚一下就错位。
2. **不跟随布局变化**：窗口 resize / 兄弟节点尺寸变了，锚点位置变了，浮层留在原地。
3. **锚点消失检测不了**：Element 被卸载了，Rect 还在，浮层悬空。

代价是每帧一次 `absoluteOrigin()`：O(父链深度) × 浮层数，几百纳秒。可忽略。

★ 但**锚点也可以是一个点**（右键菜单落在指针处）。所以 `prefer === OVERLAY_AT_POINTER`
时不用 `anchor`，用 `FocusManager::lastHit()` 那次命中的指针坐标。

## 4. 定位算法

### 4.1 主流程

```
placeEntry(OverlayEntry $e, BoxConstraints $c): void
  ① 量：$box->layout(BoxConstraints::unbounded())          // 面板自尺寸
     若 (w > c.maxWidth || h > c.maxHeight)：
        $box->layout(BoxConstraints::tight(c.maxWidth, c.maxHeight))   // 超大面板退化
        w = c.maxWidth; h = c.maxHeight
  ② 锚矩形：
     anchor !== null      ⇒ [ax, ay, aw, ah] = absoluteRect(anchor)
     prefer === AT_POINTER ⇒ [ax, ay, aw, ah] = [px, py, 0, 0]
     否则（CENTER）       ⇒ 跳过 ③④，直接居中
  ③ 首选方向 → 候选原点（见 4.2 表）
  ④ 翻转：主方向放不下且反方向放得下 ⇒ 换反方向（**只翻一次**）
  ⑤ 夹取：x = clamp(x, 0, max(0, maxW - w)); y 同理
  ⑥ 写 $e->x / $e->y
```

### 4.2 首选方向表

| `prefer` | 原点 | 反方向 |
|---|---|---|
| `BELOW` | `(ax, ay + ah)` | `ABOVE` |
| `ABOVE` | `(ax, ay - h)` | `BELOW` |
| `RIGHT` | `(ax + aw, ay)` | `LEFT` |
| `LEFT` | `(ax - w, ay)` | `RIGHT` |
| `CENTER` | `((maxW-w)/2, (maxH-h)/2)` | 无 |
| `AT_POINTER` | `(ax + 4, ay + 4)` | `LEFT` / `ABOVE`（贴右下角时） |

### 4.3 为什么不做"通用避让"

**通用避让** = 依次尝试八个方向，取第一个放得下的。

否决理由（v5 原话，对我们更硬）：

> 同屏不同机弹出方向不同，**golden 无法比**。

Drift 的 golden 是**逐字节 PNG**。通用避让会让"同一个 Select 在 960×640 与 1383×729
两个窗口尺寸下弹出方向不同" ⇒ 同一份代码两张基准图 ⇒ 要么放弃 golden，要么给每个尺寸存一张。

⇒ 纪律：**只翻一次，翻不下就夹取**。夹取的结果在任何尺寸下都只依赖锚点与面板尺寸，
可复现。

### 4.4 锚点矩形的坐标系（嵌套浮层的真坑）

`RenderBox::absoluteOrigin()` 沿 `parent()` 累加到**渲染树根**（`RenderBox.php:69-80`）。
主树的根就是客户区原点 ⇒ 没问题。

但**锚点可能在另一个浮层里**（菜单里的子菜单、对话框里的 Select）：

```
主树
 └ 菜单浮层 A（画在 translate(A.x, A.y)）
     └ 菜单项「最近打开」
         └ 子菜单浮层 B 的锚点 ← 它的 absoluteOrigin 只到 A 的根盒 = (0,0)
```

⇒ B 会把原点算成 `(0, 0)` 附近，**弹到左上角**。

**解法**：给浮层根盒一个基准偏移，`absoluteOrigin()` 遇到它就加上并停止：

```php
// RenderBox 新增两个字段（唯一一处要改 Layout 层的地方）
protected float $baseX = 0.0;   // 非 0 ⇒ 本盒是某棵浮层树的根，absoluteOrigin 到此为止
protected float $baseY = 0.0;

public function setBase(float $x, float $y): void
public function baseOrigin(): array   // [x, y]

// absoluteOrigin 改为：
for ($node = $box; $node !== null; $node = $node->parent()) {
    $x += $node->offsetX();
    $y += $node->offsetY();
    if ($node->hasBase()) {          // 浮层根：加上自己的落点后停止
        $x += $node->baseX();
        $y += $node->baseY();
        break;
    }
}
```

★ `hasBase` 用一个独立 bool 而不是"`baseX !== 0`"：浮层原点**可能就是 (0,0)**
（模态），用值判会漏。

★ 这个改动有**三个消费者**，都要一起验：
1. 嵌套浮层的锚点（本节）
2. 浮层里的 IME 候选框（`imeCaretRect()` → `absoluteOrigin`）
3. 浮层里的拖放目标（将来的 `DropTarget` 命中）

`placeEntry()` 每帧把 `$e->element->effectiveBox()->setBase($e->x, $e->y)` 写一次 ——
**写在这里而不是 `Frame::run`**：`Frame` 只拿到算好的原点，它不该知道 base 的存在。

## 5. 绘制

`Frame::run` 的签名改为：

```php
/**
 * @param list<OverlayEntry> $overlays 已由 Application::placeOverlays() 算好 x/y
 */
public function run(
    Element $root,
    BoxConstraints $constraints,
    float $timestampMs,
    array $overlays = [],
): void
```

绘制段：

```php
$canvas = $this->surface->beginFrame($timestampMs);
$box->paint($canvas);

foreach ($overlays as $e) {
    // ① scrim 先画 —— ★ 必须"每个 entry 画自己的"，不能"所有 scrim 一起画在最后"：
    //    否则三层浮层时，最上面的 scrim 会把中间那层也压暗，看起来像"中间层被禁用了"。
    if ($e->scrim) {
        $canvas->drawRect(0.0, 0.0, $constraints->maxWidth, $constraints->maxHeight,
            Paint::fill(Color::rgba(0, 0, 0, 0.32)));
    }

    // ② 面板
    $pb = $e->element?->effectiveBox();
    if ($pb !== null && $pb->hasSize()) {
        $canvas->save();
        $canvas->translate($e->x, $e->y);
        $pb->paint($canvas);
        $canvas->restore();
    }
}
$this->surface->endFrame();
```

★ `translate()` 只改 PHP 侧偏移、**从不调 Skia**（既有坑）。
所以面板内的每个 draw 自己加偏移 —— 这是现有 `Frame::run` 已经在做的事，形状不变。
⇒ 换成数组只是把"一次 translate"变成"循环里 n 次"，**没有引入新坑**。

★ **绘制顺序 = 栈顺序**，不引入 z-index（与既有裁决一致）。

## 6. 命中与路由

### 6.1 指针（`dispatchPointer`）

```
for (i = count-1; i >= 0; i--):
    e = stack[i]
    inPanel = 点落在 e 的面板盒内（e.x/e.y 换算局部坐标后 hitTest）

    if inPanel:
        路由进 e（focusHit / hoverTo / 光标 / 激活）
        return

    // 点在 e 外面
    if e->barrier:
        if 相位是 down:
            if e->dismissOnTapOutside: stack->popTo(上一个)
            吞掉这次按下（不穿透）
        if 相位是 move/leave:
            focus->hoverTo(null)      // 悬停照退，但不关
        吞掉
        return

    // barrier = false（Tooltip / Toast）：继续往下问
```

★ **与现有代码的差别只有一处**：现在 `dispatchPointer` 的浮层段是 `if ($this->menuElement !== null) { ... }`
（单个），改成 `for` 循环。**语义完全一致**，只是从"一个"变成"从顶往下"。

★ **`hitsModalPanel()` 可以删掉**：它现在的存在理由是"模态盒盖满客户区 ⇒ `hitsMenu()` 恒真 ⇒
只能看命中链里有没有 `RenderPopupPanel`"。新模型下不需要这个补丁 ——
模态的 `barrier=true` 且面板盒**不盖满**（它是居中的一块），
"点没点到面板"由 `hitTest` 直接回答。

⇒ **`hitsModalPanel()`（`:1718-1727`）删除，`placeModal()` 里"紧约束盖满"（`:688-694`）删除。**
这是净减法：一个私有方法 + 一个分支消失。

### 6.2 滚轮（`dispatchInput` 的 `ScrollEvent` 分支）

与指针同构：从顶往下问，`barrier=true` 且轮在外面 ⇒ 吞掉（不穿透滚主树）。

★ 但**`barrier=false` 的浮层（Tooltip）不该吞滚轮**：用户滚页面时 Tooltip 应该跟着锚点走或直接消失。
⇒ 规则：`barrier=false` ⇒ 滚轮穿透到主树（Tooltip 自己跟随锚点，见 §9 边界表）。

### 6.3 键盘（`dispatchInput` 的 `KeyEvent` 分支）

Esc 的现有优先级链要改：

```
现在： modal !== null ? (dismissible ? closeModal : 吞) : (menuElement !== null ? closeMenu : …)
改成： for (i = count-1; i >= 0; i--):
          e = stack[i]
          if !e->dismissOnEsc: 吞掉并 return   // ★ "拒绝"不等于"放行"（既有裁决）
          stack->popTo(i-1)
          return
```

★ 保留既有裁决原文（`Application.php:1488-1490`）：

> `dismissible=false` ⇒ **吞掉但不关**。"拒绝"不等于"放行" —— 若把 ESC 交回加速键链，
> Ctrl+W 之类能绕过"必须处理的对话框"，模态就白做了。

### 6.4 焦点

`FocusManager::collect($root, array $popupRoots)` —— 把可变参数改成数组：

```php
// 现在
$this->focus?->collect($root, ...($this->menuElement !== null ? [$this->menuElement] : []));

// 改成
$roots = [];
foreach ($this->overlays->all() as $e) {
    if ($e->element !== null) { $roots[] = $e->element; }
}
$this->focus?->collect($root, $roots);
```

`focusTrap` 的实现：`collect()` 收一个 `?Element $scope`；非 null 时只收 scope 子树内的
可聚焦节点，且 Tab 到边界时**在 scope 内循环**。

★ **焦点回锚**：`pop()` 时若 `restoreFocus` 还 mounted ⇒ `focus->focusElement($restoreFocus)`；
否则 `focus->focusElement(null)`（焦点清空，下一次 Tab 从头开始）。
不做"回到上一个焦点"的猜测 —— 猜错就是焦点跑到用户没预期的地方。

## 7. 生命周期与泄漏防线

### 7.1 五个操作

| 操作 | 做什么 | 幂等 |
|---|---|---|
| `push(e)` | `panel->createElement()->mount(null, ctx)` → 入栈 → 快照 `restoreFocus` | 否（同一条目推两次是 bug，断言拦） |
| `pop()` | 出栈 → `element->unmount()` → 焦点回锚 | 是（空栈 ⇒ 无事） |
| `popTo(e)` | 关掉 e 之上全部（e=null ⇒ 全清） | 是 |
| `remove(e)` | 精确移除（owner 卸载时用，不要求它在栈顶） | 是 |
| `top()` | 读栈顶 | — |

### 7.2 `owner` 自动 pop（结构性防线）

```php
// Element::unmount() 末尾（新增一行）
$this->owner?->onElementUnmounted($this);   // 不行：Widget 层不能认识 App 层
```

★ **协议方向问题**：`Element` 在 `Drift\Widget`，`OverlayStack` 在 `Drift\App`。
§4.3 禁 `Widget → App`。所以不能直接调。

**解法：反向注册**。`OverlayStack` 维护 `ownerId => list<entry>`，并在
`Application::frame()` 的 focus.collect 段顺手清扫：

```php
// Application::frame() 新增一段（紧跟 focus.collect 之后）
// ★ 为什么放这里：这一段的语义就是"树重建完了，检查有没有节点已经不在了"。
//   focus.collect 已经在做同一件事（清掉已卸载的焦点），两件事同源。
foreach ($this->overlays->all() as $e) {
    if ($e->owner !== null && !$e->owner->isMounted()) {
        $this->overlays->remove($e);
        Errors::report(sprintf(
            '浮层 #%d 的归属节点已卸载，浮层被自动关闭。两条修法：'
            . '① 在归属节点的 dispose 路径里显式关闭它；② 别把浮层挂在会被回收的节点上。',
            $e->id,
        ), Errors::DIAGNOSTIC);
    }
}
```

★ 为什么用 `Errors::DIAGNOSTIC` 而不是直接静默：**这是应用 bug**（页面走了没关对话框），
但**不能让它炸**（用户已经看到对话框了，炸掉更糟）。Diagnostic 进环形缓冲，
smoke 与 `recentDiagnostics()` 能断言。

★ 为什么不做 lint：`owner` 是运行期赋值，静态不可判。**结构性防线 > 静态检查 > 文档承诺**。

### 7.3 受控值 ⇒ 面板重读（`overlaySignature()`，2026-10-24）

★ 本节的**前提**是本册 §2.1 那条设计：`OverlayEntry::$panel` 是**一棵独立的根渲染树**
（`mount(null, ctx)`）。好处是面板不跟着主树每帧重建；代价是**主树重建不带动面板**。

对 `Menu` / `Modal` / `Tooltip` 这类"开的那一刻内容就定了"的浮层没影响。但
`Select` / `ComboBox` 的面板内容来自**受控属性**（`loading` / 选项表 / `emptyText`）——
应用 `setState` 之后面板**不会自己重读**。远程取数就是这个形状：面板开着 → 请求回来 →
`setState` 换选项表 → 面板必须跟着变。

**声明式收口**（`Widget::overlaySignature()`，与 `pointer()` / `keyboard()` 同一族）：

```php
// Select::build() 里
return Button::make($this->label())
    ->overlayPanel($this->panelFactory())
    ->overlaySignature(fn (): string => $this->contentSignature());
```

**框架侧两道闸**（`Application::syncPanelSignatures()`，在 `placeOverlays()` 的 settle
段**之前**调）：

| 闸 | 判据 | 作用 |
|---|---|---|
| ① 锚点重建过吗 | `$e->anchor->widget() !== $e->seenAnchor` | `Widget` 不可变 ⇒ 换实例就是"那个 State 重建过"。没换 ⇒ **连签名都不算**（签名要拼整张选项表）|
| ② 内容变了吗 | `$signature() !== $e->lastSignature` | 应用每次重建都造新的 `Option` 实例，只看①会让面板每帧重建 ⇒ 滚动位置回顶部 |

★★ **签名必须是"语义"不是"身份"**：`(value,label)` 序列拼字符串，不是比对象。
★ **只有"无态"面板调 `markNeedsBuild()` 才无事发生**，而这是对的 —— 静态面板的内容
只由 Widget 决定，而面板的 Widget 是开面板那一刻造好的。
★ **为什么在 settle 之前**：标脏只是置标，重建在紧随的 settle 里；`placeEntry()` 排在
settle 之后 ⇒ "重建 → 布局"成立。放到 `Frame::run()` 的浮层 settle 段会得到"这一帧
排过的还是旧盒"，即 `76549c7` 修掉的面板空白一帧。
★ **代价（如实记录）**：面板比主树**晚一帧**（本帧 `placeOverlays()` 跑时主树还没
settle）。60fps 下 16ms，用户不可见；但用例必须跑两帧。

★★ **与私有态的分工**（这是本缝最容易被混淆的地方）：

| 面板内容取决于 | 谁负责传播 | 例子 |
|---|---|---|
| **受控属性**（住在 Widget 上） | 框架（本节） | `Select` 的三态 / 选项表；`ComboBox` 的选项表 |
| **控件私有态**（住在 State 上） | 控件自己 `Subject::notifyChanged()` | `Select` 的方向键高亮；`ComboBox` 的查询词 |

2026-10-24 之前两条都压在控件的 `didUpdateWidget()` 里，而漏掉 `parent::` 就**全静默**
（面板永不更新、不报错）；`ComboBox` 更是**根本没有**受控那条 ⇒ 面板开着换选项表
纹丝不动。收进框架后，这类坑结构上不存在。

## 8. 迁移：`showMenu` / `showModal` 保留

应用侧**零破坏**：

```php
public function showMenu(Widget $panel, ?Element $anchor = null): void
{
    if ($this->root === null) { return; }

    $anchor ??= $this->focus?->lastHit();

    $e = new OverlayEntry();
    $e->panel = $panel;
    $e->anchor = $anchor;
    $e->prefer = OverlayEntry::BELOW;
    $e->barrier = true;
    $e->scrim = false;
    $e->dismissOnTapOutside = true;
    $e->dismissOnEsc = true;
    $e->focusTrap = false;
    $e->owner = $this->currentPage();   // 无路由时 null

    $this->overlays->push($e);
}

public function showModal(Modal $modal): void
{
    if ($this->root === null) { return; }

    $e = new OverlayEntry();
    $e->panel = $modal;
    $e->anchor = null;
    $e->prefer = OverlayEntry::CENTER;
    $e->barrier = true;
    $e->scrim = true;
    $e->dismissOnTapOutside = $modal->isDismissible();
    $e->dismissOnEsc = $modal->isDismissible();
    $e->focusTrap = true;
    $e->owner = $this->currentPage();

    $this->overlays->push($e);
}
```

★ **`showModal()` 里不再有 `closeMenu()`**。这是本册唯一一处**行为变化**：
旧语义"模态与菜单天然互斥"（`Application.php:614-616` 的原话），
新语义"模态可以盖在菜单之上"。
判定：旧语义是槽位的产物，不是需求。模态在下拉之上打开是正常交互
（在下拉里点「新建分类…」弹出对话框），且关掉对话框后下拉应该还在。

⇒ 若确实要"打开模态时关掉菜单"，那是**应用的策略**（`showModal` 前自己 `closeMenu()`），
不是框架的强制。**把策略从框架挪回应用**是本册的第二条净减法。

### 8.1 兼容方法

| 方法 | 新实现 |
|---|---|
| `closeMenu()` | `overlays->popTo(null)`（全清，语义不变：它原来就清整个槽位） |
| `isMenuOpen()` | 栈里有 `barrier=true && scrim=false` 的条目 |
| `menuElement()` | 栈顶条目（测试用；名字保留，加 `@deprecated` 注释指向 `overlays()`) |
| `menuOrigin()` | 栈顶条目的 `[x, y]` |
| `closeModal()` | 找到最上面的 `scrim=true` 条目并 `remove` |
| `isModalOpen()` | 存在 `scrim=true` 的条目 |
| `modal()` | 最上面 `scrim=true` 条目的 `panel`（它是 `Modal`） |

★ `modal()` 返回类型是 `?Modal`，而 `panel` 是 `Widget` ⇒ 需要 `instanceof` 检查。
**必须 `use Drift\Widget\Modal;`** —— 漏 use 的 `instanceof` 恒 false 且不报错（咬过 3 次）。

## 9. 边界情况表（推演到底）

| # | 情况 | 规则 | 为什么 |
|---|---|---|---|
| 1 | 面板比客户区还大 | `tight(客户区)` 重量一次；内容溢出由面板自己 `Overflow::Clip` | 夹取后 w 仍 > maxW 时 `clamp` 的上界是负数 |
| 2 | 锚点被虚拟化回收（滚出视口） | `anchor->isMounted() === false` ⇒ 自动 pop | 锚点不在屏幕上了，浮层悬空是错的 |
| 3 | 锚点还在但滚出视口 | 浮层**跟着滚出去**（每帧重算 rect，可能落到客户区外 ⇒ 夹取到边缘） | 夹取会让它贴边 —— 这是可接受的降级，比"自动关"温和 |
| 4 | 窗口 resize 导致浮层放不下 | 下一帧 `place()` 重新翻转+夹取 | 无状态重算，不需要监听 resize |
| 5 | 栈里有 5 层浮层 | 允许；每层独立 barrier/scrim | 无上限。**上限由应用控制**，框架不猜 |
| 6 | 同一条目 push 两次 | 断言拦（`E-OVERLAY-DUP`） | 重复 push 会让 `element` 被覆盖 ⇒ 前一个泄漏 |
| 7 | `popTo()` 传一个不在栈里的条目 | 无事发生（幂等） | 调用方可能在竞态里传了已关的条目 |
| 8 | 浮层里的 `TextField` 获得焦点 | `imeCaretRect()` 走 `absoluteOrigin`，靠 `baseX/Y` 得到正确坐标 | 见 §4.4 消费者 2 |
| 9 | 浮层里的 `ScrollView` 滚动 | 与主树同构（命中换算减 `e.x/e.y`） | 现有代码已是这个形状 |
| 10 | 浮层里的浮层（子菜单） | `anchor` 在父浮层内 ⇒ `absoluteOrigin` 靠 base 链逐层累加 | 见 §4.4 |
| 11 | 拖动中打开浮层 | 允许；`gestureArena` 与浮层无关（arena 只认主树命中） | 拖动中的浮层（如拖放 feedback）走 `barrier=false` |
| 12 | `barrier=false && scrim=true` | 构造时响亮失败 | 界面撒谎（§3.1） |
| 13 | 模态打开时窗口失焦 | **不关**（v5 判据） | 切到别的程序再回来，对话框还在是正常的 |
| 14 | 模态里再开模态 | 允许；`focusTrap` 只最上面那层生效 | 栈天然支持 |
| 15 | 关闭浮层后焦点回锚，但锚点已卸载 | 焦点清空（`focusElement(null)`） | 不猜 |

## 10. 备选方案与否决

| 备选 | 否决理由 |
|---|---|
| **加第二个槽位**（`$menu2`） | 治标。第三个浮层又不够；且 `placeMenu` 要复制一份 |
| **把浮层做成树的一部分**（`Stack` + 绝对定位，v6 的"节点形态"） | 浮层需要的"盖满客户区 + 独立焦点域 + 独立命中域"用树内节点表达要给每个祖先加特判。★ 2026-10-22 起 `Stack` 原语已落地（W6 L4-4）⇒ "没有 `Stack` 所以做不了"这条前提**已失效**，但结论不变：`Stack` 解决的是**层叠**，不是**独立焦点域 / 命中域** |
| **每个浮层一个 `Application` 级回调表** | 等价于栈，但顺序要靠注册序 —— 注册序不是绘制序 |
| **`modal: bool` 单参数** | 见 §3.1，两态表达不了三种形态 |
| **存 anchor 的 Rect 快照** | 见 §3.2，三种坏法 |
| **通用避让（8 方向尝试）** | 见 §4.3，golden 不可比 |
| **`showModal()` 保留 `closeMenu()`** | 见 §8，那是槽位产物不是需求 |

### 推翻条件

| 决策 | 什么情况下应推翻 |
|---|---|
| 浮层不挂进主树（第二棵根渲染树） | 若出现"浮层要参与父容器的布局"（如内联 Tooltip 撑开行高）⇒ 那根本不是浮层，是 `Stack` 里的普通节点 |
| 只翻一次方向 | 若真机上出现"翻一次仍放不下、夹取后完全遮挡锚点"的高频场景 ⇒ 加"翻两次"（主→反→贴边），仍不做 8 方向 |
| `barrier` / `scrim` 分离 | 无。这是两件事 |
| `owner` 自动 pop + Diagnostic | 若 Diagnostic 在正常业务里被高频触发（说明"页面卸载但保留浮层"是常见需求）⇒ 改成显式 `detach()` 保留 |

## 11. 失败模式

| # | 失败 | 表现 | 防线 |
|---|---|---|---|
| 1 | 浮层原点没进 `absoluteOrigin` | 浮层里的 IME 候选框贴屏幕左上角 | `baseX/baseY` + smoke 夹具（浮层里的 TextField） |
