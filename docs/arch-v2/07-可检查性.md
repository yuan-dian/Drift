### 1.5 golden 是**量具**，不是测试套件

`tools/golden-raster.php` 的头注释：

> ★ 这不是测试套件是**量具**：改 canvas 的人自己跑，md5 一个字节都不许变。
> 覆盖路径：opaque/半透明/圆角/描边-hole/裁剪/save-translate/段落字形。

用法是**手工**的：

```bash
php tools/golden-raster.php > _build/golden-before.txt
（改动）
php tools/golden-raster.php > _build/golden-after.txt
diff _build/golden-before.txt _build/golden-after.txt   # 必须无输出
```

★ 这个定位**是对的**：golden 一旦进 CI 就变成"每次改动都要重生成基线"，
而重生成基线的那个动作会掩盖真回归。做成"人自己跑、diff 必须空"，
责任落回改动者身上。

★ 但它有个**代价**：没有 CI 兜底 ⇒ 有人改了 `RasterCanvas` 忘了跑，
回归就漏了。本册**不改这个定位**（理由见 §12），只加一条：
`05` 的 `RasterCanvas` 改动**必须在提交信息里贴 diff 结果**（纪律，不是机制）。

## 2. 四条盲区（三条已知 + 一条新发现）

### 2.1 B1：`DeadCommand` 查配对，不查 handler 分支

`DeadCommand`（209 行）双向检查"发出的名字必须在注册集、注册集里每条必须被发出"。
但它**不查**"注册了但 handler 里没这个分支"。

`NavigationCommands::handleCommand()` 用前缀动态路由：

```php
if (str_starts_with($name, 'nav.')) { … }
```

前缀路由**静态不可判**（`nav.` 后面可以是任意字符串）。

★ **这是"宁漏不误响"的自觉取舍**，不是缺陷。本册**保持**。
处置：在 `07` 这一节里记下来，让后来人知道"这里有个洞，是故意的"。

### 2.2 B2：`internal-leak` 查类型不查方法

`State::markDirty()` 标 `@internal`（`State.php:79`），但应用代码调了 **5 次**：

```
apps/showcase/src/Pages/MotionPage.php:88, :116, :122, :128, :134
```

用法是 `tickFrame()` 里改完值之后标脏 —— **合法需求**（`setState(fn() => null)`
裹一层空闭包很别扭），但**没有 `@api` 入口**。

⇒ 这是"标记与用法打架"：不是代码错了，是**标记错了**。

**处置两步**：

| 步 | 动作 |
|---|---|
| ① | `State::markDirty()` 升 `@api`（`03` §6.4），docblock 写清与 `setState()` 的分工 |
| ② | `internal-leak` 加"方法级"检查：`@internal` 方法被非 `Drift\` 代码调用 ⇒ WARN |

★ ② 的误报风险：`@internal` 方法很多（`bindTo` / `consumeDirty` / `adoptBoxes`…），
而它们**大部分**确实只被框架调。所以判据要精确：**只查"被 `apps/` 与 `tools/Smoke/`
调用的 `@internal` 方法"**，且报 WARN 不报 ERROR（允许豁免标注）。

★ 为什么先升 `@api` 再加 lint：如果先加 lint，那 5 处会立刻变成 WARN，
而它们**是对的用法** —— 那会把一条正确的代码标记成问题，是坏的量具。

#### 2.2.1 落地实况（2026-10-22，W7 第 40 步）

**判据没按原稿写，因为原稿的写法会误报到不能用。**

原稿：`@internal` 方法被非 `Drift\` 代码调用 ⇒ WARN。落地时先量了规模：
`src/` 里"只有 `@internal` 标注、没有任何 `@api` 同名"的方法名有 **93 个**，
其中 `tick` / `start` / `finish` / `reset` / `box` / `slot` / `of` / `kind` 这类
**到处重名**。按名字匹配 ⇒ 应用自己的 `$ctrl->reset()` 全被标成泄漏。
误报比漏报贵得多：人会开始整条忽略这条规则，量具就死了。

⇒ 改成**只报接收者能静态解析的调用**，解析不出来就**跳过**：

| 形态 | 解析方式 |
|---|---|
| `Cls::m()` | 类名直接可解析（`use` 别名 / 同命名空间回退） |
| `self::m()` / `static::m()` | 当前类 |
| `parent::m()` | 当前类的父类（`extends` 时已登记） |
| `$this->m()` | 当前类，沿 `extends` 链找声明（**子类覆写优先**） |
| `$var->m()` | `$var` 的类型来自 `new` 赋值 / 参数类型 / 属性类型 |
| `foo()->m()` / `$a['k']->m()` | **不收**（链式接收者，不猜） |

落点：`SourceFile` 新增四个事实表 `methods()` / `parents()` / `varTypes()` /
`calls()`（都是 token 扫描的副产物，不新增一趟）；`InternalLeak` 拆成
`checkTypes()` + `checkMethods()`；`Tokens` 补 `nextIndex()` / `prevIndex()`
（写调用点时要"再往后看一个"）。

★ **只报"声明在框架类里"的内部方法**。应用给自己类的方法标 `@internal`
（同包私有）是合法用法 —— 实测 `apps/users` 有 3 处 `$this->mutate()` 撞在这条上。
判据用 `Project::isFrameworkFqn()`。

★★ **`Project::isFramework()` 不能只看命名空间**。`src/Platform/Win32/ResizeHook.php`
**刻意不带** `namespace`（AOT 下 C++ 壳按符号名直接调一个全局具名入口，带前缀就找不到）
⇒ 只看命名空间会把框架文件判成"消费者"，于是框架内部互调被报成泄漏（实测命中）。
判据要落到**物理位置**：composer.json 的前缀表 `src/` ⇒ `Drift`。

★ **顺手修了一处"标记与用法打架"**：`Widget::mutate()` 原来是 `@internal`，
但它是 `final protected` 的**封存守卫** —— 应用自定义 Widget 写自己的链式方法时
**必须**调它（否则那些方法能绕过封存、在挂载后改字段，`§10.1` 的不可变纪律从
这一处漏光）。升 `@api`（`protected` + `@api` = 子类扩展点），docblock 写清职责。
同 L6-1 的 `markDirty`：**改标记，不改用法**。

**量具侧证据**（`--selftest` 18/18，`internal-leak` 该响 5 条）：

| 夹具 | 验什么 | 期望 |
|---|---|---|
| `apps/MethodBad.php` | `$this->`（沿链）/ `Cls::`（静态）/ `$var->`（参数类型）三种可解析接收者 | 3 条 WARN |
| `apps/MethodGood.php` | ①调 `@api` 方法 ②调**自己覆写**的同名方法 ③接收者是 `foo()->m()` | 0 条 |

★ 第 ② 条是"覆写优先"的判据：`@internal` 在基类、覆写后就是应用自己的方法，
不该报 —— 这也是"沿链找声明"必须从**子类开始**的原因。
★ 第 ③ 条把"不猜"写成断言：`foo()->m()` 永远不报，即使 `m` 真是内部方法。
**故意漏**，因为猜错的代价是误报。

**全仓实况**：421 个文件 **0 error / 0 warn**（方法级上线后归零）。

### 2.3 B3：改基类方法前没人数覆写点

`Element::settle()` 有 **2 个定义点**（`Element.php:282` + `ErrorBoundaryElement.php:45`）。
`03` §5.1 的方案要把它拆成 `settle()` + `settlePass()`，如果只改基类，
`ErrorBoundaryElement` 的覆写会**静默失效**（错误边界从"到节点"退化成"到整帧"，
不报错、不崩，只在真出错那天才看得见）。

⇒ 这不是 lint 能抓的（"覆写了一个方法"本身没错）。**两条处置，第二条更强**：

**① 流程纪律**（弱）：改一个基类方法前，先 `grep -rn "function <名字>" src/ apps/` 数覆写点。

**② `#[\Override]`（强，`10` §2 A1）**：给"基类**有默认实现**"的覆写方法标 `#[\Override]`。
标完之后，改基类方法名 ⇒ 编译器把每一处覆写点按 `file:line` 报出来。
**不需要人记得跑任何脚本**，而且这是**编译期强制**，不是纪律。

★ **★ 反斜杠不能省**：`src/` 里 222/223 个文件都在命名空间里 ⇒ 写 `#[Override]` 会解析成
`Drift\Widget\Override`，**编译期零效果、不报错、构建照样通过**（`10` §2 A0）。
所以这一步与 lint `attribute-unqualified` 必须同批，且 **lint 先上**。

```php
#[\Override]
protected function settlePass(): void { ... }   // 父类若没有同名方法 ⇒ 编译错
```

★ 增量价值的边界（不要夸大）：**抽象方法**（`performLayout` 21 / `intrinsicWidth` 15 /
`paint` 22）漏覆写本来就是编译错，`#[\Override]` 对它们**零增量**。
真正被救的是**非抽象**的那批：`adoptBoxes`（6）、`build`（14，`02` §6.3 给它加默认实现后）、
`settlePass`（1）、`hitTestSelf` / `overflow` / `rebuild` / `unmount` …

★ **原计划的 `tools/overrides.php` 因此取消**（`09` §3 W0 第 8 步改为 A0+A1）。
理由：`#[\Override]` 的输出与它完全相同，但**自动、不漏、不依赖人记得**。
`grep -rn "function settlePass" src/` 也做得到同样的事 —— 那个脚本本来就是冗余的。

### 2.4 B4（新发现）：注释里写的"机制原因"会腐烂

`SubjectBuilder.php:29-31`：

> ② 返回值该是"代表变化的最小值"（摘要），返回每次新建的对象/**数组** ⇒ `===`
>   永不相等 ⇒ 退化成每帧重建

**这句话对数组是错的**（PHP 的 `===` 对数组是逐键值严格比较）。而它守着的机制
（lint `select-purity`）是对的 —— 于是**没人会去验证注释**，因为代码一直工作正常。

⇒ 同类风险在别处也存在。本册加一条**写注释的纪律**（不是机制）：

| 判据 | 说明 |
|---|---|
| 注释里写"因为 X 所以 Y"时，X 必须是**可执行验证**的 | 要么写进 smoke 夹具，要么不写"因为" |

## 3. 判据：「忘写」→「写不出来」的三级阶梯

这是本册的核心。**每一条新约束都该问：它能做到第几级？**

### 3.1 三级

| 级 | 手段 | 效果 | 成本 |
|---|---|---|---|
| **L1 写不出来** | 类型系统 / 构造函数必填 / `final` / 私有构造 | 错误**在编辑器里**就红了 | 低（设计时想清楚） |
| **L2 写出来就报** | lint / 运行期断言 / 自校验 | 错误**在构建或首帧**就报 | 中 |
| **L3 报不出来就断言** | smoke / conformance / golden | 错误**在 CI** 报 | 高（要写夹具） |

★ **优先级：能用 L1 就不用 L2，能用 L2 就不用 L3。**
理由：L3 的夹具是**逐条手写**的（成本随约束数量线性增长），而 L1 一旦建立，
**所有**违反都免费被抓。

### 3.2 本仓已经用到哪一级（逐条对账）

| 约束 | 现在的手段 | 级 | 能否升级 |
|---|---|---|---|
| 会超的容器必须声明溢出策略 | `RenderFlex::__construct` 的 `$overflow` **无默认值** | **L1** | — 已最优 |
| `Cell` 必须绑定 `State` | 运行期 Fatal（`Cell.php:61`） | L2 | **升 L1**：构造函数私有（`03` §3.2） |
| `State` 的 `watch()` 只能在 `initState()` | 运行期守卫（`State.php:165-167`） | L2 | 不可升（PHP 没有"只在某方法内可调"的类型） |
| `settle()` 的循环不能被覆写绕过 | 无（靠注释） | — | **升 L1**：`settle()` 改 `final`（`03` §5.1） |
| 修饰是字段不是节点 | 无 | — | 不可（是约定） |
| `instanceof` 必须 `use` | lint `instanceof-missing-use` | L2 | — 已最优 |
| **内置注解必须写 `#[\X]`** | 无（靠人记得，且漏了**不报错**） | — | **升 L2**：lint `attribute-unqualified`（`10` §2 A0，W0） |
| **改基类方法名不能静默脱钩** | 无（`protected` 非抽象 ⇒ 零警告） | — | **升 L1**：`#[\Override]`（`10` §2 A1，W0） |
| 命令双向可达 | lint `dead-command` | L2 | — 已最优（B1 是自觉取舍） |
| 布局是纯函数 | 无（只有 docblock） | — | **升 L2**：`LayoutSelfCheck`（`04` §5.2） |
| 帧段顺序 | 无（只有注释） | — | **升 L2**：`FramePhase` 断言（`06` §2.4） |
| 控件不许 `instanceof RasterCanvas` | 无 | — | **升 L2**：lint `backend-branch`（`05` §2.5） |
| Optional op 前必须查能力位 | 无 | — | **升 L2**：lint `optional-op-guard`（`05` §2.5） |
| 同一帧不能 rebuild 两次 | 无（静默每帧重建） | — | **升 L2**：`noteRebuilt()`（`03` §5.3） |
| 业务层不依赖 UI 层 | 无（现状 0 违规，但没人守） | — | **升 L2**：lint `store-imports-ui`（`03` §6.3） |
| 属性初始化器不许 `new Cell` | 运行期 Fatal（陷阱） | L2 | **升 L1**：构造函数私有（同上） |

★ 这张表就是本方案的**可检查性总账**：15 条约束里，**9 条要新建或升级**，
其中 4 条能升到 L1（免费的），5 条升到 L2。

★ 后加的两条（`attribute-unqualified` / `#[\Override]`）是同一族的**第二、三次出现**：
`instanceof` 漏 `use` 咬过 3 次，注解漏 `\` 是同一形状（**名字解析错了，不报错，只是没效果**）。
它们的处置也一样 —— **不写纪律，写 lint**。

### 3.3 为什么 L1 优先：三个例子的成本对比

| 约束 | 若用 L3（smoke） | 若用 L1（类型） |
|---|---|---|
| 会超的容器必须声明溢出策略 | 要为每个容器写"不声明就报错"的夹具，且**新增容器时忘了写夹具就漏了** | 构造函数必填 ⇒ 新容器**不写就编译不过** |
| `Cell` 必须绑定 | 要写夹具"未绑定的 Cell 写入报错" | 构造函数私有 ⇒ **造不出来** |
| `settle()` 不被绕过 | 要写夹具"覆写 settle 只包一遍时异常冒到 Frame"（极难写） | `final` ⇒ **覆写不了** |

⇒ **L1 的收益随"未来新增的同类代码量"增长，而 L3 的收益固定（只覆盖已写的夹具）。**

|---|---|

| 自动快照（每次跑存一张图） | golden 已经证明"md5 手工 diff"更好（§1.5）。自动快照会掩盖真回归 |

## 5. 几何断言升为一等公民

### 5.1 现状

938 条断言里，**197 行**涉及 `size()` / `offsetX()` / `offsetY()`。
它们的形式是散落的：

```php
check('padding 生效', $box->offsetX() === 8.0, 'got ' . $box->offsetX());
check('宽 100', $box->size()->width === 100.0, 'got ' . $box->size()->width);
```

⇒ 两条断言、两次手写、两次字符串拼接。而几何断言通常要**四个数一起**：

### 5.2 `expectBox()` 助手

```php
/**
 * 断言某个盒的矩形（客户区坐标）。
 *
 * ★ 为什么用 `absoluteOrigin()` 而不是自己沿父链累加：MEMORY 记着
 *   "真机量出的'盒左边'要以 `absoluteOrigin` 为准"（像素扫描会把标签/分节线
 *   当成边框，差过 21px）。
 *
 * ★ 为什么四个数一起：几何错通常是"整体偏了一个 padding"，
 *   分开断言会得到四条消息，合起来一条就够定位。
 */
function expectBox(RenderBox $box, float $x, float $y, float $w, float $h, string $name = ''): void
{
    [$ax, $ay] = RenderBox::absoluteOrigin($box);
    $size = $box->size();

    $ok = $ax === $x && $ay === $y
        && $size !== null && $size->width === $w && $size->height === $h;

    check(
        $name !== '' ? $name : '盒矩形',
        $ok,
        sprintf('期望 (%.1f, %.1f, %.1f×%.1f)，实际 (%.1f, %.1f, %s×%s)',
            $x, $y, $w, $h, $ax, $ay,
            $size === null ? 'null' : (string) $size->width,
            $size === null ? 'null' : (string) $size->height),
    );
}
```

#### 5.2.1 落地实况（2026-10-22，W7 第 41 步）

`expectBox()` 已进 `tools/smoke.php`（`boxOrigin()` 之后）。与原稿的三处差异：

| 项 | 原稿 | 落地 |
|---|---|---|
| 签名 | `expectBox(RenderBox $box, …)` | `expectBox(?RenderBox $box, …)` —— 盒为 null 时**断言失败并写明原因**，不是 TypeError |
| 盒没 layout | 未提 | `size()` 为 null 单独一条消息（`07` §9 第 5 条） |
| 反例自检 | 未提 | **必须**：子进程用例 `--case=expectbox` 故意给错期望，外层断言"它真的会红" |

★ **助手自己也要有反向自检**（G2）。只写正例的助手等于"永远绿" —— 它自己算错了
也看不出来。做法与 `lint --selftest` 同理：`runCase(__FILE__, 'expectbox', null)`
跑一个故意错的子进程，断言三条 FAIL 都出现且消息里带"期望 … 实际 …"两组数。

★★ **子进程用例块必须写在 `--case=` 链内**：链尾有一句
`exit(0); // 走到这里说明"该中止的没中止"` = "未知用例静默退出 0" ⇒ 放在链外的
用例块**永远不执行**，现象是子进程**零输出**、外层断言拿到空字符串。

**改写了 10 条现有几何断言**（`07` §8 的原话：只改 10 条，验证助手可用）：

| # | 断言 | 改法 |
|---|---|---|
| 1 | `Layout · absoluteOrigin 补回内容原点（0 + 4, 0 + 2）` | 原来是 2 个数 → 补上尺寸 ⇒ `(4, 2) 10×6`（**真原点**） |
| 2 | `Layout · RenderProxy + mods 内距：盒尺寸也加了内距` | 补上原点 `(0,0)` |
| 3 | `Stack · Loose 尺寸 = 最大子` | 同上 ⇒ `(0,0) 100×80` |
| 4 | `Stack · Expand 有界轴拉满` | ⇒ `(0,0) 100×80` |
| 5 | `Stack · Expand 的无界轴退化` | ⇒ `(0,0) 40×40` |
| 6–10 | `Dock · top/bottom/left/right/center` 五槽 | 4 条断言 → **5 条**，全部改绝对矩形 |

★ Dock 那组是这次最值的改写：原写法只断 `offsetX/Y`（**相对内容盒**）+ 部分尺寸 ——
`left` 槽的 x 与宽、`right` 槽的宽**没人管**。改成绝对矩形后五槽的四个数全钉住，
且 `center (30,20) 45×65` 这种非零原点顺手证明了 `absoluteOrigin()` 的父链累加是对的。

★ 第 1 条保留原断言名并加了"尺寸不变"：它测的是**内容原点补回**，不是尺寸；
但既然要断矩形，尺寸一起断更省事 —— 尺寸若变，这条会先红。

★ 数字没有一个是"跑出来再抄回去"的：尺寸来自原断言，原点来自 `absoluteOrigin()`
的定义（root 盒 = 0，孩子 = 父内容原点 + 子 offset）。改完 10 条**一次全绿**，
说明这套数字是**推出来的**、不是拟合的。

smoke 1071 → **1073**（Dock 4 条 → 5 条 + 量具自检 1 条）。

### 5.3 为什么不用容差

| 方案 | 问题 |
|---|---|
| `abs($actual - $expected) < 0.5` | 布局是**确定性**的（同样的约束 + 同样的树 ⇒ 同样的浮点运算顺序）⇒ 容差会掩盖"差了 0.3px"的真实 bug |
| `===`（严格） | 唯一正确的做法 |

★ 与 `04` §5.2 的自校验同一条判据：**浮点误差在纯函数里是确定的，加容差等于允许"轻微不纯"。**

★ 唯一的例外：**涉及字体度量的断言**（`Text` 的宽高依赖 `DeterministicMetricsProvider`，
它是确定性的，但换字体文件就变）。⇒ 那类断言用 `>=`/`<=` 上界，不用容差。

### 6.2 三档

抄 v6 `15` §3，按我们的段名落地：

| 档 | 什么时候 | 推什么 | 成本 |
|---|---|---|---|
| **full** | 结构变了（节点增删）/ 首次 | 全量 `nodes` | O(树) |
| **delta** | 只有属性变了（label / value / enabled） | 只推变了的节点的 `[index, key, value]` | O(变化数) |
| **coalesce** | 滚动 / 动画期间 | 攒起来，帧末合并成一次 | O(变化数) |

**判据（怎么知道结构变了）**：`06` 的 `State::$pendingDirty` 不够（它只说明"有 State 脏"）。
需要**结构版本号**：

```php
// Element
private static int $structureVersion = 0;

/** @internal `mount()` / `unmount()` / `updateChildren()` 里 +1 */
public static function bumpStructure(): void
```

`Application` 记住上一帧的 `$structureVersion`：

```php
$version = Element::structureVersion();
$mode = $version !== $this->lastStructureVersion ? 'full'
      : ($this->scrolling || $this->animating ? 'coalesce' : 'delta');
```

#### 6.2.1 落地实况（2026-10-22，W7 第 43 步）

**只落两档**（`full` / `coalesce`），`delta` 按 §6.4 的诚实结论**没做**。

| 档 | 判据 | 行为 |
|---|---|---|
| `full` | 结构版本号变了 **或** 焦点变了 | **立即**推整棵（不看 coalesce，也不看 D1 节流） |
| `coalesce` | 动画中（`$animating`）、结构没变 | 攒着，**每 4 帧**合并推一次（`SEMANTICS_COALESCE_MAX = 4`） |
| `none` | 没 sink | 零开销（早退，连版本号都不读） |

**结构版本号**（`Element`）：

```php
private static int $structureVersion = 0;
public static function bumpStructure(): void   // mount() / unmount() / 子表重排
public static function structureVersion(): int
```

★★ **`updateChildren()` 绝不能无条件 +1**。它**每次 rebuild 都会被调**，无条件 +1
会让版本号每帧都变 ⇒ "结构没变"永远判不出来（等于没做）。所以判据是
`compositionChanged($old, $next)`：数量不同、或**某个位置上的实例换了**才算变。

★ 为什么要在 `updateChildren()` 里单独判一次：**重排也算结构变**（语义树的顺序
变了），而重排**不触发** `mount()`/`unmount()`（子被复用）⇒ 只靠那两个钩子会漏。

★★ **`delta` 没做的诚实理由**（§6.4 的结论在落地时复核过）：精确 diff 要"每个
节点记住上次推的值"，那是 O(树) 的额外内存；没有字段表就只能推"整棵树的当前值"，
省的是序列化与 IPC、**不是遍历** ⇒ 是个"每帧仍遍历全树、只少一次序列化"的半成品。
硬做它只会让文档上写着三档、实际只省了 1%。**两档 + 明确的"delta 待评估"更诚实。**

★ **`scrolling` 这个状态不存在**：本仓的滚动是**一次性事件**（滚轮 → `scrollBy()`
→ `setState()`），没有"滚动中"的持续状态 ⇒ coalesce 只由 `$animating` 触发。
滚动引发的结构变化（虚拟列表换行）走 `full` —— 那正是对的：**行换了就不能攒**
（增量表达不了"多了几个节点"，攒着会让读屏的树与真实树错位）。

★ 观察面：`Application::semanticsMode()`（`@internal`）返回上次推送的档位 ——
没有它，夹具只能数推送次数，"走的是哪一档"验不出来。

**夹具 6 条**（smoke 1077 → **1083**）：

| # | 断言 | 反例方向 |
|---|---|---|
| ㉑ | 结构版本号随挂载增长（`mount()` 里 +1） | 不 +1 ⇒ 首帧判不出结构变 |
| ㉒ | 首帧结构变了 ⇒ 推 `full` | — |
| ㉓ | 动画中 8 帧 ⇒ 推 **2** 次（每 4 帧） | 不攒 ⇒ 8 次 |
| ㉔ | 动画每帧重建但结构没变 ⇒ 版本号**不动** | `updateChildren` 无条件 +1 ⇒ 版本号涨 |
| ㉕ | coalesce 第 1 帧**不推**（攒着） | "没走 coalesce"这条会照过 ⇒ 用"不推"当区分性证据 |
| ㉖ | 虚拟列表滚动换了行 ⇒ 结构变 ⇒ 立即 `full` | 把滚动当 coalesce ⇒ 读屏树错位 |

### 6.3 焦点永不节流

| 事件 | 推送 |
|---|---|
| 焦点变化 | **立即 full**（不管当前是哪一档） |
| `announce`（live region） | 500ms 节流（v6 `15` §5） |
| 滚动 / 动画 | coalesce |

★ 理由：**读屏用户靠焦点知道"我在哪"**。焦点延迟 50ms 就会让人怀疑键盘失灵。

### 6.4 1.0ms 预算

| 项 | 值 |
|---|---|
| 每帧语义推送预算 | **1.0ms** |
| 超了怎么办 | 本帧降为 coalesce（攒着，下帧一起推） |
| 怎么测 | `SurfaceProfile` 的 `semantics` 段已经在记 |

★ **不做的**：delta 的精确 diff（"哪个节点的哪个属性变了"）需要每个节点记上次推送的值 ——
那是 `O(树)` 的额外内存。**用结构版本号做粗判**（结构没变就推 delta，但 delta 的内容
仍是"整棵树的当前值"）⇒ 省的是**序列化与 IPC**，不是遍历。

⇒ 诚实结论：**delta 档在现状下省不到 O(树)**。真正省的是"无 sink"（已经做了）
与"coalesce"（攒帧）。**所以本册只实现 full / coalesce 两档，delta 记为"结构版本号落地后再评估"。**

★ 这条是**对 v6 三档的一处诚实降级**：v6 有 `Spec::FIELDS` 字段表 + 脏位，
它能 O(1) 知道"哪个字段变了"；我们没有。硬做 delta 会得到一个"每帧仍遍历全树、
但少一次序列化"的半成品。

## 9. 边界情况

| # | 情形 | 期望行为 |
|---|---|---|
| 1 | 某条 lint 规则在夹具上零发现 | `selftest` 的第 ③ 项会报"产出了发现但没配夹具断言"（反向：**配了断言但零发现**也要报） |
| 2 | 新加一条 lint 但没配夹具 | `selftest` 报（同上） |
| 3 | `internal-leak` 方法级检查误报 | 报 WARN 不报 ERROR；允许 `@api` 标注消掉。**接收者解析不出来时一律不报**（`foo()->m()`），宁可漏 |
| 4 | 标了 `#[\Override]` 但父类真没这个方法 | **编译错**（`10` §2 A1）—— 这是好事，它防的是「以为在覆写、其实没覆写」 |
| 5 | `expectBox()` 的盒 `size()` 为 null | 断言失败，消息里写 `null`（不是崩溃） |
| 6 | `TestApp` 场景里 `pump()` 之前就 `expect()` | 允许（有些断言测的就是"首帧之前的状态"） |
| 7 | `TestApp` 场景里 `expect()` 抛异常 | 该场景失败，其余场景继续（不中止整个文件） |
| 8 | 语义 `full` 档但树是空的 | 推空数组（sink 自己要处理） |
| 9 | 结构版本号溢出（int 上限） | 不可能（每帧最多几十次 +1，`PHP_INT_MAX` 是 9.2e18） |
| 10 | `coalesce` 攒了 100 帧没推 | 必须有上限：攒到第 4 帧强制推一次（否则读屏停摆） |

★ 第 10 条要有明确实现：`coalesce` 的"攒"必须有**帧数上限 4**，
与 `06` §3.4 的 D1 同值。否则"滚动期间一直不推"会让读屏用户完全失去反馈。

## 12. 备选方案与否决

| 备选 | 否决理由 |
|---|---|
| **把 golden 进 CI** | §1.5：自动重生成基线会掩盖真回归。保持"人跑 + diff 必须空" |
| **断言 DSL（字符串表达式求值）** | `nano-hygiene` 禁 `eval`；且字符串里的表达式编辑器看不见 |
| **选择器 DSL（CSS 式）** | 需要给所有 Widget 加 `id` ⇒ 为测试改产品 |
| **自动快照（每次存图）** | 同 golden；且没有"必须无 diff"的强制力 |
| **录制回放鼠标事件** | 坐标依赖窗口尺寸，跨机器失效 |
| **迁移 938 条断言到 `TestApp`** | 0 收益 + 高回归风险；只改 10 条证明助手可用 |
| **`DeadCommand` 加 handler 分支检查** | 前缀动态路由静态不可判；保持"宁漏不误响" |
| **语义 `delta` 档（精确 diff）** | §6.4：需要每节点记上次值 = O(树) 内存；硬做只得半成品 |
| **几何断言用容差** | §5.3：布局是确定性的 |
| **`TestApp` 用 `eval` 求值字符串表达式** | `nano-hygiene` 是对的，不给测试开后门 |

### 推翻条件

| 裁决 | 什么情况下推翻 |
|---|---|
| golden 不进 CI | 出现"改了 Raster 忘了跑 golden"导致的真回归 ⇒ 改成 CI 跑但**只报警不自动更新基线** |
| 只做 full / coalesce | 语义推送成为帧预算的瓶颈（`SurfaceProfile` 的 `semantics` 段 > 1ms 常态）⇒ 那时才做 delta |
| 不迁移 938 条断言 | `TestApp` 用半年之后，如果新场景 90% 都用它 ⇒ 那时再批量迁移 |
| `coalesce` 上限 4 | 读屏用户反馈"滚动时反馈太慢" ⇒ 降到 2 |
