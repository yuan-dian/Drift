# 裁决索引

> 一张表回答"这件事现在定成什么样、什么时候该重新讨论"。只登记已经拍板的结论；待办、进度与讨论过程不进这张表。

新裁决必须同时写清**失效条件**：写不出失效条件，说明这条结论还没有真正想清楚。失效条件被触发时，先重开裁决、再改代码，不要直接改实现。旧的过程稿与战报不是裁决依据，需要考古时用 git 历史。

## 架构与表达

| # | 主题 | 现行结论 | 失效条件 |
|---|---|---|---|
| A1 | 三棵树与组合根 | Widget / Element / RenderObject 三树 + 单向下行 + 组合根注入；`BuildContext` 是只读环境快照，无 `of()` 式向上查找。 | 出现无法逐层传值的深层场景，且实测组合成本超过帧预算门槛。 |
| A2 | 读点响应式 | **读自动、写显式**：`build()` 期读 `Cell` / `Computed` 自动登记依赖，重建边界 = 读点所在 `State` 的子树（`Bind` / `Text::of` / `LiveText` 逐级收窄）；写入永远是显式调用（`Cell::set/update` 或 `setState`）。**不做**可变对象的透明代理（Vue `reactive()` 式"改属性即追踪"）。原表述"不做自动依赖追踪"已在 11-21 R0 落地后被推翻。 | 出现读点自动登记表达不了的依赖形状；或显式写入在真实应用里成为交付瓶颈，且有可验证的代理方案（含 AOT 生成物形状）。 |
| A3 | 双向绑定 | 不做；控件受控，点击只回调新值，值由应用改。 | 表单类应用出现无法用受控模型表达的交互契约。 |
| A4 | 原生控件包装 | 不做；界面全自绘。 | 无障碍或输入法出现自绘无法满足的硬性采购/平台要求。 |
| A5 | CSS 层叠与流式布局 | 不做；单遍约束布局。 | 出现需要文档流排版的真实产品形态，且成本可承受。 |
| A6 | 增量布局与 damage rect | 不做；整树重排，布局为纯函数。 | 以 `FrameTaxMeasure` 在目标节点规模复量，重排占用超过帧预算的一半。 |
| A7 | 命令标识 | 用字符串名 + `CommandRouter` + Element 冒泡链，不用整数命令 ID。 | 命令派发成为可测量的性能热点，且命名方案无法优化。 |
| A8 | 结构性重写 | D1–D7 剩余项不打包重写；按真实消费者逐项推进。 | 出现新的 P0 结构缺陷，或现有债务触发其重裁条件。 |
| A9 | 盒 chrome 单点 | 盒的"底 → 边框（含虚线）→ 圆角"只有一个实现 `BoxChrome::paint()`；`Modifier` 与 5 个自绘 chrome 盒共用。阴影**不在内**（Button 的 hover 阴影是动态、PopupPanel 有 fallback，语义不同）。 | 出现需要不同 chrome 语义的盒（例如逐边不同色/不同圆角），`BoxChrome` 无法用一个签名表达。 |
| A10 | 单轴滚动宿主 trait | 滚动 State 的共用面分两层。`SingleAxisScrollHost`：`lane()` + `tickFrame()`，三个单轴宿主（ScrollView/LazyList/TextArea）共用，`$lane` 字段留各类。`ScrollViewHost`（内嵌上一层）：`Scrollable` / `ScrollMetrics` 的八个读方法（`maxOffset`/`scrollTo`/`animateTo`/`scrollAxis`/`viewportExtent`/`scrollByAxis`/`glideByAxis`/`ensureVisible`）只给查 `RenderScrollView` 的两个宿主，各类只回答 `mainAxis()` / `scrollBox()` / `scrollController()` 三个事实。`scrollBy()` 仍各自实现（懒列表多一步换窗），`TextArea` 不进第二层（盒是 `RenderTextArea`，没有 `revealDelta()`）。 | 出现第 4 个单轴滚动宿主，或其 `tickFrame` 需要不同帧语义（如惯性刹车只作用于某类）；或 `TextArea` 的盒也长出 `revealDelta()` 一致的几何契约（届时两层合并）。 |
| A11 | 多子盒实现面 trait | 四个多子盒（Flex/Wrap/Stack/SegmentedControl）的 `addChild`/`clearChildren`/`children`/`visitChildren`/`paintContent` 收进 `MultiChildBox` trait；类型识别仍走 `ChildContainer` 接口，**不换父类**（D2 裁决：四盒布局算法无共同点，Flutter 亦为 mixin）。叶子的 `contentIntrinsic*` 不抽（各返回自身字段，是假重合）。 | 某个盒的 kids 增删 / 遍历序需要不同语义（如按 z-order 插入、跳过隐藏子）。 |
| A12 | 文本输入配置面 trait | `TextField`/`TextArea` 共有的 value/label/placeholder/两回调 + 五个 getter + `setSemanticsValue` 收进 `TextInputConfig` trait；字段留宿主、各自 `make()`/`createState()`/构造不进，单行独有（error/helper/maxLength/obscure/formatters）与多行独有（minLines/lines）不进。 | 某个控件的受控纪律分叉（值不再唯一来源 / 写回不再走 onChanged），或回调签名各异。 |
| A13 | 路由声明与状态管理解耦 | `#[Route(id,title,icon)]` 是**纯导航声明**，标在页面类上（`Page`；reducer 例外页为 `Widget`）；`RouteCatalog` 启动期反射成描述符，是 id/title/icon/pageClass 的唯一真相源，导航项与建页全从它派生。四段式 `ReducerView`+`ReducerState` 降级为**复杂页可选**的内部状态管理（需纯函数可测 `update()` 才用），不进注解、不被迫全量。 | 导航元数据出现注解之外的新真相源。（reducer 触发阈值由 A14 独占。） |
| A14 | 导航与 reducer 命名空间分离 | `Drift\Route\` 只放导航三件套（`Route`/`RouteDescriptor`/`RouteCatalog`）；页面状态机六件套迁到 `Drift\Reducer\`（`ReducerView`/`ReducerState`/`ReducerModel`/`ReducerEvent`/`ReducerEffect`/`ReducerUpdate`）。只对**纯状态转移**页值得（实测仅 Snackbar）；Dialog（同步模态取返回值）、Feedback（fire-and-forget）、AsyncTable（`AsyncCommand` 生命周期）调用形状不是 reduce，**不铺开、不造中间档**（中间档服务假想客户，反增范式）。对标 Flutter `Route` vs `Bloc`、Compose `NavController` vs `ViewModel`、SwiftUI `NavigationStack` vs `@State`。★ A28 订正：`Route`/`Routing` 的分层依据是「声明元数据 / 装配建页」而非旧注释里的「那是命令路由」（命令路由住 `Drift\Commands\`）。A14 本身只守 `Route` ↔ `Reducer`，从未约束 `Route` ↔ `Routing`；方向由 A28 定为 `Routing → Route` 单向，`Route` 不反向 import `Routing`（声明不依赖装配）。 | 出现 3 页以上真实「事件→纯更新→effect」形状且可接受各页值类样板；或导航元数据与状态机真的需要互相引用。 |
| A15 | 页面单元形态 | 页面 = `Drift\Widget\Page`（`State` 子类）**一个类**：字段 / `build()` / 事件处理器同处，不再有"Widget 壳 + State"两件套。`Page::host()` 是唯一装配入口，交出 `@internal` 的 `PageShell`；`#[Route]` 标页面类。三条判据：`RouteCatalog` 只收 `Page`/`Widget`、一个 `State` 只能绑一个 `Element`（同一实例同时挂两处、或卸载后重挂，均 Fatal）、`Page` 子类禁用 `$this->widget()`（它返回宿主而非页面）。showcase 全部页面已迁移：除 `SnackbarPage` 外都是单类，那个例外保留薄 `StatefulWidget` 壳（状态机委托 `ReducerState`，必须经 `createState()` 挂树，为的是 `update()` 可纯函数单测）；`RouteCatalog`/`PageRegistry` 的 `Widget` 分支就是为这个例外留的，不是迁移期临时代码。**不强制所有应用**：无路由的单根应用（watermark）继续用 `StatelessWidget` 组合根，长生命周期业务流住 `Store` 而不是页面。 | 页面普遍需要"描述不可变 + 每帧换新描述"的重建能力；或单类页面里 UI 态与业务态普遍混住且无法用 `Store` 隔离。 |

| A16 | 受控参数的两种形态 | 控件参数可以是**值**（`selection(TableSelection)`）或**通道**（`selectionFrom(Readable)`）：值形态的读点在页面 `build()`，变了要应用 `setState` 整页重建；通道形态的读点在控件自己的 `State`，变了只重建控件子树。判据是“变了之后谁该跟着重建”，不是“哪个 API 更新”。双向绑定仍归应用（`onSelectionChange` 写回同一个格子），页面上其它跟着变的地方用 `Bind` 开自己的读点。`Table` 是唯一同时提供两种形态的控件；其余控件只有值形态，**不为“可能有用”预先加通道**。 | 出现第二个需要通道形态的控件（届时把 `xxxFrom(Readable)` 的命名与门控要求一起定），或控件能自行收窄到行级、通道形态的收益消失。 |
| A17 | 环境能力契约 | `Drift\Widget\Environment`（**接口**）是控件与 Store 唯一的能力入口，实现是 `Drift\App\AppEnvironment`（`Application::environment()`）。契约住 Widget 层，因为实现住 App 层 —— 反过来就是 `Widget → App` 成环，而那等于让控件 import 帧循环。端口在门面上**投影成值参数**（`openFile(string, array): ?string`、`clipboardText(): ?string`），`Dialog` / `Clipboard` 的类名不进 Widget 层，那条 `Widget → Platform` 的边因此保持为 0。来源只有两类：浮层 / 定时器来自本窗（跨窗弹错窗口），对话框 / 剪贴板来自 `AppScope` 的端口槽（进程一份）。缺端口不是异常：空值 + **一条** Diagnostic。窗口拖动用 `supportsWindowDrag()` + `startWindowDrag()` 一对，"无边框"这个事实的两个后果同源。应用侧只收一个 `Environment`，不再各写一种闭包递送形状。 | 框架**控件自己**需要弹对话框 / 读剪贴板（届时把端口接口下沉成独立层，而不是把 `Dialog` 引进 Widget）；或门面长到"什么都做"（按能力族拆接口，但仍只保留一个注入点）。 |
| A18 | 状态形状 | **只有 `Cell`**：界面会读的每一块状态是一个格子，写进去当场通知（没有 `notifyChanged()` 可漏），读点交给 `Bind` 的 builder，依赖由框架采集给出。★ **2026-11-24 例外条款退役**：`extends Subject` + `notifyChanged()` + 切片订阅那条路（`SubjectBuilder::select` + `SubscribingWidget` 标记）没有实现者、也没有 `apps/` 使用者，整套删掉 —— 留着它等于允许同一件事两种写法，而 lint 只守得住其中一种。`Subject` 保留为**基座**（`Cell` / `AsyncCommand` 继承它，控件内部信号如 `SelectPanelSignal` 用它），但"多字段同频一致快照"目前**没有原语**。两条纪律不变：不给每个字段写格子之后又整块广播（两套机制一起用，每次白通知一遍）；不因为"想少写几个格子"把一个 Store 的字段合并成数组切片。粒度代价是公开的：订阅粒度 = 格子粒度，读 `phase` 这种枚举格的段会在无关档位切换时白重建一次，一次业务流 6~8 次，与进度 tick 的百次量级不同 —— 值得换"漏写依赖不存在"。 | 出现"读方必须跨字段一致快照"成为多数场景的证据（届时把切片做成 `Cell` 的**组合原语** —— 是新原语，不是回退整块广播）；或单 Store 的格子数增长到难以导航（那时拆 Store，不是换回 `Subject`）。 |
| A19 | 可观察值的读法 | 界面要跟着变的东西一律实现 `Core\Readable`：`Cell` / `Computed` / `AsyncCommand` 都是，读点即订阅，由 `State` 的采集栈统一建边（`Tracker::record`）。控件参数只收**值**、不收 `Subject` + 切片函数 —— `PageHost::from(Readable)` 取代了 `source(Subject)` + `select(callable)`，那套手写订阅 + 手工同值门控是采集栈的重复实现。连带两条：Store 不再承担"把命令的变化转发一次广播"的角色（`AsyncCommand` 自己可读）；`Routing` 因此不再依赖 `State`（依赖矩阵里那条边删掉）。 | 出现"读一次要付昂贵求值"的通道（那时需要显式的拉取/缓存契约，而不是把切片函数加回来）；或某个 `Readable` 实现必须在 `get()` 里写状态（那它就不是可观察值，是命令）。 |
| A20 | 状态色 | 状态色以 `ColorToken` 的**前景 + 容器底**成对提供：`Success`/`Warning`/`Info`/`Danger` 与 `*Surface`。业务档位经 `Rendering\StatusTone` 映射成一对 token，`Loading` 与 `Warning` 共用橙色系但保留独立语义。 控件在 `build(ctx)` 里按当前主题解析，应用侧不再写 `kind → Color` 的 if 链或状态色 hex（`Palette` 只留品牌色）。 | 出现“同一状态在不同产品要完全不同色系”的真实需求；或某对颜色在暗色 / 高对比下实测越过可读性下界 —— 那时加新 token 对，不回应用里散写 hex。 |

| A21 | 异步视图 | 控件层用 `Widget\AsyncView` 消费 `AsyncValue`：源是 `Readable`，`data` 支必填，`idle` / `loading` / `error` 有**非空白默认**；四态路由仍由 `AsyncValue::fold()` 独占。为它重新放行 `Widget → Async` 这条单向边（`Async` 不反向依赖 `Widget`，靠 `Readable` 解耦）。 | 出现更通用的“状态 → 子树”抽象能同时覆盖非异步四态，且不需要 Widget 依赖 Async；或默认支开始携带业务语义（那时把它拆回页面显式写）。 |

| A22 | 状态条控件 | **不抽**通用 `StatusLine`。users 状态栏是无 tone 的一行文本，watermark 是带语义点的 `StatusMessage`；真正重复的只有 `Row + Text + Spacer`，而语义色已经由 `StatusTone` + `ColorToken` 收口。再抽一层会把“业务 kind → tone”映射推回调用点，抽象成本高于省下的排版。 | 第三个应用也出现“消息 + 语义点 + 容器底”且读写接口稳定，届时抽的是完整状态消息控件，不是只包 `Row` 的壳。 |
| A23 | 组合根样板 | 后台装配收成原语：`AppScope::useBackgroundJobs()` 收掉 exe → 池 → 预热 → 装端口四步；`worker-argv` lint 禁止第四份开关字面量。★ 角色判定那半由 A25 再收进 `AppEntry`，`WorkerProcess` 只剩 `isWorker()` / `serve()` 两个原语。**不**做“大而全配置对象”：第二窗 / 无边框 / 材质 / 恢复 / 关闭守卫是应用语义，留在组合根；`Bootstrap.php` 必须保留 `new WindowSet(`（`app-bootstrap-loop` 判据）。 | 出现同一份装配在 5 个以上应用里逐字重复、或平台侧提出“一个配置文件描述所有窗口”的真实消费者；届时先给 `EventLoop` 加钩子，不复制循环。 |
| A24 | 重试默认支 | `AsyncView::retryOn(\Closure)` 给**默认** error 支装“错误 + 重试按钮”，省掉 showcase 异步表格与并发取数两页重抄 `Center(Column(ErrorPlaceholder + Button))`；显式 `error()` 优先于 `retryOn()`（LoadMore 页分页失败要保留旧行的形状只有页面知道，故不迁）。重试动作是 0 参闭包；`AsyncCommand::retry()` 有意不去重（在途点它要打断重来），按钮不自带 enabled，安全性来自 error 支显示时命令已不在途。 | 第四个应用需要带自定义文案 / 门控的重试支，届时扩 `retryOn()` 参数而不是造新控件；或 error 态真的会持续 running，才把 enabled 收进框架。 |
| A25 | 组合根角色分流 | 把“同 exe 双角色”从应用侧彻底收进框架：`abstract AppEntry` 的 `final run()` 判 `WorkerProcess::isWorker()`，worker 走 `serve($this->jobs())`、UI 走 `start()`；应用只写 `jobs()`（可省）与 `start()`，不 import `WorkerProcess`。`app-worker-role` lint 守“角色判定不许搬回应用层”。**不用静态模板方法**：PHP 的 `abstract static` 是 Fatal，且 worker 进程会把 warning 吐进 stdout 污染行协议（真机表现为退出码 3），实例方法才是合法形态，入口固定 `(new Bootstrap())->run()`。**不做**双 exe（worker 仍要链全部应用代码，产物与构建翻倍）与“基类接管 AppScope”（`maxWorkers` / `prewarm` 是应用语义，收进去就得再加钩子）。 | 出现第三种进程角色（如 CLI 子命令）时在基类加**带默认实现**的钩子（`cli()` / `onWorkerStart()`）。用抽象基类而不是 interface 就为这一步：interface 加方法会强制所有实现同步改，基类加带默认实现的钩子只影响真正要用的那个应用。 |

| A26 | 焦点环输入模态 | `:focus-visible` 只由**导航键**开启：`KeyEvent::isFocusNavigation()` 收口 Tab / 方向键 / PageUp / PageDown / Home / End（含 Shift 组合）；文本、Enter、Backspace、Delete、Ctrl+A/C/V 等编辑键不切模态，指针与滚轮仍关闭。应用只消费这个谓词，不另写一份键表。 | 出现"编辑键也必须提示焦点位置"的真实无障碍需求，并能给出明示规则；或新增不属于这份键表、却要切模态的导航语义。 |
| A27 | 多行输入滚动坐标 | `RenderTextArea::caretRect()` / `selectionRects()` 返回**已扣滚动偏移**的盒内视口坐标；绘制时只把段落上移，不再对整张画布做第二次 `translate`。`offsetAt()` 反向加回偏移，几何 / 命中 / 绘制共用一份契约。 | 改成"光标几何保留内容坐标"的另一套契约，或滚动引入旋转 / 缩放等非平移变换。 |

| A42 | **约束链归因的第四类：`parent-flex`** | Flex 父在 `performLayout()` 里按 grow/shrink 分配子尺寸，子拿到的 `applied` 因此不等于"父 inner 原样传下来"，与基类默认链对不上 —— 这是**合法的对不上**，早先一律兜到 `child-custom`（`Column → Expanded` 就落在这里）。判据用两个结构事实：① 父是 Flex 容器 —— 记录层在登记节点时按 `instanceof Flex` 记一个布尔，**不查类名清单**（`Column extends Flex` 由语言回答，新增 Flex 子类自动覆盖，清单不会腐烂）；② 子自己**没有** `box` / `aspect` 修饰（有则是子侧改的，即使父是 Flex 也归 `child-custom` —— 归因要指向真正动手的那一方）。 | 出现"父不是 Flex 但也在 performLayout 里重算子约束"的容器 —— 那时判据扩成"父有自定义子约束分配"这个事实，而不是再加一个类型。 |
| A43 | **属性域：反射为主、活树按需快照，编码带 tag** | S3b 的四条落点。① **反射为主，显式协议只做增强钩子**：Flutter 用 `debugFillProperties()` 让每个控件自己说，精确但 33 个控件要逐个写、漏写静默少一屏字段、新控件默认不可见；反射零侵入立刻全覆盖，新控件自动可用。所以反射兜底，控件实现 `Describable` 时优先用它 —— "能力先到、精度可加"，反过来会让属性域拖到所有控件写完才有用。② **读活树 + 按需进独立窗口，不每帧采样**：每帧反射全树必掉帧，直接违反 S3b 判据；`props(node)` 时才读，结果存进 `Recorder` 独立 200 条窗口（与报文同构），带 `liveFrame` 与 `stored`，读者知道这是"第 N 帧读到的活树值"而非"历史帧属性"。这与 A37 ④"几何必须进记录"不矛盾：几何每帧都在变且导出后没有活树，属性回答的是"现在这个值对不对"且随时可再读。③ **字段筛选由声明类回答，不维护名单**：只取 `Widget` / `State` **子类自己声明**的字段（`ReflectionProperty::getDeclaringClass()`）；基类字段 `Widget` 侧除 `sealed`（挂载期状态不是配置）外全留、`State` 侧全排除（`widget`/`element`/`dirty`/`disposers` 全是内部态）。与 A42 同一条纪律：界线由语言回答，清单不会腐烂。④ **值编码用带 tag 的联合，不裸放值**：`scalar`/`string`/`list`/`map`/`obj`/`closure`/`resource`/`ref`/`cut` 九类。必须如此的五个坑：`NAN`/`INF` 让 `json_encode` 直接失败（`Modifier::$width` 默认就是 `NAN`）；闭包裸放会 Fatal（编成 `{kind:closure, at:文件:行}`，"这个回调哪来的"本身就有价值）；资源同理；循环引用用 `spl_object_id` 栈命中给 `ref`；值对象若有 `__toString()` 直接收成文本（`Color` 因此加 `__toString()`），不逐字段展开成一屏 `r/g/b/a` —— 这是通用规则，不建会腐烂的类名表。⑤ **能力探测而非猜构建形态**：一次性读一个已知私有字段验证反射可用，失败 ⇒ 整域自报 `reflection-unavailable`，绝不返回空数组让人以为"这个控件没有配置"。⑥ 树根走 `Application::treeRoots()` 门面转发 `AppShell::treeRoots()`，**不新增第二处浮层遍历**（`SecondTreeTest` 只认一个出口）。⑦ 属性不进 `Digest`（值一变指纹就废，与报文同理）。⑧ **复用 `Redactor` 脱敏**：属性会读任意 State 字段（`password` / `token` 都在里面），报文默认脱敏而属性原样导出就是同一威胁模型两种口径。编码完成后统一后处理一遍（键名 `isSecretKey()` 判定、字符串值 `scrub()` 认 Bearer/JWT），不把开关穿进递归；计数与 `redact` 位随快照自报，关掉时 `redacted: 0` 仍与"扫了没发现"可分。 | 出现"必须回答历史帧的属性值"的真实需求（那时加帧末采样并单列窗口，不动现有 live 语义）；或 AOT 反射变完整（那时删除能力探测与降级分支）；或控件自带描述协议成为主流（那时把 `Describable` 从增强钩子升为主路径）。 |
| A44 | **点选反查走按需活树映射，不给 `RenderBox` 加 `debugOwner`** | A37 ③ 选"在 `syncBox()` 写一次 `debugOwner`"的前提是"从根建 `Box → Element` 映射每帧 2000 节点太贵"——它把**每帧**与**人点一下时**混成了一个场景。反查只在查询发生时跑，而生产焦点链早就在 `FocusManager::elementForBox()` 里做同一件按需映射（每次点击都走一遍，没掉帧）；A37 把"已有机制"漏看了。写字段的代价却很实：录制没开时盒上没有身份（CLI 直接查不了）、AOT 新增字段必须重编、`effectiveBox()` 让一个盒可能被多个 Element 认领（后写覆盖先写，反查静默指错）、调试状态混进 `syncBox()` 热路径。所以把映射收成 `Element::boxOwners()` **一份**，焦点反查与 `Query::pick()` 共用；`hitTest()` 仍走生产唯一实现，命中链上每个盒按 `spl_object_id` 反查最近 Element，自绘 chrome 这类 ownerless 盒沿父链由同一映射回答。**命中链给全链**，不只给最底层盒 —— 只给最底层就把"点在哪个包装层里"的信息丢了，而那正是布局调试要问的。树根与浮层原点经 `Application::treeRootOrigins()` 一个出口给出，不在 Debug 层再写第二处浮层遍历；坐标口径与 `InputRouter` 一致（视口坐标减根原点）。未命中与没树根分开报，不把"点空了"伪装成根节点。 | 出现每秒上千次反查的实时拾取（那时把映射按 `layoutEpoch` 缓存，但仍不写进生产盒）；或 `hitTest()` 与调试查询需要不同命中口径（那时查询要显式声明口径，不能偷偷改生产 hit-test）。A37 ③ 自此被本条取代。 |
| A45 | **页面错误边界默认接在路由容器，不改 `Page::host()`** | `ErrorBoundary` 的三层捕获（构造 / build / layout+paint）早已完整，但生产零使用。默认接线选在 `PageHostState::pageFor()`：它是页面生命周期的唯一持有者（页面 Widget 缓存 + `Offstage` 保活都在这里），因此是“页面粒度”的唯一漏斗；边界与包装后的页面一起缓存，且必须包在 `Expanded` **里面**，不让 `ErrorBoundary` 插到 Flex 与 `Expanded` 之间改变约束链路。不选 `Page::host()`：那是装配门面，改返回类型会波及所有直接挂载 `host()` 的判据与“简单应用直接返回一页”的用法，而那些场景没有多页隔离问题。不选根边界：一页坏就整窗占位，等于把页面级隔离退化成红屏。不选改 `Frame` 的 catch 为 DIAGNOSTIC：没有边界的异常被吞就是窗口冻结在上一帧且只留日志，G2 明令禁止，`noboundary` 判据必须保持红。效果：构造期（含隐藏页首次挂载）、build 期、渲染期异常都就地换成 `ErrorPlaceholder`，兄弟页和窗口继续；`Errors::DIAGNOSTIC` 留痕。不覆盖路由工厂自身的构造异常——那是装配错误，仍走 Fatal；非路由根与浮层也仍由应用自己决定。`PageHost::guard(false)` 提供严格模式开关，默认开，让 CI / 开发期能恢复 Fatal 语义，同时给判据一个可证伪的对照面。 | 非路由根或浮层成为主要页面宿主（那时在 overlay push 的唯一漏斗补同一层，不动本条）；或需要页面“切走再回来自动恢复”（那时在切页时换 key 重挂页面，而不是在帧循环吞异常——`ErrorBoundaryElement` 的“烧断”语义保持不变）。 |
| A46 | **浮层错误边界接在唯一入栈漏斗，边界做透明代理** | A45 只覆盖路由页面，浮层是独立根（`Frame` 单独 settle / paint），页边界够不着。唯一挂载漏斗是 `OverlayManager::pushOverlay()`（菜单 / Tooltip / Snackbar / 模态都走它），在那里把面板包成 `ErrorBoundary`；一个浮层仍只有 `$e->element` 一个根身份。否决双根方案（另存 guardRoot 让 `element` 继续指向面板）：生命周期 / settle / paint / 命中必须各自选一个根，选错就静默分叉，而"一个浮层一个根"是现有契约。否决逐个面板工厂包壳：四个入口就是四个漏点。跨过两个透明性坑：① `OverlayLayout::placeEntry()` 要问根盒 `panelRect()` 拿投影留白，边界盒必须转发给健康孩子，否则所有菜单整体上移一个 elevation（画得出来、位置错、不报错）；② 锚点内容签名变化时 `OverlayLayout` 对根调 `markNeedsBuild()`，边界是 StatelessElement，必须转发给孩子 State，否则下拉筛选内容再也不更新（浮层还活着，只是哑了）。`ErrorBoundaryElement` 捕获即"烧断"，关掉浮层会 unmount，下次打开自然恢复。 | 出现需要"浮层内某个子块独立降级"而非整层占位的面板（那时在面板内部自己放边界，本条仍保留最外层）；或浮层不再走 `pushOverlay()` 单一漏斗。 |

| A47 | **证据的出口顺序：格式等事实定型** | 分期按**前置条件**排，不按能力层的重要性排。① **S0（证据包）后置**：包的字段由事实形状决定，而事实到 S4 才稳定；格式定早了，每加一个域就破一次兼容——v1 四套 schema 就是这么来的。S0 因此是"事实定型后的第一期"，不是全局第一；这段时间"证据可携带"只对驱动脚本成立，对事实不成立。② **S-live 先于 S5**：宿主常驻 + 面板轮询游标的底座都已经有（`frames(since)` 是无状态游标、`Application::frame()` 已逐帧调用），成本低于 Web 视图，而它换回的是开发期手感，也是本方案里唯一被"可判性"换掉的东西。③ **S2 排最后**：它是能力层第一条，但价值在 AOT 与崩溃现场，当前痛点全在开发期；且它要动 AOT 开销与多窗口隔离，风险最高，先让 live 探出"常驻 + 窗口"的形状。④ **S6 只剩干预**：点选是查询（`Query::pick()` 已在 S4 落地），高亮与暂停是反向流，两者不能同期。 | 出现第二个证据生产者、需要提前冻结格式；或 CI 必须在 S4 之前消费证据包；或线上崩溃取证升为最高优先级（那时 S2 前移）。 |
| A48 | **诊断器不产出改法；干预是唯一反向流** | ① 诊断器只产出**确定性判断**：规则名、证据地址、度量、阈值、复算方式。**"怎么改"归机器消费者**，且必须引用诊断器给出的地址。理由不是分工洁癖：工具一旦输出建议，同一条规则同一份事实会给出不同答案（不可复算），而规则表被迫记住修法，修法随框架版本变，表会腐烂。② **干预（高亮 / 暂停）不进 `SessionQueries`**：它是消费者 → 采集的反向流，混进查询面会让"只读"承诺破功，而这条承诺正是本地与远端共用同一份消费者代码的前提。只在 dev 形态做，判据是**结构因果指纹**（`Digest::causal()`，见 A52）高亮前后逐帧相同**且**像素必须变；AOT 不做（无可交互观测面，也无空闲帧循环）。★ 原表述写的是 `Digest::ofFrame()` 逐值相同 —— 那句会恒红：`ofFrame()` 含 `skip`，而高亮要求这一帧必须画，`paintSkipped` 会从 true 变 false —— 那不是结构变了，正是高亮起了作用。 | 规则表被要求承担改法（例如"自动建议加 Expanded"成为交付项）；或 AOT 需要可交互的观测面（那时反向流要重新定义协议）。 |

## 编译器与代码纪律

| # | 主题 | 现行结论 | 失效条件 |
|---|---|---|---|
| C1 | `switch` 控制流 | 热路径禁用，用 `int $kind` + `===` 比较链。 | 编译器生成物经系统复测证明安全，且大规模迁移有可测收益。 |

| C3 | `readonly` | 保留并继续用于不可变值对象，不迁移。 | 生成形状再次变化，实测退化越过帧预算门槛，且去掉后仍能保留不可变性。 |
| C4 | 闭包 | 事件回调保持闭包，不换成接口对象；两层闭包保留。 | 回调变成每帧热路径，或 AOT 下调用成本实测超过阈值。 |
| C5 | AOT 判据 | lint 管结构性纪律，运行时与编译器层用诊断和真机判据兜底。 | 静态分析能力足以覆盖运行时所有权与生成物形状。 |
| C6 | ABI 运行期握手 | 不做；stub 是唯一事实源，构建期三向对签名。 | 出现静态契约覆盖不住的真实错配路径，且缓存 stale 无法解释。 |
| C7 | `--nano` 后端 | 不做。 | 编译器支持且出现要求极小体积的真实部署场景。 |
| C8 | 属性钩子 | **禁用**。PHP 8.4 property hook 在 AOT 下能编过（`users` 实测），但两条代价盖过那点短：① 它让"这一行在读一个会变的值"从源码里消失 —— `grep ->get()` 找不到读点，而 A19 的判据正是读点可审计；② 每字段 4 行钩子比省下的 `notifyChanged()` 还长，多字段之间还会撕裂读（2026-11-07 实测 16 字段净收益为负）。读用 `x()`、写用 `setX()`，通知由格子承担。 | 出现能静态列出钩子读点的量具（lint 像检查 `->get()` 那样把 hook 读纳入依赖判据），且实测钩子不产生额外间接调用。 |

| # | 主题 | 现行结论 | 失效条件 |
|---|---|---|---|
| A49 | **搜索的产物是地址，匹配的是自身类型** | ① **结果是地址，不是位置**：命中项一律 `{domain, address, text}`，`address` 必须能被别的查询直接解析（`node:19` → `boxModel`，`request:3` → `network`）—— 可判形式就是"把每个 `address` 喂回对应查询拿到 `found`"。不返回行号、屏幕位置、片段偏移：证据重新导出、窗口滚动、面板重排之后它们全部失效，而地址还成立（A36 ⑧）。② **匹配节点自身的类型，不匹配祖先路径**：落地第一版按完整路径匹配，`Table` 命中 **346/364** 个节点 —— 路径里含祖先类型，等于把整棵子树都算命中，搜索退化成"打印一切"。改成匹配自身类型后是 2 条，路径只用来显示"它在哪"。要列某容器的子树是 `cascade(frame)` 的问题，不该由搜索兼职。③ **只搜证据，不搜活树**：两个域都能从记录回答，于是本地 / `--remote` / `--from=<证据包>` 三条路结果逐值相同。搜活树会让"搜到的节点下次没了"变成常态，而搜索的第一用途正是"照着结果去追问"，追问必须还能解析。④ **不做正则、不打相关度**：正则有灾难性回溯与跨实现语义差异（PCRE / JS），相关度无法复算。`Padding|Text` 按字面找，找不到就是找不到，不猜用户想写"或"。大小写默认不敏感，`--case-sensitive` 显式打开。⑤ **三种"没结果"必须分开**：`scanned`（这段证据里有多少候选）/ `matched`（命中总数）/ `returned`（截断后给了多少）三数对账，另加 `evicted`（已回收节点搜不到，不等于没有过）与请求域的 `window`。少了 `scanned`，"0 条结果"会被读成"没有匹配"，而它更可能是"这个域根本没有候选"（没采 / 窗口空）—— 两者下一步动作相反：改关键词 vs 补采集。⑥ **报文不进搜索**：正文默认不采，搜它会给出"抓了就有、没抓就没有"的不稳定结论；要报文就按 `requestId` 显式取（A38）。 | 需要"相关度排序 / 模糊匹配"成为主流（那时要引入可复算的排序模型，而不是在前端随手 `filter`）；或属性 / 绘制域也进 `scanned`（那时每域要独立上限，因为属性读取走活树与反射，成本量级不同）；或需要搜"尚未进入记录的活树对象"（那时搜索与 attach 要分成两条语义，不能靠一个 `find` 兼两职）。 |
| A50 | **高亮是驱动面上的"一步"，不是记录侧的一条旁注** | ① **注解进脚本**（`Step::HIGHLIGHT`，`node` 一个扁平标量，`0` = 清除）：`Script::digest()` 只覆盖 steps，注解若只活在录制器/查询层，"同一份脚本跑两遍"会让一次高亮了一次没高亮的两次运行拿到**同一个驱动指纹** —— 差异被指纹掩盖，而指纹的全部价值就是不让差异被掩盖。进了脚本之后 `--save` / `--replay` / `--remote` 全部自然覆盖，重放方不必知道"高亮该怎么重放"。② **接口位置在 `SessionDriver`**：它改的不是记录，是**下一次绘制的样子**；`query('highlight')` 读的是"现在高亮了谁"。放进查询面等于允许"问一个问题顺手改画面"，而 A48 ② 的只读承诺正是本地与远端共用同一份消费者代码的前提。③ **跨进程只为拿到"真的上屏了没"**：`Methods::HIGHLIGHT` 回执给 `{node, drawnFrame}`，取值来自宿主记录而不是客户端缓存 —— 客户端自己记一份就会出现"宿主清掉了、客户端还以为在"。④ **解析不到就拒，且不记账**：记下一个"高亮了不存在的节点"，重放时同样解析不到，那时失败看起来像"重放坏了"，而真正的错误是当初那个号。⑤ **号 → 活元素的查找只一份**：`Element::findInRoots()`，查询面与驱动面共用；驱动面拿不到 `Query`，那份 6 行循环写成两份之后漂开的表现是"查询能查到、高亮查不到"这种最难查的半坏。 | 出现"面板里悬停即高亮"的连续流（那时高亮要能节流合并，`Step` 从"一次请求一步"改成"一段状态"）；或 AOT 需要可交互观测面（那反向流要重新定义协议，不只加一个方法）。 |
| A51 | **叠加层必须自带失效判据与"画了没"的独立记账** | 叠加层（焦点环、调试高亮）绕过 `setState`，所以 `Frame::run()` 的三条判据（layout 跑过 / paintEpoch 变 / 浮层集合变）一条都不会动 —— 只把它交给 `afterPaint` 而不管失效，表现是"设了高亮但屏幕上什么都没有"：`Frame` 发现树没变就整帧跳过，闭包根本不跑。因此三处并联：① `AppShell::frame()` 的 `paintRequested` 与 `continueFrame()` 的调帧判据都计入 `debugHighlight !== paintedHighlight`（与焦点环同一条纪律）；② `setDebugHighlight()` 同值早退 + `scheduleFrame()` —— 高亮恰恰发生在"页面已经稳定、没人会再标脏"的时候；③ **"画了"由壳报、由录制器落账**（`devFacts['overlayDrawn']` → `Recorder::$overlayDrawn`），只报布尔不报节点号（号是调试层词汇，壳不该为了一笔记账去懂它），而"请求了"另有 `highlightNode` / `highlightFrame` —— 两者分开，才能把"元素已卸载 / 盒没尺寸 / 帧被跳过"这些静默失败与"高亮正常"区分开。**稳态必须回落到跳过**：`paintedHighlight` 只在真的 `painted` 之后更新，否则每帧无条件重画（CPU 空转，而肉眼只看到"高亮是对的"）。 | 出现第二个需要"画了没"记账的叠加层（那时把这对字段收成一个 `OverlayFact` 而不是再加一组）；或出现叠加层需要重排（那它就不是叠加层了，该走浮层）。 |
| A52 | **"结构因果"与"这一帧跑了哪几段"要分开摘要** | `Digest::ofFrame()` 一直是"可复现部分的全集"（`rebuilt` + `causes` + `stages` + `skip`），而 `skip` 会被**合法的**中断改变：高亮要求这一帧必须画，`paintSkipped` 从 true 变 false。拿全集判"高亮没改结构"会恒红，而红得没道理。于是 `Digest::causal()` 只留 `rebuilt` + `causes`（`ofFrame()` 由它 + `stages` + `skip` 组合，键序不变 ⇒ 历史指纹不破），`ofCausal()` 是整份记录的结构指纹。`stages` 也不进 `causal`：它是"这一帧跑了哪些**壳段**"，与结构无关，而且 Paint 段不由壳记（记在 `SurfaceProfile` 计时里）—— 放进来只会让将来的段调整误伤这条判据。**两条一起才算证明**：结构指纹不变 **+** 像素必变；只证明前者会奖励"压根没画"，只证明后者会奖励"靠重建顺带重画"。 | 出现"结构相同但因果不同"的新需求（那时 `causal` 要带上 `incomplete` 之类的新轴）；或 Paint 变成壳段（那时 `stages` 会随跳过变化，更不能进 `causal`）。 |
| A53 | **录制器属于应用，不属于进程** | 多窗口是常态，而进程级单例在多窗口下不是"不支持"，是**静默串证据**：第二个窗口一挂上，它首帧的全量 `build` 就把自己的节点写进第一个窗口的节点表。实测两个 `PageHostApplication` 交错推帧：第一个会话节点表 361 → 449、帧窗口多出两帧、`digest` 跟着变，而两份报告各自看起来都正常。① **归属写在录制器上**（`bindTo($app)` + `ownerId`），不写在查询层：查询层各自握着实例，串不串它看不见；② **帧内"当前录制器"由栈回答**（`enter()` / `leave()`，`null` 也压一层）：不压 `null`，第二个窗口的帧会从栈里落空、落到进程默认值上，也就是别人的录制器 —— 而这一条**无法用"谁在用"反推**，只能由帧边界声明；③ **无主的录制器是逃生口不是常态**：测试 / bench 手工装的没有主人，帧照写（老夹具一行不改），一旦认主就只能写给它自己的那一份；④ **`close()` 是解绑不是硬重置**：同进程可能还有别的窗口在录，`uninstall()` 清的是"这个世界"；登记表按**对象号**记不按 `tag`，因为 `reset()` 会换 `tag`，按 `tag` 记会让解绑删不掉自己那一行（表现为"关掉会话后 `installed()` 仍是 true"）；⑤ **重复开会话按窗口拒**：拒的是"这个窗口已经有会话"，不是"这个进程里已经有录制器"—— 后者把多窗口挡在门外，却挡不住真正的污染源（第二个窗口从不走 `open()`）。**触发了 A36 的第三条失效条件**（多窗口各自持有录制器成为常态），处置就是本条：不改"一份证据一份驱动"，改为"一份证据对应一个窗口"。 | 出现"一个窗口要同时录两路"的真实需求（那时录制器要能按域分流，而不是按窗口独占）；或 `Discovery` 多条目上线后需要跨窗口合并视图（那时合并属于投影，仍不进采集）。 |
| A54 | **调试代码按"能不能进产物"分三层，不按"是不是调试"分** | 混合模型下这是两条完全不同的成本线：dev 壳的 `sources` 不含 `src`（`apps/dev/project.yml`），框架与调试代码全部由内嵌 ZendVM 解释 ⇒ **改多少行都不编译、还能热改**；AOT 侧 `tpc` **全量编译 `sources`、没有死码消除**（`Optimizer` 只有 FuncCall / LoopVar / SsaProp / SsaType 四个），类可达即整类进产物 ⇒ 调试代码全额付账。实测 showcase：`Debug/` 占生成 C++ 的 9.3%（20,119 / 216,388），其中约四成是发布态永不执行的审查面。于是分三层：**L1 证据**（写面 + 记录类型，热路径真的会调，编）、**L2 内省**（仅 dev，不编）、**L3 审查面**（`Query` / `Evidence` / `Protocol` / `DebugSession` / `Replay`，只被 `tools/` 调，用 `ignore` 排出）。实测排出 −7,931 行（−39%）。四个坑：① `ignore` 是 list 型项，`mergeConfig` 对 list 走**整体替换** ⇒ 唯一声明放 `build/base.yml`、各应用不重写（一重写就得抄全表；原先 showcase / users / watermark 三处各写一份，第一版就漏了 `Session.php`）；② 排父接口必须连子接口一起排（`Session extends SessionQueries, SessionDriver`，漏一个就是悬空继承，编译期才炸）；③ 排完要查孤儿（`Json` 排掉两个消费者后只剩自己）；④ tpc 对不存在的 ignore 条目**静默 `continue`**（当"optional exclusions"），路径拼错零报错。**手写白名单靠不住**：`php tools/check-debug-scope.php` 守「每个 AOT 应用里编译进产物的调试侧文件集合恰好等于 17 项写面白名单」——多一项报泄漏、少一项报热路径被排、拼错报条目不存在；`--selftest` 四组变异全咬红，8 个应用全绿，已接 `verify` 工作流。 | tpc 引入死代码消除或方法级裁剪（界由工具自己维持，不再需要人写名单）；或 S2 常驻黑匣子上线后发布态也要读证据（那时读面要回到产物，只保留导出侧）。 |
