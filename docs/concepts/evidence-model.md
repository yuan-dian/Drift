# 证据模型：从帧因果到可携带的证据

> 调试器的产物不是一屏界面，是一份能被追问、能被复算、能被机器读的证据。本页定义证据的形态、四层分工、投影规则与分期判据。[调试模型](debug-model.md)讲的是一帧怎么被记下来，这里讲记下来之后怎么用。

## 为什么把中心放在证据上

成熟 DevTools 已经不在比"面板有几个"。把它们拆成能力层，比拆成视图更有解释力：

| 能力层 | 形态 | 代表 |
|---|---|---|
| **常驻观测** | 不是"打开面板才开始记"，默认有一份低开销环形缓冲，出事回看 | Sentry 的 breadcrumb、Chrome 的 trace、Flutter 的 timeline |
| **多维对齐** | 结构、时间、输入、网络、绘制挂在同一条轴上，单看一个域只能猜 | Chrome Performance 的 tracks |
| **因果链** | 不是"状态是什么"，是"谁触发、波及谁" | Chrome 的 `Initiated by`、React 的 "who scheduled this update" |
| **自动判断** | 阈值、回归、根因、建议——这是"工具"与"助手"的分界 | 各类 APM 的告警与归因 |
| **证据可携带** | 能导出、能分享、能进 CI、能给机器读 | trace 文件、profile 导出 |

另有一条横切：**构建态分层**。线上留低开销标量（采样），开发期开全量深检。没有哪一家只在开发期有用。

对照当前实现：

| 能力层 | 现状 |
|---|---|
| 常驻观测 | **开发期已有**：`debug serve` 自走 + `brief --attach` 只读连接；发布态常驻黑匣子已落地（A60/A61），但不进证据包 |
| 多维对齐 | **已有**：帧号贯穿因果 / 几何 / 网络，`debug node` 一次给三域事实；绘制归因仍属 S3d 未做 |
| 因果链 | **领先**：三挂点精确记录，不是采样也不是启发式 |
| 自动判断 | **已有**：S1 的确定性发现规则（慢帧 / 扇出 / 约束改写等），只说哪里不对，不产出改法 |
| 证据可携带 | **已落地**：`Evidence` NDJSON 包（manifest + 逐域 counts + 三指纹）+ `Recorder::hydrate()`；`brief` / `network` / `web --from/--out` 走同一份证据（`EvidenceTest` 9 用例） |
| 构建态分层 | **无**：AOT 不带任何记录 |

所以这不是"再加几个面板"。缺的是把已有事实变成证据，再让证据有多个出口。

## 证据的三个成员

```
Evidence = (Drive, Facts, Findings)
```

| 成员 | 内容 | 作用 |
|---|---|---|
| **Drive** | 目标、视口、环境参数、步骤序列（帧时间戳、输入、具名副作用） | 让这一份事实可以被**重新走一遍** |
| **Facts** | 帧记录、因果边、节点表、段账、几何与约束链、网络骨架 | 这一份运行**实际发生了什么** |
| **Findings** | 由规则产出的确定性判断 | 哪里不对，以及凭什么这么说 |

三者缺一，证据就退化成日志：

- 有 Facts 没 Drive：能看，不能验。换个人换台机器无法复现，所有结论都只是"当时看到过"。
- 有 Drive 没 Findings：能验，不能用。机器与人都得自己做一遍统计，而统计方式一旦不写下来就不可比对。
- 有 Drive + Facts + Findings：现在三者齐了；缺的不是事实，是按预算把结论送到终端 / Web / 机器，不能让人翻全量。

## 三条指纹，不能合并

```
digest(Drive)     ——  驱动是否相同（不含任何结果）
digest(Facts)     ——  因果是否相同（不含时间）
digest(External)  ——  外部条件是否相同（不含时刻与报文）
```

| 指纹 | 覆盖 | 明确排除 | 回答的问题 |
|---|---|---|---|
| `digest(Drive)` | 目标、视口、`meta`、逐步动作 | 运行结果 | 两遍跑的是不是同一件事 |
| `digest(Facts)` | 逐帧重建集合、因果边、段账、节点表、结构、几何 | 时间戳、帧内耗时、各段纳秒、外部响应 | 两遍跑的因果是不是逐值相同 |
| `digest(External)` | 请求的 `method` + `url` + 顺序、输入事件序列、平台事件**种类** | 响应体、响应头、到达时刻、耗时 | 两遍面对的外部条件是否可比 |

分开的必要性在于**故障归属**：驱动相同而 `Facts` 不同 ⇒ 引擎不确定；驱动就不同 ⇒ 后面的比较没有意义。合成一个指纹，这两种情况都是"红了"，而修复动作完全相反。

第三条是被"网络进证据"逼出来的，不是设计洁癖。网络是**外部世界**：同一个脚本重跑，服务端慢 200ms 是常态。如果网络事实进 `Facts` 指纹，那指纹每跑一次都不同，等于没有指纹——而且失败信息会指向"引擎不确定"，把排查引到完全错误的方向。

反过来，把它整个排除在外也不行：`Facts` 相同但一次走了本地假数据、一次走了真实接口，两边的重建数完全不同，而指纹会宣称"一致"。所以要有第三条：**只覆盖"发了什么"，不覆盖"多久回来"**。

现有实现已经是第一部分形状（帧指纹排除时间与耗时，脚本指纹独立），这件事不需要改代码，需要的是把它写成**证据的定义**——否则以后有人为了"更严格"把时间塞进事实指纹，指纹就永远红，等于没有。

## 十一个域

| 域 | 内容 | 现状 |
|---|---|---|
| 时间轴 | 帧号、墙钟、帧内耗时、是否跳过 settle / paint | 已有 |
| 因果 | `kind` · `from` · `to` · `site` · `detail` | 已有 |
| 结构 | 节点 id → 父 id + Widget 短类名 | 已有；**无 Widget 配置、无 State 字段** |
| 几何 | 尺寸、偏移、**约束链**（谁限定了它） | **新增**；原料已在盒上（见下节） |
| 绘制 | 本帧真画的节点集合、层缓存命中数、各边界重录原因 | **新增**；独立 60 帧窗口，默认关 |
| 段账 | 每段纳秒 + 段外耗时单列 | 已有 |
| 驱动 | 目标、视口、环境、步骤 | 已有 |
| 网络 | 请求骨架、发起者、落在哪一帧、落地后重建了谁 | **新增**；门面已有唯一入口，传输是接口 |
| 异步 | 后端调度过的 job：提交 / 派发 / 结算帧、状态、耗时、发起者、落地节点 | A63 已落地；默认关，独立 200 条窗口 |
| 摘要 | 帧 / 节点 / 驱动 / 外部四份指纹 | 已有三份，第四份随网络 |
| 发现 | 阈值发现与基线回归已落地（只有确定性度量才断言） | **切片** |

前两个域合起来已经能回答"这一帧为什么变成这样"，这是当前实现真正的强项。几何与网络是**把同一个"为什么"推广到另外两个问题**：为什么这么大、这个请求是谁发的。绘制域回答第三问：这一帧画了谁、省了谁；异步域回答第四问：谁排了队、谁真的跑过、结算落在哪一帧。发现这一域不增加采集，只把已有事实变成结论。

绘制域与异步域**不进指纹**，这条与另外三个事实域不同：它们是预算相关的观测量（开不开这两个域不改变应用行为），进指纹会让"同一个应用、两份不同的预算"算出不同指纹，而那正是指纹要排除的东西。

**属性从不在十个域里，证据包曾经有个 `props` 段（`Evidence::D_PROPS` / `K_PROP`），已按 A55 删除。** 它是 S3b 早期的产物：写进包、从包读回、hydrate 进 Recorder 的 200 条窗口，可**没有任何查询读它**——`Query::props()` 只读当场活树，离线会话明确拒绝活树依赖。它曾经"在包里、不在指纹里"只是碰巧对：指纹留白是因为它不可复算，不是因为它不重要；哪天有人把它补进指纹，dev 与 AOT 立刻互不认。现在三层同时收口：不进包（格式层判据 `testPropsNeverEnterEvidencePackage`）、不进指纹、只在 dev 现读（`ObjectDump` 与 `eval $node` 共用）。升版本不必要——证据格式靠"遇到未知 kind 显式报错"演进，绝大多数从没采过 props 的老包仍然可读。

## 检查器：把"为什么"第二次用在布局上

"检查器"（Inspector）在成熟工具里是三种东西的合称：Chrome Elements 的 DOM 树 + 盒模型叠加 + 计算样式，Flutter Inspector 的 Widget 树 + Select Widget Mode + Layout Explorer，Android Layout Inspector 的组件树 + bounds + 设计稿叠加。它们共同回答三个问题：

1. **这是什么**（结构）
2. **它多大、在哪**（几何）
3. **为什么是这个大小**（约束链）

第三问只有 Flutter 的 Layout Explorer 勉强回答，而且给的是"当前约束值"，不是"约束怎么变成这个值的"。

### 我们的落点不是"做一棵树"

树是最容易做、也最容易做错的表面。真正的判断是：**布局的"为什么"能不能像重建的"为什么"那样被精确记录。**

能，因为三件事同时成立：

- `RenderBox::layout(BoxConstraints)` 是**纯函数**，注释里明写"约束 → 尺寸，同时定位子节点；不参与脏判定"；
- 约束改写过程是**显式分步**的：`tighten`（尺寸修饰）→ `deflate`（padding）→ `loosen`（对齐）→ `performLayout`（子类量内容）→ 夹进父区间；
- 盒上已经留着 `lastConstraints`（子类实际收到的）与 `appliedConstraints`（上次生效的），前者是"收到了什么"，后者是"和上次一样吗"。

所以约束链不是采出来的近似——而且它也不该是**记录**出来的：中间改写值（`tighten` 之后、`deflate` 之后、`loosen` 之后）都是 `layout()` 的局部变量，方法结束就没了。但复算的输入齐全：`appliedConstraints`（父给了什么）、`lastConstraints`（子实际收到了什么）、`Modifier`（全部修饰，见下）、父链可上溯。**沿父链重算一遍 `tighten → deflate → loosen` 就能逐值复现这条链**——这正是"复算优于采样"的又一次应用，和 `digest` 是同一个哲学：

```
TableBox 800×600
  ← 收到 tight(800, 600)
  ← Expanded 给 tight（父已用 200，剩余 600）
  ← Column flex 3/5（总 flex 5）
  ← PageShell：窗口 800×600 减去标题栏 200
```

**为什么复算优于在 `layout()` 里插记录钩子**：钩子会污染纯函数（`LayoutSelfCheck` 靠"同约束连排两遍比尺寸"判纯函数，钩子有状态第二遍就不等了）、把每帧 O(节点数) 的存储挂在热路径上、而且存下来的链和真正发生的链可能不同步（钩子忘了记一步，链就静默缺一跳）。复算则随时可验证：重算两次逐值相同即证明复算器是对的——判据免费。代价是查询时 O(深度) 的一次遍历，发生在**查询路径**上而不是帧路径上，这正是证据模型"采集要便宜、消费可以贵"的分工。

这和 `why` 是同一个形状：`why` 在重建域回答"谁让它脏了"，`constraints` 在布局域回答"谁限定了它"。两者都是"边 + 来源"，可以共用链式折叠与投影——**同一个底座用第二次，不是第二套机制**。

### 几何事实放在哪：进记录，不是从活树现看

复算的输入必须能被导出后读到，否则"证据可携带"当场失效。所以几何在**帧末**从
`Application::root()` 先序采样，落成 `GeometryRecord`（全是标量）：收到的约束
（`appliedConstraints`，父给的、经本盒修饰收紧）、内容盒约束（`lastConstraints`、
再经 padding 与 align）、尺寸、位置、四层盒子的修饰摘要。查询只读这份记录，
不碰活盒——导出到另一个进程问同一节点，得到同一个答案。

采样按**变化**存而不是按帧×节点全存：每个 id 留一份几何签名，帧末重算签名，
相同就不记这一帧，查询时从目标帧往前找最近的一条。`appliedConstraints` 本来就是
"上次生效的"，约束没变时快速路径不改它，所以签名天然不会假变。代价 O(变化量)
而不是 O(帧数 × 节点数)；几何窗口单独设 60 帧（比帧窗口 600 短得多），超出必须
自报，不能让"查不到"看起来像"那时没有这个节点"。

**查不到必须分三种说**：复合控件（如 `PageShell`）没有自己的 `RenderBox`，这是
永久事实；几何窗口外是暂时事实，换个帧号可能就有；节点地址不存在是地址错了。
三者混成一句"没找到"，读者会把第一种当第二种，一直等一条永远不会出现的记录。
无盒节点还要给下一步（"查有盒的子节点 N"），否则只是把失败说得好听一点。

一处结构纪律：Debug 层不得依赖 Layout（依赖方向 lint 会拦），所以采样写在
`Recorder`（它已经依赖 `Widget\Element`），`GeometryRecord` 只当纯值对象；盒的
类型从 `Element::renderObject()` 推断，不 import Layout。这不是绕规则——规则
是对的，证据层不认识渲染器才能让两端各自演化。

### 两个真实缺口

**缺口一：盒不认识元素。** `RenderBox` 只有 `Element → Box` 的单向关系，`hitTest` 返回盒，因此"点屏幕上一点 → 选中树里那个节点"目前没有反查路径。早先的设想是"从根遍历建一张 `Box → Element` 映射，按帧失效"——这个想法是错的：2000 个节点每帧遍历一遍，代价比它要诊断的东西还大。

正确的做法在一行代码里：`Element::syncBox()` 是**造盒与同步的唯一写点**，在那里顺手写 `$box->debugOwner = $this->debugId`。盒换代表时自然跟着更新，不需要按帧重建映射，也不需要遍历。代价是一个属性写入，且只在录制开启时写（与三个静态 tap 同一个开关形态）。

**缺口二：`layout()` 里没有节点身份。** 有了 `debugOwner` 就同时解决了——约束链的每个节点都能自己报出"我是谁"。

### 盒模型不需要任何底层改动

Chrome Elements 的盒模型（content / padding / border / margin 四层可视化、每层可点）初看是我们缺的——**原料其实全都在**。每个盒都挂着 `Modifier`（`RenderBox::$mods`）：四边 padding、`BoxStyle`（含 border）、inset（即 margin）、width/height 修饰、alignment。四层就是：margin = `inset`、border = `BoxStyle`、padding = 四边 pad、content = `size` 减 padding。检查器要做的只是暴露一个只读投影（`boxModel()`），**不新增字段、不改 layout**。上一轮评估说"padding 没保留成字段"是错的：它在 `Modifier` 里，只是没暴露成"盒的四层"这个形状。

### 事件监听是声明制，反而更可枚举

Chrome 能列出"元素上挂了哪些监听器"，因为 DOM 有 `addEventListener` 这个注册动作；注册是运行时的，所以 Chrome 靠枚举事件属性反推。我们的输入是声明制的：`pointerOwner` / `draggableOwner` / `windowDragOwner` 沿父链查 Widget 的**构造参数**（`pointerOwnsPressValue()`、`draggableValue()`、`pointerHandlerValue()`），还带让位规则（`isFocusable()` / `Activatable` 让位给更近的声明者）。这意味着"这个点的事件被谁处理、有哪些候选、谁让位了"**全部可以静态枚举**——不需要任何注册面改造。Chrome 的注册制回答不了"如果没有命中，**本来会**轮到谁"；声明制沿父链一列就出来。

### 源码跳转按构建态分开

之前写"不做源码跳转"是把构建态差异写成了绝对结论。`Recorder::callSite()` 已经在用 `debug_backtrace` 取 `file:line`（AOT 下缺则返回空串）；dev 形态下"跳到这个 Widget 的类定义"一行反射（`ReflectionClass::getFileName()`）就有。正确表述与"实时 attach / 反射读 State"同一条线：**dev 做（运行时栈 + 反射），AOT 不做（无源码映射）**。

### 反射只影响一半

属性面板（Widget 配置、`State` 私有字段）需要反射，所以**只在 dev 形态有**。但结构、几何、约束链**只需要数字与 id**，不需要反射——这意味着 AOT 发布态的黑匣子也能回答"这个表格为什么只有 200 宽"。

这是分期上的一条硬划分：**几何先行（两种构建态都能做），属性后置（仅 dev）**。把两者绑在一起，会让"布局调试"无谓地等反射。

## 网络：请求是因果的一部分

抓包工具回答"发了什么、回了什么"；Chrome Network 面板加一层"什么时候发的、多久回来、谁发起的"（initiator）。这两层之外还有第三层，是抓包和成熟 DevTools 都给不了的：

**响应落地时，落在哪一帧、让谁重建了、卡在哪一段。**

这才是"网络进证据"的理由。否则它只是又一个抓包客户端，而抓包客户端已经足够多了。

### 底座已经合适

三处现成，一处缺口：

- `AsyncHttp::request()` 是**唯一入口**（`get` / `post` 都走它），一次挂载覆盖全部调用点；
- `HttpTransport` 是接口，注释明写"替换实现不动门面与应用"，`inFlight()` 的注释甚至写着"测试与 devtools 用"——它确实是为观测留的扩展点；
- `Future` 有 `then` / `onProgress` / `resolve` / `reject`，结算点明确。
- **缺口**：multipart 与大 body（> 64KB）走 `submitWorker`，**绕过 transport** 直接 `dispatch->submit()`。

#### 实现校订：不写装饰器，挂在门面唯一入口

原方案是 `RecordingTransport` 装饰器包住后端、再在 `submitWorker` 两端补同样的记录。实现前核对发现这条路的**写入点有两个**：装饰器覆盖帧内路径，`submitWorker` 里手写的两条记录覆盖 worker 路径。两处写同一套骨架，迟早漂移——而漂移的正好是"上传为什么慢"这类最该被记录的请求。既然 `AsyncHttp::request()` 本来就是两条路径的共同入口，**在门面挂一次**才是单点：

- 发起：`request()` 在校验之后、分流之前调 `Recorder::tapNetworkStart()`，返回 requestId；
- 结算：给两条路径返回的 Future 挂同一个 `Future::onSettle()` 观察钩子，成功记 status / 字节 / 耗时，失败记失败态；
- 进度：multipart 的 `onProgress` 只在**根任务**那条 Future 上传播（`then()` 派生链收不到），所以进度观察下推到 `submitWorker()` 内部的根 Future；在派生 Future 上挂只会得到 `derived-chain` 诊断且永远收不到。

代价是给 `Future` 加一个**结算观察钩子**（`onSettle()`）。它与 `then()` 的区别是硬性的：观察者不派生 Future、不改值与失败传播、不撑非空 `$links`（所以"失败没人接 ⇒ Fatal"判据不变）、观察者抛错只留诊断不影响结算链。这是"观测不改被观测"在异步原语上的落点。

装饰器方案并没有被浪费：它提醒我们 `HttpTransport` 是预留的扩展点。只是对**记录**这件事，门面单点比后端装饰更可靠——后端可以换（Swoole 等），记录不该跟着换实现重写一遍。

### 记什么，不记什么

| 默认记（骨架，进证据面） | 按预算采（报文，`RecordOptions::bodies()` 开启后按 id 查） | 不记 |
|---|---|---|
| `method`、`url`、`host` | 请求体（非 multipart） | 响应头全文 |
| 状态码、响应字节数、耗时 | 响应体 | 绝对墙钟（有帧号就够） |
| `startedAtFrame` / `settledAtFrame` | 脱敏处数、截断标记 | 完整调用栈 |
| **发起者**（`request()` 调用点，复用 `callSite()`） | 格式（JSON / text） | 完整进度曲线 |
| 落地后 N 帧内该子树的重建数 | — | `onProgress` 只存一条终值标量 |

三条取舍的理由：

- **骨架默认轻量**：可导出、可被 AI 读、不撑爆协议单条 8MB 的上限；抓包工具在"看报文"上做得更好，证据的定位先是骨架。
- **报文单独一层**：接口 200、耗时正常、落地也对，但字段是错的、用户数据不对——这类问题光看骨架永远定位不了。用户明确提出后这条从"边界情况"升为"主流场景"，翻转了原裁决。`RecordOptions` 默认不抓正文；显式开启后按 `requestId` 单独查（`networkBody`），未开启时报 `bodies-not-captured`，不与“抓了但为空”混为一谈。单条截断 64KB、JSON 递归脱敏凭证键（业务字段保留，否则"rows 是空的"就看不见）、独立 200 条窗口、**不进 digest**（体量大且时刻变化会让指纹失效）。
- **必须记帧号**：抓包给不了这个。有了 `startedAtFrame` / `settledAtFrame`，瀑布图能直接贴在帧时间轴上，而不是另开一条独立的时间基准。

### 因果边怎么建

`Future::then` 的回调里通常是一个 `setState`。而 `markDirty` 已经能记"谁让谁脏"——缺的只是"此刻正在处理哪个响应"。解法是 `onSettle()` 观察者在 `resolve()` **设置状态之后、跑 `$links` 之前**触发（见上节），此刻压一个"当前网络事件"标记，`markDirty` 顺手把它写进因果边的 `detail`。

★ 顺序是硬约束：观察者若挪到 links 之后，用户 `then()` 里的 `setState` 已经跑完，归因就永远写不进去。这条顺序由变异判据守着。同样被守着的还有"帧末清标记"——不清，下一帧无关的 `setState` 会被错记成上一次响应的落地，制造一条看起来合理、实际不存在的因果边。

于是 `why(node)` 会多出这样一条边：

```
TableState  因为 api/rows.php 在 #41 帧返回（pending 3 帧，18.2ms）
```

这条边是抓包、Network 面板、火焰图都给不了的：它们知道请求什么时候回来，不知道回来之后**精确地**改了什么。

### 容量与裁剪

请求数不受帧数约束——600 帧里可能上万次请求。所以网络域要有**自己的容量**（建议 500 条）与自己的裁剪账，并遵守同一条纪律：简报里必须写"网络记录 500/500，更早的已被丢弃"。

这是"窗口是常态"这条规则第一次跨域：**每个域都有自己的窗口，证据包必须逐域自报**。

## 跨域对齐：一个节点的三张脸（S4）

成熟 DevTools 的三块面板（Elements / Profiler / Network）不是三份独立报告，靠一条共享的时间游标联动。我们的对应物是**帧号**。但直接把三个查询拼起来会得到一个看起来对齐、实际各取各的假答案——三个域的"缺省帧"语义本来就不同：

- `why(node)` 缺省取**最近一次重建它的帧**（多动作场景里最后一帧常常是静止帧，按它回答等于"没重建"）；
- `boxModel(node)` / `constraints(node)` 缺省取 `lastFrameId()`，而且几何按**变化**存储：目标帧没重新采样就往前找最近一条，返回的 `frame` 可能小于请求的帧；
- 网络没有缺省帧；`startedAtFrame` 与 `settledAtFrame` 是两个时刻，`landed[]` 记的是结算同帧被改的节点。

所以对齐的第一条纪律是：**帧只在一个地方选，三域一律用同一个显式帧号查，各自回显自己实际命中的帧号**。若某域回退到了更早的帧，必须显示真实帧号并标 `stale`，不能伪称与目标帧一致。实测里 `why(node=2, frame=2)` 得 `frame=2`，而 `boxModel(node=2, frame=2)` 得 `frame=1`——这正是会被拼接式实现抹掉的差异。

第二条纪律：**查询层只给事实，不给结论**。`align(node, frame)` 返回三域各自的命中与缺失、实际帧号、stale 标记、逐域窗口；"重建了但几何没变、也无网络归因 ⇒ 可能是父传播还是无因重建"是投影层的规则，与 `Brief` 的发现同形。查询层一旦自己判"这里不对"，证据与意见又长在一处。

第三条纪律：**节点 → 请求反查不建第二份真相**。`landed[]` 已在请求侧，对齐时扫网络窗口（500 条）即可。但要分三种"没有"：这条请求在窗口外、窗口内有请求但没有归因到这个节点、 node 根本不在因果记录里。空数组不区分这三者，等于把"没问题"和"没数据"说成一句。

```
align(node=2, frame=2)
  frame=2  node=2  path="PageShell > Card"
  causal:  {found:true,  frame:2, rebuilt:true, causes:1}
  geometry:{found:true,  frame:1, stale:true, size:{w:800,h:600}}   ← 实际是上一帧的快照
  network: {found:false, reason:"no-landed-request", window:{...}}  ← 不冒充"没有网络"
  windows: {frames:600, geometry:60, network:500}
```

`found` 与 `complete` 分开：`found` 只是"这个地址在证据里存在"（任一域有值），`complete` 才是三域齐全。把前者误读成后者，是继"假对齐"之后的第二种静默错误——所以两个字段都必须出现在返回值里，且判据要逐值核对。

**关于兼容**：S4 会把既有查询的 miss 形状归一为 `{found, reason, window}`（`network()` 现在没有 `found`，几何用 `reason` 而网络用 `miss`）。这是刻意的破坏：消费者只有四个（report / brief / network / panel），都能同步改；形状不统一每加一个消费者都要重学一遍三种拼法，代价远高于一次性收口。既有的 `miss` 字段保留为 `reason` 的别名一段时间，让外部脚本不立刻断，但判据只看归一后的形状。

`debugOwner` 不属于 S4 的对齐本身：几何采样从根先序走，Element 与盒天然配对。它只属于"点屏幕一点 → 命中 RenderBox → 反查节点"那条支线，且 `StatefulElement::syncBox()` 是第二个写点（有提前 return），不能只在基类写一行就以为覆盖了全部造盒路径。


## 窗口是常态，不是异常

录制器是环形缓冲，容量固定（`Recorder::DEFAULT_CAPACITY` 现在是 600 帧）。这意味着**任何时候拿出来的证据都是被裁过的**，"窗口外不可查"是设计而不是缺陷。

由此得到一条硬规则：**任何交给消费者的证据都必须自报裁剪**——裁掉了多少、裁在哪、怎么取回。不说，读者就会把"我没看到"当成"不存在"，然后给出一个语法正确、语义全错的结论，而报告本身看不出来。

这条规则的第一个实例已经在面板里：`… 另 N 支（M 个节点）未展开`。投影层要把它变成普遍义务，而不是某一处的贴心。

一旦证据有多个域，这条规则还要**逐域**执行：帧有帧的窗口（600），网络有自己的（500 条请求），几何与绘制各有独立窗口（都是 60 帧，但两者互不覆盖），属性按节点存最近快照。节点表另有 `evicted` 域记录已回收地址，保证离线查询仍能把"这个号发过但已回收"与"地址写错"分开。所以证据包不能只报一个"窗口"，要报**每个域各自的窗口与裁剪量**——否则读者会把"网络记录满了被丢了"误读成"这段时间没发请求"。

投影层还要防一个近亲错误：**不同域用了不同的默认窗口**。`hotspots` / `nodes` 的聚合窗口默认是最近 300 帧，而 `frames` 给的是整个环形窗口（600）——简报的表头写"600 帧"，聚合数字却只数了 300 帧，两个数字对不上，而报告看起来很正常。原型就踩了这一脚（见"实现校订"第 11 条）。

## 四层

| 层 | 职责 | 关键约束 |
|---|---|---|
| **L0 采集** | 三个录制挂点、绘制后叠加、命中测试、IO 唤醒 | 未安装时只多一次静态判空；深检按需开 |
| **L1 证据** | 各事实域 + 四份指纹，只读、可导出 | 不改写、不补充推断；写入只发生在采集层。属性与活树点选按 A55 已降为即时内省，不再写进证据 |
| **L2 投影** | 事实 × 预算 → 视图 + 裁剪账 | 纯函数、无状态、排序确定、自报裁剪 |
| **L3 消费者** | 终端、Web、机器（AI / CI） | 只能读投影，不能触达事实内部 |

**越层访问禁止**：消费者不直接遍历帧记录，投影不反过来查询消费者，采集层不知道谁会看。这条是防止重演"四套 schema、两套协议、两套身份"的结构性约束——形态一旦允许越层，各层就会各自长出一份真相。

底座不动：三个挂点、帧边界、命中测试、IO 唤醒都是现成的，渲染管线不需要改。这是整个方案成本可控的根本原因。

## 投影：消费者只有视口，没有全景

```
project(facts, budget) → (view, omitted[])
```

三条规则：

1. **纯函数**。同样的输入与预算必须给出逐字节相同的输出：无时间戳、无随机顺序、排序必须有确定的次级键（耗时降序 → 帧号升序）。
2. **自报裁剪**。`omitted` 必须带三件事：裁掉多少、裁在哪、怎么取回。
3. **不能只按时间截断**。简报必须永远包含最贵的几帧与最热的几个节点——否则窗口一长，真正的根因正好被裁掉，而读者以为是"没什么问题"。

这是面板那条"虚拟化在格式化之前"的推广。屏幕与上下文窗口是同一个概念的两个实例：

| 消费者 | 视口 | 错误写法 |
|---|---|---|
| 终端 | 24 行 | 先格式化全部再切片（2000 次 `sprintf` 白做） |
| 机器 | 几千 token | 先序列化全部再截断（对方不会滚，会瞎猜） |

同一类错误的本质是**先物化全量，再假装只有一小块**。正确顺序是先摊平成轻量结构，再只物化视口内的那一份。

投影的四个出口：

| 投影 | 形状 | 给谁 |
|---|---|---|
| `brief` | 结构化的几行结论 + 地址 | 机器、CI 摘要 |
| `table` | 定宽行表 | 终端 |
| `tree` | 带键与深度的行 | 终端、Web |
| `json` | 完整但分页 | 工具、存档 |

## 消费者平权

| 消费者 | 带宽 | 交互 |
|---|---|---|
| 终端 | 24 行 | 按键追问 |
| Web | 一屏多视图 | 鼠标追问 |
| 机器（AI） | 几千 token | 工具循环追问 |
| CI | 0 | 只比指纹与发现 |

四者共用**同一个查询面、同一套投影函数、同一份指纹**，差异只在带宽。没有任何一个消费者能访问事实的内部结构。

一致性判据：**同一份证据在三种消费者里的结论必须相同**。这条不是为了好看，它是 v1 死因的正面判据——那一版有两套协议、两套节点身份，于是同一个问题在不同入口得到不同答案，而没人能说清哪个对。

顺带一个已经对的形状：增量游标是**无状态**的（调用方持有"看到哪了"，服务端不记）。这正是机器循环需要的语义——漏一条只是"再问一次"，而订阅一旦漏一条，之后每一条都是错的。

### 干预是唯一的反向流

驱动（`frame` / `input` / `effect`）与查询都是"调用方 → 证据"。干预——高亮一个盒、暂停帧循环——方向相反，是"消费者 → 采集"，因此它**不属于查询面**：一旦放进去，`SessionQueries` 的"只读"承诺就破了，而这条承诺正是本地与远端能共用同一份消费者代码的前提。

暂停已经落地（`pause` / `resume`，后者带 `frames` 就是单步）。它改的是**推进的节奏**，不是记录：`t` 仍然只来自脚本，所以"直跑"与"中途暂停再跑完"两份记录逐值相同。这也是它敢在线做的理由——它不会把被观测对象的证据弄脏。高亮还没做，它的判据与暂停不同（那里要证明的是"染色不改变结构"）。

它只在 dev 形态做。AOT 不做——发布态没有可交互的观测面，也没有空闲的帧循环：帧的 `t` 来自墙钟，谁按什么节奏推进都改变记录，暂停在那里不是"改节奏"而是"改事实"。

## 发现：把"找针"收回一半

机器擅长解释，不擅长找针。如果证据里只有原始事实，每次使用都要先做一遍统计：慢、不可比、不可复算。

发现是确定性的判断层。第一批规则（全部可用现有查询算出）：

| 规则 | 判据 | 原料 |
|---|---|---|
| 慢帧 | 帧内耗时 > 预算（默认一帧 16.7ms，可配） | 时间轴 + 段账 |
| 段占比异常 | 某段占帧内耗时 > 60% 且绝对值 > 2ms | 段账 |
| 重建扇出异常 | 单帧重建数 > 阈值，且集中在少数结构根 | 因果 + 结构折叠 |
| 长列表未虚拟化 | 某个容器的同形折叠组计数 > 阈值 | 结构折叠的计数与成员 |
| 同节点跨帧重复重建 | 某节点重建次数 / 窗口帧数 > 0.5，且自身写入占多数 | 跨帧节点聚合 |
| 约束放宽 / 收紧 | 子盒收到的宽度上限相对父内容盒改写 ≥ 8px 且 ≥ 10%，子盒本身 ≥ 100px | 一帧全量盒几何（`boxes`） |

每条发现必须带五样东西：规则名、证据地址（帧号 / 节点 id / 段名）、度量值、阈值、可复算说明。缺任何一样，它就从"证据"退化成"意见"。

**分布分工**：

- 工具说**哪里不对**（规则，确定性，可关、可配阈值）；
- 机器说**为什么、怎么改**（解释与方案，允许不确定，必须引用证据地址）；
- 人决定**改不改**。

关键约束：发现必须可复算。同一条规则、同一份事实，必须得到同一条结论。否则"工具说的"就变成不可否证的权威——那和让模型瞎猜是同一种病，只是换了个说话的人。

### 几何事实的第一个消费者：简报

S3a 的 `boxModel` / `constraints` 若只有测试在问，就还是"能力有了、没有消费者"，和当年 D3 传输的处境一样。把它接进简报时**没有新增任何采集**，只加了一个读操作：`boxes(frame)` 一次给出该帧所有盒的紧凑事实（node / parent / type / applied / inner / size / width 修饰），投影层跨盒比较"父内容盒给的上限"与"子实际收到的上限"。

不在查询层判"这里不对"：查询只给原料，判断留在投影层，否则证据与意见长在同一处。也不让简报自己挑几个节点逐个问 `boxModel`——挑节点的逻辑会在 gather 与规则里各写一份，选错（复合控件没有盒）还静默没结论。

规则说**可复算的改写**，不说"这是 bug"：

```
· TableBox → Column 宽被放宽到 536（父内容 320，+216px，宽度修饰 536）   frame:1 node:21
· Stack → SizedBox 宽被收紧到 202（父内容 760，-558px，宽度修饰 202）    frame:2 node:32
```

两个方向各最多一条，按（父类型 → 子类型 → 改变量 → 原因）去重——表格 12 行同形单元格是一条事实，不是 12 条发现；1px 图标不参与（低于 100px 的盒不算布局结论）。每条都指回 `constraints(node, frame).chain` 与 `boxModel(node, frame)`，读者可以直接复核那一跳。

几何窗口只有 60 帧（因果是 600），所以 `clean` 还多一条门槛：一帧都没有盒、或请求的帧早于几何窗口起点，报 `geometry-inconclusive` 而不是"没发现问题"；裁剪账也要写"几何覆盖 #N（几个盒）"。这与因果树被 `maxDepth` 截断时的纪律是同一条——**没看见不等于没有问题**。

### 诊断器不产出改法

层次上只有一条线：诊断器产出**确定性判断**——规则名、证据地址、度量值、阈值、复算方式；"怎么改"属于机器消费者，且必须引用诊断器给出的地址。

把"根因建议"放进诊断器有两个后果：一是工具开始输出不可复算的结论（同一条规则、同一份事实，两次给出不同建议）；二是规则表被迫记住"怎么修"，而修法随框架版本变，规则表会腐烂。所以诊断器的词表里有"慢帧""扇出异常""约束放宽"，没有"应该加一个 `Expanded`"。

架构图上这一格最容易画错：诊断器只放检测与对齐，建议归"AI 与 CI"那一格。

## AI 读的是什么

把"AI 可读"理解成"输出 JSON"是错的。一份 600 帧 × 数百节点的完整记录是几 MB，塞不进上下文；就算塞进去，模型也只能把它当作文本统计，结论不可复算、无法否证。

机器真正需要的是三件事，而它们恰好是三条对证据模型的**硬约束**：

| 约束 | 反例 | 现状 |
|---|---|---|
| **语义内建** | 截图里"这个方块是 Table"靠人认；证据里必须是字符串 | 已有：记 Widget 短类名而不是 Element 子类名，记写入点而不是只记节点 |
| **地址稳定** | 追问是"第 3 步那个节点"，不是"屏幕第 7 行" | 已有：节点 id、帧号、段名；面板的行键正是它的视图化 |
| **自报裁剪** | 全量 JSON 丢过去，它不会滚，会瞎猜 | 半有：面板有，投影层要变成义务 |

于是机器的用法不是"读一份快照"，而是一个闭环：

1. **简报**：拿预算内的几行结论（最贵帧、最热节点、已有发现）；
2. **定位**：按游标增量取，或用地址直接问某一帧；
3. **追问**：问"为什么这个节点重建"、"这一帧的因果关系"；
4. **复算**：拿到指纹，重跑同一份驱动，验证结论。

每一步都落在一个已有的查询上，不需要为机器单开一套接口。**这是"消费者平权"的实际含义**：机器不是特殊公民，它只是带宽小、必须分步问。

至于截图——它在**行为、性能、结构**这三类问题上确实不再是必需品，因为这些问题本来就是符号的。但像素错位、字体回退、抗锯齿、颜色不在其列：那类问题归视觉回归基线，本来也不该靠人眼。把"不需要截图"说成"截图没用"，是把两类问题混成一类。

### 顺序的三条理由

**S0 后置的排序已经验证。** 上一版把它排第一，实践推翻了：证据包的字段由事实形状决定，而事实形状到 S4 才稳定。格式定早了，每加一个域就破一次兼容——那正是 v1 四套 schema 的来历。S0 已在事实定型后落地；排序依据（先便宜、先可推翻假设）仍然成立。

**S-live 先于 S5 落地，是因为它比 Web 视图便宜。** 宿主不退出、观察者轮询游标，两件事的底座都已经有（`frames(since)` 是无状态游标，`Application::frame()` 已逐帧调用）。落地前，开发期一次循环是"改代码 → 跑脚本 → 看报告"，几十秒；有了它才是成熟 DevTools 的手感。成熟工具全部建立在这件事上，而它恰好是这套方案里唯一被"可判性"换掉的东西。

**S2 排在最后不是因为它不重要**——它是能力层第一条，也是唯一能覆盖 AOT 的一期。但它的价值在线上与崩溃现场，而当前痛点全在开发期；且它要动 AOT 开销与多窗口隔离，风险最高。S-live 先上，S2 可以复用同一套"常驻 + 窗口"的形状，避免做两遍。

### 被推翻或修正的四条旧判断

- **S1 提前**——成立，且确实是第一个落地的。理由不变：发现与简报不需要任何新采集，写入点聚合、重建排行、段账、根因链都已经在查询面上，缺的只是规则与投影。
- **S2 之前必须先解决多窗口**——先落地的是"拒绝"：`DebugSession::open()` 见到已有录制器直接抛，不留"开了就错"的中间态。**拒绝不算解决**，2026-11-25 补成真正的隔离（A53）：录制器绑到应用、帧内由栈回答"当前录制器"，判据是"两个窗口交错跑 == 各自单独跑"逐值相同。当初把它推给 S2 的理由不成立——隔离与常驻没有共同机制，谁也不该等谁。
- **S6 把点选与高亮/暂停放一起**——拆开。点选是**查询**（`Query::pick()` 已落地，属 S4 的能力）；高亮与暂停是**反向流**（消费者 → 采集），混在同一期会让"查询只读"这条承诺含糊。
- **S3 拆三段**——成立。S3a 不需要反射（数字与 id），两种构建态都能做；S3b 必须要反射，只能在 dev；S3c 与反射无关，但有一处 worker 路径绕过 transport 的结构缺口，必须先补。顺带一条实施教训：**几何采样从根先序走，Element 与 Box 天然配对，不需要 `debugOwner`**；它只在"点屏幕一点 → 命中 RenderBox → 反查 Element"那条路上才需要，把两者算成同一件事会多出一次错误的字段改动。

## 实现校订（原型验证之后）

写了一份原型（`devtools/bin/debug-brief.php` + `devtools/View/Brief.php`）：用现有查询面在一张真实页面上算出发现，不新增任何采集。它跑通了，也暴露了十条设计上没写死的东西。这些不是"实现细节"，是会静默给出错误结论的地方：

| # | 原来的说法 | 实测暴露 | 改成 |
|---|---|---|---|
| 1 | "机器仅凭简报能定位到正确帧与节点"当判据 | 需要模型参与，不可复现、进不了 CI | 拆成两条确定性判据：**正确答案出现在简报前 N 条**（纯字符串比较）+ **同一份证据两次投影逐字节相同**；模型评测降为离线，不进 CI |
| 2 | 没写发现与指纹的关系 | 一旦发现参与指纹，改一条规则阈值就让全部历史证据"指纹不同" | 指纹只覆盖 Drive + Facts；发现是派生视图，带规则名与规则版本，**不进指纹** |
| 3 | 发现只带地址 | 滑动窗口下同一份证据重跑会落在不同窗口，发现不可复算 | 发现与简报都必须带 `window: [from, to]`，比较前先对齐窗口 |
| 4 | 假定树的节点总带 `ids` | `ids` **只在份数 > 1 时存在**（单个节点不给，免得同一件事两种写法）；直接读 `ids[0]` 拿到 0，报告里印出 `node:0`，不报错 | 代表 id 用 `id`、份数用 `count`，`ids` 只用于展开 |
| 5 | 投影自报裁剪 | 查询层默认 `limit` 是 10 / 10 / 30，投影吃默认值就数不出自己裁了多少 | **裁剪只发生在投影层**：投影一律传 `limit: 0`（不截断），查询层的 `limit` 只服务人读 |
| 6 | 发现规则从根上扫 | 表格页的 12 个同形兄弟在第 8 层；原型先给 `maxDepth: 2`、后又给扫描器限深 4，规则**永远不触发**，报告看起来"没问题" | 扫描深度与查询深度必须同一个来源；规则要读截断标记，简报要说明"扫到第 N 层，更深处未检查"——**裁剪不能伪装成结论** |
| 7 | 节点表随帧窗口回收 | 节点表只增不减（清帧不清节点），长跑泄漏，导出还带着已卸载的节点 | S0 之前定回收策略：按代际标记或引用计数 |
| 8 | "崩溃取证"没有限定范围 | 进程级崩溃时落盘钩子不一定执行 | PHP 层由 Frame catch 与 RECOVERABLE 面包屑覆盖；Win32 原生过滤器附 sidecar（A62），但 sidecar 每 30 帧刷一次 ⇒ 最多落后半秒 |
| 9 | 证据包"完整但分页" | 600 帧 × 每帧数百条边是几十 MB，默认全量不可用 | 默认导出 = 窗口内慢帧 + 节点表 + 发现 + 驱动；全量要显式 `--all` |
| 10 | 路径直接截断 | 从头截留下 `PageShell > Card > Column > …`，每个节点都长这样 | 路径**从尾部**裁：`… > Table > TableBox` |
| 11 | "投影一律传 `limit: 0`"就够了 | 还有**聚合窗口**：`hotspots` / `nodes` 的 `frames` 默认 300，而 `frames` 给的是全窗口（600）。只归零 `limit` 时，表头写 600 帧、聚合只数 300 帧，数字互相矛盾而不报错 | `frames: 0` 与 `limit: 0` **两个都归零**。前者是"看多少帧"，后者是"返回多少条"，是不同的两件事 |
| 12 | 几何查不到就说"窗口外" | `PageShell` 这类复合控件**永远没有自己的 RenderBox**。把它说成窗口外，读者会一直等一条不会出现的记录——和"裁剪伪装成结论"同型 | 三种 miss 分开：`no-render-box`（永久，附"查有盒的子节点 N"）/ `unknown-node`（地址错）/ `outside-geometry-window`（暂时）。实测 node 1 曾是第一种却报成第三种 |
| 13 | "约束链复算"等于"从活树重算" | 活树在导出后不存在，历史帧的节点也可能已卸载；那样做出来的查询只在 attach 时能用，直接违反"证据可携带" | 帧末采标量进 `GeometryRecord`，查询只读记录再复算；签名去重让代价 O(变化量)，几何窗口 60 帧独立自报 |

## 边界

原来这张表有 12 条“不做”，它们混了三种性质完全不同的理由：**构建态不可达**（发布态不带反射级检查）、**有更好的工具**（报文抓包做得好得多）、**原则自洽**（证据只读、订阅会连锁漏）。三种理由混在一张表里，就会重演同一类错位：属性域曾按“要进 AOT 证据包”的成本付费（脱敏 + tag 编码 + 快照 + 排版，两套实现合计 545 行），可它在 AOT 里读不出字段（`PropReader::available()` 那段自检就是为此写的），在 dev 里又不如 PHP 原生直接 —— 两头都不划算。已按 A55 收口成一份 `ObjectDump` 反射原语（334 行，其中代码约 242 行）：只读当场活树、与 eval 共用，两头和中间都不再重复付费。

一条判据替代 12 条禁令：

> **一条事实只有在「AOT 产物里也能用纯标量复现」时，才算证据。**

这条判据不新：“跨会话对象引用不做”用的就是它，只是从没人拿它去判属性域。按它分三层，每层的成本结构完全不同：

| 层 | 归属 | 内容 | 编进产物 |
|---|---|---|---|
| **L1 证据** | 两态共有、进指纹 | 时间轴、因果、结构、几何、绘制、网络骨架、段账、驱动、摘要、发现 | **编**：写面与记录类型在热路径上。实测生成 12,188 行，占产物 5.6% |
| **L2 内省** | 仅 dev、不进指纹 | 属性、内存、报文原文、调用链、源码位置、任意表达式 | **不编**：交给 PHP 原语（`__debugInfo` / `gc_status` / `stream_wrapper_register` / `debug_backtrace`）与一个 `debug eval` 出口（A55） |
| **L3 审查面** | 只在 `tools/` | 查询、证据导出与导入、远程协议、会话驱动 | **不编**：用 `ignore` 排出。实测 −7,931 行（−39%） |

三层不是“重要性排序”，是三种不同的成本结构：**L1 的成本是每帧纳秒**（实测 `tapRebuild` 无录制器 +35 ns、有录制器 +65 ns；361 次重建约 12.6 µs，占 16.7 ms 帧预算的 0.08%）；**L2 的成本是零**（dev 侧零编译）；**L3 的成本是产物体积**（`tpc` 全量编译、无死码消除，类可达即整类进产物）。

按这三层重看原来那 12 条：

| 原条目 | 归到哪 | 现在的说法 |
|---|---|---|
| 像素级视觉回归 | 不做 | 归 golden 基线；证据是符号的 |
| 实时属性编辑 | 不做 | 控件不可变；改了就与运行时不是同一份，证据立刻失效 |
| 把机器的结论写回证据 | 不做 | 证据只读，发现由规则产出；写回解释，可复算当场失效 |
| 跨会话对象引用 / 全量历史帧 / 订阅式推送 | 不做 | 序列化不了；内存不可接受；漏一条之后每条都错 |
| 用框架自己的树控件画检查器 | 不做 | 观测面会随故障一起塌；高亮走绘制后叠加，面板在进程外 |
| 发布态携带反射级检查 | **L2** | dev 有完整反射；AOT 读不出，所以内省只活在 dev、且不进证据包 |
| 记录请求体与响应体 | **L2** | 不进证据；dev 侧改用 `stream_wrapper_register` 旁路成文件，于是不再是“不做” |
| 源码跳转 | **L2** | `callSite()` 的运行时栈 + 反射取定义位置：dev 做、AOT 不做 |
| 每帧遍历树建“盒 → 元素”映射 | **L1 的代价问题** | 2000 节点每帧一次不划算；在造盒的唯一写点写一次 `debugOwner` |
| 一个录制器服务多个窗口 | **已收口** | A53：录制器属于应用，帧内由栈回答 |
| 实时 attach 一个正在跑的真窗口 | **已落地（dev-only，A57）** | 协作式 tick：有桥时 `waitEvents` 有上界、每轮收一次消息；`t` 来自墙钟 ⇒ live 可观察不可重放，不进证据语义 |

三层的界最初是靠 `ignore` 清单维持的，而清单本身有一串坑：它是 list 型项、合并时**整体替换**（`ProjectYamlLoader::mergeConfig` 的 `array_is_list` 分支），任何应用一重写就把基础排除整张顶掉；排父接口必须连子接口一起排（`Session extends SessionQueries, SessionDriver`）；排完还要查孤儿（`Json` 排掉两个消费者之后只剩自己）；而 tpc 对不存在的 ignore 条目静默跳过，拼错路径零报错。A54 当时的做法是「唯一声明在 `build/base.yml` + `check-debug-scope` 守等集」，但清单只会越写越长（A69/A70 各加一个域类），且它有一个静默口子：把审查面类误加进写面白名单永远不报。

A72 把界从「清单」换成「位置」：审查面 28 个文件物理搬到 `devtools/`（命名空间 `Drift\DevTools\`），写面 17 个留 `src/Debug/Session`。各应用的 `sources` 只有 `../../src` ⇒ 审查面**不在编译范围里**，`ignore` 的 24 条调试条目全部删除。守门器随之改判四条结构断言：`src/Debug` 只许写面、`src/` 的代码不得引用 `Drift\DevTools\`（注释不算）、没有任何 sources 把 `devtools/` 收进编译范围、`ignore` 不得再有遗留调试条目；`--selftest` 16 条合成用例全咬红，8 个应用全绿。新增一个审查面类从此不需要改配置——它在 `devtools/` 里，就天然不进产物。

## 与既有裁决的关系

继承：

- **A32**：记录只有帧因果一份真相，采点收在唯一漏斗上——证据的事实部分就是它。
- **A33**：协议少而稳，传输只是执行器——投影与消费者都建立在这个查询面上，不再新增协议层。
- **A34**：单帧因果按结构折叠，不按类型排名——发现的"长列表未虚拟化"直接用它的折叠计数。
- **A35**：选中与折叠是视图状态，行键而非下标——投影层的"地址稳定"是它在证据层的表述。

新增 **A36**：证据是产品，面板与视图是出口。
新增 **A37**：检查器的中心是约束链（不是树），网络进证据记的是"边"（不是报文）。这两个域不改变架构中心，只是把"为什么"从重建推广到布局与网络；同时它逼出了第三条指纹 `digest(External)` 与 `S3` 的三段拆分。

需要修订的两处旧边界（原先写"不做"，现在改为分构建态）：

| 原结论 | 修订为 |
|---|---|
| 实时 attach 一个正在跑的真窗口：不做 | **dev 形态做**（反射完整、事件循环有空闲、IO 可注册）；发布态仍不做 |
| 反射读 State 属性：不做 | **发布态不做，dev 形态只读做**，且只做内省、**不进证据包**（A55）；序列化必须有深度与节点数上限 |

属性编辑与进程内树浏览器仍然不做，理由见上表前五行——它们不是“构建态做不到”，是**原则不许**，所以三层重划之后位置不变。

分期映射：原 D5（导出 + CI 基线）落在 S0 / S5；原 D6（崩溃取证）落在 S2。

第三轮新增两条（2026-11-25，按“能不能进产物”重划边界）：**A54** 调试代码分三层归属——L1 证据编、L2 内省不编、L3 审查面用 `ignore` 排出；**A55** 内省不是证据，且内省交给 PHP 原语而不是自己实现。这一轮不改架构中心，改的是“哪些代码该进产物、哪些事实不该进证据包”。

第二轮修订（实施之后）新增两条：**A47** 把分期的排序依据从"能力层重要性"改成"前置条件"（S0 后置、S-live 前移、S2 最后、S6 只剩干预），**A48** 划清诊断器与机器的分工，并明确干预是唯一反向流、不进查询面。这一轮也把上面那张"未定"清单全部收口，见文末。

## 已定（原开放条款的收口）

这八条曾经写成"未定"，理由是怕过早拍板。现在事实形状已经稳定，逐条给结论——留着"未定"会让实现各自选一个默认值，而默认值分叉正是 v1 的死因之一。

| # | 问题 | 结论 | 依据 |
|---|---|---|---|
| 1 | 简报要不要带最小像素快照 | **不带**。证据是符号的；像素问题归视觉回归基线 | 见"AI 读的是什么" |
| 2 | 阈值默认值 | 慢帧 16.7ms；扇出 > 100 节点且集中度 ≥ 60%；跨帧重复 ≥ 50%；同形折叠组 ≥ 8；约束改写 ≥ 8px 且 ≥ 10%，子盒 ≥ 100px。**全部可配**，且必须回显进 `Finding.threshold` | 默认值来自实测；`Thresholds` 十个字段都有默认值，当前 CLI 暴露 slow / fanout / repeat 三项 |
| 3 | 证据包版本策略 | **带版本号；旧版本读新文件报错，不降级**。降级会交出一份半证据，比报错危险 | 与"窗口外必须自报"同一条纪律 |
| 4 | 多窗口 | **每个窗口一份录制器**（A53）：录制器绑到应用、帧内压栈；`Discovery` 多条目与跨窗口并列视图已落地（A59，投影层不 join） | 命名空间方案要求每个写点都知道"我在哪个窗口"，而唯一可靠的来源就是当前帧——那与"随应用走"是同一件事，只是多一层要维护的映射 |
| 5 | 预算单位 | **字符数**。token 估算依赖模型，换一个模型预算就变，直接破坏"两次投影逐字节相同" | 投影的确定性优先 |
| 6 | 约束链粒度 | **只复算派生修饰，不记 `flex` 分配边**。复算的输入（父 `inner`、子 `applied`、父类型）已经够；多记一条边只是把复算变成半个采样 | S3a 判据"两次复算逐字节相同" |
| 7 | 网络隐私 | A38 已裁：默认脱敏，`redact:false` 与 `redacted:0` 可分 | A38 |
| 8 | 判据形态 | 数值按**定点截断**比较（`GeometryRecord::pack()` 已是定点）；链只做"两次复算逐字节相同"，不做跨机器容差 | 容差会让"不一样"也通过 |

真正还开放的一件工程事是 S3d 的归因粒度（算到节点还是算到 layer）；S0 的字段清单已定型在 `Evidence::RECORDS`。
