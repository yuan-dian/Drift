# 开发态 VM 双模：改 PHP 不重编译

> 借鉴 `Drift3/docs/blueprint/02-开发态VM与热更新双模.md` 与其 `probe/vm-shell` 真机结论。
> 2026-11-05 落地。本仓文档，不改 Drift3 原始文档。

## 0. 结论

开发态改成「**AOT 只编一个壳（入口 + C++ 桥），业务 PHP 全部运行期动态加载**」。
改 `src/` 或 `apps/` 下任意 PHP 保存，`drift-dev` 自动重启窗口，**壳不重编**。
生产态 `drift-build` 的全静态 AOT 路径逐字节不变。

## 1. 用法

```bash
php tools/drift-dev.php                 # 默认 hello，改代码自动重启
php tools/drift-dev.php showcase        # 指定应用
php tools/drift-dev.php --no-watch      # 只跑一次
php tools/drift-dev.php --rebuild       # 强制重编壳
php tools/drift-dev.php --selftest      # 指纹判据自检（含反例）
```

首次运行编译 `dev.exe` 一次（实测 5.7–7.0s，只编壳与桥），之后只要 cpp-src /
壳配置不变就永远跳过编译。Ctrl+C 退出运行器。

## 2. 形态与红线

| | 开发态 | 生产态 |
|---|---|---|
| 工程 | `apps/dev/project.yml` | `apps/<app>/project.yml` |
| sources | `dev-shell.php` + `cpp-src` + 两个桥接回调文件 | `.` + `src` + `cpp-src` |
| 业务 PHP | 内嵌 ZendVM 运行期 `require` | 全静态编译 |
| 控制台 | `no-console: false`（要 stdout/stderr） | `true` |

- **AOT 注册过的类被动态 require 同名源码会 Fatal「already in use」** ⇒ 业务 PHP
  绝不进 dev 的 `sources`。这是 `apps/dev/project.yml` 的头号红线。
- 字面路径 `require` 会被 tpc 内联 ⇒ 壳必须用**变量路径**
  `require getenv('DRIFT_DEV_ENTRY')`（`probe/vm-shell` 已证）。
- 动态入口 `apps/dev/dev-entry.php` → `tools/autoload.php`（读 composer.json 的
  PSR-4）→ `App\<名字>\Bootstrap::run()`。只支持 composer.json 里有该前缀的应用。

**为什么有两个 `src/` 文件例外**：`cpp-src/win32/drift_win32.cc` 的 WndProc 以
`extern void php_drift_resize_hook_pump(Int)` 静态链接 PHP 侧具名函数
（`src/Platform/Win32/ResizeHook.php` + `ResizeHookState.php`）。不收进壳就是
LNK2019（实测）。它们是**链接期契约**，不是业务代码；`ResizeHookState` 由 AOT
注册后 autoload 不会再加载它，故无重声明冲突。其余 389 个 `src/` 文件全动态。

## 3. 热更语义

**跨进程重启，不是同进程状态保留式热更。** 内嵌 ZendVM 对同一路径的 `require`
会缓存 opcode，同进程重刷读不到新代码；且本框架没有 Store/Cell、`StatefulWidget`
状态模型，状态也不该跨热更保留。运行期 ini 显式 `opcache.enable=0`：既避开
ASLR 下 opcache 拒绝启动导致进程秒退，也避免 opcode 缓存挡住热更。

按映像名 `taskkill /IM dev.exe /F` 强杀旧进程 ⇒ dev 重启不走优雅 shutdown；
正常关窗路径由 `probe-window.py` 的判据 ⑤ 单独验证。

## 4. 工具链改动

- `tools/drift-dev.php`：壳输入指纹（`_build/dev-shell.sha`，只含进 AOT 的文件）、
  业务输入快照（mtime + size，排除 `build/` 缓存目录）、自动重启、运行期 ini、
  PATH 前置 PHP 发行版目录（`php8ts.dll`）。
- `tools/drift-build.php`：`distributeRuntime()` 抽出共用；新增短路「输入未变且
  产物仍在 ⇒ 跳过编译」，仍分发运行时 ini 与 TLS 信任根。实测 **0.69s**（原重链
  5.7s / 无缓存 27.9s）。`--full` 不受短路影响。
- `tools/probe_win.py::App` 加 `env_extra` / `state_name`；`tools/probe-window.py`
  加 `DRIFT_PROBE_EXE` / `DRIFT_PROBE_ARGS_JSON` / `DRIFT_PROBE_ENV_JSON`，让
  prod exe、dev 壳、dev 运行器三种形态复用同一套五条判据与自动关窗。
  `state_name` 是必要修正：状态文件按**应用名**命名，换 exe 形态时按 exe 名
  隔离会落空（表现为窗口尺寸还原成上次值，看着像渲染不一致）。
- `tools/Lint/Rules/NanoHygiene.php`：按文件精确豁免两个 dev 壳文件
  （`require` / `getenv` 正是它们存在的理由，且永不进 `--nano`），不按目录豁免。

## 5. 验证

- P0 动态链路探针 6 项：autoload、框架类动态加载、动态代码调 AOT 桥函数
  `drift_thread_id()`、AOT 注册的 `ResizeHookState`、**AOT 方法回调动态闭包**。
- **改业务 PHP 不重编**：临时改 `HelloApplication::title()`，旧 `dev.exe`
  （sha256 `d55b4bb0…` 前后一致）跑出新标题；源码随后还原、工作区干净。
- 真机 `probe-window.py showcase` **0 FAIL / 5 条 × 3 形态**（prod AOT、dev 壳、
  dev 运行器），窗口由探针自己关、退出码 0。
- `drift-dev --selftest` 5/5，含两条反例牙检：改业务 PHP **不**触发重编壳、
  构建缓存变化 **不**触发重启。
- gate **17/17（121.7s，含两套 golden 零刷新）**、lint **1023 文件 0 error**、
  docref **106 ok / 0 FAIL**、`API-SURFACE.md` 零 diff；`hello` AOT 重建 24.8s、
  `dev` 壳 5.1s，两者第二次调用均走 0.7s 短路。

> 上面的数字是落地当时的那一次结果。§7 之后 gate 为 **18 项**（新增 `devshell`）、
> lint **1022 文件**（删 `probe-showcase.php`）、`--selftest` **10 条**。

## 6. 已知边界（不假装绿）

- **「自动重启后新窗口可见」未做窗口级断言**：Windows 上 `proc_open` 对 AOT
  进程返回的 `pid` 在 `tasklist` 里查不到、`running` 会误报，`FindWindowW` 又受
  句柄复用与旧窗遮挡影响 ⇒ 一次性验证脚本的该条判据是**红**的，不能算过。
  已有的进程级证据是运行器日志「检测到改动 ⇒ 已重启（第 1 次）」+ 新的
  `dev.exe` PID；窗口渲染本身由三种形态的 `probe-window.py` 5/5 覆盖。
  要补闭环，得让 dev 壳在启动时自报真实 PID（例如动态入口 `echo getmypid()`），
  再由运行器按该 PID 精确回收。
- dev 帧率低于 AOT（ZendVM 解释），未量测；Xdebug / 断点未验证（官方 `debug.md`
  只说 AOT 不支持 Xdebug，未明说 ZendVM 模式）。
- **双模语义 golden 已做（§8），逐像素 golden 仍未做**：dev 态与 prod 态只比了
  `showcase` 首屏的窗口尺寸 / 非白像素 / DPI / 退出码；语义层现有
  `aot-equivalence.php`（解释器↔AOT）与 `dual-mode-equivalence.php`（解释器↔dev 壳）
  两条逐值判据，共用同一份 `Fingerprint::snapshot()`。**逐像素基线**仍未做
  （首屏时序本就有差，见 §7）。
- dev 壳默认 `memory_limit=128M`，解释器 CLI 是 `-1`：一次挂 27 页的量具工作负载
  会在 `TtfFace` 加载字体时撞上限。无头指纹入口按解释器对齐；这是**资源上限，
  不是框架语义**，也不改 GUI 形态的 ini。

## 7. 验证链随之更新（同日第二棒）

dev 壳把「每棒全 AOT 重建」降级为发版前一次，代价是 **AOT 编译期语义在日常看不见**。
分层、必跑清单与「哪些手段不能删」写在
[`architecture/12-工程与工具.md`](architecture/12-工程与工具.md) §3；这里只记本仓改动：

- **入口收敛**：`probe-window.py <app> --dev` / `--dev-runner` 取代三个
  `DRIFT_PROBE_*` 环境变量的日常拼接（环境变量保留给自定义形态）。三种形态仍共用
  同一套五条判据与自动关窗。
- **闸门补位**：`gate.php` 新增 `devshell` 项（跑 `drift-dev --selftest`）。自检
  5 → 10 条：新增三条壳红线（sources 精确白名单 / 变量路径 require / 桥接回调存在）
  与两条反例。变异验证：往 sources 塞 `../../src` ⇒ selftest 1 FAIL、gate 该项
  exit 1；还原后 0 FAIL。
- **删除** `tools/probe-showcase.php`（手量坐标 + `proc_close` 等窗口消失），功能由
  `probe-real.php` 与 `probe-window.py` 覆盖；`arch-v2/09` 的历史提及保留原文并补订正。
- **保留**：gate 全项、无头 preview / raster、两套 golden、`aot-equivalence.php` +
  `fingerprint.php`、`probe-real.php`。理由见 12 §3.2 —— dev 壳是「少编译」，
  不是「少一层验证」。
- 已知差异：`--dev-runner` 抓首屏更早（非白率明显低于另两种形态），判据 ③ 阈值仍过；
  没有为对齐数字去改 settle 语义。

## 8. 双模语义等价（同日第三棒）

`03` C7/B11 要求「一套 golden 同时验两路语义一致」。本仓的落法不是新建基线，
而是**把解释器侧的 `Fingerprint::snapshot()` 当唯一 expected**，两条量具各守一路：

| 命令 | 比对 | 层 |
|---|---|---|
| `php tools/aot-equivalence.php` | 解释器 ↔ 全 AOT probe（27 页 × 2 通道逐值） | T2 |
| `php tools/dual-mode-equivalence.php` | 解释器 ↔ dev 壳（ZendVM 动态加载） | T2 |

新量具配 `tools/dual-mode-fingerprint-entry.php`（`DRIFT_DEV_ENTRY` 指向它 ⇒ dev.exe
**不开窗**，只吐与 `fingerprint.php --tsv` 同格式的 TSV）。★ 刻意放 `tools/`
而不是 `apps/dev/`：后者的整棵目录树是 `drift-build.php` 的输入指纹，放那边
会让「改一个纯运行期入口」也触发 dev 壳重编。判据 7 条：槽类型已知 /
解释器有内容 / 无头入口退出码 0 且无 Fatal / dev 侧吐出规范行 / 两通道行数一致 /
逐行相同；三态退出码 `0 等价 · 1 不等价 · 2 无法判定`，`2` 不冒充 `0`。

- **不进 `gate.php`**：`dev.exe` 是本地编译产物、不进 git，CI 上没有它 ⇒ 进闸门
  要么假绿要么恒红。与 `aot-equivalence.php` 同属 T2 手动量具，见 12 §3。
- **不用 `inspect.php --check`**：它的快照对「合法结构改动」极敏感，头部明写不进
  gate；逐值的几何 / 绘制命令才对应 dev 壳可能悄悄改变的那部分语义。
- `--selftest` 5 条正反例；`--entry=` 可换无头入口（变异牙检用）；
  `--quiet` 只出 `PASS` / `FAIL n` / `SKIP(...)`。
- 实测 **54 行逐行相同**；变异（改 geom 首行哈希 + 丢掉 paint 通道）⇒
  `D③ paint` 与 `D④` 两条精确报红、exit 1；删掉 `dev.exe` ⇒ exit 2。
