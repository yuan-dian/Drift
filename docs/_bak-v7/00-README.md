# Drift v7 设计方案

> 状态：**设计稿（零实现）**。2026-10-20 起。
> 目标：**跨平台多端声明式 GUI 框架**，首版只落 Win32，抽象先到位。
> 关系：Drift2 的实现与 design-v6 的方案**只作灵感与排坑**，不是基线。本册从 TypePHP 的编译器事实重新推导。

---

## 0. 一句话

**一棵树、一次写入、一个边界、一条时间线、一段命令、一条通道。**

六条不变式，每条都由「TypePHP 的编译器事实」或「某个成熟框架的公开失败模式」逼出来，没有一条是口味。

---

## 1. 六条不变式

| # | 不变式 | 一句话 | 否决了什么 |
|---|---|---|---|
| **I1** | **一棵树** | 节点自己就是状态 + 行为 + 结构，没有配置树/复用层/渲染树三层 | Flutter 三棵树、WPF 保留模式 + 逻辑/视觉双树 |
| **I2** | **一次写入** | 写状态的地方就置脏位，不比较、不推断、不 diff | React 的 `memo` 地狱、Compose 的稳定性推断黑盒、Vue 的 Proxy 语义 |
| **I3** | **一个边界** | 改孩子只有一条路；身份 = 位置 + key | Flutter 的 `canUpdate(runtimeType)`、key 与型别双轨 |
| **I4** | **一条时间线** | 一帧 = 五个纯阶段，每段可单独喂数据跑 | 隐藏的第二次布局、paint 里触发 build |
| **I5** | **一段命令** | 绘制产出扁平 op 流，命令段属于节点、用局部坐标 | 全局显示列表、画布上重算排版 |
| **I6** | **一条通道** | **可回放**的输入、命令、测试、AI 全走 `dispatch(int, array)`；常规交互用闭包但不进通道 | 事件冒泡链、全局回调注册表、TEA 的 Msg 类型 |

## 2. 四条被编译器逼出来的设计律

这四条不是"最佳实践"，是**不做就会静默错或直接崩**。详见 [11-编译器约束映射](11-编译器约束映射.md)。

| # | 律 | 编译器事实 | 后果 |
|---|---|---|---|
| **L1** | **热路径零可空、零 `mixed`、零 Native 对象** | `?T` / `union` / `callable` 退化 `php::Var`；**Native 对象不能进 PHP 数组、也不能进普通对象属性**；固定值属性不能 `unset` 也不能赋 `null` | 节点是**普通 class**，字段用原生标量 + 哨兵值（`INF` / `-1` / `''`）；`#[Native]` 只给不进容器的小值对象 |
| **L1b** | **容器不能住进属性** | Std 容器**不能嵌入原生类属性**，赋给属性会被 `toArray()` **拷贝成 PHP 数组**（v6 探针实测） | 孩子与 op 段用 **packed PHP array**；Std 容器只做函数局部或 `#[StdVector]` 参数 |
| **L2** | **可回放的交互 = 命令 ID（int）；常规交互可以闭包** | `callable` 属性退化 `php::Var`（**只在热路径上才是问题**）；`Closure::bind` 不支持；Native 对象不能进数组 | 判据 = 「这条交互要不要进"重放即复现"的日志」。要 ⇒ 命令 ID；不要 ⇒ 闭包。**闭包永不进 `layout`/`paint`** |
| **L3** | **身份 = 位置 + key；行为走 `int $kind` + `switch`，不靠虚方法分派** | 静态类型已知时虚方法会被编译成直接调用，**静默吞掉子类覆写**；`get_class()` 在热路径上是一次动态查找 | 节点带 `int $kind`，分派点唯一且可读；虚方法只在静态类型即具体类型时用 |

★ **命令 ID 是本方案的阿基米德点**：它不是妥协，而是**把约束变成特性**——
命令 ID 让 UI 变成「可编程接口」，同时顺手解决了 React/Compose 的「回调导致无法序列化、无法回放、无法给 AI 操作」。
**约束与特性在这里是同一件事。**

★★ **但不要把这条律推广成"禁止闭包"**（v7 第一版就是这么写的，是重税）：
命令 ID 的收益是**可回放**，代价是每个交互都要一个常量 + 一个 `switch` 分支。
所以它只用在**必须可回放**的路径上（菜单、快捷键、AI 驱动、撤销栈、跨进程 worker）；
按钮点击这类"用户速度、不需要回放"的交互，闭包完全够用（见 [02](02-状态与命令.md) §5）。
L2 真正禁止的是**把闭包存进每帧都要读的属性**。

## 4. 与既有工作的关系（借了什么 / 否了什么）

### 从 Drift2 的实现借（**已验证有效，直接继承**）

| 借来的东西 | 为什么 |
|---|---|
| 确定性软光栅 + Skia 双后端 | golden 的物质基础；`RasterCanvas` 纯 PHP，天生可移植 |
| `Canvas` 是 op 天花板（不是 `DisplayList`） | 实测结论：主树是 `paint($canvas)` 直接画 |
| 滚动条 thumb 必须在派发里先于内容接管 | thumb 是 paint 期画的，`hitTest` 看不见 |
| 拖动 resize 走壳侧同步泵 + 专用轻量重排入口 | 模态尺寸循环里 PHP 主循环被挂起 |
| 退出路径上窗口已死 ⇒ 壳侧缓存最后已知几何 | `WM_CLOSE` 同步 `DestroyWindow` |
| 溢出/最小尺寸/IME 候选框/滚轮取负/手势 arena | 每条都是真机踩出来的，详见 [09](09-帧与异步.md) / [07](07-输入与焦点.md) |
| 扁平语义快照数组 | 同时满足 UIA 的"推"与 NSAccessibility/AT-SPI 的"拉" |

### 从 design-v6 借（**结构对，但需要按编译器事实重写**）

| 借来的 | 改动 |
|---|---|
| 一棵树、无 View | 保留。但补上"为什么在 TypePHP 里是**被迫**的"（无 `get_class()` ⇒ 无法做 `runtimeType` 比较） |
| 19 op 正交 | 保留。补上三层能力分级（Core/Extended/Optional），因为跨平台不可能全量 |
| 写时脏位 | 保留。补上"脏位是位域，一帧只清一次"的具体时序 |
| 布局三策略 S1/S2/S3 | 保留。**补上 `measure`/`place` 两步分离**（v7 第一版揉成一个 `layout()`，被 v6 纠正） |
| 文本三拆 | 保留。补上"度量归 Drift"的硬理由 |
| 异步三问 | **改四问**（上游 `Swoole\Thread` 已可用，仅 ZTS） |
| a11y 三档 | 保留。补上推/拉模型统一 |

### 明确否掉的

| 否掉 | 理由 |
|---|---|
| Flutter 的 Element 复用层 | 存在的唯一理由是"Widget 便宜 / RenderObject 贵"；TypePHP 的普通类**类型化属性已是 `Z_LVAL_P(o + offset)`**（官方 `performance.md`：与访问 C struct 几乎一致）⇒ 节点本身就是便宜的固定布局对象，重建≈改字段 |
| Compose 的稳定性推断 | 黑盒，跨模块失效，社区第一性能问题。我们**不推断**——写即置脏 |
| React 的 `memo` / hooks 依赖数组 | 手工依赖声明的心智税；我们**不需要**，因为脏位是写入口自带的 |
| SwiftUI 的属性图自动订阅 | 闭源 + 更新时机不可观测。我们做**运行期记录式订阅**（`Tracker` 显式栈）+ 可 dump 的表——同一机制，但不黑盒 |
| Vue 的 Proxy | 解构丢响应；且 TypePHP 没有动态属性 |
| TEA（单一 Model + Msg） | 纯数据可序列化很好，但每个交互都要定义 Msg + 分支，样板税高。折中：**命令 ID 只用于可回放路径**，常规交互用闭包，不背 Msg 样板 |
| WPF 的 XAML + 依赖属性 | 字符串路径绑定会静默失败；且 TypePHP 无反射，绑定无从解析 |

## 5. 目标与非目标

**目标**
1. Win32 首版可交付：能跑真应用，不是 demo。
2. 抽象先到位：第二个平台（macOS）只写壳 + 适配器，**框架零改动**。
3. 可测：整条管线无窗可跑，喂 JSON 出 PNG。
4. 可诊断：一帧为什么慢，能指到阶段 + 节点。
5. 可编程：UI 状态机可被程序（含 AI）读写驱动。

**非目标（首版）**
- GPU 加速（离屏光栅 + 整帧上屏已够）
- 原生控件 / 原生菜单（自绘路线）
- 多窗口
- 富文本编辑（首版单行 + 多行纯文本 + 选区）
- 移动端（抽象留口，实现不做）

## 6. 待验证的编译器未知数

设计里有几处**依赖编译器行为但未实测**，全部登记在此，P0 第一件事就是实测：

| # | 未知数 | 影响 | 若不成立的退路 |
|---|---|---|---|
| V1 | `#[Native]` 值对象（`BoxConstraints`）传参，是否真比 4 个 float 参数快 | 约束模型 | 退回 4 个 float 参数 |
| V2 | `#[Native]` 类能否跨 `-m lib` 边界（SDK 形态） | 框架编一次 vs 每应用重编 | 每应用重编（Drift2 现状，可接受） |
| V3 | 遍历 packed `array<int, Node>` 时 `toObject(Node::class)` 的实际开销 | 孩子遍历（每帧每节点） | 父持索引 + 类型化 accessor 方法 |
| V4 | 闭包作为**参数**（不存属性）的开销 | `Repeater` 是否可用闭包 | 数据驱动 CellSpec + 对象构建器 |
| V5 | 固定 `int` 位域（`$flags & 0x3`）是否保持原生 | 脏位成本 | 多个 `bool` 字段 |
| V6 | `#[Getter]` + `#[Immutable]` 在 Native 类上的实际开销 | 值对象设计 | 直接用 `public` 字段 |
| V7 | 产物能否用 **NTS** 运行时构建（C++ 常驻库宿主的前提） | 并发模型是否必须 ZTS | 留在 ZTS；`Swoole\Thread` 那条支线彻底关掉 |
| V8 | `enum` 在 Native 语境下是否可用 | 命令/角色常量形态 | `final class` + `public const`（已按此设计） |
| V9 | ~~op 流容器选型~~ —— **已由约束解掉**（段是属性 ⇒ 只能 packed array） | — | 只剩"追加开销"可优化（预分配 + 游标） |

★ **V1–V6 决定性能上限，V7 决定能不能并行，V8/V9 决定两处实现细节**——
**没有一条会动摇架构形状**。这是本方案与 design-v6 最大的方法论差异：
v6 的未知数（如 `?int` 是否退化）会推翻整个约束模型，本方案把未知数全推到"可替换实现"层面。
