# 08 平台与能力矩阵

> 本册回答：**框架问 OS 要什么、怎么诚实表达"某平台没有这个"、第二个平台要写多少。**

---

## 1. 能力三态（UDA 的 SupportLevel）

```php
final class Support
{
    public const FULL        = 0;   // 有真机证据
    public const PARTIAL     = 1;   // 能用但有差距，必须带 reason
    public const UNSUPPORTED = 2;   // 调用即明确错误
}
```

```php
final class Capability
{
    public int    $level  = Support::UNSUPPORTED;
    public string $reason = '';        // PARTIAL 必填，UNSUPPORTED 可空
}
```

★ **为什么不用 `?Interface`（返回 null 表示不支持）**：
`null` 只能表达"有/没有"，不能表达"有但打折"。
而跨平台最真实的状态恰恰是"有但打折"——托盘在 Linux 上就是这种（DE 差异）。

★ **`PARTIAL` 必须带 `reason`**，且 `reason` 会进诊断日志。
"为什么我的托盘图标不显示" ⇒ 日志里写着 `PARTIAL: Linux 需要 StatusNotifierItem，当前 DE 不支持`。

★ **`UNSUPPORTED` 不是异常**：调用方必须显式分支（编译期无强制，但 lint 抓"没查 level 就用"）。
**"查询时明确"比"调用时崩溃"好一个数量级。**

## 2. 端口清单（9 个）

沿用 Drift2 已验证的拆分（这一步它做对了）：

| 端口 | 必须？ | 内容 | 首版 Win32 |
|---|---|---|---|
| `Platform` | **必须** | 6 个子端口 + `pump()` + `now()` + `configDir()` + `assetDir()` + `fatalBox()` | ✅ |
| `Screen` | **必须** | `scale()` `viewport()` `systemTheme()` | ✅ |
| `WindowHost` | **必须** | 创建/显示/关闭/标题/最小尺寸/客户区/最大化/位置/还原/光标/语义推送 | ✅ |
| `SurfaceProvider` | **必须** | `surface(): RenderSurface` | ✅ |
| `InputSource` | **必须** | 归一化事件队列 | ✅ |
| `TimerHost` | **必须** | 帧定时器 | ✅ |
| `Clipboard` | 可空 | 文本读写 | ⏳ 返回 `null` |
| `Dialog` | 可空 | 文件选择 / 消息框（阻塞） | ⏳ 返回 `null` |
| `Tray` | 可空 | 托盘图标 | ⏳ 返回 `null` |

★ **"必须"的定义**：缺了它应用跑不起来 ⇒ 进主接口，**不存在"不支持"状态**。
**可空**的定义：缺了它应用能跑，只是少个功能 ⇒ 独立端口，用 `null` 表达。

★ **`assetDir()` 是本方案新增的**（Drift2 没有）：
Skia 后端找 `fonts/` 时用了 `GetModuleFileNameA`——那是 Skia 桥里**唯一**一处 Win32 调用。
把它挪进端口，`drift_skia.cc` 就变成真正的零平台代码（可用 grep 断言守住）。

## 3. 壳层：21 个桥 → 8 个关注点

| # | 关注点 | 函数 | 每平台估行数 |
|---|---|---|---|
| 1 | 窗口生命周期 | `create show close setTitle setMinSize clientSize isMaximized position place restore setCursor` | 400–600 |
| 2 | 消息泵 | `pump` | 120–180 |
| 3 | 定时器 | `setTimer killTimer` | 40–60 |
| 4 | 单调时钟 | `nowMs` | 10 |
| 5 | 屏幕与主题 | `dpi systemDark` | 40–60 |
| 6 | IME | `imeCaret` | 30–50 |
| 7 | 呈现 | `present` | 40–70 |
| 8 | 失败路径 / 目录 | `messageBox configDir assetDir` | 30 |
| 9 | 无障碍推送 | `a11yPush` | 250–400 |

**每平台合计 ≈ 1000–1500 行 C++**（不含 Skia 静态库）。**唯一硬骨头是无障碍。**

★ **反向的好消息**：`drift_skia.cc`（渲染，384 行）**零改动可复用**，
`RasterCanvas`（纯 PHP）零改动，框架层零改动。
**新平台成本几乎全在"窗口 + 无障碍"两件事上。**

## 4. 壳侧三条致命契约（不是坑，是规格）

这三条在 Drift2 上都是"踩了才知道"，本方案把它们写成**壳层必须满足的规格**：

### 4.1 窗口死亡后仍要能回答几何

```
问题：WM_CLOSE 同步 DestroyWindow ⇒ 主循环跳出后句柄已死
     ⇒ "退出时保存窗口位置"拿不到几何 ⇒ 静默无输出（连报错都没有）
规格：壳层必须维护「最后已知几何」缓存：
      · 活着时每次 WM_MOVE/WM_SIZE 刷新
      · WM_DESTROY 时抓最后一次
      · 查询时先问活窗口，失败则读缓存
```

### 4.2 拖动 resize 期间的帧必须由壳同步驱动

```
问题：模态尺寸循环（Win32 的拖动 resize）里 PHP 主循环被挂起
     ⇒ 定时器驱动的帧会滞后（帧 A 贴到客户区 B ⇒ 右侧留空）
规格：壳在 WM_SIZE 里同步调用一个**专用的轻量重排入口**：
      · 只做 placeMenu + Frame::run
      · 不 pumpIo / 不 pumpTasks / 不跑动画 / 不动焦点 / 不推语义
      · 时间戳复用上一帧（不读时钟）
      · ★ 不得重入主 frame()（Skia 下会画出"布局宽对、内容窄"的异常）
```

★ 配套两条：
- 尺寸不匹配时**原尺寸贴 + 余区填底色**，**禁止拉伸**（拉伸会让用户以为布局错了）；
- `enqueue` 对 resize 做 coalesce：松手一帧直达最终态。

### 4.3 溢出在"预览期"必须降级为裁剪

```
问题：用户拖窄窗口 ⇒ 自然宽度 327 > 可用 322 ⇒ 直接 Fatal（Drift2 实测）
规格：拖动预览期置 LayoutTolerance::$previewing，三处校验全部降级为裁剪；
     松手后的正式帧仍然响亮失败。
```

★ **`previewing` 是 try/finally 作用域，不是全局开关**——否则真 bug 被永久静默。

## 5. 能力矩阵（首版填 Win32，其余留空）

| 能力 | Win32 | macOS | Linux | 移动 |
|---|---|---|---|---|
| 窗口 | Full | Full | Full | 单窗口桩 |
| 消息泵 | Full | Full | Full | Full（vsync 驱动） |
| 定时器 | Full | Full | Full | Full |
| 屏幕 / DPI / 主题 | Full | Full | Partial（DPI 靠 Xft.dpi） | Full |
| IME | Full | Full | Partial（IBus 依赖） | Full |
| 呈现 | Full | Full | Full | Full |
| 无障碍 | Full（UIA） | Full（NSAccessibility） | **Unsupported 首版**（AT-SPI 需独立线程） | — |
| 剪贴板 | 未实现 | — | — | — |
| 托盘 | 未实现 | — | — | — |
| 对话框 | 未实现 | — | — | — |
| 滚动物理 `scrollPhysics` | **Partial**（离散档位、无速度 ⇒ 不做惯性） | Partial（`NSEvent` 有 momentum ⇒ 可做） | Partial（X11 只有档位） | Full（触屏有真实速度） |
| 异步线程 | Full（ZTS + Swoole） | Full | Full | — |

★ **`Partial` 必须写原因，`Unsupported` 必须能被查询到**。
这张表是**数据**（`build/capabilities.php`），不是散文——它要能被 `--dump-caps` 打印、被测试断言。

## 6. 新平台接入清单

1. `src/Platform/<Os>/` 写 9 个端口的实现（`<Os>Platform` 实现主接口）。
2. `cpp-src/<os>.cc` + `<os>.stub.php`（成对同名）覆盖 8 个关注点。
3. `apps/<app>/bin/<os>/Bootstrap.php` 换一行平台类名——**唯一**该出现平台名的共享位置。
4. `build/<os>/platform.ini` 声明 `libs` / `defines` / `subsystem` / `assetDir`。
   ★ TypePHP 的 `project.yml` 支持 `if` 条件（`PHP_OS_FAMILY`），**平台源文件选择是原生能力**，不需要构建脚本 hack。
5. `fonts/` 随包分发，路径走 `Platform::assetDir()`。
6. 验收三闸（顺序不能反）：
   - ① `RasterCanvas` 全量 smoke 在 `php.exe` 里过（不建窗、不碰 OS）；
   - ② 真机开窗 + 一帧像素（`present` 通）；
   - ③ 真机探针：滚动条拖动 / 拖动 resize / IME 候选框 / 无障碍树。

## 7. 框架不得做的事（划掉，防止反复讨论）

| 禁止 | 理由 |
|---|---|
| 系统字体查询 | 度量会随机器变，golden 失效（§06） |
| 平台原生控件 | 违反"不把渲染外包"；且每平台接线成本 × N（Aria 的固有成本） |
| 原生菜单栏 | 风格割裂；自绘 `MenuBar` 已覆盖 |
| 在框架内读 `getenv()` / `__DIR__` | AOT 编译期固化；路径是平台能力 |
| 在框架内创建光标/图标资源 | 那是平台能力 |
| GPU swapchain（首版） | 离屏光栅 + 整帧上屏已够；接口留了口 |

## 8. 多平台构建

```
build/
  win32/platform.ini      libs = comctl32 uiautomationcore oleaut32
                          subsystem = windows
  macos/platform.ini      libs = -framework Cocoa -framework Metal
  linux/platform.ini      libs = X11 fontconfig
```

`drift-build` 按 `PHP_OS_FAMILY` 读对应 ini，组装 `project.yml` 的 `sources` / `link-libs`。

★ **`--zts` 参数位现在就留**（不实现）：上游已让 `Swoole\Thread` 可用，但**仅 ZTS**。
留位是为了将来开异步线程不必重写构建脚本。

## 9. 跨平台实现细节（v6 补齐）

### 9.1 生命周期倒置（C1）

| | 桌面 | 移动端 |
|---|---|---|
| 入口 | `run()` **阻塞**，自己开窗 | `boot(root, surfaceId)` 接**已存在的 Surface** |
| 返回 | 退出时返回 | **注册回调即返回**（非阻塞） |
| 进程 | 应用自己控制 | **随时可能被杀** |

★★ **v7 第一版说"移动端只需换个 `Platform` 实现"——这是错的**：
入口形状本身要变（阻塞 vs 非阻塞），且"进程随时被杀"要求 `onSuspend` 必须落盘状态。
⇒ 端口里必须有 `run()` / `boot()` 两个形态，或把 `run()` 定义成"非阻塞注册 + 主循环由壳驱动"。
**首版只实现 `run()` 阻塞形态，但接口留 `boot()` 位。**

### 9.2 修饰键归一 `Modifier::Primary`（C2）

```php
// 应用只写 Primary
$node->shortcut(Modifier::Primary | Key::S, Command::SAVE);
```

| 平台 | `Primary` 解析为 |
|---|---|
| Win32 / Linux | `Ctrl` |
| macOS | `Cmd`（`Meta`） |

★ **这与 [07](07-输入与焦点.md) §5"框架只报按了什么"不矛盾**：
- 事件层仍只报**物理位**（Ctrl / Shift / Alt / Meta 各一位）——不重写事件。
- `Primary` 是**应用声明快捷键时用的归一常量**，解析发生在 `KeyChord` 匹配处，一处。

★ 不做的话，每个应用都要自己判断 `PHP_OS_FAMILY`——那是把平台知识漏到应用层。

★ 反例（Qt 的教训）：Qt 做的是**事件级自动映射**，于是"同一个快捷键在两平台行为不同"且难查。
**我们只归一"声明"，不归一"事件"。**

### 9.3 位图预乘（C3）

| 后端 | 期望 |
|---|---|
| D3D / Win32 | **预乘** alpha |
| Metal | **非**预乘 |

★ 转换错 ⇒ 半透明边缘发黑（预乘当非预乘）或发白（反之），**且只在 mac 上出现**——
Win32 首版不会暴露，所以必须现在就写进端口契约（`Surface::upload()` 声明预乘约定）。

### 9.4 ClearType / 子像素（C4）

★ DirectWrite 默认开子像素抗锯齿 ⇒ **必须显式关掉，用灰度 AA**。
否则文字发彩边（深色背景 + 缩放后尤其明显），且 golden 与 mac 不一致。

★ 理由：子像素 AA 依赖具体像素排列（RGB / BGR），**跨设备不可复现**。

### 9.5 滚轮单位归一（C5）

| 平台 | 原始 | 归一后 |
|---|---|---|
| Win32 `WM_MOUSEWHEEL` | `WHEEL_DELTA` 的倍数（120 = 1 档） | 1 档 = `WHEEL_NOTCH_PX` |
| macOS `scrollingDeltaY` | **有"行/像素"两种模式**（`hasPreciseScrollingDeltas`） | 同上 |
| X11 按钮 4/5 | 方向可能与 Windows 相反 | 同上 |

★★ **后端归一成"内容上移为正、单位 DIP"**，框架只认这一个语义。
方向对但单位错 ⇒ 滚太快/太慢；方向错 ⇒ 完全反直觉。两者都是"能跑但难用"。

★ **不变量**：`ScrollEvent::delta` 正 = 内容上移（看到下面）。
平台惯例的翻译**只在壳一处**（Drift2 的 `WM_MOUSEWHEEL` 已取负）。
★ 拿不到 momentum ⇒ `scrollPhysics` 只能是 `Partial`（见 [04](04-布局.md) §4.2）。

### 9.6 接口五条规则（C6）

| # | 规则 | 违反的后果 |
|---|---|---|
| 1 | 参数只有**标量 + `array`**，不传对象 | 对象过界 = `Var` 装箱 + 生命周期不明 |
| 2 | **失败返回 `0`/`false`/`''`，不抛异常** | 异常穿过 C++ 栈 = **UB** |
| 3 | 句柄**只由后端创建/释放** | 双释放 / 悬空 |
| 4 | **只有 `fileDialog` 一个自泵方法** + `inDialog` 防重入 | 嵌套消息泵 ⇒ 重入崩溃 |
| 5 | 尺寸一律 **DIP**（逻辑像素） | 混用物理像素 ⇒ 高 DPI 全错 |

★ 第 2 条是 ABI 级约束，不是风格：C++ 栈上没有 PHP 的异常表，展开即未定义行为。
所以**每个桥函数都必须有"失败返回值"**，且调用方必须检查。

### 9.7 `pumpEvents` 与 `waitEvents` 分离（C7）

| 方法 | 语义 | 谁需要 |
|---|---|---|
| `pumpEvents()` | 非阻塞，取走当前事件 | 移动端（能 poll 不能阻塞）、有帧要画时 |
| `waitEvents(float $timeoutMs)` | 阻塞到有事件或超时 | 桌面（无帧可画时省 CPU） |

★ v7 第一版只有一个阻塞 `pump()` ⇒ **移动端没法用**（主循环不归应用管）。
拆开后桌面仍是 `waitEvents(∞)` 的单循环，行为不变。

### 9.8 capability 具体清单（C8）

| 能力 | 类型 | Win32 |
|---|---|---|
| `perMonitorDpi` | bool | true |
| `unifiedPointer` | bool | true（`WM_POINTER`） |
| `imeComposing` | bool | **false**（只取提交串） |
| `hover` | bool | true |
| `rightClick` | bool | true |
| `safeAreaInsets` | bool | false（桌面无） |
| `onBackHook` | bool | false（桌面无） |
| `nonBlockingRun` | bool | false（首版） |
| `scrollPhysics` | enum | **`Partial`**（离散档位） |

★ **只有三态 `SupportLevel` 不够，还要有"条目"**。没有清单，`Partial` 就只是个形容词。

### 9.9 新后端 checklist 与 golden 复用（C9）

1. 实现 9 个端口（§2）
2. 壳侧 8 个关注点（§3）
3. `build/<os>/platform.ini`
4. `Bootstrap.php` 换一行平台类名
5. 无头 smoke 过（`RasterCanvas`）
6. 真机一帧（`present` 通）
7. **op golden 在两端一致** ← 判据：抽象没漏语义
8. 像素 golden 允许不同（字体 / AA 差异）
9. 真机探针四条（滚动条 / resize / IME / a11y）
10. 能力矩阵填满（每条 `Partial` 带 `reason`）

★★ **第 7 条是移植的真正验收**：两个后端消费**同一份 op 流**，
op 哈希一致 ⇒ 抽象层没有平台特定的语义泄漏。像素不同是允许的（光栅器不同），op 不同就是设计漏了。

### 9.10 接口不变是硬要求（C10）

★ **加能力只加新方法，老平台返 `None`/`false`，不改老签名**。
接第 5 个平台时，前 4 个不用动——这是"可移植"的操作定义。

★ 违反的代价是可累加的：改一次签名 ⇒ N 个平台同时要改，而其中 M 个平台你没有测试环境。
