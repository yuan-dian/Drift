# 06 文本

> 本册回答：**度量归谁、整形怎么做、编辑态怎么存、IME 为什么天然跨平台。**

---

## 1. 三拆

文本是 GUI 里唯一"看起来简单、实际最深"的部分。拆成三个互不依赖的子系统：

| 子系统 | 输入 | 输出 | 缓存键 | 谁用 |
|---|---|---|---|---|
| **度量 Measure** | 字体 + 字号 + 字符串 | 宽/高/基线/逐簇步进 | `(fontId, size, text)` | 布局 |
| **整形 Shape** | 度量结果 + 可用宽度 | 行盒（每行起点/长度/基线）+ 字形序列 | `(fontId, size, text, width)` | 绘制 |
| **编辑 Edit** | 字节偏移 + 选择 + 输入 | 新的 `(text, offset, selection)` | 无（有状态） | `TextField` |

★ **三者缓存键不同，所以必须拆**：改宽度只失效整形，不改度量；打字失效两者，但不改编辑态。

★ 这也是 Drift2 已有的正确决策，本方案继承并补一条：**整形结果必须可导出成 `GLYPH_RUN`**，
否则每帧都要重新整形（Drift2 的 `Paragraph` 是"局部缓冲 + 每帧重建"，长文本会痛）。

## 2. 度量必须归 Drift（硬约束）

| 方案 | 后果 |
|---|---|
| 用平台 shaper（CoreText / DirectWrite / HarfBuzz） | **三平台三套度量** ⇒ 断行位置不同 ⇒ 光标/命中/选区全错；golden 无法跨平台 |
| 用 Skia 的 `SkParagraph` | 同上，且引入 ICU（体积 + 版本绑定） |
| **自己读字体表算** | 一套度量跑遍所有平台；golden 跨平台可比；代价是字距/连字要自己实现 |

**首版范围**（明确划界，避免"文本永远做不完"）：

| 做 | 不做 |
|---|---|
| `cmap`（字符→字形）、`hmtx`（水平步进）、`OS/2`（sTypo 行高）、`head`（unitsPerEm）、`kern`（成对字距） | `GPOS`（复杂定位）、连字、双向文本（RTL）、竖排 |
| 逐簇回退（一个字符缺字就换下一个字体） | 全文本整形（HarfBuzz 级） |
| UAX#14 的**子集**（空格/标点/CJK 边界） | 完整 UAX#14 |

★ **行高取 `OS/2` 的 sTypo 而不是 hhea**：hhea 在部分中文字体上偏大，会让行距看起来"松"。
这是 Drift2 实测结论，直接继承。

★ **RTL / 连字不做，但要在数据结构上留位置**：`GlyphRun` 的字形序列已经是有序数组，
将来加 RTL 只是改变生成顺序，不改容器。**留结构不留实现**。

## 3. 字体：随包目录，不查系统

```
<exe 目录>/fonts/            ← 随包分发（embedded-files 或并列目录）
    NotoSansSC-Regular.ttf
    NotoSansSC-Bold.ttf
    NotoSansMono-Regular.ttf
```

| 纪律 | 理由 |
|---|---|
| **禁止 `SkFontMgr::create()`（系统字体管理器）** | 一查系统字体，度量就随机器变 ⇒ golden 失效 |
| **禁止 `getenv()` 找字体目录** | 路径由 `Platform::assetDir()` 回答（平台能力，§08） |
| **禁止依赖 `__DIR__` / `cwd`** | AOT 编译期固化；`cwd` 在双击启动时不是仓库根（Drift2 踩过：界面全白、布局全对） |

★ 字体加载失败**不中止**，但 `fontReady()` 必须如实返回 false，并记一条 Diagnostic。
否则症状是"矩形全对、字全没了"，看起来像排版 bug（Drift2 实测过）。

### 3.1 回退链

```php
$chain = [FontFamily::sans(), FontFamily::emoji(), FontFamily::symbol()];
```

逐**簇**（不是逐字符）查 `cmap`：簇内任一字符缺字 ⇒ 整簇换下一个字体。
缺字清单累积到 `FontDiagnostics::$missing`，可由 `--dump-fonts` 导出（codepoint + 出现次数）。

★ **逻辑家族，不是物理字体名**：`sans()/serif()/mono()` 由 `Theme` 映射到具体字体文件。
"Microsoft YaHei" vs "PingFang SC" 这种跨平台名字差异，在这里被吸收掉。

## 4. 整形

```
输入：text, maxWidth, fontId, size
① 逐簇取字形 + 步进（度量结果）
② 贪心断行：累加步进，超过 maxWidth 则回退到最后一个合法断点（UAX#14 子集）
③ 产出行盒：{startByte, endByte, baselineY, width}
④ 产字形序列：{glyphId, x, y}[]  → 可打包成 GLYPH_RUN
```

★ **断点合法性**：空格后可断、CJK 字符间可断、标点前后有禁则（`，。、` 不出现在行首）。
首版只做这三条，覆盖 95% 的中英文场景。

★ **行高与基线**：`baselineY = ascent * size / unitsPerEm`；行距 = `(typoAscender - typoDescender + lineGap)`。
**不用 `hhea`**（见 §2）。

## 5. 编辑态

```php
final class EditState
{
    private string $text = '';
    private int $caret = 0;          // ★ 字节偏移，不是字符索引
    private int $selStart = -1;      // -1 = 无选区
    private int $selEnd   = -1;
    private int $anchor  = 0;        // 选区锚点（拖选时不动的一端）
}
```

| 决策 | 选择 | 理由 |
|---|---|---|
| 偏移单位 | **字节** | PHP 字符串是字节；`mb_substr` 每次 O(n)，打字时不能用 |
| 光标移动粒度 | **簇**（grapheme cluster） | 移动一个"用户看到的字符"，不是字节也不是码点 |
| 选区 | **两端点 + 锚点** | 拖选时锚点固定、活动端移动；只存 `(min,max)` 无法表达方向 |
| 越界 | 夹到 `[0, strlen]`，且落在簇边界 | 防止光标停在半个 UTF-8 序列中间（会画出乱码） |

★ **字节偏移 + 簇边界**是本册唯一"必须自己想清楚"的地方：
用字符索引 ⇒ 每次编辑要重算全串偏移（O(n)）；
用字节但不管簇 ⇒ 光标停在半个 emoji 上，删一个退格删掉半个字。

★ **`substr_replace` 对 MB 级字符串是 O(整串)**（Drift2 实测）。
大文本（>64KB）必须走 rope / 分段，首版不支持大文本，**明确限 1MB 并在超限时 Fatal**。

## 6. IME：契约只有两样东西

```
① 插入符矩形（逻辑像素，窗口坐标）  ← 平台据此摆候选框
② 提交串（committed string）        ← 走普通字符输入路径
```

★ **不读组字串（`GCS_COMPSTR` / `markedText`）**。理由：
- 自绘组字串要自己实现"下划线 + 候选 + 回退"，且各平台行为不同（Flutter 的富文本输入是公认重灾区）；
- 只取提交串，则**三平台的 IME 契约完全一致**：Win32 的 `WM_IME_COMPOSITION(GCS_RESULTSTR)`、
  macOS 的 `insertText:`、Linux 的 IBus `commit` 信号，语义相同。

★ **候选框贴屏幕左上角 = 没有可见 caret**（Drift2 实测）：
组字开始时必须 `CreateCaret(1×1) + ShowCaret`，结束清理。
这是 Win32 的怪癖，但**根因是通用的**：平台需要"一个可见的插入符"才肯定位候选框。

★ **`caretRect()` 必须能找到真正的字段节点**：有 label 的 `TextField` 会包一层布局节点，
用"父挂接的第一个盒子"去找会拿到包装层。必须用 `findNode(kind)` **穿过包装层**找指定类型
（Drift2 的 `findBox` 教训）。

## 7. 缓存与失效

| 缓存 | 键 | 容量 | 失效 |
|---|---|---|---|
| 度量 | `(fontId, size, text)` | LRU 512 | 字体加载 |
| 整形 | `(fontId, size, text, width)` | LRU 256 | 文本/宽度变 |
| 字形位图 | `(fontId, size, glyphId)` | 位图图集 | 字体加载 |

★ **缓存键里必须有 `width`**：同一段文本在不同宽度下断行不同。
漏了 `width` 的症状是"窗口缩放后文本不重排"——看起来像布局没触发。

★ **缓存是纯函数的一部分**：`shape(text, width)` 加不加缓存，输出必须相同。
所以缓存**不得影响正确性**，只影响速度——这让 golden 在缓存命中/未命中时结果一致。

## 8. 编辑交互的细节（v6 补齐）

> 前面七节讲"怎么量、怎么整形、怎么编辑"。这一节讲**用户手指头那点事**——
> 它们全是"看起来简单、写起来必错"的地方。

### 8.1 拖选 vs 滚动：按方向裁决，不按距离

```
水平位移 > 垂直位移 ⇒ 选文本
垂直位移 > 水平位移 ⇒ 滚动
```

★ **为什么是方向不是距离**：方向是用户已经表达的意图，距离只是量。
按距离裁决会在"斜着拖"时随机选一个，体验是"有时候选中、有时候滚了"。

★ 两者都要进 `GestureArena`（[07](07-输入与焦点.md) §3），不能各自判断。

### 8.2 边缘自动滚动 = 帧驱动源

★★ 拖选到视口边缘要自动滚动。**必须实现为"自循环请求帧，直到松手"**：

```
进入边缘区 ⇒ requestFrame 自循环（每帧滚一点）
离开边缘 / 松手 / 取消 ⇒ 停止循环
```

★ 写成"在 `onMove` 里滚一次"的症状是：**拖到窗口外就不动了**
（因为鼠标不再移动 ⇒ 没有 `onMove`）。这不是优化，是功能是否成立。

### 8.3 双击选词：CJK 要另立规则

| 文本 | UAX#29 的结果 | 用户期望 |
|---|---|---|
| `hello world` | `hello` | `hello` ✓ |
| `任务管理` | **`任`**（每个汉字算一个词） | `任务管理` |

★ UAX#29 对 CJK 是"每字一词"——这是标准的规定，不是 bug。
产品决策：**双击选"连续同脚本字符段"**，不直接照抄 UAX#29。

★ 这条必须写死，否则实现者会"照标准做"，然后被用户报"双击只选了一个字"。

### 8.4 选区绘制四条

| 规则 | 不这么做的症状 |
|---|---|
| 多矩形（每行一个） | 跨行选区只能整块高亮 |
| **行尾延伸半个字宽** | 选中整行时看不出"含换行" |
| **空行也占一个矩形** | 选中空行时视觉上断成两截 |
| **失焦变灰，不消失** | 点别处后选区消失 ⇒ 用户以为丢了 |

★ 选区画在**绘制相**、与文字同层（否则滚动时错位）。

### 8.5 拖选不写 `Cell`

★ 拖选过程中只更新 `node.local`，**松手时提交一次** `onSelectionChanged`。
理由：拖选是每秒几十次的高频动作，写 `Cell` = 几十次依赖检查 + 布局。

★ 这与 [20](20-动画与过渡.md) §2 同构：**`Cell` 存意图，`node.local` 存过程。**

### 8.6 撤销栈的内存上限（要算，不要估）

| 文本规模 | 步数 | 全量快照内存 |
|---|---|---|
| 10⁴ 字 | 100 | **3MB**（可接受） |
| 10⁵ 字 | 100 | **30MB**（不可接受） |

★ 判据：**全量快照上限 10⁴ 字，超过改 diff**。
这条不是拍脑袋——按"每字符 ~300 字节（含 span 结构）"算出来的。

★ 三条撤销纪律：
1. 新编辑清空 redo 栈；
2. 撤销后**必须调一次** `onChanged`（否则受控方不知道值变了）；
3. 撤销后光标 = 快照里的选区（不是"末尾"）。

### 8.7 剪贴板换行

★ 内部存 `\n`，**出口转 `\r\n`，入口转回**。方向容易搞反——
搞反的症状是"粘贴进来多了一堆空行"或"复制出去在记事本里挤成一行"。
