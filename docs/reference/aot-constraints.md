# AOT 约束与代码纪律

> 把 tpc → C++17 的编译器事实翻译成可执行的编码纪律，并说明守不住时问题会在哪一层暴露。

## 怎么读这份文档

每一条约束都按同一个顺序展开：先是**编译器事实**，说明生成物或真机里实际发生了什么；再是**代码纪律**，说明在 `src/` 与 `apps/` 里应该怎么写；最后是**否则怎样**，说明违反之后在哪一层暴露、是否会静默。三段分开写，是为了让"知道结论"和"知道为什么"能分别被审查。

只写现行有效的约束。已经被解禁或被推翻的旧结论不写成条文，也不复述它曾经是什么。凡涉及分派形态的结论，都会标明口径：`apps/*` 是 `bin` 口径（编译出 exe），`tools/drift-codegen.php` 是 `lib` 口径（SDK 分发）——同一份源码在两种模式下生成物可以不同。

## 一、类型退化：用具体类型加哨兵

**编译器事实。** 真实混合联合、`mixed`、`callable`、`?array`，以及两支类型不同的三元表达式，合流后都退化成 `php::Var`。`php::Var` 传进形参声明为 `float` 或原生 `Int` 的方法时，生成的 C++ 类型对不上。可空对象形参和返回值现在生成 `php::Object` 加可空守卫，不再退化。

**代码纪律。** 热路径只用具体类型。需要表达"没有值"时，对象字段用"非空对象 + `bool` 标志"；标量字段用带内哨兵，浮点用 `\NAN`，整数用 `-1`。纯对象联合、交叉类型、DNF 对象声明可以正常写，不必为此拆签名。

**否则怎样。** 退化本身不报错，但一旦流进带类型的形参就变成编译期 C2440。这类退化在解释器里完全正常，只有 AOT 产物会出问题。

## 二、switch 与 `int $kind` 比较链

**编译器事实。** 在 `$this->intProp` 上写 `switch`，生成物会先经属性表取值再转成 C++ 整数，历史上在这里生成过无法编译的形状。现在仍按禁用处理：该形状没有系统复测，也没必要为它冒险。

**代码纪律。** 热路径用 `int $kind` 配合 `===` 比较链代替 `switch`，例如 `ToggleBase::activate()` 与 `Curve::map()` 的写法。`match` 可以继续使用，但它是否生成跳转表未经证实，不把它当作性能承诺。

**否则怎样。** 违反后在 C++ 编译期报 C2440，不会拖到运行期。因为全仓已经没有 `switch`，这条纪律目前没有消费者，但仍然生效——一旦有人新加，就会踩中。

## 三、三元与属性读取

**编译器事实。** 三元 `?:` 的两支声明类型不同时，C++ 没有对应的运算符重载，报 C2678。把 `$this->box->maxWidth` 这类属性读直接当实参传给形参是 `float` 的方法，会先得到 `php::Variant` 再传 `float`，报 C2440——这是本仓最高频的同形状错误，而且没有 lint 能覆盖，因为"哪个形参是 `float`"需要跨类类型推导，PHP 本身没有静态类型。

**代码纪律。** 两支类型不同的三元拆成 `if/else`。属性读先落到局部标量再传参，不内联进调用。

**否则怎样。** 三元在编译期报 C2678，属性读在编译期报 C2440。属性读这一条只能靠 T2 兜底：解释器、lint、smoke 都发现不了，只有真机 AOT 构建会拦住。

## 四、对象模型：继承字段与 `#[\Native]`

**编译器事实。** 父类声明的 `private` 字段不进子类的属性表；tpc 按运行时类型查属性表，所以在子类实例上访问父类 `private` 字段会报 `Undefined property`，或者动态新建一个属性并读到 `NULL`。`readonly` 属性不能在构造之外赋值。`#[\Native]` 类不能进 PHP 数组、不能持有容器、不能作 Fiber 参数。

**代码纪律。** 会被继承的类，字段一律用 `protected`——`Element` 的 `$box`、`$mounted`，`RenderFlex` 的字段都是这样，语义不变、只放宽可见性。可变字段用 `private`，不要图省事标 `readonly`。纯 PHP 类做树节点，`#[\Native]` 只做叶子值对象。内置编译期注解一律写全 `#[\X]`，命名空间内裸写 `#[X]` 会静默解析成当前命名空间下的类而失效，lint 规则 `attribute-unqualified` 守这一条。

**否则怎样。** 继承字段用 `private` 是最隐蔽的一条：解释器与 smoke 全绿，只有真机上子类读到错值导致布局错误，例如 `RenderAppBar extends RenderFlex`。`#[\Native]` 做节点会在跨数组或过 Fiber 时失败。注解不写反斜杠则不报错、只是没效果。

## 五、闭包 arity

**编译器事实。** AOT 严格校验回调的实参个数，PHP 解释器会忽略多传的实参。派发点固定传几个参数，回调就必须声明几个形参，少一个就在真机报 `Fatal: expects exactly N argument, M given`，被错误边界接住后整页变错误占位，而且日志里看不出是 arity 问题。

**代码纪律。** 按槽位固定签名写回调：`keyboard`、`pointer` 回调收两个形参，`function (KeyEvent $event, Element $self)`、`function (PointerEvent $event, Element $self)`；`hover` 回调收一个形参，`function (bool $entered)`。内联闭包和"`$this->keyHandler()` 这类返回闭包的间接工厂"两种形态都要守。不要照搬那种靠上下文对象或 phase 闭包少声明参数的写法。

**否则怎样。** 违反后解释器、lint、smoke 全绿，真机整页错误占位。lint 规则 `callback-arity` 按写死的期望值守这条，既管内联闭包也管同文件内的间接工厂；变量传入、跨文件工厂、首参不是闭包字面量也不是方法调用的形状它不检查，这些地方要靠 T2 兜。

## 六、可空对象：解禁边界与仍然守的字段层

**编译器事实。** `?Obj` 形参、`?Obj` 返回值，以及链式调用的接收者，现在都生成 `php::Object` 并保留静态类：`bin` 口径下 `Box::make()->add(1)->add(2)->value()` 全静态直调，没有缓存调用。但对象字段存进的是 PHP 属性表——可空字段与非空字段的写入生成同形，读点也只是"多一次空检查"对"多一次布尔检查"，没有量级差。非空对象字段的属性访问是内联缓存读，不是静态偏移读。

**代码纪律。** 形参、返回值、链式都可以按可空或链式写，热路径不必再为了静态分派把链式拆语句。字段层继续用"非空对象 + `bool`"或带内哨兵。要避开的是 `$this->可空字段?->m()` 这一族写法：空安全调用按运行时类名查表读属性，跨实例读 `private` 或在该形状上读到 `null` 是静默的，与静态类型是否退化无关。先取局部变量再判空再调用。

**否则怎样。** 链式在 `lib` 口径下去虚化不生效，第二跳起仍是动态分派，所以"已解禁"只在 `bin` 口径成立。`?->` 的静默读空在解释器、smoke、真机都可能发生且不报错，只能靠写法规避。

## 七、readonly 标量属性的现行生成形状

**编译器事实。** 当前编译器下，`readonly` 标量属性的读生成 `php::toFloat(typephp_read_property_scoped(o, …, get_persistent_class(…)))` 这类形状：带检查的 Zend 结果与作用域类解析；非 `readonly` 属性读生成 `php::toFloat(o.attr(get_persistent_prop(…)))`。两者不再逐字相同——`readonly` 读多一次函数调用和一次类解析，属于常数级退化，折算后远小于帧预算门槛。`readonly` 自身不等于慢；真正贵的是 getter 方法调用。

**代码纪律。** 继续用 `final readonly class` 与 `readonly` 属性表达不可变值对象，不为了这点常数级退化把它改成可变类。类内一律直读 `$this->x` 不走 getter——`#[\Getter]` 生成的 `getXxx()` 是普通方法调用，"不用手写"不等于"运行时免费"。

**否则怎样。** 去掉 `readonly` 换不回直接槽位读：getter 更慢，去掉 `readonly` 还丢了不可变性。这条约束的价值是让人别为伪优化牺牲不可变性，而不是让人回避 `readonly`。

## 八、C++ 侧整数除法与截断

**编译器事实。** 默认原生标量模式下，推断出的 `int` 局部变量固定为 C++ 原生整数，两个原生整数相除直接落 C++ 的 `/`：`7 / 2` 得到 `3`，而非整除的 PHP 语义应得 `3.5`。这一条静默——不崩、不报错、编译期无警告，只是数值偏。`int / float`、`float / int`、`float / float` 都不受此影响，只有两端都是整数时才错。官方提供文件级 `use varint_types;` 与单表达式 `std::any($v)` 恢复 Zend 算术，但那会跳过整数优化 pass、改变浮点除法和常量求值，本仓不启用。

**代码纪律。** 除法两端至少有一个写成 `(float)`，让非整除保留小数。优先用局部的 `(float)` 或 `std::any()`，不为了这一条给整文件加 `use varint_types`——那是兼容出口，不是推荐默认值。

**否则怎样。** 违反后数值静默偏小，几何或进度类计算会悄悄错位，任何解释器侧验证都发现不了。若某个文件确实需要 Zend 整数扩展语义而引入 `use varint_types;`，必须重跑 AOT 等价与指纹检查，不能用"解释器绿"代替。

## 九、降级诊断与错误码

**编译器事实与运行时事实。** AOT 约束分两种失败方式。能静态判定的写法问题交给 lint；"没报错但能力静默退化"由 `Diagnostics::degraded($key, $message)` 报告，统一带 `[DX] ` 前缀，按 key 只报一次、不中止程序；判决级的失败由 `Errors::report()` 处理，Fatal 写 `Errors.log`、弹原生错误框并 `exit(3)`。异步路径里，结构化错误用具名 Failure 码传递，应用侧读码即可，不必 `instanceof`。

**代码纪律。** 新踩一条 AOT 坑，先在本文件登记约束与错误码，再写进源码注释（若有具体位置）。给静默退化加可观测性时用 `Diagnostics::degraded()`，不要直接 `Errors::report(DIAGNOSTIC)`。登记外部证据时要写清来源、编译器版本以及本仓是否独立复测；没复测的只能进纪律，不能写成实测结论。

**否则怎样。** 不登记，下一次就会有人重新踩同一个坑；退化不报告，就变成"日志无痕"的静默故障。常见 C++ 错误码：`C2440`（三元/属性读类型不匹配、`switch` 取值）、`C2678`（`?:` 两支异型）、`C2065`（嵌套常量链）、`C2872`（类常量与方法同名）、`C3861`（Skia 重载参数不符）、`C2653`（Skia API 改名）、`C2660`（函数实参个数不符）、`C2129`（匿名命名空间外的 static 转发声明）。错误分级与 `[DX]` 日志的完整口径见[诊断与错误码](./diagnostics.md)。

## 十、怎么验证

约束是否有效，按三层验证，判据清单只在 `php bin/drift verify --list`：

- **T0**，纯 PHP：跑 lint 与静态判据，覆盖 `callback-arity`、`attribute-unqualified`、`str-concat-loop` 等可静态判定的纪律。
- **T1**，dev 壳：`php tools/drift-dev.php <app>`，改 `apps/<app>/src/` 的 PHP 即时生效，能验解释器和壳层逻辑，但验不了 AOT 生成物。
- **T2**，真机 AOT：`php tools/drift-build.php <app> --full` 加真机探针。属性读 arity、`#[Native]` 做节点、继承字段 `private`、`?->` 静默读空、整数除法截断这些只有 T2 能拦住。

改 `src/` 或 `cpp-src/` 必须跑 T2 重编译验证。命令入口与分层细节见[命令速查](./cli.md)，测试分层与 CI 见[协作流程](../contributing/workflow.md)。
