## 2. 对上一轮设计稿 §5 的三处订正

### 2.1 不引入 `patternMask`

§5 计划让 PHP 推一个能力位、C++ 按位分派。复核后否定：

- **结构**：「能力」是语义数据的**派生物**。再加一个 mask，等于同一事实存两份
  （控件声明一次、mask 再算一次），漂移时 UIA 与语义树会给出相反答案。
- **DX**：若让控件手写 mask，就把 `UIA_*PatternId` 这类平台编号漏进跨平台
  Widget 层；若由框架算，mask 只是 `UiaNode` 已有字段的冗余投影。
- **更优解**：C++ 侧把 `simplePattern()` 改成**分派表**
  `{PATTERNID, predicate(nodes, idx), make(...)}`。predicate 只读 `UiaNode` 的
  语义数据，新增能力 = 加一行表项，不再堆 if 链。这条走的是 Chromium
  `AXNodeData` + 平台桥映射、Flutter `SemanticsConfiguration` 的路子：
  渲染层填语义属性，平台层只负责翻译。

### 2.2 `ITextProvider` 不是「薄实现」

§5 说 `DocumentRange` 覆盖整串即可。复核官方契约后否定：`ITextProvider`
的 `DocumentRange` / `GetVisibleRanges` / `RangeFromPoint` 都必须返回
`ITextRangeProvider`，后者是一整套字符级 API（Move / ExpandToEnclosingUnit /
GetText / GetBoundingRectangles / Select / AddToSelection …）。语义树只有整串
`value`，没有字符度量与选区 ⇒ 做出来必然是「能 `GetCurrentPattern`、方法全回空」
的空壳，而 UIA 核心对空壳不报错 —— 正是本项目反复踩的假绿。

`IGridProvider` 需要 `gridRow/gridCol/rowCount/colCount`，`IScrollProvider` 需要
滚动百分比与视口尺寸，当前 `SemanticsNode` 都没有。**三者一并推迟**，
前置条件写进 §5，不做无数据面的空壳。

### 2.3 真债务是「一个字段改六处」

`SemanticsNode` → `toArrays()` → `pushSemantics()` → `a.get()` → `UiaNode` →
`simpleProperty()`，任一处漏改都静默。光加字段不解决可维护性。
**补一条三向静态对账**进 `tools/cpp-bridge-check.php`（`verify --fast` 的
`cppbridge` step）：`toArrays()` 的键集（扣掉 devtools 专用键）必须与 C++
`a.get()` 的键集完全相等，缺一侧直接红。

## 3. 本轮落地范围

1. **属性面**：`hint` / `automationId` / `acceleratorKey` 三个标量语义字段，
   C++ 答 `UIA_HelpText` / `UIA_AutomationId` / `UIA_AcceleratorKey`。
   空串留 `VT_EMPTY`（不答），与既有三态同款纪律。
2. **事件面**：`driftUiaApply()` 按**节点身份** diff（结构变了交给
   `ChildrenInvalidated`），对 name / value / enabled / focusable 发
   `UiaRaiseAutomationPropertyChangedEvent`；文本节点 value 变化额外发
   `UIA_Text_TextChangedEventId`。两个事件都要：读屏客户端订阅的是事件，
   不是快照。
   ★ 身份 = `key` 非空取 `key`，否则取 `automationId`，两者都空则跳过。
   只认 Element key 会迫使业务为「可被观察」额外加布局层身份 —— 而
   `automationId` 本来就是给自动化的稳定标识，用它认节点是同一份事实；
   两者都空仍跳过，保留 §66「不按索引比」的纪律（滚动/排序会误报）。
3. **能力面**：分派表化 + 新增**一个**从现有数据派生的容器
   `ISelectionProvider` —— `GetSelection()` 从 `parent == idx && selectState == 2`
   的子节点生成，零新增传输字段、零第二份真相。
4. **判据**：PHP 行为判据 + 三向静态对账 + 真机探针（属性 / Pattern / 事件），
   变异逐组真红。
5. **真消费者接线**：`FormPage` 的「搜索」`onChanged` 补 `setState`。
   `SetValue` 与键盘输入共用 `onChanged`，框架契约把「值变化要不要重建」交给应用；
   只赋值不重建时 provider 报成功、语义树却是旧值 ⇒ 读屏读到陈旧 Value、
   也收不到 TextChanged。没在框架里替应用重建，是为了不让「UIA 写值」与
   「键盘输入」走两套重建语义。

## 4. 剩余边界（诚实记录）

- `ITextProvider` / `ITextRangeProvider` / `IGridProvider` / `IScrollProvider`
  未落地；前置数据面见 §2.2。官方约 30 个 Pattern，当前 7 个。
- 属性变更事件的**行为判据**只验到 `TextChanged`（普通 automation event，
  复用现成 `AutomationEventSubscription`）。`AddPropertyChangedEventHandler`
  需要另一套回调 IID（`40cd37d4-c756-4b0c-8c6f-bddfeeb13b50`）与按值
  `VARIANT` 的 ctypes 回调签名，且 vtable 槽位是 **35**（34 是
  `…NativeArray`，数错就崩）；本轮不实现，`UiaRaiseAutomationPropertyChangedEvent`
  的调用由 `cpp-bridge-check.php` 的结构对账盯住。
- 真机判据有两条通道：`probe-uia-state.py` 的扩展判据要真实输入（桌面锁定会
  SKIP），`tools/probe-uia-p02.py` 全程走 UIA COM（`Invoke` 切页 / `SetValue`
  改值），不需要前台窗口。
- 顶栏焦点链硬编码「Tab 4 次」仍是脆弱判据（P0-3 遗留），本轮不碰顶栏。
- 真机实测两个坑：showcase 顶栏也有一个「搜索」**Button**，按名字取第一个
  会拿到按钮（属性全空、无 `ValuePattern`），判据必须按 `ControlType == Edit`
  挑节点；空串属性在客户端侧读到 `VT_BSTR ''`（UIA 核心兜底），不是
  `VT_EMPTY` —— 别把「没答」写成 `is None`。
