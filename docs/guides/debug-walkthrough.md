# 调试器上手：5 分钟从简报到定位

> 本篇是任务型入口：第一次用 Drift 调试器时，按什么顺序问，5 分钟内从一个"看起来不对"的页面走到一个具体节点与那一帧。命令的全量参数看[命令速查](../reference/cli.md)，"为什么这么记"看[调试模型](../concepts/debug-model.md)。

调试器不替你判断"哪个控件是坏的"，它回答三个能站得住的问题：这一帧发生了什么、为什么变成这样、证据在哪。这篇按"你现在想知道什么"组织，每一步都给出能直接跑的命令和该看哪一列。所有命令从 `php bin/drift debug <动词>` 进，省略动词等同 `report`。

## 第 0 步：先有一份证据

后面每一条追问都对着**同一次运行**，否则两次运行的时间戳与异步交付顺序不同，你会拼出一个不存在的因果。最简单的一次运行是：

```
php bin/drift debug brief --page=table --frames=2
```

`--page` 给路由 id（也可以是应用类名），`--frames` 推几帧。同一个页面名、同一组动作驱动出来的证据，可以被任意多个出口反复读——这就是黄金路径成立的前提：**一次驱动，多次追问**。

## 第 1 分钟：先读简报，不要先猜节点

```
php bin/drift debug brief --page=table --frames=2
```

简报按固定顺序给三样东西，先看前两样：

- **发现**：预算内"哪里不对、为什么、下一步查哪"。每条发现带一个**地址**（形如 `frame:1 node:32 w`），它就是后面所有追问的入口——带着帧号和节点号一起用，只用节点号会拿当前帧的几何去配旧发现。
- **帧行**：最慢帧的分段耗时与"段外"耗时。段外大说明时间花在框架没打点的地方，别在分段里找。
- **裁剪账**：这一域采没采、窗口多大。写"绘制未采集"就是真的没采，不是"这帧没画"。

看到一条发现，先记下它的 `frame:N node:M`，再进入第 2 步。发现讲的是布局收紧、重建扇出这类可复算的事实，不是"建议怎么改"——改法要结合你的页面语义。

## 第 2 分钟：按地址追问一个节点

拿着第 1 步的地址，把三域对齐：

```
php bin/drift debug node table --node=32 --frame=1
```

这一行给出同一个节点的因果（这一帧在不在、有没有重建）、几何（尺寸）、网络（有没有落地请求）与各自的窗口覆盖。四个问题一次答完，不用分别跑三个出口。

要问"它为什么重建、谁一路写下来的"：

```
php bin/drift debug report --page=table --frames=2 --why=32
```

`--why` 摊开这个节点的父链与终点写入点。看不懂树上的 `×N` / `>` 记号时回到[调试指南](./debugging.md)的"问帧因果"一节——那里逐条解释了同形折叠与单链折叠。

## 第 3 分钟：画面不对，看几何与那一帧的树

节点号对不上你眼睛看到的控件时，按帧回放结构树：

```
php bin/drift debug tree --page=table --frames=2 --frame=1 --depth=4
```

`--frame` 决定回放**哪一帧**：那时还没出生的节点不出现，那时已离开的节点也不出现，而今天已经回收、当时还活着的节点照样画出并标注。行尾的"重建"说明这一帧动过它。几何按同一帧贴好。比两帧之间发生了什么：

```
php bin/drift debug tree-diff --page=table --frames=6 --base=2 --frame=4
```

`--base` 不含、`--frame` 含，所以 `(2,4]` 与 `(4,6]` 正好拼成 `(2,6]`。它只报出生 / 离开 / 重建——没有逐帧类型与父快照，移位与改型不报，这是能力边界不是漏报。

要看真机像素加几何线框，另起一个终端：

```
php bin/drift debug web --page=table
```

浏览器里点画布上的盒与结构树双向联动；`0` 适配、`1` 回真机 1:1。**画面不进证据**：它不参与指纹、不进基线，`--assert` 不看它——像素是给人看的，断言只认数字。

## 第 4 分钟：从一段文本或一个请求倒着找

不知道节点号、只知道界面上写着什么：

```
php bin/drift debug find --page=table --frames=2 --pattern=SizedBox
```

命中的是**自身类型**，不是含祖先的整条路径（搜 `Table` 不会把整棵子树都算命中），产物是可被别的出口直接解析的地址 `node:N` / `request:N`。搜索按字面文本，不做正则、不打相关度。它给 `scanned` / `matched` / `returned` 三数：0 条结果时先看 `scanned`，是"没采到候选"还是"搜了没命中"，两者的下一步动作相反。

网络没回来时看骨架与落地帧：

```
php bin/drift debug network --page=async-table --frames=4 --resolve
```

请求原文默认不采，出口会明说 `bodies-not-captured` 而不是返回空——那是"没开"和"开了但为空"的区别。要按请求看它落地时重建了什么，用 `find` 拿到的 `request:N` 地址继续追问。

## 第 5 分钟：把现场存下来，让结论可复现

一次性的观察不算证据；能重跑才算。存成脚本：

```
php bin/drift debug report --page=table --frames=2 --save=case.json
php bin/drift debug report --replay=case.json --at=2
php bin/drift debug report --replay=case.json --verify
```

`--save` 存帧边界、输入、具名副作用与目标 / 视口；`--replay` 在**新进程**里重跑（不是恢复快照，`State` 里的闭包存不下，能重跑是因为布局是纯函数、时钟是注入的）；`--verify` 跑两遍比对节点表与逐帧因果，不一致退出 3，可直接进 CI。`--at=N-1` 与 `--at=N` 各跑一次，"第 N 帧发生了什么"就出来了。

## 症状 → 第一步

不确定从哪开始时，按你看到的现象选第一行：

| 你看到的现象 | 第一条命令 | 为什么是它 |
|---|---|---|
| 页面整体慢 / 不知道哪里不对 | `debug brief` | 发现 + 最慢帧分段先收窄范围 |
| 一个控件尺寸 / 位置不对 | `debug brief` 拿到地址，再 `debug node` | 几何与因果在同一行对齐 |
| 一个控件反复重建 | `debug report --why=<节点>` | 摊开写入点与父链 |
| 这一帧和上一帧比变了什么 | `debug tree-diff --base=A --frame=B` | 事件取生命周期两端，不是两棵被截断的树相减 |
| 知道文案 / 类型，不知道节点号 | `debug find --pattern=…` | 产物是能被继续追问的地址 |
| 数据没落地 / 请求回来了界面没变 | `debug network`、`debug async` | 骨架与结算帧、落地节点 |
| 想看真机长什么样 | `debug web` | 真机像素打底 + 几何线框，画面不进证据 |
| 想对着读屏视角看 | `debug a11y` | 语义树是 L2 内省；下标是 UIA 下标，不是结构节点号 |

## 什么时候换工具

三个出口各解决"一次驱动"不够用的一种情况，参数与上面同一套：

- **`debug panel`**：同一次运行里反复追问，时间轴 + 因果树 + 原因，`Tab` 切换。`--keys=j,j,enter,w,q` 把键盘操作变成可进 CI 的非交互模式。
- **`--remote`**：多问题对着同一次运行、且要跨进程验证读到的值一致时加在任一驱动出口上；报告由同一段代码组装，头行出现"（宿主进程 N）"就是真的交出去了。
- **`debug serve` + `--attach`**：页面自己在跑，你只想连上去看。起一个常驻宿主，另一个终端用 `debug brief --attach` 只读地接；`ctl` 让它 pause / 单步 / 继续。dev 壳还能以 `DRIFT_DEBUG_LIVE=1` 接真窗口（`debug pick-live` 布防后点选），那是 dev 形态，发布产物不做。

遇到退出码时先查[命令速查](../reference/cli.md)的退出码表：`0` 完成 / `1` 进程异常 / `2` 这次不能继续 / `3` 判据不通过。应用自身的 Fatal 也用 `3`，那是产物进程的码，与 CLI 无关。

## 三条别踩的边界

1. **诊断器不给改法**：规则给地址、度量、阈值与复算方式；"怎么改"是你结合语义判断的事。把 `--min-severity` 过滤光了会报 `suppressed`，不是 `clean`——"我没看"不等于"没问题"。
2. **内省不是证据**：`debug eval` / `debug probe` / `debug a11y` 当场读活对象，不进证据包、不进指纹。`eval` 默认关、只绑 loopback；`a11y` 的语义下标不能拿去 `debug node --node=N`。
3. **没采 ≠ 没有**：绘制 / 异步 / 报文正文默认关，窗口只有有限帧。看到"未采集"先决定要不要开采集，别把空窗口读成"没有发生"。
